# 03. 근태관리 (Attendance)

## 1. 개요 및 조정사항

원본 요구사항: 현장별/개인별 근태 등록, 휴무·연차·병가 기록 및 일수 관리, 업무일지 작성.

**조정**: 생체인증·GPS 기반 출퇴근 체크(위치 검증)는 제외하고 **수동 체크인/체크아웃 버튼** 방식으로 구현합니다. 연차 일수 자동 계산(근속연수 기반 법정 연차 산정)까지는 포함하되, 회계연도별 이월/소멸 같은 세부 인사 규정은 단순화합니다.

## 2. 사용자 스토리

- 직원으로서, 출근/퇴근 시 앱(또는 웹)에서 버튼 하나로 체크인/아웃하고 싶다.
- 직원으로서, 연차를 신청하면 지점 관리자가 승인/반려할 수 있길 원한다.
- 지점 관리자로서, 우리 지점 직원들의 이번 달 근태 현황(지각/결근/휴가)을 한눈에 보고 싶다.
- 직원으로서, 오늘 업무일지를 작성해 관리자와 공유하고 싶다.

## 3. 데이터 모델

### AttendanceRecord
| 필드 | 설명 |
|---|---|
| id, staffId(FK), date | 하루 1레코드 (staffId+date unique) |
| checkInAt, checkOutAt | datetime, nullable |
| status | enum(정상, 지각, 조퇴, 결근, 휴가) — 서버에서 checkInAt과 지점별 출근기준시각 비교해 자동 산정 |
| note | 관리자 메모(선택) |

### LeaveRequest
| 필드 | 설명 |
|---|---|
| id, staffId, type(연차/병가/경조사/기타), startDate, endDate, days(자동계산), reason, status(대기/승인/반려), approverId, reviewedAt | |

### LeaveBalance (연차 잔여일수)
| 필드 | 설명 |
|---|---|
| id, staffId, year, totalDays(입사연차 기준 자동계산), usedDays, remainingDays(computed) | |

### WorkLog
| 필드 | 설명 |
|---|---|
| id, staffId, date, content(text), createdAt | staffId+date unique(하루 1건 권장, 수정은 가능) |

인덱스: `AttendanceRecord(staffId, date)` unique, `LeaveRequest(staffId, status)`

## 6. 비즈니스 로직 & 엣지케이스

- **체크인 중복 방지**: 동일 staffId+date로 이미 checkInAt이 있으면 409 에러(`ALREADY_CHECKED_IN`)
- **자동 지각 판정**: 지점별 `Branch.standardCheckInTime`([00문서 §2-1](00_공통설계서.md#2-1-branch지점-데이터-모델--위탁계약-필드) 참고, 예: 09:00) 설정값과 비교해 10분 초과 시 `지각`으로 자동 분류
- **결근 자동 처리(배치)**: 매일 자정 스케줄러(Cron)로 "당일 checkInAt이 없고 승인된 휴가도 없는 재직자"를 `결근`으로 자동 기록 — 관리자가 매번 수기로 표시할 필요 없게 함
- **연차 일수 계산**: `days = (endDate - startDate + 1)`, 주말 제외 여부는 Phase 2. 신청 시점에 `remainingDays < days`면 400 에러로 신청 자체를 막지 않고 경고만 표시(실무상 마이너스 연차 허용 케이스 존재 — 관리자 재량으로 승인 가능하게 설계)
- **승인 시 잔여일수 차감**: 승인 시점에만 `usedDays += days` (신청만으로는 차감 안 함 — 반려 시 복구 로직 불필요해짐)
- **업무일지 관리자 열람**: 지점 관리자는 본인 지점 전 직원 업무일지 열람 가능(원본 "본사→현장 업무일지" 요건과 연결 — 04 게시판 문서의 게시판 성격과는 별개로, 근태 도메인 내 데이터로 유지)

## 7. 권한/보안 규칙

- Staff(Role=STAFF)는 본인 근태/휴가/업무일지만 CRUD — 01문서의 STAFF 권한에 따라 동료 직원 데이터는 조회 자체가 차단됨
- BRANCH_ADMIN은 본인 지점 소속 Staff 전체의 근태 조회 + 휴가 승인 권한, 근태기록 직접 수정은 관리자만(정정 사유 필수 입력)
- SUPER_ADMIN은 전 지점 조회만(현장 운영에 직접 개입하지 않는 원칙)

## 8. 구현 우선순위

**Phase 1(필수)**: 체크인/아웃, 월별 근태 조회, 휴가 신청/승인, 잔여연차 표시
**Phase 2(선택)**: 자동 결근 배치, 지점 근태 요약 대시보드, 업무일지, 근태 정정 이력(AuditLog 연동)
