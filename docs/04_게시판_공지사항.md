# 04. 게시판(공지사항) (Board)

## 1. 개요 및 조정사항

원본 요구사항: 본사→현장, 현장→이용자 별도 게시판. 본사→현장 게시판에는 교육 매뉴얼/자료 탑재 기능 추가.

**조정 없음** — 이 기능은 CRUD 게시판으로 원본 그대로 구현해도 1인 개발 부담이 크지 않아 **거의 원본 그대로** 구현합니다. 다만 "댓글", "좋아요" 등 커뮤니티성 부가기능은 범위에서 제외합니다.

## 2. 사용자 스토리

- 본사 관리자로서, 전 지점(또는 특정 지점)에 공지를 올리고 필요시 교육자료 파일을 첨부하고 싶다.
- 지점 관리자로서, 본사 공지를 확인하고 우리 지점 회원들에게 전달할 공지를 따로 작성하고 싶다.
- 회원으로서, 내가 다니는 지점의 공지사항을 앱에서 확인하고 싶다.

## 3. 데이터 모델

### Post
| 필드 | 설명 |
|---|---|
| id | UUID |
| scope | enum(HQ_TO_BRANCH, BRANCH_TO_MEMBER) |
| branchId | FK, nullable — scope=HQ_TO_BRANCH이고 전체공지면 null(전체), 특정 지점 대상이면 지정 |
| authorId | FK → Account |
| category | enum(공지, 교육자료, 이벤트, 기타) — scope=HQ_TO_BRANCH일 때 "교육자료" 카테고리로 이용자 매뉴얼 탑재 요건 커버 |
| title, content | text |
| attachments | Attachment[] (별도 테이블: url, fileName, fileType) |
| pinned | boolean — 상단 고정 |
| viewCount | int |
| publishedAt | datetime |
| createdAt/updatedAt | |

### Attachment
| 필드 | 설명 |
|---|---|
| id, postId(FK), url, fileName, fileType, fileSize | 이미지 또는 문서(매뉴얼 PDF 등) |

### PostReadReceipt (선택, Phase 2 — 읽음 확인)
| 필드 | 설명 |
|---|---|
| id, postId, accountId, readAt | 공지 열람 여부 추적 |

인덱스: `Post(scope, branchId, publishedAt DESC)` — 목록 조회 최적화

## 4. 화면 목록

| 화면 | 대상 | 설명 |
|---|---|---|
| 본사 공지 목록/작성 | SUPER_ADMIN | 전체/특정지점 대상 선택, 첨부파일 업로드 |
| 지점 게시판(본사 공지 열람) | BRANCH_ADMIN | 본사 공지 확인 |
| 지점 공지 작성 | BRANCH_ADMIN | 이용자 대상 공지/이벤트 작성, 이미지 첨부 |
| 회원 공지함 | Member(앱) | 우리 지점 공지 목록/상세 |
| 교육자료함 | BRANCH_ADMIN | 본사가 올린 "교육자료" 카테고리만 모아보기(원본 "게시판 내 직원관리 탭" 요건) |

## 5. API 명세

| Method | Endpoint | 권한 | 설명 |
|---|---|---|---|
| GET | /api/v1/posts?scope=&branchId=&category= | scope별 권한 분기 | 목록(페이지네이션) |
| POST | /api/v1/posts | SUPER_ADMIN(HQ_TO_BRANCH), BRANCH_ADMIN(BRANCH_TO_MEMBER) | 작성 |
| GET | /api/v1/posts/:id | 열람 권한자 | 상세, viewCount 증가 |
| PATCH | /api/v1/posts/:id | 작성자 본인 | 수정 |
| DELETE | /api/v1/posts/:id | 작성자 본인 또는 SUPER_ADMIN | 삭제(소프트) |
| POST | /api/v1/posts/:id/attachments | 작성자 | 파일 업로드 |

## 6. 비즈니스 로직 & 엣지케이스

- `scope=HQ_TO_BRANCH`이고 `branchId=null`인 게시글은 "전체 지점 공지"로 취급해 모든 BRANCH_ADMIN 화면에 노출
- BRANCH_ADMIN이 작성하는 `BRANCH_TO_MEMBER` 게시글은 자동으로 본인 `branchId`가 세팅되어(수정 불가) 다른 지점에 실수로 노출되는 것을 원천 차단
- 첨부파일 업로드는 용량 제한(예: 파일당 10MB, 이미지 5장/문서 3개까지) 및 확장자 화이트리스트(jpg/png/pdf) 적용 — 보안 요구사항(임의 파일 업로드 방지)
- 삭제는 소프트 삭제(`deletedAt`)로 처리해 회원이 이미 본 공지의 참조 무결성 유지
- 회원 앱에서는 미열람 공지 뱃지(빨간 점) 표시를 위해 `PostReadReceipt` 활용(Phase 2)

## 7. 권한/보안 규칙

- HQ_TO_BRANCH 게시글 작성은 SUPER_ADMIN만
- BRANCH_TO_MEMBER 게시글 작성은 BRANCH_ADMIN(본인 지점), 회원은 읽기 전용
- 회원은 본인 소속 지점(branchId)의 BRANCH_TO_MEMBER 게시글 + 전체 HQ 공지 중 "회원 공개" 설정된 것만 조회(HQ 공지는 기본적으로 직원 대상이므로 회원에게는 비공개가 기본값 — `visibleToMember` boolean 플래그로 제어)

## 8. 구현 우선순위

**Phase 1(필수)**: Post CRUD, scope 분기, 첨부파일(이미지) 업로드, 목록/상세 화면
**Phase 2(선택)**: 읽음 확인, 상단 고정, 조회수, 카테고리 필터 UI

## 9. 테스트 체크리스트

- [ ] BRANCH_ADMIN이 작성한 공지가 타 지점 회원에게 노출되지 않음
- [ ] 전체공지(branchId=null)가 모든 지점 관리자에게 노출됨
- [ ] 첨부파일 10MB 초과/허용되지 않은 확장자 업로드 시 거부
- [ ] 삭제된 게시글이 목록에서 사라지되 기존 알림/참조는 깨지지 않음
