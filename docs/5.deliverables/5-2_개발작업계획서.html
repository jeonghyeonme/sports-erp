스포이즘 ERP 개발 작업계획서

과업 스포이즘 기업성장을 위한 ERP 시스템 개발 수행 방식 1인 개발, 기능 단위로 세로 완성 구성 Phase 0~6, 참고용 순서(실제 진행은 기능 간을 오가며 비선형적) 근거 1-1_공통설계서.md §7

적용 원칙 — 8개 기능 + 확장 범위를 날짜로 쪼개기보다, 기능 단위로 묶어 "이 정도 범위가 끝나면 이런 데모가 나온다"는 완성 단계만 정의한다. 실제 작업 순서는 기능 간을 오가며 유동적으로 진행된다.

기능 문서마다 있는 "Phase 1(필수) / Phase 2(선택)" 구분이 실질적인 우선순위다 — 범위를 줄여야 하면 각 Phase의 선택 항목부터 쳐낸다(아래 참고).

Phase별 상세

각 Phase는 완료 시점에 실제로 시연 가능한 데모를 산출물로 남긴다.

Phase 범위 데모 산출물 관련 문서
Phase 0 모노레포 구조, Git, 환경설정, DB 스키마 전체 설계, 인증 뼈대, 배포 파이프라인 로그인만 되는 빈 앱 1-1
Phase 1 권한관리(RBAC 4-Role, BranchScopeGuard) + 회원관리(핵심 CRUD) 관리자가 회원 CRUD하는 웹 1-21-6
Phase 2 인사정보관리(파견 모델) + 근태관리 직원 · 근태 관리 1-31-4
Phase 3 강사·프로그램 게시 + 예약/결제(모의) 회원 앱에서 예약 가능 1-81-7
Phase 4 게시판(공지사항) + 혼잡도관리 공지 · 혼잡도까지 완성 1-51-9
Phase 5 통합 테스트, UI 폴리싱, 배포, 발표자료(ERD·시연 시나리오) 최종 데모 4-1
Phase 6확장 자산·비품관리, 문서관리(산출물2 대응) · 부가세 분리, 매출 집계, 강사 정산 · 교육 실시 기록 확장 범위 데모 1-101-7
범위 조정
범위를 줄여야 할 경우 각 Phase 문서에 표시된 "Phase 2(선택)" 항목부터 순서대로 제외한다 — 예: 근태관리의 자동 결근 배치, 예약/결제의 노쇼 자동 처리, 혼잡도관리의 QR 자동계산 등. 핵심 기능(각 문서 "Phase 1 필수")은 유지하고, 완성도를 높이는 항목만 스트레치 목표로 미룬다.
