# 12. 원본 요구사항 추적표 및 구현 현황 차이 분석

> 이 문서는 세 가지를 다룹니다.
> 1. **요구사항 추적(Traceability)**: `reference/제안요청서 원본.pdf`(㈜유니비즈컨설팅, 2022.06)에 적힌 원문 요구사항 항목을 하나씩, 이 프로젝트의 어느 설계 문서가 어떻게 받아서 어떤 조정을 거쳤는지 표로 연결합니다(§1). 각 조정의 상세 근거는 [decisions/](../decisions/README.md)와 도메인 문서 ADR에 있으므로, 이 문서는 "원본 → 설계 문서 → 결정 근거"를 잇는 인덱스 역할을 합니다.
> 2. **설계 대비 실제 구현 상태**: 도메인별로 API·화면·자동 테스트가 어디까지 있는지, 그리고 **RFP가 요구하는데 아직 구현하지 않은 것**을 코드에서 실측한 결과입니다(§2, 2026-10-19 재실측).
> 3. **RFP 조항별 충족 판정**: 원문 요구사항 표의 글머리(•) 하나를 한 조항으로 보고 구현 / 조정 / 부분 / 미구현 / 해당 없음으로 판정한 표와 집계입니다(§3, 2026-10-19).
>
> 원본 PDF는 한글 텍스트에 ToUnicode 매핑이 없는 폰트로 저장되어 있어 `pdftotext`(poppler)로는 추출이 안 되고, PyMuPDF로 재추출했습니다(추출 결과는 세션 스크래치패드에만 존재, 저장소에는 포함하지 않음). 페이지 번호는 PDF 쪽수가 아니라 **원문에 인쇄된 쪽 번호**(p.1~9)입니다.
>
> 요구사항 정의서(`docs/deliverables/요구사항정의서.xlsx`)의 RFP 추적·충족 판정·미구현·범위 제외 시트는 이 문서의 §1·§3·§2-3·§2-4에서 자동 생성됩니다(`scripts/deliverables/requirements.py`).

## 3. RFP 조항별 충족 판정 (2026-10-19)

원문 요구사항 표(p.5 기능·성능, p.6 시스템~제약)의 글머리(•) 하나를 한 조항으로, 과업(p.3~4)·산출물(p.7)·개념도는 항목 하나를 한 조항으로 본다.

**판정 기준**
- **구현** — 조항이 말한 것을 코드·화면·문서로 그대로 했다(근거에 경로·테스트·문서).
- **조정** — 결과는 냈지만 방식을 바꿨다. 바꾼 근거가 결정(D·ADR)으로 남아 있다(예: 모의 결제, 경로 표시를 MAP으로 해석).
- **부분** — 조항의 일부만 했다. 빠진 부분은 §2-3에 있다.
- **미구현** — 하지 않았다(의도적 제외 포함 — 비고에 사유).
- **해당 없음** — 발주기관·계약·대면 행위처럼 포트폴리오 프로젝트에 대상이 없다. 집계 분모에서 뺀다.

## 4. 결론 — 다음에 채울 순서 (2026-10-19)

§1의 조정(역할 4개, 1단계 승인, 모의 결제, 혼잡도 수동 입력·5단계 자동 판정, 경로 표시, 모바일 웹)은 결정 근거가 있는 **의도된 범위 조정**이라 재작업 대상이 아니다. 9월에 세운 순서(실DB 전환·Write API·미착수 도메인·화면 연결·격리 가드 중앙화)와 10월의 RFP 문구 회복 M1~M10은 끝났다. 남은 것은 §2-3이고, 성격별로 나누면:

1. **코드로 메울 수 있는 부분 조항** — 공지 시설 지정(F4-3, `Post`에 시설 필드가 필요해 스키마 변경 승인 먼저), 세부 권한 표(F1-2·N7-2, 범위가 커서 결정 먼저). 휴무·병가 일수(F3-2)·입력 필드 속성(N6-5)·회원 웹 첨부 표시는 log/137로 끝.
2. **문서로 메울 수 있는 조항** — 사용자 매뉴얼·교육 자료(T4-1·P5), 단계별 진행 보고서(P4). 보안관리계획(N8-1)·개발보안 점검표(N2-1)·라이선스 목록(N10)은 log/139로 끝 — 점검표의 남은 조치 4건(정수 상한·임시 비밀번호·비밀번호 조합·계정별 로그인 제한)은 security-plan §8과 함께 본다. 산출물 보강(STATUS 다음 할 일 2(d))과 묶인다.
3. **사용자 작업** — 메모리 85% 경보 콘솔 적용(F10-2).
4. **의도적 제외 유지** — 기대효과 분석·유사기업 분석(P2-2·P2-3·T2-1). 재론하려면 차별화전략 §2-1의 기각 이유부터 본다.
