# 개발보안 점검표 — 구현단계 보안약점 49개

> RFP 설치및운영(1-2 #2 "소프트웨어 개발보안 준수") 대응. 계획·약점 조치표는 [security-plan](security-plan.md), 판정은 [요구사항추적표](../reference/요구사항추적표.md) §3-2 N2-1, 경위는 log/139.
> **기준**: 행정안전부 「소프트웨어 보안약점 진단가이드」(2021 개정) 구현단계 보안약점 49개 — 7개 유형(입력데이터 검증 및 표현 17 · 보안기능 16 · 시간 및 상태 2 · 에러처리 3 · 코드오류 5 · 캡슐화 4 · API 오용 2). 사용자가 고른 기준은 "행안부 47개"였고, 47개는 2021 개정 전 판이라 현행 49개로 점검했다(개정판은 XML 외부 개체 참조·서버사이드 요청 위조 등을 더했다).
> **항목 이름은 작성 세션이 가이드 원문을 받지 못해(네트워크 정책이 KISA·행안부 사이트를 막음) 기억에 의존한 목록이다 — 원문과 한 번 대조해야 한다.**

## 판정과 집계 (2026-10-19, 코드 `dev` 기준)

| 판정 | 뜻 | 개수 |
|---|---|---|
| 대응 | 코드·설정으로 막았고 근거를 적었다 | 34 |
| 부분 | 대부분 막았지만 남은 경우가 있다 — 조치 칸에 무엇을 할지 | 4 |
| 해당 없음 | 이 스택(TypeScript·Node·React, 해당 기능 없음)에서 생기지 않는다 | 11 |

**점검 중 찾아 고친 것**: 입력-4(크로스사이트 스크립트) — 문서 `fileUrl`을 아무 문자열로 받아 관리자 웹이 그대로 `<a href>`에 넣었다. `javascript:` 주소를 저장하면 다른 관리자가 누를 때 스크립트가 실행될 수 있었다. 서버가 http(s)만 받고(`create-document.dto.ts`), 화면은 http(s)일 때만 링크로 그린다. `document-rules.spec.ts`가 `javascript:`·`data:`·상대 경로 400을 본다.

점검 방법: 각 항목에 해당하는 코드 경로를 grep·읽기로 확인했다(정적 점검 도구는 돌리지 않았다). 근거가 테스트면 테스트 파일 이름을 적었다.

## 1. 입력데이터 검증 및 표현 (17)

| # | 보안약점 | 판정 | 근거·조치 |
|---|---|---|---|
| 입력-1 | SQL 삽입 | 대응 | 모든 질의가 Prisma 메서드 또는 `$queryRaw` 태그 템플릿(값은 바인딩)이다. 문자열을 이어 붙이는 `$queryRawUnsafe`는 운영 코드에 없다(테스트 도우미 `row-lock.ts`만, 테이블 이름은 테스트 상수) |
| 입력-2 | 코드 삽입 | 대응 | `eval`·`new Function`·`child_process`를 쓰지 않는다(api·두 웹 grep 0건) |

| 입력-4 | 크로스사이트 스크립트 | 대응 | React가 텍스트를 이스케이프한다. `dangerouslySetInnerHTML`은 공지 본문 한 곳뿐 — 서식 HTML은 api가 허용 목록으로 걸러 저장하고(`sanitize-html`, 스크립트·이벤트 속성·`style`·`img`·`javascript:` 없음) 두 웹이 DOMPurify로 다시 거른다(D62, `post-rich-content` spec·`member-notice` 화면 테스트). 사용자 값을 `href`에 넣던 문서 `fileUrl`은 이번에 http(s)로 제한(위 "찾아 고친 것") |
| 입력-5 | 운영체제 명령어 삽입 | 해당 없음 | OS 명령을 실행하지 않는다 |
| 입력-6 | 위험한 형식 파일 업로드 | 대응 | 확장자·MIME 허용 목록(pdf·png·jpg·webp·docx·xlsx·pptx·hwp), 파일당 10MB·글당 5개, 붙이기 때 저장소에서 실제 크기·형식을 다시 확인한다(신고값 불신). 파일은 비공개 버킷에 두고 서버가 실행하지 않는다(D57, `post-attachments.spec.ts`) |
| 입력-7 | 신뢰되지 않은 URL 주소로 자동접속 연결 | 대응 | 서버가 사용자 입력으로 리다이렉트하지 않는다. 화면의 `window.location.assign`은 api가 발급한 저장소 서명 URL에만 쓴다(`PostAttachments`·`NoticeAttachments`) |
| 입력-8 | 부적절한 XML 외부 개체 참조 | 해당 없음 | XML을 파싱하지 않는다(JSON만) |
| 입력-9 | XML 삽입 | 해당 없음 | 같은 이유 |
| 입력-10 | LDAP 삽입 | 해당 없음 | LDAP을 쓰지 않는다 |
| 입력-11 | 크로스사이트 요청 위조 | 대응 | 인증이 쿠키가 아니라 `Authorization: Bearer` 헤더라 다른 사이트가 사용자의 인증을 실어 요청을 보낼 수 없다. 참고: CORS가 모든 출처를 허용(`enableCors`)하지만 토큰을 자동으로 보내는 수단이 없어 위조 요청이 되지 않는다 |
| 입력-12 | 서버사이드 요청 위조 | 대응 | 서버가 외부로 보내는 요청은 환경변수 `SUPABASE_URL`의 저장소뿐이고 경로는 서버가 만든다. 문서 `fileUrl`은 저장만 하고 서버가 가져오지 않는다 |
| 입력-13 | HTTP 응답분할 | 대응 | 응답 헤더에 사용자 값을 넣는 곳은 내려받기 파일 이름뿐이고 `encodeURIComponent`로 인코딩한다(`dev-storage.controller.ts`·Supabase `download=` 인자). Express가 헤더의 CR·LF를 거부한다 |
| 입력-14 | 정수형 오버플로우 | 부분 | 페이지 크기는 상한으로 자른다(`pagination.ts`). DTO 정수 입력 16개 중 상한(`@Max`)이 있는 것은 3개 — 취득가액·정원 등에 아주 큰 값을 넣으면 DB 정수 범위를 넘어 500(내부 정보는 노출되지 않음). **조치**: 금액·수량·정원에 현실적인 `@Max` 지정 |
| 입력-15 | 보안기능 결정에 사용되는 부적절한 입력값 | 대응 | 역할·계정·지점 판단은 서명된 JWT와 DB에서만 한다. 요청 본문의 `branchId`는 가드가 소유를 확인하고(D46), 지점 관리자는 서버가 본인 지점으로 강제한다. `forbidNonWhitelisted`로 DTO에 없는 필드는 400 |
| 입력-16 | 메모리 버퍼 오버플로우 | 해당 없음 | 메모리 안전 언어(TypeScript)이고 네이티브 확장을 직접 쓰지 않는다 |
| 입력-17 | 포맷 스트링 삽입 | 해당 없음 | 사용자 값을 서식 문자열로 해석하는 API를 쓰지 않는다(템플릿 리터럴만) |

## 2. 보안기능 (16)

| # | 보안약점 | 판정 | 근거·조치 |
|---|---|---|---|
| 보안-1 | 적절한 인증 없는 중요 기능 허용 | 대응 | `JwtAuthGuard` 전역(`APP_GUARD`) — 인증 없이 열리는 경로는 `@Public`을 붙인 로그인·토큰 갱신·로그아웃(갱신 토큰 자체로 확인)·가입·연동·공개 지점 목록·헬스체크·로컬 전용 `dev-storage`뿐 |
| 보안-2 | 부적절한 인가 | 대응 | `RolesGuard`·`BranchScopeGuard` 전역, 리소스 id 라우트는 `@ScopedResource`(빠뜨리면 `branch-scope-coverage.spec.ts` 실패), 공격 케이스 표 `branch-isolation.spec.ts`, 인사 권한 `hr-authority.spec.ts` |
| 보안-3 | 중요한 자원에 대한 잘못된 권한 설정 | 대응 | 첨부 버킷 비공개(`public=false`), service_role 키는 Lambda에만, Function URL은 비밀 헤더 없이는 403(`lambda.ts`) |
| 보안-4 | 취약한 암호화 알고리즘 사용 | 대응 | 비밀번호 bcrypt, 갱신 토큰 SHA-256 해시 저장, JWT HS256(HMAC). MD5·SHA-1·DES를 쓰지 않는다 |
| 보안-5 | 암호화되지 않은 중요정보 | 대응 | 비밀번호는 해시로만, 갱신 토큰은 해시로만 저장. 모든 구간 HTTPS/TLS. 전화번호는 평문 저장이지만 목록 응답에서 마스킹하고 상세 열람은 기록한다(ADR-MEM-04·D47) — 필드 암호화는 하지 않았다 |
| 보안-6 | 하드코드된 중요정보 | 부분 | 배포 비밀값은 환경변수로만 읽고 없으면 부팅 실패(`secrets.ts`). 다만 데모 비밀번호가 저장소에 있고(`demo-password.ts`, 시연용 공개) **채용한 직원의 첫 비밀번호도 같은 값**이다(`staff.service.ts`). **조치**: security-plan S2·S3 — 무작위 임시 비밀번호 + 첫 로그인 변경 강제(인증 방식 변경이라 승인 먼저) |
| 보안-7 | 충분하지 않은 키 길이 사용 | 대응 | JWT·ORIGIN 비밀값은 32바이트 무작위(aws-lambda/README §1, `set-lambda-env.sh`가 빈 값이면 `randomBytes(32)`). 길이를 부팅 때 검사하지는 않는다 |
| 보안-8 | 적절하지 않은 난수 값 사용 | 대응 | 토큰 id·업로드 토큰·파일 이름은 `crypto.randomUUID`. 운영 코드에 `Math.random` 없음(시연 데이터 생성기는 결정적 mulberry32 — 보안 용도 아님) |
| 보안-9 | 취약한 비밀번호 허용 | 부분 | 가입·변경 모두 8자 이상(`MinLength(8)`). 문자 종류 조합·흔한 비밀번호 차단은 없다. **조치**: 영문·숫자 조합 규칙 추가 검토 |
| 보안-10 | 부적절한 전자서명 확인 | 대응 | 서명 검증은 JWT 하나이고 `@nestjs/jwt`가 서명·만료를 검증한다. 다른 전자서명은 다루지 않는다 |
| 보안-11 | 부적절한 인증서 유효성 검증 | 대응 | TLS 검증을 끄는 설정(`rejectUnauthorized: false`·`NODE_TLS_REJECT_UNAUTHORIZED`)이 없다 — Node 기본 검증 그대로 |
| 보안-12 | 쿠키를 통한 정보노출 | 해당 없음 | 쿠키를 쓰지 않는다(토큰은 헤더, 회원 웹 갱신 토큰은 localStorage — 그 위험은 security-plan S5) |
| 보안-13 | 주석문 안에 포함된 시스템 주요정보 | 대응 | 주석에 비밀값·접속 문자열이 없다(비밀값은 저장소에 없음, security-plan §3). 데모 계정 이메일만 있다 |
| 보안-14 | 솔트 없이 일방향 해시 함수 사용 | 대응 | 비밀번호는 bcrypt(솔트 포함, cost 10). 갱신 토큰 SHA-256은 솔트가 없지만 원문이 추측 불가능한 서명 토큰이라 사전 공격 대상이 아니다 |
| 보안-15 | 무결성 검사 없는 코드 다운로드 | 대응 | 실행 중 외부 코드를 받지 않는다(CDN 스크립트 없음). 의존성은 `package-lock.json`의 무결성 해시로 `npm ci` 설치 |
| 보안-16 | 반복된 인증시도 제한 기능 부재 | 부분 | Worker가 로그인·가입·연동에 rate limit(같은 연결 12번째부터 429). 계정 잠금은 범위 제외(권한관리 A-8)이고 연결을 바꾸면 우회된다(log/079). **조치**: security-plan S4 — 수용, 재론 시 계정별 제한 |

## 4. 에러처리 (3)

| # | 보안약점 | 판정 | 근거·조치 |
|---|---|---|---|
| 에러-1 | 오류 메시지 정보노출 | 대응 | `AllExceptionsFilter`가 알 수 없는 예외를 500 `INTERNAL_ERROR`로만 응답하고 스택은 서버 로그에만 남긴다. 로그인 실패는 아이디·비밀번호 중 무엇이 틀렸는지 구분하지 않는다 |
| 에러-2 | 오류상황 대응 부재 | 대응 | 저장소 실패는 502 `STORAGE_ERROR`, 미설정은 503으로 구분한다. 첨부 파일 지우기 실패는 요청을 성공으로 두고 기록만 남긴다(`removeQuietly` — 고아 파일은 용량만 쓴다) |
| 에러-3 | 부적절한 예외 처리 | 대응 | 예외를 삼키는 빈 `catch`가 없고, DB 고유 제약 위반(P2002)은 의미 있는 409로 바꾼다 |

## 5. 코드오류 (5)

| 캡슐-1 | 잘못된 세션에 의한 데이터 정보노출 | 대응 | 세션 상태를 서버 공유 변수에 두지 않는다(무상태 JWT, 요청마다 `req.user`). Lambda 실행 환경 재사용 간에 남는 전역 상태는 Prisma 연결과 설정값뿐 |
| 캡슐-2 | 제거되지 않고 남은 디버그 코드 | 대응 | 로컬 전용 `dev-storage` 경로는 배포 환경에서 404(Supabase 드라이버 사용 시 메모리 드라이버가 없다). 운영 코드의 `console.log`는 서버 시작 한 줄뿐 |
| 캡슐-3 | Public 메소드로부터 반환된 Private 배열 | 해당 없음 | Java 등의 접근 제어자 문제 — 응답은 매번 새로 만든 DTO 객체 |
| 캡슐-4 | Private 배열에 Public 데이터 할당 | 해당 없음 | 같은 이유 |
