# 공용 산정 상수 (Q-01 규모 산정)

> **상태**: 초안 (2026-09-22).
> **용도**: 도메인 사이클([process/03_도메인_사이클_템플릿.md](../process/03_도메인_사이클_템플릿.md)) 3단계(수치화)에서 매번 새로 리서치하지 않고 여기 값을 가져다 쓴다. **숫자를 다시 도출하지 말 것** — 가정이 틀렸다고 생각되면 이 문서를 고치고, 참조하는 모든 도메인 문서에 그 사실을 알린다.
> **결정 근거**: 사용자 확정 3건 — ① 실측 데이터 없음, 전부 산정으로 추정 ② 설계 목표는 3년 후 목표치 기준 ③ 대표 업장 규모 1,000세대.

## 산정 체인

| 단계 | 계산 | 값 | 근거 유형 |
|---|---|---|---|
| ① 대표 단지 상주인구 | 1,000세대 × 2.2명/가구 | **2,200명** | 실측: 2023 인구주택총조사 가구원수 분포(1인35.5%·2인28.8%·3인19.0%·4인이상16.8%, 4인이상=4.3인 가정)의 가중평균 |
| ② 지점당 등록 회원 수 | 2,200 × 25% | **550명** | **가정(약함)**: 문체부 2023 국민생활체육조사 민간체력단련장 이용경험률 42.1%를 상한 참고치로 두고 할인. 근거 데이터 없음 — 재검토 대상 |
| ③ 일일 활성 방문자 | 550 × 36%(주 2.5회 방문 ÷ 7일) | **≈200명/일** | 가정: 헬스장 업계 통상 경험칙(국내 데이터 아님) |
| ④ 피크 동시 재실자 | Little's Law(L=λW), 영업 18h·평균체류 70분·피크계수 2.5배 | **≈33명/지점** | 계산(Little's Law) + 가정(피크계수는 트래픽공학 관행 차용) |
| ⑤ 현재 전사 동시 재실 | 98개 업장 × 33명 | **≈3,200명** | 계산 |
| ⑥ 3년 후 목표 | 연 10% 성장 가정(98→130개 업장) × 33명 | **≈4,300명** | **가정(제안값)**: RFP 산출물4 KPI(3년 신규계약 증가율)와 연결되지만 수치 자체는 제안 |
| ⑦ 전사 로그인 도착률 | Little's Law 역산: λ=L/W, L=⑤(3,200명), W=평균체류(70분) | **≈45.7명/분(≈0.76명/초)** | 계산(Little's Law) — "동시 재실자 수 = 도착률×체류시간"이 정상상태에서 성립한다는 원리를 반대 방향(도착률 역산)으로 적용. 2026-09-27, §31(k6 실측) 대응으로 추가 |
| ⑧ 순간 피크 로그인 도착률 | ⑦ × 피크계수 2.5배(④와 같은 값 재사용) | **≈1.9명/초(≈114명/분)** | 계산 + 가정(④의 피크계수 재사용 — 수업 시작 직전 등 순간 집중) |
| ⑨ 동시 진행 중인 로그인 건수 | Little's Law 정방향: L=λW, λ=⑧, W=로그인 1건 처리시간 | **정상 처리(65ms, 로컬 실측) 시 ≈0.12건 / 장애 상황(15.16초, 2026-09-27 Render 무료 티어 k6 p95 실측) 시 ≈28.5건** | 계산 — **핵심 통찰**: 평소 트래픽은 결코 크지 않다(초당 2명 미만). 그런데 처리시간 W가 늘어나는 순간 Little's Law에 따라 동시 진행 건수 L도 그만큼 늘어난다 — "지연 → 동시 요청 누적 → CPU 경합 심화 → 더 심한 지연"으로 이어지는 **자기강화 루프**다. §31에서 관찰된 40 VU 램핑 중 응답시간이 완만히 늘지 않고 급격히 무너진 패턴(7.4s→15.16s→17.11s)이 이 구조와 정합적이다 |
| ⑩ 로그인 1회당 API 요청 수 | 로그인 후 한 세션에서 부르는 API 수 | **10건** (민감도 30건 — 혼잡도 폴링 포함) | **가정(약함)**: 근거 데이터 없음. admin-web 화면 한 번 진입이 조회 2~4건이라는 점만 참고. member-app 로그가 쌓이면 갱신. 2026-09-30, D37 추가 |
| ⑪ 피크 API 도착률 | ⑧ × ⑩ | **≈19 rps(현재 규모) / ≈26 rps(3년 후, 2.56명/초 기준)** / 민감도 30건 시 ≈77 rps | 계산 |
| ⑫ 필요한 동시 실행 수(Lambda) | Little's Law L=λW, λ=⑪, W=50ms(일반 조회, D37 로컬 실측 + 가정) | **≈1.3건(3년 후) / ≈3.9건(민감도)** — 상한 10이면 처리 한계 200 rps | 계산 — ⑨의 루프는 "L이 늘면 W가 는다"(공유 CPU)에서 생겼다. Lambda는 요청마다 CPU가 따로라 이 고리가 없고, 남는 공유 자원은 DB 커넥션이라 상한으로 묶는다(D37 결정 1) |
| ⑬ 일일 API 요청 수 | 지점 수 × ③ × ⑩ | **≈19.6만/일(98개 지점)** | 계산 — Cloudflare Workers 무료 한도(10만/일)를 넘는다. member-app 출시 전 유료 전환 근거(D37 결정 2) |

## 약한 고리 (재검토 대상)

- **등록률 25%**(②), **일일 방문율 36%**(③), **3년 성장률 연 10%**(⑥) — 근거가 약하다. 실제 스포이즘 데이터를 확인할 수 있게 되면 이 문서를 갱신한다.
- ~~이 값은 동시 재실자이지 동시 API 요청자가 아니다. ... 이 배율은 아직 산정하지 않았다.~~ → **2026-09-27 ⑦~⑨로 해소**. 남은 약한 고리: "로그인 이벤트가 시설 도착과 1:1 대응한다"는 가정(약함) — 실제로는 예약 확인·PT 세션 조회 등으로 하루 중 여러 번 로그인할 수도, 반대로 refresh token(14일)으로 한 번 로그인하면 한동안 재로그인이 없을 수도 있다. member-app 출시 후 실제 로그인 로그가 쌓이면 갱신할 것.
- ⑨의 3년 후 버전: λ=⑥(4,300명)/70분≈61.4명/분, 피크≈2.56명/초, 장애 상황(15초) 동시 진행≈38.4건 — 지점 수가 늘수록 이 자기강화 루프의 임계점에 더 쉽게 도달한다는 뜻이다.
