# 개발 문제 상황 점검표 — 고밀도화 단계에서 챙길 것

> 2026-10-11 작성([log/106](../log/106.md)). 시연 데이터를 계약 상태별 지점 5곳으로 고밀도화할 때(STATUS 다음 할 일 2), **도메인 기능을 늘리기보다 실제로 문제가 터지는 상황을 찾아 해결한다**는 사용자 방향에 따라 만든 점검표다.
> 지점별 시나리오를 돌릴 때 아래 카테고리마다 "이 장면에서 이 문제가 나는가"를 확인하고, 해결하면 `상태`와 근거(ADR·D·log 번호)를 갱신한다. 새 결정은 이 문서가 아니라 도메인 ADR이나 `decisions/`에 남기고 여기서는 ID로 가리킨다.

## 1. 확인된 결함 — 먼저 재현 테스트로 증명할 것

| # | 문제 | 상황 | 해결 방향 | 상태 |
|---|---|---|---|---|
| R1 | **결제와 취소 경합** | 취소가 결제 상태를 트랜잭션 처음에 읽고 끝에서 조건 없이 덮어쓴다(`reservation.service.ts` cancel). 회원 결제와 관리자 취소가 겹치면 "승인된 돈이 실패로 기록·환불 없음"이 되거나, 두 트랜잭션이 서로 기다리다 교착으로 한쪽이 500을 받는다 | 결제·취소 모두 예약 행을 같은 순서로 먼저 잠그고(ADR-RSV-01과 같은 방식), 결제 상태 변경은 읽은 상태일 때만 바꾼다 | 미해결 — 코드 읽기로 확인, 재현 테스트 전 |
| R2 | **갱신 토큰 재사용** | 갱신이 "읽기 → 폐기 확인 → 폐기 표시"로 나뉘어 같은 토큰의 동시 요청 두 개가 모두 통과한다(`auth.service.ts` refresh). 회원 웹의 한 번만 보내기는 탭 하나 안에서만 막는다 | "폐기 안 된 경우에만 폐기"를 한 문장으로 하고 바뀐 행이 0이면 거절. 이미 쓴 토큰이 다시 오면 그 계정 세션을 모두 끊는 재사용 탐지도 검토 | 미해결 — 코드 읽기로 확인, 재현 테스트 전 |

## 3. 혼잡도 — 회원 앱 "이용 시작/종료" 신호 설계 시 풀 문제

지금은 관리자가 현재 인원을 숫자로 덮어쓴다(나중 값이 이김). `FacilityCheckIn`·`CongestionSnapshot` 테이블은 스키마에만 있고 쓰지 않는다(혼잡도관리 A-8 범위 제외: QR 체크인·자동계산). 신호를 받기 시작하면:

| 문제 | 상황 | 해결 후보 |
|---|---|---|
| 동시 신호의 카운트 유실 | 같은 시각 여러 명 입장 → "읽고 +1 해서 쓰기"면 유실 | 숫자를 직접 고치지 않고 열린 체크인 수를 센다, 또는 DB 안에서 원자적 증가 |
| 신호 중복 | 두 번 누르기·재연결 재전송·503 뒤 재시도 | "회원·시설당 열린 체크인 1개"를 DB 제약으로 + 요청 멱등 키 |
| 순서 꼬임 | 퇴장이 입장보다 먼저 도착, 기기 시계 오차 | 서버 수신 시각 기준. 짝 없는 퇴장은 무시하거나 보정 기록 |
| 퇴장 누락 | 인원이 계속 쌓임 | 스케줄러 없이 조회 시 N시간 지난 체크인을 자동 퇴장으로 간주(지연 만료) |
| 정원 초과 시 누가 먼저 | 수영장처럼 정원 강제 시설 | 시설 행 락 + 먼저 커밋한 순서(예약과 같은 방식). 안내용 시설은 거절 없이 "매우 붐빔"만 — 시설 종류별 정책 |
| 몰림 처리량 | 출근 시간 신호 몰림 + 상한 10 | 신호는 쓰기 1번으로 가볍게, 클라이언트 짧은 대기 후 재시도(멱등 키 필수), 조회는 엣지 짧은 캐시 |
| 가짜 신호 | 집에서 "입장" | QR·위치 확인은 범위 제외 — "회원당 열린 체크인 1개 + 지점 소속 회원만"으로 제한하고 한계를 명시 |

범위 제외 항목(혼잡도관리 A-8)을 구현하는 일이고 제약 추가가 필요할 수 있어, 착수 전에 사용자 승인을 받는다.

## 4. 고밀도화 시나리오와 연결 (계획)

| 지점(계약 상태) | 시나리오에 넣을 문제 장면 |
|---|---|
| 정상 A(서초) | 아침 동시 입장(혼잡도), 결제 중 관리자 취소(R1), 몰림 시간 처리량 — 일부러 동시 10개(Lambda 상한)를 넘겨 503 `SERVER_BUSY`와 해결 안내가 가는지, 재시도가 중복 처리를 만들지 않는지(D49 세션 모드에선 동시 처리 수 ≈ 연결 수) |
| 정상 B(강남) | 지점 격리, 파견 이동 중 근태 귀속, 두 기기 동시 로그인 갱신(R2) |
| 갱신 임박 | 본사 대시보드 집계 성능, 운영 실적 데이터 신선도 |
| 만료 | 차단하지 않는 상태 전이 경계 |
| 계약 종료 | 종료 전이와 채용·발령 동시 요청(ADR-STF-07의 지점 행 락), 과거 조회 유지 |
