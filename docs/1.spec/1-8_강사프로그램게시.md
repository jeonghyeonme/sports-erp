# 07. 강사·프로그램 게시 (Instructor & Program)

## 1. 개요 및 조정사항

원본 요구사항: 종목별 강사/프로그램 정보 게시, 종목별/시간대별/연령대별 프로그램 리스트 게시.

**조정 없음** — CRUD + 목록 필터링 수준으로 1인 개발 부담이 크지 않아 원본 그대로 구현합니다. 1-7(예약)·1-9(혼잡도) 문서와 데이터가 강하게 연결되는 "기준정보(마스터 데이터)" 성격의 기능입니다.

## 2. 사용자 스토리

- 지점 관리자로서, 신규 강사를 등록하고 프로필(경력/전문분야)을 관리하고 싶다.
- 지점 관리자로서, 새 프로그램(요가, PT 등)을 개설하고 시간표를 등록하고 싶다.
- 회원으로서, 종목/시간대/연령대로 프로그램을 필터링해서 찾고 싶다.

### 3-1. `pricingType` — 지점별 유·무료 프로그램 관리의 핵심

`Program`이 이미 `branchId`를 갖고 있어 같은 종목이라도 지점마다 별도 row로 관리되고, 가격도 지점 관리자가 독립적으로 설정합니다. 여기에 더해 "이용 방식" 자체가 다른 세 갈래를 명시적인 enum으로 구분합니다 — `price===0`이라는 암묵적 규칙 대신 코드/화면 분기의 기준으로 삼습니다.

| pricingType | 의미 | 예약/결제 방식 | 예시 |
|---|---|---|---|
| `FREE_ACCESS` | 자유이용형 — 예약 없이 상시 이용 | 1-7문서 Reservation/Payment 대상 아님. 1-9문서 `FacilityCheckIn`(QR 체크인)만으로 이용 기록 | 헬스장 자유이용, 독서실 |
| `PAID_SESSION` | 회차 예약형 (무료 회차도 가능) | 1-7문서 `Reservation` 생성, `price>0`이면 `Payment`까지 진행 | 요가·필라테스 그룹 클래스 |
| `PT_PACKAGE` | 세션 차감형(PT) | 1-6문서 `PTSession`으로 관리, Reservation/Payment 미사용 | 개인 PT, 골프레슨 |

> `PAID_SESSION`인데 `price=0`인 경우는 "정원은 관리해야 하지만 무료인 클래스"(예: 신규 회원 체험 클래스)로, "예약 자체가 없는 자유이용(`FREE_ACCESS`)"과는 구분됩니다.

### 3-2. `status` — 지점별 "진행중인 프로그램" 파악

원본 요구사항에는 없지만, 실사용 단계에서 "이 지점은 지금 뭘 운영 중인가"를 바로 답할 수 있어야 한다는 요구가 있어 추가했습니다. `isActive` 불리언 하나로는 "아직 시작 전"과 "끝난 것"을 구분할 수 없어서, 4단계 상태로 명시했습니다.

| status | 의미 | 허용되는 다음 상태 |
|---|---|---|
| `PREPARING` | 준비중 — 등록됐지만 `startDate` 이전 | → RUNNING, ENDED(개강 취소) |
| `RUNNING` | 진행중 — 현재 운영 중 | → PAUSED, ENDED |
| `PAUSED` | 휴강(일시중단) — 강사 공백 등으로 임시 중단 | → RUNNING, ENDED |
| `ENDED` | 종료 — 더 이상 운영하지 않음(과거의 `isActive=false`에 대응) | (종결 상태) |

지점별로 "지금 진행중인 프로그램"을 파악하는 것은 `Program(branchId, status)` 인덱스를 태운 단순 조회 하나로 해결됩니다 — `WHERE branchId=? AND status='RUNNING'`. 지점 대시보드에는 상태별 개수(준비중 N · 진행중 N · 휴강 N)를 함께 보여줍니다.

> 상태 전이는 Phase 1에서는 관리자가 수동으로 변경합니다. Phase 2에서 `startDate`/`endDate` 도달 시 자동으로 PREPARING→RUNNING, RUNNING→ENDED 전환하는 배치를 추가할 수 있는데, 관리자가 수동으로 PAUSED로 바꿔둔 경우는 자동 전이가 덮어쓰지 않도록 예외 처리가 필요합니다.

### ProgramScheduleTemplate (요일별 기본 시간표 — 회차 대량 생성용)
| 필드 | 설명 |
|---|---|
| id, programId, dayOfWeek(0~6), startTime, endTime | 이 템플릿 기반으로 매주 `ScheduleSlot`을 배치 생성(Phase 2). `pricingType=FREE_ACCESS`인 프로그램은 회차 개념이 없으므로 템플릿 대상에서 제외 |

인덱스: `Program(branchId, status)`(지점별 진행중 프로그램 조회), `Program(branchId, category, ageGroup, pricingType)`, `Instructor(branchId)`

## 6. 비즈니스 로직 & 엣지케이스

- 강사 비활성화(`isActive=false`)는 기존에 연결된 예약/PT세션 데이터를 깨뜨리지 않도록 물리 삭제 대신 소프트 삭제 원칙 적용(1-1문서 §4)
- 프로그램은 `isActive` 대신 `status`로 생애주기를 관리합니다 — `ENDED`(또는 `PAUSED`)로 전환 시 이후 신규 예약만 차단하고, 이미 예약된 미래 회차는 유지하되 관리자에게 "휴강 처리 필요" 안내
- `PATCH /programs/:id/status`는 §3-2 표에 없는 전이(예: ENDED → RUNNING)를 요청하면 409(`INVALID_STATUS_TRANSITION`)로 거부
- 회차 일괄 생성 시 기존 회차와 시간 중복 검사(같은 시설, 겹치는 시간대에 다른 프로그램이 이미 있으면 경고 — 시설 스케줄 충돌 방지, 1-9문서 Facility와 연동)
- 필터 조합(`category`+`ageGroup`+`pricingType`)은 쿼리 파라미터 조합에 따라 동적 WHERE 절 구성, 인덱스는 가장 많이 쓰이는 `branchId+category` 우선
- `pricingType=FREE_ACCESS`인 프로그램을 등록/수정할 때는 `price`·`capacity`(회차 정원) 입력을 비활성화하고 1-9문서의 `Facility`와 연결만 요구(자유이용은 시설 자체의 정원으로 관리되므로 프로그램 단의 정원은 무의미)

## 7. 권한/보안 규칙

- BRANCH_ADMIN은 본인 지점 강사/프로그램만 CRUD
- 회원은 조회만 가능(본인 소속 지점 기준 필터 기본 적용, 타 지점 프로그램도 열람은 허용할지는 정책 선택 — 기본값: 본인 지점만 노출)

## 8. 구현 우선순위

**Phase 1(필수)**: 강사/프로그램 CRUD, 회차 개별 등록, 필터 목록(종목/연령대), 상태 수동 전이 + 지점 현황판
**Phase 2(선택)**: 요일 템플릿 기반 회차 일괄 생성, 시설 시간대 충돌 검사, 휴강 처리 시 예약자 알림, startDate/endDate 기반 상태 자동 전이 배치

## 9. 테스트 체크리스트

- [ ] 종목/연령대/pricingType 필터 조합이 정확히 동작
- [ ] FREE_ACCESS 프로그램 등록 시 가격·정원 입력이 비활성화됨
- [ ] status 필터(`RUNNING` 등)로 지점별 진행중 프로그램만 정확히 조회됨
- [ ] 지점 현황판 API가 상태별 개수를 정확히 집계
- [ ] 허용되지 않은 상태 전이(ENDED → RUNNING 등) 요청 시 409
- [ ] ENDED/PAUSED 프로그램은 신규 예약 목록에서 사라지지만 기존 예약은 유지
- [ ] BRANCH_ADMIN이 타 지점 프로그램 수정 시도 시 403
