# 04. 게시판(공지사항) (Board)

## 1. 개요 및 조정사항

원본 요구사항: 본사→현장, 현장→이용자 별도 게시판. 본사→현장 게시판에는 교육 매뉴얼/자료 탑재 기능 추가.

**조정 없음** — 이 기능은 CRUD 게시판으로 원본 그대로 구현해도 1인 개발 부담이 크지 않아 **거의 원본 그대로** 구현합니다. 다만 "댓글", "좋아요" 등 커뮤니티성 부가기능은 범위에서 제외합니다.

**추가 반영(2026-09-15)**: 원본 산출물4(개발 진행 보고서)는 "스포이즘 지점별 팀장급 직원들을 대상으로 어플 사용 교육을 **2회 이상 대면 교육** 제공"을 성과 요건으로 명시합니다(p.4). 지금까지는 "교육자료 탭"(§4)으로 자료 게시만 다뤘을 뿐, **실제로 교육을 몇 번 했는지 세는 기록 자체가 없었습니다.** `TrainingLog`(아래 §3)로 가볍게 보완합니다 — 별도 워크플로(승인/일정조율 등)는 만들지 않고, "언제·어느 지점에·어떤 방식으로 교육했는지"만 기록하는 로그 테이블 하나로 끝냅니다.

## 2. 사용자 스토리

- 본사 관리자로서, 전 지점(또는 특정 지점)에 공지를 올리고 필요시 교육자료 파일을 첨부하고 싶다.
- 지점 관리자로서, 본사 공지를 확인하고 우리 지점 회원들에게 전달할 공지를 따로 작성하고 싶다.
- 회원으로서, 내가 다니는 지점의 공지사항을 앱에서 확인하고 싶다.

## 3. 데이터 모델

### TrainingLog (교육 실시 기록 — 신규, 원본 산출물4 "2회 이상 대면교육" 대응)
| 필드 | 설명 |
|---|---|
| id | UUID |
| branchId | FK → Branch |
| conductedAt | date — 교육 실시일 |
| method | enum(ONSITE/대면, ONLINE/온라인) — 원본이 명시한 "대면"과 구분해 실제로 대면 교육 횟수만 따로 집계 가능하게 함 |
| attendeeStaffId | FK → Staff, nullable — 원본 "팀장(지점장)급" 대상자 특정 시 기록, 전체 지점 직원 대상이면 null |

## 6. 비즈니스 로직 & 엣지케이스

- `scope=HQ_TO_BRANCH`이고 `branchId=null`인 게시글은 "전체 지점 공지"로 취급해 모든 BRANCH_ADMIN 화면에 노출
- BRANCH_ADMIN이 작성하는 `BRANCH_TO_MEMBER` 게시글은 자동으로 본인 `branchId`가 세팅되어(수정 불가) 다른 지점에 실수로 노출되는 것을 원천 차단
- 첨부파일 업로드는 용량 제한(예: 파일당 10MB, 이미지 5장/문서 3개까지) 및 확장자 화이트리스트(jpg/png/pdf) 적용 — 보안 요구사항(임의 파일 업로드 방지)
- 삭제는 소프트 삭제(`deletedAt`)로 처리해 회원이 이미 본 공지의 참조 무결성 유지
- 회원 앱에서는 미열람 공지 뱃지(빨간 점) 표시를 위해 `PostReadReceipt` 활용(Phase 2)
- **위탁계약 종료 지점의 게시판**: `Branch.contractStatus=TERMINATED`가 되어도 기존 게시글은 삭제하지 않고 열람만 유지합니다(소프트 삭제 원칙과 동일한 태도 — [1-1문서 §2-1](../00_공통/1-1_공통설계서.md#2-1-branch지점-데이터-모델--위탁계약-필드)). 다만 해당 지점을 대상으로 한 신규 `BRANCH_TO_MEMBER` 작성은 409(`BRANCH_TERMINATED`)로 차단합니다. `HQ_TO_BRANCH` 공지는 본사가 작성 주체이므로 이 제약과 무관합니다.
- **교육 실시 기록은 등록 전용, 워크플로 없음**: 승인/일정조율/알림 같은 절차는 만들지 않습니다 — 이미 일어난 교육을 사후에 기록하는 단순 로그입니다(신청→승인 흐름이 있는 1-3문서의 변경 신청과는 성격이 다름). 지점별 누적 횟수는 `TrainingLog(branchId, method='ONSITE')` 카운트로 계산하며 별도 캐시 필드를 두지 않습니다(빈도가 낮아 실시간 집계로 충분).

## 7. 권한/보안 규칙

- HQ_TO_BRANCH 게시글 작성은 SUPER_ADMIN만
- BRANCH_TO_MEMBER 게시글 작성은 BRANCH_ADMIN(본인 지점), 회원은 읽기 전용
- STAFF(Role)는 본인 지점의 HQ_TO_BRANCH(특히 교육자료)·BRANCH_TO_MEMBER 게시글을 모두 조회만 가능(작성 불가) — 원본 요구사항의 "운영교육 매뉴얼" 열람 주체가 바로 STAFF
- 회원은 본인 소속 지점(branchId)의 BRANCH_TO_MEMBER 게시글 + 전체 HQ 공지 중 "회원 공개" 설정된 것만 조회(HQ 공지는 기본적으로 직원 대상이므로 회원에게는 비공개가 기본값 — `visibleToMember` boolean 플래그로 제어)

## 8. 구현 우선순위

**Phase 1(필수)**: Post CRUD, scope 분기, 첨부파일(이미지) 업로드, 목록/상세 화면
**Phase 2(선택)**: 읽음 확인, 상단 고정, 조회수, 카테고리 필터 UI
**Phase 6(확장)**: `TrainingLog` 등록/조회, 지점별 누적 횟수 배지

## 9. 테스트 체크리스트

- [ ] BRANCH_ADMIN이 작성한 공지가 타 지점 회원에게 노출되지 않음
- [ ] 전체공지(branchId=null)가 모든 지점 관리자에게 노출됨
- [ ] 첨부파일 10MB 초과/허용되지 않은 확장자 업로드 시 거부
- [ ] 삭제된 게시글이 목록에서 사라지되 기존 알림/참조는 깨지지 않음
- [ ] BRANCH_ADMIN이 교육 실시 기록 등록 API 호출 시도 시 403(SUPER_ADMIN 전용)
- [ ] 지점별 대면(ONSITE) 교육 횟수가 정확히 집계됨
