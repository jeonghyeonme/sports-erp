# 03. 근태관리 (Attendance)

> ⚠️ **대체됨(2026-09-23)**: 이 문서의 내용은 [docs/domains/근태관리.md](../../domains/근태관리.md)로 병합되었습니다. 이 파일은 5개 문서가 아직 참조 중이라 링크 정리 전까지 남겨둔 상태이며, 정리 완료 후 삭제 예정입니다(추적: [docs/process/05_문서_마이그레이션_추적.md](../../process/05_문서_마이그레이션_추적.md)). **새 내용을 여기에 추가하지 마세요.**

## 1. 개요 및 조정사항

원본 요구사항: 현장별/개인별 근태 등록, 휴무·연차·병가 기록 및 일수 관리, 업무일지 작성.

**조정**: 생체인증·GPS 기반 출퇴근 체크(위치 검증)는 제외하고 **수동 체크인/체크아웃 버튼** 방식으로 구현합니다. 연차 일수 자동 계산(근속연수 기반 법정 연차 산정)까지는 포함하되, 회계연도별 이월/소멸 같은 세부 인사 규정은 단순화합니다.

## 2. 사용자 스토리

- 직원으로서, 출근/퇴근 시 앱(또는 웹)에서 버튼 하나로 체크인/아웃하고 싶다.
- 직원으로서, 연차를 신청하면 지점 관리자가 승인/반려할 수 있길 원한다.
- 지점 관리자로서, 우리 지점 직원들의 이번 달 근태 현황(지각/결근/휴가)을 한눈에 보고 싶다.
- 직원으로서, 오늘 업무일지를 작성해 관리자와 공유하고 싶다.

## 3. 데이터 모델

### AttendanceRecord
| 필드 | 설명 |
|---|---|
| id, staffId(FK), date | 하루 1레코드 (staffId+date unique) |
| checkInAt, checkOutAt | datetime, nullable |
| status | enum(NORMAL/정상, LATE/지각, EARLY_LEAVE/조퇴, ABSENT/결근, ON_LEAVE/휴가) — `AttendanceStatus`(schema.prisma). 서버에서 checkInAt과 지점별 출근기준시각 비교해 자동 산정 |
| note | 관리자 메모(선택) |

### LeaveRequest
| 필드 | 설명 |
|---|---|
| id, staffId, type(ANNUAL/연차, SICK/병가, FAMILY_EVENT/경조사, OTHER/기타), startDate, endDate, days(자동계산), reason, status(PENDING/대기, APPROVED/승인, REJECTED/반려), approverId, reviewedAt — `LeaveType`/`LeaveStatus`(schema.prisma) | |

### LeaveBalance (연차 잔여일수 — `type=ANNUAL`만 대상)
| 필드 | 설명 |
|---|---|
| id, staffId, year, totalDays(입사연차 기준 자동계산), usedDays, remainingDays(computed) | **`LeaveRequest.type=ANNUAL`(연차)만 이 테이블의 `usedDays`에 반영됩니다.** SICK(병가)·FAMILY_EVENT(경조사)·OTHER(기타)는 한국 실무상 연차와 별도로 유급/무급 여부가 회사 재량으로 갈리는 항목이라, 승인은 하되 연차 잔여일수는 차감하지 않고 이력만 남깁니다(§6 참고) |

### WorkLog
| 필드 | 설명 |
|---|---|
| id, staffId, date, content(text), createdAt | staffId+date unique(하루 1건 권장, 수정은 가능) |

인덱스: `AttendanceRecord(staffId, date)` unique, `LeaveRequest(staffId, status)`

## 5. API 명세

| Method | Endpoint | 권한 | 설명 |
|---|---|---|---|
| POST | /api/v1/attendance/check-in | Staff | 오늘자 레코드 생성/checkInAt 기록 |
| POST | /api/v1/attendance/check-out | Staff | checkOutAt 기록 |
| GET | /api/v1/attendance?staffId=&month= | Staff(본인)/BRANCH_ADMIN(지점) | 월별 조회 |
| GET | /api/v1/attendance/summary?branchId=&month= | BRANCH_ADMIN | 지점 근태 요약(지각N회, 결근N회 등 집계) |
| POST | /api/v1/leave-requests | Staff | 휴가 신청 |

| PATCH | /api/v1/leave-requests/:id/reject | BRANCH_ADMIN | 반려 |
| GET | /api/v1/leave-balance/:staffId | Staff(본인)/BRANCH_ADMIN | 잔여 연차 |
| GET | /api/v1/leave-requests?staffId=&status= | Staff(본인)/BRANCH_ADMIN(지점) | 신청 목록 — "휴가 승인함" 화면(§4)에 필요한데 원래 이 표에 빠져 있었음(2026-09-18 정정, 구현 과정에서 발견) |
| POST | /api/v1/work-logs | Staff | 업무일지 작성 |
| GET | /api/v1/work-logs?staffId=&date= | Staff/BRANCH_ADMIN | 조회 |

**구현 정정(2026-09-18)**: 이 문서의 "Staff"는 Role=STAFF만이 아니라 **Account.role이 BRANCH_ADMIN인 사용자도 포함**합니다 — 1-1문서 §3.1이 이미 "BRANCH_ADMIN도 Staff 레코드를 1:1로 가진다"고 정의해뒀는데, 이 문서는 "지점장도 매일 출퇴근을 체크하는가"를 명시하지 않고 있었습니다. 실제 사업장은 주 7일 운영이라 지점장도 본인 근태·휴가·업무일지를 셀프서비스한다고 해석해 구현했습니다(체크인/체크아웃/휴가신청/업무일지 API는 STAFF·BRANCH_ADMIN 둘 다 호출 가능). "본인 지점 조회 + 휴가 승인"이라는 관리 권한은 이 셀프서비스 위에 얹히는 별도 레이어입니다.

**연차 자동계산 공식(2026-09-18, §3 "입사연차 기준 자동계산"의 구체화)**: 근로기준법 원칙을 단순화해 `입사 1년 미만 = 11일`, `1년 이상 = 15일 + floor((근속연수-1)/2)`(최대 25일)로 계산합니다. 월별 개근 판정 같은 정밀 규정은 범위 밖입니다.

## 6. 비즈니스 로직 & 엣지케이스

- **체크인 중복 방지**: 동일 staffId+date로 이미 checkInAt이 있으면 409 에러(`ALREADY_CHECKED_IN`)
- **자동 지각 판정**: 지점별 `Branch.standardCheckInTime`([1-1문서 §2-1](../00_공통/1-1_공통설계서.md#2-1-branch지점-데이터-모델--위탁계약-필드) 참고, 예: 09:00) 설정값과 비교해 10분 초과 시 `LATE`(지각)로 자동 분류
- **결근 자동 처리(배치) — 휴무일 판정 추가(2026-09-15)**: 기존 조건("당일 checkInAt이 없고 승인된 휴가도 없는 재직자")은 **오늘이 그 직원의 근무일인지 자체를 확인하지 않았습니다.** 이 업종은 주 7일 운영되는 시설이라 직원이 요일별 교대·휴무제로 일하는 게 정상인데, 이 조건대로면 **모든 정규직·계약직 직원이 자기 정기 휴무일마다 매주 자동으로 "결근" 처리**됩니다. 수정된 조건: 매일 자정 스케줄러(Cron)로 "① `employmentType`이 정규직/계약직이고, ② 오늘 요일이 `Staff.offDays`([1-3문서 §3](1-3_인사정보관리.md)) 에 없고(=오늘이 근무일), ③ `checkInAt`이 없고, ④ 승인된 휴가도 없는 재직자"를 `ABSENT`(결근)로 자동 기록합니다. **파트타임은 이 배치의 대상에서 제외**합니다(§3 참고 — 근무일이 주 단위로 고정되지 않아 자동 판정 자체가 부정확해지므로, 결근 여부는 관리자가 수동으로 판단). 공휴일은 이번 범위에서 다루지 않습니다(전 지점 공통 캘린더가 없어 별도 스코프 — 필요해지면 `Holiday` 마스터 테이블 추가로 확장 가능)
- **연차 일수 계산**: `days = (endDate - startDate + 1)`, 주말 제외 여부는 Phase 2. 신청 시점에 `remainingDays < days`면 400 에러로 신청 자체를 막지 않고 경고만 표시(실무상 마이너스 연차 허용 케이스 존재 — 관리자 재량으로 승인 가능하게 설계)
- **승인 시 잔여일수 차감**: `type=ANNUAL`(연차) 신청이 승인된 시점에만 `LeaveBalance.usedDays += days` (신청만으로는 차감 안 함 — 반려 시 복구 로직 불필요해짐). `SICK`/`FAMILY_EVENT`/`OTHER`는 승인해도 `LeaveBalance`를 건드리지 않음 — 연차 잔여일수와 무관하게 별도 이력(`LeaveRequest.status=APPROVED`)으로만 관리
- **업무일지 관리자 열람**: 지점 관리자는 본인 지점 전 직원 업무일지 열람 가능(원본 "본사→현장 업무일지" 요건과 연결 — 04 게시판 문서의 게시판 성격과는 별개로, 근태 도메인 내 데이터로 유지)

## 7. 권한/보안 규칙

- Staff(Role=STAFF)는 본인 근태/휴가/업무일지만 CRUD — 1-2문서의 STAFF 권한에 따라 동료 직원 데이터는 조회 자체가 차단됨
- BRANCH_ADMIN은 본인 지점 소속 Staff 전체의 근태 조회 + 휴가 승인 권한, 근태기록 직접 수정은 관리자만(정정 사유 필수 입력)
- SUPER_ADMIN은 전 지점 조회만(현장 운영에 직접 개입하지 않는 원칙)

## 8. 구현 우선순위

> **범위 제외(2026-09-20, 향후 확장 가능성만 남김)**: 자동 결근 배치 — 스케줄러가 없어 제외했다. 필요해지면 근태 조회 시점에 "기록 없는 근무일"을 결근으로 계산하는 방식이나 스케줄러 도입으로 확장할 수 있다.

**Phase 1(필수)**: 체크인/아웃, 월별 근태 조회, 휴가 신청/승인, 잔여연차 표시 — **완료(2026-09-18, API+화면)**
**Phase 2(선택)**: 지점 근태 요약 대시보드·업무일지 — **완료(2026-09-18)**. 자동 결근 배치·근태 정정 이력(AuditLog 연동)은 스케줄러 인프라·AuditLog 실연결이 선행돼야 해 **여전히 미구현**

## 9. 테스트 체크리스트

- [ ] 동일 날짜 중복 체크인 방지
- [ ] 출근 기준시각 10분 초과 시 자동 "지각" 처리
- [ ] 휴가 승인 시 잔여연차 정확히 차감, 반려 시 미차감
- [ ] 병가(SICK)/경조사(FAMILY_EVENT) 승인 시 `LeaveBalance.usedDays`가 변하지 않음(연차와 분리 확인)
- [ ] **정기 휴무일(`offDays`)에 해당하는 요일에는 체크인이 없어도 결근 자동 배치가 `ABSENT`로 기록하지 않음**
- [ ] 파트타임 직원은 체크인이 없어도 결근 자동 배치 대상에서 제외됨
- [ ] BRANCH_ADMIN이 타 지점 직원 근태 조회 시 403
