# 183. 중간 제출 산출물 폴더를 RFP 산출물 표 기준으로 묶음 (2026-10-25)

> [진행 로그 인덱스](README.md)

**계기**: "산출물 디렉토리 안에 산출물들 다 때려넣으니까 뭐가 어떤 RFP 이행한 결과물인지 모르겠어"(사용자). `04_산출물/`에 파일 11개가 한 줄로 놓여 있었다.

**한 일** (`scripts/deliverables/pack-midterm.mjs`):
- `04_산출물/`을 RFP 산출물 표(p.7) 항목마다 한 폴더로 — `산출물1_ERP시스템앱`(요구사항·데이터 정의서, P1 조정), `산출물2_경영관리현황분석`(기업분석및제안서, P2-1 완료 · P2-2·P2-3 제외), `산출물3_개발작업계획서`(아키텍처설계서, P3 조정), `산출물4_단계별개발진행보고서`(진행보고서 5부, P4), `산출물5_사용교육자료`(빠른 시작 PDF, P5), 그리고 산출물 표에는 없는 `과업4_이용자매뉴얼`(T4-1). 조항 ID·상태는 요구사항추적표 §3과 같다.
- `04_산출물/읽어보기.txt` — 폴더마다 RFP 원문·이행 상태·무엇을 냈는지·조정/제외 사유. 묶음 README.txt의 04 설명도 같은 구조로.
- `--outputs-only` — 이미 만든 묶음에서 04와 README.txt만 다시 만든다. 사용자가 손으로 채운 01(중간보고서 PDF)·03(주차별 PDF)을 지우지 않으려고. 01~04 폴더가 바로 안에 없으면 멈춘다(압축을 풀면 한 단계 안쪽에 생기는 경우).
- `.gitignore`에 `/docs/midterm-submission/` — 사용자가 로컬 저장소 docs 아래에 둔 제출 폴더(약 20MB)가 커밋되지 않게.

**검증**: 01·03에 PDF를 넣은 복사본에 `--outputs-only` 실행 → 01·03 그대로, 04만 6개 폴더 11개 파일로 바뀜. 폴더를 한 단계 위로 주면 멈춤 확인. 사용자 PC의 `docs/midterm-submission`에는 이 세션이 닿지 않아 실제 폴더에서는 돌려 보지 않았다 — 검증되지 않음.
