# 085. 회원 웹 배포 준비 — CI·hook에 member-web, 홈 카드 캐시, Worker 경유 호출 수 실측 (2026-10-08)

> [진행 로그 인덱스](README.md)

**계기**: 브리프 B1-4.
- 회원 웹(B1-1~B1-3, [077](077.md)·[083](083.md)·[084](084.md))을 배포할 수 있게 검증 경로를 갖춘다.
- 방문당 호출 수를 실측해 design-constants ⑩을 고친다.
- 문서를 정리한다.

**한 일**

1. **CI·커밋 hook**
   - CI에 `member-web (lint · build)` 잡을 더했다.
   - 커밋 전 hook에 member-web lint·빌드를 더했다. 빌드는 admin-web 뒤에 돈다. admin-web 빌드가 `dist`를 비우기 때문이다(D41).
   - 루트 CLAUDE.md의 "검증 수단"을 고쳤다.
2. **홈 카드 60초 메모리 캐시(사용자 결정 2026-10-08)**
   - 혼잡도와 최근 공지를 대상으로 한다. 같은 방문 안에서 60초 안에 홈으로 돌아오면 다시 부르지 않는다.
   - 캐시는 탭 메모리에만 있고, 로그아웃·세션 만료 때 비운다.
   - 새로고침 버튼은 캐시를 건너뛴다.
   - 혼잡도 새로고침의 30초 잠금(ADR-FAC-04)은 화면 진입 시각이 아니라 실제로 서버에서 받은 시각을 기준으로 바꿨다. 그래야 캐시로 홈에 다시 들어와도 간격이 지켜진다.
   - 결과: 홈 재진입 2회 → 0회. B1-3의 한 방문 13회가 11회로 줄었다.
3. **로컬 Worker 경유 확인(`wrangler dev`, 실제 `wrangler.jsonc`·빌드 결과물·로컬 api)**
   - 라우팅
     - `/`는 관리자 웹이다.
     - `/m/`·`/m/reservations`·`/m/notices/x`는 회원 웹이다.
     - `/m`은 `/m/`로 307 리다이렉트된다. 그래서 B1-2에서 겪은 끝 슬래시 문제가 Worker 앞에서는 생기지 않는다.
     - `/api/*`는 프록시된다.
   - **Worker 호출 수**는 wrangler 로컬 trace(root span)로 셌다.
     - 한 방문에서 api 11회, Worker 11회였다. 정적 자산은 Worker를 거치지 않는다.
     - 깊은 경로(`/m/reservations`)를 새로고침하면 api 호출과 별도로 Worker가 1회 더 돈다. D41 결정 2대로다.

**실측(로컬 Worker 경유, 프로덕션 빌드, 2026-10-08)**

| 방문 유형 | api 호출 | Worker 호출 |
|---|---|---|
| 혼잡도·공지만 보고 나감(새 로그인) | 3 (login, facilities, posts) | 3 |
| 같은 방문, 저장된 세션으로 들어옴 | 4 (refresh, me, facilities, posts) | 4 |
| 기능을 다 씀: 로그인 → 공지 목록·상세 → 홈 → 예약·결제 → 내 예약 → 내 정보 → 홈 | **11** | 11 |
| 재방문: 홈 → 내 예약 → 취소 → 깊은 경로 새로고침 | 9 | 10 |

**⑩을 10으로 둔 이유(사용자 결정)**
- 실측 범위는 3~12회다. 평균 방문이 어느 쪽에 가까운지는 실제 이용 패턴이 없어 모른다.
- 11로 바꾸면 ⑬이 약 10.1만이 되어 Workers 무료 한도(10만)를 넘는다. 그러면 D40의 "수도권 83곳이면 무료 안"이라는 근거가 흔들린다.
- **D40 재고 메모**: D40의 재고 트리거("하루 요청 9만 건 초과")를 그대로 쓴다. 배포 후 Cloudflare 대시보드에서 Worker 일일 요청을 보고, 9만을 넘으면 Workers 유료(월 $5)를 검토한다. D40 파일은 결정 기록이라 고치지 않았다(D38).

**하지 못한 것**
- **Worker 배포와 운영 환경 실측**: 이 세션은 `workers.dev`로 나가는 연결이 조직 정책으로 막혀 있다(agent proxy 403, `cloudflare-worker/README.md`와 같은 제약). 배포는 사용자가 로컬에서 한다.

  ```bash
  npm run build:web
  cd cloudflare-worker
  npx wrangler deploy
  ```

- **회원 가입·연동 화면**: B1 범위에 없었다. API(`POST /members/register`·`/members/link`)만 있다. 지금 회원 웹은 이미 계정이 있는 회원만 로그인할 수 있다.
- 덱의 `req-shot-member` 캡처 갱신: 보호 영역이라 요청이 있을 때만 한다.

**검증**
- 커밋 hook에서 api jest 전체, 세 앱 lint·빌드를 돌렸다.
- member-web은 CI 잡과 같은 명령을 로컬에서 실행해 통과했다(lint 0건, 빌드 성공).
- doc-check를 통과했다.
