# 176. 중간 제출용 산출물 전부 재생성 — 10/14 기준 문서를 10/23 사실로 (2026-10-23)

> [진행 로그 인덱스](README.md)

**계기**: 중간 제출(D67)에서 "산출물은 최신화해야 하니 새로 뽑자"(사용자). 요구사항 정의서만 10/22 기준이었고 제안서·설계서·매뉴얼 등은 10/14(log/110) 기준이라 세부 권한(D60)·혼잡도 예약 합산(ADR-FAC-05)·관리자 웹 직원 전용(D66)·보안 조치(ADR-AUTH-08)·NestJS 11(D65)이 빠져 있었다.

**한 일**:
- 그대로 다시 만든 것: 요구사항 정의서(라우트 103), 데이터 정의서(테이블 34·컬럼 290), 매뉴얼 화면 캡처 22장.
- 원천을 먼저 고친 것: `schema.prisma` 주석 4곳(혼잡도 `currentCount`·`level`·`lastUpdatedAt`이 "현장 인원" 기준이라는 것, `mustChangePassword`) — 주석만, 스키마 변경 없음. 회원 웹 이용 안내의 혼잡도 문장(강습 예약 인원은 바로 더해지고 현장 인원은 직원이 입력).
- 생성기 내용 갱신: 사용자 매뉴얼(임시 비밀번호·첫 로그인 변경, 관리자 웹은 직원 계정만, 현장 인원 입력), 진행 보고서 5부(log/145~175, D65~D67, 556건·e2e 14건, 다음 계획 세 갈래), 기업 분석 및 제안서(관리 영역 현황·대체 구현·규모·남은 조항 6개·경과 10/14~10/23·다음 계획), 아키텍처 설계서(구성요소·모듈·세부 권한 4.4절·혼잡도 6.5절·CHECK 20·트리거 8·마이그레이션 11·결정 이력 D51~D67·검증 범위·남은 것). 설계서 그림 2를 다섯 관문(세부 권한 가드 추가)으로.

**근거**: D67, 요구사항추적표 §3(72조항, 58/64 = 91%), D60, D65, D66, 혼잡도관리 ADR-FAC-05, 권한관리 ADR-AUTH-08. 수치는 코드에서 셌다 — 관리자 웹 경로 21(`*` 제외), 회원 웹 14(홈 포함), 마이그레이션 SQL의 CHECK 20(같은 제약 재생성 1건 제외)·트리거 8·조건부 유일 인덱스 3.

**검증**: 두 Word를 PDF로 변환해 쪽수(설계서 19·제안서 14)와 새 절·그림 2를 눈으로 확인. `prisma validate`·`format --check` 통과. 진행 보고서는 결정 인덱스 대조(생성기 검사) 통과.
