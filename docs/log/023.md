# 23. ADR-BRD-02가 발견한 죽은 코드(`ResponseInterceptor`)를 정리했다 (2026-09-25)

> [진행 로그 인덱스](README.md)

**계기**: §19에서 "등록할지 삭제할지 별도 판단 필요"로 남겨뒀던 것을 사용자가 정리해달라고 요청.

**판단**: `git log --all`로 이 파일의 이력을 확인해보니 `eb79377`(폐기된 `wip/real-db-auth-phase1` 브랜치의 실DB 기반 인증/회원관리 Phase1 커밋, CLAUDE.md가 이미 "삭제됐지만 병합 조상이라 히스토리에서 도달 가능"이라고 적어둔 바로 그 커밋)에서 만들어진 뒤로 단 한 번도 등록되거나 참조된 적이 없었다 — `main.ts`·`app.module.ts`·`test/helpers/app.ts` 어디에도 `useGlobalInterceptors`/`APP_INTERCEPTOR` 등록이 없다. 즉 "언젠가 마저 연결할 진행 중 작업"이 아니라 **지나간 아키텍처 국면(실DB 직접 전환 시도)의 잔재**라고 판단해, 지금 전역 등록(모든 컨트롤러 응답 경로에 영향을 주는 위험한 변경)하는 대신 삭제 쪽을 택했다.

**한 일**: `apps/api/src/common/interceptors/response.interceptor.ts`, `apps/api/src/common/types/paginated.interface.ts` 삭제(둘 다 사용처 0건 확인 후). 이 과정에서 같은 `eb79377` 커밋에서 나온 것으로 보이는 **또 다른 미사용 파일**(`common/types/request-user.interface.ts` — 실제 쓰이는 `common/interfaces/request-user.interface.ts`와 이름이 같은 별개 파일, `@prisma/client`에서 `Role`을 import)을 우연히 발견했다 — 이번 요청 범위(ResponseInterceptor)를 벗어나는 별개의 정리 대상이라 손대지 않고 기록만 남긴다.

**검증**: 삭제 후 `npm run test`(15 suites, **218 passed**, 삭제 전과 동일 — 아무것도 안 깨짐을 그대로 확인), `eslint`·`nest build` 클린. 문서(`docs/domains/게시판.md` ADR-BRD-02 절)에 정리 완료를 반영.

**커밋**: 이 절을 포함한 커밋.
