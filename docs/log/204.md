# 204. 검색 없는 목록에 검색 — 예약·자산·업무지원·변경 이력 서버 검색어 q, 치는 대로 검색 (D74 2차) (2026-11-08)

> [진행 로그 인덱스](README.md)

**계기**: 목록 일관화 2차(D74) 중 사용자가 "검색 없는 목록에 검색 추가"를 골랐다. 네 목록 모두 서버가 쪽을 나누는 목록(D43)이라 화면에서만 거르면 지금 쪽 20건만 걸러진다 — 서버에 검색어를 더했다. 새 브랜치 `claude/list-search`.

**한 일**
- **API 검색어 `q`**(부분 일치, 영문 대소문자 무시, 앞뒤 공백 자르고 50자까지 — `common/http/pagination.ts` `searchTerm`, 회원 목록과 같은 방식):
  - 예약 `GET /reservations?q=` — 회원 이름·회원번호·프로그램 이름(체크인할 사람 찾기).
  - 자산 `GET /assets?q=` — 자산코드·품명·위치.
  - 업무지원 `GET /support-requests?q=` — 제목·요청자 이름.
  - 변경 이력 `GET /audit-logs?q=`(본사) — 처리자 이름, 대상 이름(직원 이름·회원 이름·번호·자산 이름·코드·지점 이름). 대상은 entity마다 다른 표라 맞는 id를 먼저 모아(대상마다 500개 상한) `entityId`로 거른다 — 이력 행에 이름을 복사하지 않는 D44 원칙 그대로.
- **지점 격리**: 검색어는 지점 조건과 따로 붙는다(`BranchScopeGuard`가 고정한 branchId는 그대로). 테스트로 확인 — 서초 지점 관리자가 강남에만 있는 회원 이름으로 예약을 찾으면 0건.
- **화면**: 네 목록 머리에 검색창(`type="search"`, 무엇으로 찾는지 placeholder). `lib/use-debounced.ts`(`useDebouncedValue`, 0.3초) — 치는 대로 검색하고 검색어가 바뀌면 1쪽부터. 자산 CSV도 같은 검색어로 받는다.
- **테스트**: api `list-search.spec.ts`(고밀도 템플릿, 4건 — 검색어는 시드에서 골라 개수를 박지 않음, D58), 화면 자동 테스트 1건(21건 — 예약 현황 회원 이름 검색·빈 결과).
- **측정 도구**: B05(오늘 예약 체크인)는 오늘 23:00 회차를 만들어 재는데 23시(KST) 이후에는 지난 회차라 만들 수 없다 — 그 시간엔 이유를 달고 건너뛴다. 화면 테스트도 처음엔 "오늘 23:10"으로 썼다가 같은 이유로 실패해 이틀 뒤 회차 + 화면 날짜 범위로 바꿨다.

**근거**: D74(2차 — 사용자 선택), D43(서버 쪽 나누기), D46(지점 격리), D44(변경 이력은 이름을 복사하지 않는다), D58(시드 개수를 박지 않는 테스트).

**검증**: api `list-search` 4건 통과, api 타입체크·lint(경고 1건은 기존 `main.ts`), admin-web lint·타입체크·빌드, 화면 자동 테스트 21건 통과, 측정 19건 통과·1건 건너뜀(B05, 23시 이후). 전체 jest는 커밋 전 hook. 자산·업무지원·변경 이력 화면의 검색창은 화면 테스트가 없다 — 검증되지 않음(API는 테스트, 화면은 같은 훅·타입체크). 검색은 `contains`라 인덱스를 쓰지 않는다 — 지점당 수천 행 규모에서는 문제없다고 보고 측정하지 않았다(검증되지 않음).
