# 067. `dev` 전환을 마치고 병합된 작업 브랜치를 정리했다 (2026-10-06)

> [진행 로그 인덱스](README.md)

**계기**: [066](066.md)에서 준비한 브랜치 이름 변경([D39](../decisions/D39.md))을 사용자가 실행했다.

**확인한 것**:
- 원격: `main-5x9td9`가 사라지고 `origin/dev`가 생겼다. 원격 기본 브랜치(HEAD)는 `dev`다. 내용은 PR #18 병합 커밋 `73a655d` 그대로다.
- 배포: Actions "Deploy api (AWS Lambda)" 실행 #7(`dev`, workflow_dispatch)이 성공했다. AWS 인증(OIDC)·업로드·버전 발행·별칭 이동·Health check가 모두 성공했고 롤백 단계는 건너뛰었다. 인증이 통과했으므로 신뢰 정책 `sub`에 `dev`가 들어갔다.
- 사용자 로컬: `main-5x9td9` → `dev`로 이름을 바꾸고 `origin/dev` 추적으로 맞췄다. `origin/HEAD`도 `dev`다.
  - Windows PowerShell 5.x는 `&&`를 지원하지 않는다. 안내 명령은 한 줄씩 실행하게 다시 줬다.

**정리**:
- 원격 작업 브랜치 6개를 사용자가 삭제했다: `local/lambda-k6`, `fix/lambda-url-not-public`, `docs/lambda-cli-runbook`, `docs/restructure`, `claude/affectionate-turing-sz8f1p`, `claude/upbeat-fermi-1lc6tk`.
  - 이 세션의 원격 브랜치 삭제는 권한 검사에서 거부돼 사용자가 직접 실행했다.
- 로컬 사본 2개도 삭제했다.
- 남은 원격 브랜치는 `dev`, `main`, 그리고 이 세션의 작업 브랜치(`claude/eager-hypatia-ilap57`, 이 PR 병합 후 삭제)다.
- CLAUDE.md의 CI 설명을 `dev`·`main` push로 고쳤다. D39 작업 때 빠뜨린 한 줄이다.

**남은 것(사용자)**:
- 신뢰 정책에서 옛 `sub` 값을 제거한다.
- Render를 일시정지하거나 연결 브랜치를 `dev`로 바꾼다.
- 이 PR이 `dev` 대상 첫 PR이다. 병합 후 `dev` push에서 CI가 도는지가 새 트리거의 첫 확인이 된다.
