# 211. RFP 충족률 분모에서 해당 없음 제외, T3-2·N8-2를 해당 없음으로 — 58/72 = 81% → 58/62 = 94% (D76) (2026-11-09)

> [진행 로그 인덱스](README.md)

**계기**: 최종 발표 전에 사용자가 조정·부분·미구현 목록을 보고, 해당 없음은 충족률에 넣지 않고 해당 없음으로 옮길 조항은 옮기자고 결정. 옮길 후보로 제시한 것은 T3-2(검수·도입)와 N8-2(업무위탁 DPA) — 둘 다 부분으로 남기는 안도 함께 설명했고, 사용자가 옮기는 쪽을 골랐다.

**한 일**
- **D76**: 충족률 = (구현+조정) / (조항 수 − 해당 없음). log/182의 "어떤 판정도 분모에서 빼지 않는다"를 대체. 미구현(의도적 제외 3개)은 분모에 남긴다.
- **판정 이동**: T3-2 부분 → 해당 없음(검수·도입은 발주기관 필요, 기대효과 분석은 P2-2가 따로 센다), N8-2 부분 → 해당 없음(DPA 서명은 실운영 전제, D67). N7-3은 부분 유지(테스트 키 호출은 실운영 없이 가능).
- **추적표**: §3 판정 기준·집계·T3-2·N8-2 행·읽는 법, §2-3에서 두 행을 빼고 옮긴 사실 한 줄, §4 4번.
- **산출물 생성기**: `rfp-evidence.js`(분모 = 조항 − 해당 없음, 요약 문장·표 머리), `requirements.py`(집계 제목·해당 없음 설명 — 집계 값은 추적표에서 읽는다), `proposal.js`(조항 충족 줄, 미충족 표의 두 행). `progress-reports.js`의 81%는 그 시점(2026-10-22)의 보고 내용이라 두었다. 산출물 파일 자체는 재생성 때(STATUS 2번).

**결과**: 구현 52 · 조정 6 · 부분 1 · 미구현 3 · 해당 없음 10 → **58/62 = 94%**(기능·성능 28/28 = 100%, 시스템~제약 17/18 = 94%, 과업·산출물 13/16 = 81%).

**근거**: D76, D67(실운영 안 함), log/182(옛 분모 규칙), 요구사항추적표 §3.

**검증**: 추적표 §3-1~3-3 표의 판정 열을 스크립트로 다시 세어 집계와 일치 확인(72개, 위 결과 그대로). `node --check`(rfp-evidence.js·proposal.js)·`py_compile`(requirements.py) 통과. 생성기를 실제로 돌려 산출물을 만들지는 않았다 — 검증되지 않음(재생성 때). `node scripts/doc-check.mjs` 통과.
