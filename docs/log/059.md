# 059. Lambda로 운영을 옮겼다 — Worker 경유 로그인·조회 확인, 종합 발표 덱 반영 (2026-10-05)

> [진행 로그 인덱스](README.md)

**계기**: 종합 발표 덱을 검토하던 사용자가 현황을 알려 줬다.
- Worker가 Lambda를 가리키도록 전환했고, Worker로 접속해 로그인과 데이터 조회까지 확인했다.
- DB와 API 사이의 헬스체크는 따로 하지 않았다. 배포 워크플로의 헬스체크는 DB를 거치지 않는 고정 응답이다([056](056.md)).

**한 일**:
- STATUS를 "Lambda로 운영 전환"으로 갱신했다. 남은 일은 k6 재측정과 Render 정리다.
- 덱을 고쳤다([4-5 구성안](../presentation/4-5_종합발표_슬라이드구성.md)).
  - 구성도·진화·스택·주간 슬라이드의 Lambda 상태를 "첫 배포"에서 "운영 전환"으로 바꿨다.
  - Render 문제와 Lambda 전환 방침은 4주차 발표에서 이미 다뤘다. 그래서 9/30 배포 점검 슬라이드를 뺐고, Lambda 슬라이드는 "예고한 전환을 이렇게 설계했다"로 바꿨다.
  - 요구사항 조정 슬라이드에서 결정 번호 표기를 뺐다. 발표자만 아는 정보라서다.
  - AI 검증 슬라이드 뒤에 문서 구조 슬라이드를 추가했다(읽는 시점별 3계층).
  - 사용자가 편집기에서 한 편집 6건은 생성기에도 반영했다: 숫자 슬라이드 삭제, 연결 띠 3개 삭제, 마무리 문장 삭제, 남은 것 배너 삭제.

**근거**: D37, D38, 사용자 확인(10/5).

**검증**: 생성기 린트 통과, doc-check 통과. Lambda 동작은 사용자가 브라우저로 확인한 것이다. 이 세션에서는 확인하지 않았다(네트워크 정책상 접속 불가). 부하 상황은 **검증되지 않음**. 게시한 덱의 렌더 결과는 확인하지 않았다.

**커밋**: STATUS, 이 파일, 4-5 구성안, deck-source(생성기·결과 스냅샷).
