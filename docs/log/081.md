# 081. 트래픽·인프라 후보 이슈 21건을 분류했다 — 대부분 실DB 이관으로 이미 풀렸고, 남은 것은 목록 페이지네이션과 폴링 (2026-10-07)

> [진행 로그 인덱스](README.md)

**계기**: 작업 브리프 B4. [traffic-infra-review](../architecture/traffic-infra-review.md)는 2026-09-28 mock 코드를 읽고 쓴 "후보 이슈"였다. 대안 비교·결정 없이 6개 도메인 §12에 "아직 ADR 아님"으로 걸려 있었다.

**한 일**
- 후보를 실DB 코드(`apps/api/src/modules/*`) 기준으로 하나씩 다시 확인했다. 1차 스캔에서 빠진 예약및결제·권한관리·인사정보관리 목록도 함께 봤다. 21건을 이미 해결 / ADR 승격 / 범위 제외로 나눴다. 사용자가 분류표와 4가지 선택을 확인했다(D 번호 D43, offset 페이지네이션, 자동 폴링 금지, B6을 B8에 흡수).
- **이미 해결 10건**: 대부분 D31~D36 이관 때 함께 풀렸다. 결근 미리보기는 D33, 시설·프로그램·회원 N+1은 조인, `bookedCount`는 회차별 `_count`, 회원번호·이메일은 D27·D28, 문서는 D34, 게시판은 D36, refreshToken은 ADR-AUTH-04가 맡는다.
- **ADR 승격 5건 → 결정 3개**
  - [D43](../decisions/D43.md): 쌓이는 목록(회원·예약·결제·자산)에 offset 페이지네이션을 넣는다. D37 R4를 이어받는다. D41은 B1(회원 웹 형태)용으로 비워 두었다.
  - ADR-FAC-04(혼잡도관리): `GET /facilities`는 자동 폴링하지 않는다. 혼잡도는 수동 보정 때만 바뀐다(D10). Worker 캐시는 `BranchScopeGuard`보다 앞에 있어 기각했다.
  - ADR-RSV-04(예약및결제): 결제 목록의 메모리 날짜 필터를 DB 조건으로 내린다. 이번에 새로 찾았다.
- **범위 제외 6건**: 근태 월별 집계 캐싱, 프로그램 예약 수 집계 필드, 게시글 보관 정책, 회원 `contains` 검색 인덱스, 예약·결제 이력 아카이빙(design-constants ⑮). 권한관리·인사정보관리는 목록이 인원 수에 묶여 제외했다. 각각 재고 트리거를 적었다.
- 구현은 하지 않았다. 브리프에 B8(목록 페이지네이션, 옛 B6 흡수)을 추가했다. B1 주의에는 혼잡도 자동 폴링 금지를 넣었다.

**근거**: D31~D37, D40, ADR-BRD-02, ADR-MEM-02·03, ADR-AUTH-04, design-constants ⑩⑫⑬⑮. 누적 속도(하루 약 1,700건)는 ⑮의 가정(약함)이다. 이번 세션에 실측한 값은 없다.

**문서·코드 어긋남 2건 정정**
- 강사프로그램게시 §12가 "`bookedCount`가 플랫폼 전체 예약을 스캔한다"고 적고 있었지만, 코드는 이미 회차별 count였다.
- design-constants ⑮가 traffic-infra-review의 없는 항목 "예약 이력"을 가리키고 있었다. 분류 #19로 고쳤다.

**검증**: 문서만 바꿨다. `node scripts/doc-check.mjs` 통과(393개 파일). 코드는 읽기만 했고, 테스트는 돌리지 않았다(코드 변경 없음).
