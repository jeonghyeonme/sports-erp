# 113. 구현된 도메인도 RFP 문구 단위로 재대조 — 누락 7건·부분 충족 3건을 추적표에 추가 (2026-10-14)

> [진행 로그 인덱스](README.md)

**계기**: RFP 문구 회복(D51)을 이어 가기 전에, 사용자가 "이미 구현된 도메인에도 RFP 누락이 있는지" 확인을 요청했다.

**한 일**: RFP p.4 개념도·p.5 기능 표(1~8, 10~11)·p.6 인터페이스·데이터 항목을 코드(컨트롤러 권한, admin-web·member-web 화면, aws-lambda 경보 설정)와 문구 단위로 대조했다. 기존 §2-3 목록에 없던 것을 요구사항추적표 §2-3에 추가하고 STATUS 남은 묶음 (f)로 올렸다.
- 누락 7건: 본사→현장 근태관리(본사 메뉴 없음 — 근태관리 A-7 원칙이 개념도와 다름, API는 본사 허용), 관리자의 근태 등록·정정 없음, "출력"(내보내기·인쇄) 기능 없음, 게시판 직원관리 탭(교육자료 분류 필터) 없음, 인사기록 한 화면 조회(부분), 회원용 강사 정보(부분), Lambda 메모리 85% 경보 없음.
- 부분 충족 3건: 혼잡도 30분 경과 경고 없음, 오류 데이터 진단 절차 문서 없음, 시설별 공지 불가.
- 근태관리 요약 카드의 "본사는 근태에 개입하지 않는다" 원칙 옆에 RFP와 다르다는 표시를 달았다(결정은 사용자).

**근거**: RFP 원문(docs/reference/제안요청서 원본.pdf p.4~6), D51.

**검증**: 코드 확인은 grep(근태 컨트롤러 `@Roles`, `csv`·`print` 검색 0건, `BoardPage` 필터는 범위만, 회원 웹에 `/instructors` 호출 없음, aws-lambda/README 경보 3종). doc-check 통과. 코드 변경 없음.
