## 2. refreshToken 정리 — [권한관리](../domains/권한관리.md) ADR-AUTH-04

- **문제**: 로그인·갱신·가입 직후 발급할 때마다 행이 하나씩 생기는데, 폐기만 하고 지우지 않았다.
- **고친 것**: `auth.service.ts`의 `issuePrismaRefreshToken`에서 발급 전에 그 계정의 만료·폐기 토큰을 `deleteMany`로 지운다. 폐기된 토큰을 다시 쓰려 하면 행이 없으므로 여전히 401이다.
- **테스트**: `test/auth-refresh-token.spec.ts`를 새로 만들었다.
  - 회전: 새 토큰이 발급되고, 쓴 토큰을 다시 쓰면 401
  - 정리: 그 계정의 만료·폐기 행만 지우고, 살아 있는 세션과 다른 계정 행은 남긴다
  - 로그아웃한 토큰은 다음 발급 때 지워지고, 다시 쓰면 401
  - 수정 전 코드에서는 정리 테스트 2건이 실패하는 것을 확인했다.
- **문서·코드 불일치 발견**: 권한관리 §11은 AUTH-T02(rotate)를 "자동+수동 테스트 통과(2026-09-28)"라고 적었다. 그런데 `/auth/refresh`를 부르는 자동 테스트 파일이 없었다. 이번 spec으로 메웠고 §11에 그 사실을 적었다.

## 3. 배포 DB 기존 행 정리 — **사용자 승인 대기**

배포 DB에는 k6로 약 1.2만 행이 쌓였다. 만료·폐기되지 않은 행이 대부분이라 위 코드만으로는 바로 줄지 않는다. 아래 SQL을 로컬 DB에서 트랜잭션 안에서 돌려 보고 롤백해서 확인했다. 확인 내용: 계정당 최신 5개만 남고, 만료 행은 지워진다.

```sql
-- 확인
SELECT count(*) AS total,
       count(*) FILTER (WHERE "expiresAt" < now() OR "revokedAt" IS NOT NULL) AS dead
FROM "RefreshToken";
SELECT "accountId", count(*) FROM "RefreshToken" GROUP BY 1 ORDER BY 2 DESC LIMIT 5;

-- 정리(한 트랜잭션): 만료·폐기 행 삭제 → 계정마다 최신 5개만 남김
BEGIN;
DELETE FROM "RefreshToken" WHERE "expiresAt" < now() OR "revokedAt" IS NOT NULL;
DELETE FROM "RefreshToken" r USING (
  SELECT id FROM (SELECT id, row_number() OVER (PARTITION BY "accountId" ORDER BY "createdAt" DESC) AS rn
                  FROM "RefreshToken") t WHERE rn > 5
) old WHERE r.id = old.id;
SELECT count(*) FROM "RefreshToken";
COMMIT;
```

영향: 계정마다 최근 5개보다 오래된 기기 세션은 다시 로그인해야 한다.
