# 096. 결근 확정·자산 정보 수정 화면 — API만 있던 마지막 두 기능 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "결근 확정·자산 수정 화면 시작하자"고 했다. 요구사항추적표 §3 "API만 있는 기능의 화면"에 남은 마지막 두 건이다. API·규칙은 그대로 두고 admin-web만 바꿨다.

**근거**
- 근태관리 ADR-ATT-02: 결근은 배치가 아니라 관리자의 명시적 확정이다. 미리보기는 저장하지 않고, 확정하면 다시 계산해 저장한다(멱등).
- 자원문서관리 A-5 `PATCH /assets/:id`: 품명·위치·메모·내용연수·수량만 고친다. 고정자산 수량은 항상 1이다.

**한 일**
- **결근 확정**(`components/AbsenceConfirmSection.tsx`, 근태관리 화면의 지점 관리자 영역, 휴가 승인함 아래)
  - 지난달 / 이번 달(어제까지) 칩으로 고른다. 서버가 오늘 이전만 후보로 본다.
  - 직원별 일수·날짜를 보인다. 이어지는 날은 `09-01~09-05`처럼 묶는다.
  - "결근 N건 확정"을 누르면 확인 모달이 뜬다. 되돌릴 수 없다는 안내와 선택 메모가 있다.
  - 확정하면 토스트로 실제 저장 건수를 알리고, 미리보기·근태 요약을 새로 읽는다.
  - 휴가 승인함 아래에 둔 이유: 대기 중인 휴가를 먼저 승인해야 그 날이 결근 후보에서 빠진다.
- **자산 정보 수정**(`AssetsPage.tsx`의 `EditAssetModal`)
  - 행의 "수정"으로 연다. 고칠 수 있는 것은 품명·보관 위치·메모와, 고정자산의 내용연수 또는 소모품의 재고 수량이다.
  - 분류·취득가액·취득일·구분은 회계 기록이라 읽기만 한다. 폐기된 자산에는 "수정" 버튼이 없다.
  - 폼은 모달이 열릴 때 한 번만 채운다(admin-web lint 규칙 — effect로 복사하지 않음).
- 도움말(근태·자산)에 사용법을 한 줄씩 더했다. 오류 해결 문구 `INVALID_QUANTITY`를 실제 서버 의미(고정자산 수량 1)에 맞췄다.

**검증**
- admin-web lint 경고 0, 빌드(타입체크) 통과.
- 로컬 api(`sports_erp_dev`) + vite에 Playwright로 서초 관리자 화면을 확인했다.
  - 9월 미리보기 → 확정 모달 → 메모를 넣고 확정: `POST /attendance/absence-confirm` 201, 토스트 "결근 90건을 확정했습니다", 목록이 "확정할 결근이 없습니다"로 바뀜.
  - 10월 미리보기: 직원 3명이 `10-01~10-09`로 묶여 보임.
  - 자산 수정: 러닝머신(고정자산)의 보관 위치를 바꿔 저장 → `PATCH /assets/:id` 200, 목록에 반영되고 모달이 닫힘.
- **관찰**: 로컬 시드 직원은 출근 기록이 거의 없어 한 달 내내 결근 후보로 나온다. 배포 DB도 시드가 같으면 시연 때 같은 모습이다.
- **검증되지 않음**
  - 배포(Worker 재배포 전에는 화면이 보이지 않는다)
  - 소모품 수량 수정 경로
  - 휴대폰 폭 레이아웃
