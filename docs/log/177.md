# 177. RFP 이행 증빙 — 72조항 한눈 표 + 조항별 쉬운 말 한 줄·결정 기록·화면, HTML 아티팩트와 PDF (2026-10-23)

> [진행 로그 인덱스](README.md)

**계기**: 중간 제출(D67)의 두 번째 묶음. 사용자가 구성(앞에 72조항 한눈 표, 뒤에 조항별 상세)을 확정했다. 형식은 D67대로 HTML 아티팩트 → PDF이고, "구현한 것"은 기술 근거 대신 쉬운 말 한 줄로 **교체**한다.

**한 일**:
- `scripts/deliverables/rfp-plain.json` — 72조항마다 쉬운 말 한 줄과 화면 연결. 판정은 요구사항추적표 §3을 그대로 읽고 여기서 바꾸지 않는다. 다른 조항 화면을 함께 쓰는 경우(N7-1 → F5-2 등)도 여기서 정한다.
- `capture-rfp.mjs` — 견본 13장에서 30장으로 늘렸다(회원 웹은 휴대폰 크기, 로그인 실패의 "해결" 줄, 도움말 패널, 확인 창, 변경 이력, 업무지원 요청, 주간 시간표 등). 시연 층의 현장 인원 입력 시각이 시연 기간 끝 18시라 찍는 시각에 따라 "51일 전"이 되므로, 캡처 전용 DB에서 운영 중 시설만 8분 전으로 맞춘다.
- `rfp-evidence.js` — Word 생성에서 HTML 생성으로 바꿨다. 요약(58/64, 영역별 집계, 상태 뜻) → 한눈 표(조항·원문·상태·한 줄) → 영역별 조항 카드(RFP·한 줄·결정 기록 제목·화면). 결정 제목은 요약표·ADR 제목의 첫 구절만 쓴다. 같은 HTML을 Chromium으로 인쇄해 `docs/deliverables/RFP이행증빙.pdf`(A4 49쪽)를 만든다.
- 아티팩트로 게시(그림 30장을 함께 올림, 비공개).

**근거**: D67, 요구사항추적표 §3, 중간발표 4-7 "이행 상태 이름"(구현 → 완료, 미구현 → 제외).

**문제와 대응**: PDF 인쇄가 멈췄다 — (1) Chromium이 Google 글꼴을 받으려면 프록시가 필요해 `HTTPS_PROXY`를 넘겼다(TLS 검증은 그대로), (2) `loading="lazy"` 그림이 화면 밖이라 끝내 안 떠 인쇄용 사본에서만 지연 로딩을 뺐다.

**검증**: 생성기가 조항 누락·여분·없는 화면 파일이면 멈춘다(72조항·화면 30장 통과). PDF는 쪽 묶음을 눈으로 확인(한눈 표·카드·그림 크기). 아티팩트 화면은 게시 후 사용자 확인 전 — 검증되지 않음.

**남은 것**: 중간보고서 덱(이행 현황 표 문장을 이 한 줄과 통일), 제출 폴더 정리.
