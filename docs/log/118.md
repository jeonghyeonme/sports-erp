# 118. RFP 중간 작업 M4 — 인사 변경 신청 → 지점 관리자 1단계 승인 (2026-10-15)

> [진행 로그 인덱스](README.md)

**계기**: 작업 브리프 B2 권장 순서 셋째(D51). 요구사항추적표 §2-3 "인사 변경 신청 → 관리자 승인"(RFP 1-1 #2 "권한부여/승인 시 수정"). D11이 1단계 승인으로 정했고 테이블만 있었다.

**사용자 결정(2026-10-15)**: 항목은 이름·연락처 / 지점 관리자 본인은 지금처럼 직접 수정(신청은 STAFF만) / 승인을 변경 이력 `STAFF_PROFILE_CHANGED`로 남김 / 같은 항목 대기 중 재신청은 409(먼저 취소).

**구현 중 정한 것**: ① 경로를 `/staff-change-requests`로 따로 뒀다 — 설계 원문의 `/staff/change-requests`는 `GET /staff/:id`와 겹친다. ② 상태 값에 "취소"가 없어 취소는 대기 행을 지운다(스키마 변경을 피함). ③ 신청함 목록의 연락처는 마스킹(ADR-MEM-04), 이력에는 연락처 값을 넣지 않는다(D44 결정 4). ④ 직원 화면에서 "내 정보" 표가 상세로 이어지지 않아, 신청 폼을 상세가 아니라 "내 정보" 화면 아래에 뒀다.

**한 일**:
- api: `StaffChangeRequestService`·`StaffChangeRequestsController`(인사정보관리 ADR-STF-09). 대기 검사·생성은 직원 행 락, 승인·반려·취소는 "대기일 때만" 조건부 갱신, 승인은 직원 값 반영 + 변경 이력 같은 트랜잭션. 가드 리소스 종류 `staffChangeRequest`(신청자의 현재 지점, D46).
- admin-web: `components/StaffChangeRequests.tsx` — 직원 "내 정보" 아래 신청 폼·내 신청 목록(취소), 지점 관리자 직원 목록 위 "정보 변경 신청함"(승인·반려, 대기 건이 있을 때만). 변경 이력 이벤트 "인사 정보 변경(신청 승인)". 오류 해결 문구 3개, 도움말.
- 테스트: `staff-change-requests.spec.ts` 새 파일(9건), `branch-isolation` 공격 표 2행(승인·반려).

**근거**: D11, 인사정보관리 ADR-STF-09, D52(이력 방식)·D44 결정 4(개인정보 미기록), ADR-MEM-04(목록 마스킹), D46.

**검증**:
- jest: `staff-change-requests`(동시 신청 2건 중 1건 포함)·`branch-isolation`·`branch-scope-coverage` 통과. 전체 jest는 커밋 hook이 돈다. 동시 승인·반려 경합은 조건부 갱신으로 막았지만 테스트는 없다 — **검증되지 않음**.
- admin-web lint·빌드 통과.
- 화면: 복사본 DB(확인 뒤 삭제)에서 Playwright로 직원 신청 → 지점 관리자 신청함(마스킹) → 승인 → 신청함이 사라지는 것 확인. **화면은 자동 테스트가 없어 검증되지 않음(수동 확인만)**.

**커밋**: api staff 모듈(서비스·컨트롤러·DTO)·`scope-owners.ts`·`prisma/audit.ts`, 테스트 2개, admin-web 컴포넌트·`StaffPage`·`AuditLogsPage`·`types.ts`·`error-hints.ts`·`help-content.ts`, 인사정보관리 문서, 요구사항추적표 §2-3 한 행 삭제, 브리프 B2, STATUS.
