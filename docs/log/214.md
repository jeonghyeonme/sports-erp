# 214. 11주차 발표 덱 정리 — 측정 수치·기준선·스크롤 비교·목록 일관화 장을 빼고 14장 (2026-11-09)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 log/213 덱(22장)을 검토.
- 작업 20개·세는 것 네 가지는 측정 도구의 내부 사정이라 의미가 없다 — "접근 경로가 단순해졌다, 6단계를 3단계로 줄였다"로 충분.
- 기준선이 보여 준 것 세 가지도 "불필요한 단계를 걷어 내고 자주 쓰는 기능의 접근성을 올렸다"로 충분.
- 화면 안 순서는 순서도만, 아래 카드 두 장은 불필요. 회차 등록 스크롤 0번은 발표 거리가 아니다. 전후 표는 작업량에 비해 과하다.
- 목록 일관화의 핵심(서버 단 정렬·검색)은 원래 있었어야 할 기능이라 내비칠 거리가 아니다.
- 질문: "PT 탭이 먼저 열린다"는 관리자 웹에서 쓸 수 없는 기능, 회원 앱 기준이어야 하지 않나.

**한 일**
- 생성기 `deck48.py`에 `DROP`(뺀 장: `ux-measure`·`ux-found`·`ux-pt-after`·`ux-slot-compare`·`ux-result`·`p2`·`list-rule`·`list-shot`)을 두고 22 → 14장. 장 구분 번호를 PART 01 사용감 · 02 문서 파일 · 03 운영 실적 차트로, 순서 장·장 구분 문구를 "자주 쓰는 기능의 접근 경로를 단순하게"로, `ux-order`는 순서도만, `ux-pt-compare` 노트에 PT 세션 차감이 지점 업무라는 설명. 구성안 4-8의 서사·목록·시간 배분·Q&A(목록 일관화·측정 도구는 질문 대비로) 갱신. 덱 재게시(뺀 장 파일 삭제).
- **PT 질문에 대한 사실**: PT 세션 차감은 PT 수업이 끝날 때 지점(프런트)이 회원의 남은 횟수를 차감하는 관리자 업무다(회원관리 — 회원 상세 PT 잔여세션의 "세션 사용", 지점 관리자 권한). 회원 웹에는 차감 기능이 없고 회원이 스스로 차감하면 안 된다. 그래서 "남은 PT가 있으면 PT 탭 먼저"(D72)는 관리자 웹의 지점 관리자용이다. 단, 회원 웹에 남은 PT 횟수를 보여 주는 화면이 있는지는 이번에 확인하지 않았다 — 검증되지 않음.
- **목록 일관화 정정**: 정렬은 "DB는 두고 서버에서"가 아니라 API가 정렬 인자를 받아 DB 쿼리(정렬 + 쪽 나누기)로 한다 — 전에는 화면(브라우저)이 받은 20건만 정렬했다. 구성안 Q&A에 적음.
