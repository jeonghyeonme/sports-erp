# 100. 상세 전화번호 열람 기록 — 관리자가 회원·직원 상세를 열면 AuditLog에 남긴다 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: RFP 잔여 항목(요구사항추적표 §2-3, 1-2 #7). 목록은 마스킹하지만(ADR-MEM-04) 상세는 원문을 주는데, 누가 언제 봤는지 남지 않았다. D44는 이 열람 기록을 범위 밖으로 두었다.

**한 일**:
- 사용자에게 네 가지를 물어 모두 권장안으로 정했다: ① AuditLog 재사용(스키마 변경 없음) ② 상세를 열 때마다 기록(ADR-MEM-04 유지, "번호 보기" 버튼안은 고르지 않음) ③ 조회는 SUPER_ADMIN만 ④ 보존 1년을 규칙으로 적고 자동 삭제 없음. → [D47](../decisions/D47.md)
- api: `prisma/audit.ts`에 `PHONE_VIEWED`·`AuditEntity('Staff'|'Member')`와 `recordPhoneView`(관리자만, 직원 본인·빈 번호 제외) 추가. `GET /members/:id`·`GET /staff/:id`가 응답 직전에 기록한다. `AuditLogService`가 회원 이름도 쪽 단위 한 번에 붙인다.
- 새 라우트는 없다 — 기존 두 상세 라우트는 이미 `@ScopedResource`와 `branch-isolation` 공격 표에 있다. 그래서 두 파일은 고치지 않았고, 타 지점 403에서 기록이 남지 않는 것을 새 spec에서 확인했다.
- admin-web: 변경 이력 화면에 이벤트 "전화번호 열람", 대상 열을 "직원 박서연"/"회원 이수진"처럼 종류와 함께 표시, 화면 설명·도움말(회원 상세·직원 상세·변경 이력)에 열람 기록이 남는다고 적었다.

**근거**: D47(이번 결정), D44(기록 형식·본사 전용 조회), ADR-MEM-04·STF-T03(상세 = 원문), D42(쿼리 수 — 관리자 상세 1회당 INSERT 1회), design-constants ⑮(용량 — 연 약 100MB, 지점당 하루 10회 가정·근거 없음).

**검증**:
- 실DB jest 전체 35 스위트 404건 통과(새 `phone-view-audit.spec.ts` 10건 포함). api lint 오류 0(기존 `main.ts` 경고 1건), api 빌드 통과.
- admin-web·member-web lint·빌드 통과. admin-web 변경 이력 화면은 Playwright로 확인했다: 서초점 관리자로 회원·직원 상세를 연 뒤 본사 계정에서 "전화번호 열람"을 고르면 2건이 처리자 김민수, 대상·지점과 함께 보인다.
- 추가 지연(약 10~20ms)은 추정이고 실측하지 않았다.
