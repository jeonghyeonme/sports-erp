## 229. 계약 갱신용 영업 리포트(D81) — 지점 하나의 계약·운영 성과·서비스 품질을 인쇄용 한 장으로, 기업 분석 대체 문서 점검 (2026-11-16)

**계기**: 11주차 덱 "다음 할 일" 셋(영업 리포트·산출물 재생성·사용감 점검)을 사용자가 정리하며 — ① 영업 리포트는 "계약 갱신용 — 지점별 기록으로 한 시각화를 재활용해 본사와 지점 간 계약 지속·조항 변경을 할 수 있게", ② 기업 분석 및 제안서(14쪽, RFP는 20쪽 이상)는 다른 문서들로 대체해 둔 것이니 내용이 충분한지 확인, ③ 운영 게시판 교육 자료 갱신.

**한 일**:
- **영업 리포트**([D81](../decisions/D81.md)) — 형태·내용은 사용자 선택(인쇄용 화면, 계약 개요·회차 / 운영 성과 / 서비스 품질, 조항 메모 없음). `GET /branches/:branchId/renewal-report`(본사 전용, `renewal-report.ts` — D75 집계 재사용, 스키마 변경 없음), 관리자 웹 `/branches/:branchId/renewal-report`(지점 상세 "갱신 리포트"), 인쇄 CSS(메뉴·상단 바·버튼 제외, 차트 두 열·viewBox로 인쇄 폭 맞춤), 화면 도움말, 사용자 매뉴얼·빠른 시작 한 줄, 요구사항 정의서 라우트 설명.
- 인쇄본을 시연 데이터(마포점)로 PDF로 떠 봤더니 처음엔 3쪽 — 절마다 쪽을 안 나누게 해서 1쪽이 비었고, 차트가 화면 폭으로 그려져 인쇄 폭에서 카드 밖으로 넘쳤다. 카드·차트 단위로만 안 쪼개고, 차트 SVG에 viewBox를 줘 비율대로 줄여 A4 한 장에 들어가게 했다.
- **기업 분석 대체 문서 점검**: 추적표 §1-3대로 분석 본문은 `reference/기업구조및관리시스템분석`(약 1.7만 자)·`차별화전략`(약 1.6만 자)·도메인 문서 9개의 현황·요구 분석(§0~2, 약 2.4만 자)에 나뉘어 있다 — 합쳐 약 5.7만 자로, 제출본(14쪽 ≈ 3만 자)과 같은 밀도면 약 26쪽. RFP 과업1의 항목(지점현황·지역분포·근무자구조·조직도, 인적/물적자원·본사와 지점·현장관리·관리 효율성)이 모두 있다. 다만 상태 표가 낡아 있었다(2026-09 기준 "Phase 1", 문서관리 "파일 업로드 미구현") — 지금 상태로 고치고 위탁계약 행을 더했다. 추적표 §1-3·P2-1에 대체 구성(요약 제출본 + 분석 본문 문서)을 적었다.
- **교육 자료**: 빠른 시작 PDF를 다시 만들었다(갱신 리포트 한 줄 포함). 운영 게시판 교체는 이 세션에서 운영 주소에 접속할 수 없어(프록시가 workers.dev 연결 실패) 하지 못했다 — 사용자가 게시판 글 수정 화면에서 첨부를 바꾼다.

**근거**: D81, D75, D69, 차별화전략 §2, 요구사항추적표 §1-3.

**검증**: api `renewal-report.spec`(새 6건 — 회차가 DB와 같음, 운영 성과가 운영 실적 API 13개월과 같고 12개월 합계는 이번 달 제외, 품질 숫자가 DB와 같음, 업무지원 처리 반영, 지점 관리자 자기 지점 403, 없는 지점 404)·`branch-isolation`(공격 표 1줄)·`branch-scope-coverage`·`permission-coverage` 통과. 화면 자동 테스트 35건(새 2건 — 본사 리포트 세 묶음·인쇄 버튼, 지점 관리자 버튼 없음·직접 주소 본사 전용 안내) 통과. admin-web lint·빌드 통과. 인쇄본은 시연 데이터로 PDF를 떠 눈으로 확인. 전체 jest는 커밋 전 hook.

## 230. 운영 의존성 취약점 3건 → 0 — NestJS 11.2.10(multer 2.5.0)·follow-redirects 1.16.3, 같은 메이저 패치만 (2026-11-16)

**계기**: 사용자가 PC에서 `npm ci` 결과의 "23 vulnerabilities"를 보여 줬다. 운영 의존성만 세면(`npm audit --omit=dev`) high 3건 — D65(2026-10-22)로 0건이던 것이 그 뒤 새 공지로 생겼다: `follow-redirects`(axios 경유, 교차 출처 리디렉트에 자격 증명), `multer`(파일 필터 비동기 처리 중 요청이 끊기면 서비스 거부 — `@nestjs/platform-express`가 2.4.0으로 고정).

**한 일**: D63의 방식(같은 메이저 안에서만 올린다) 그대로 — `@nestjs/common·core·platform-express·testing` 11.2.7 → 11.2.10(platform-express가 multer 2.5.0을 고정), `follow-redirects` 1.16.1 → 1.16.3. 잠금 파일은 사용자 PC와 같은 npm 11.5.2로 만들었다 — 컨테이너의 npm 10으로 `npm audit fix`를 돌리면 잠금 파일 서식이 통째로 바뀌고 api 쪽 중첩 설치는 그대로 남아(옛 platform-express 11.2.7) 되돌렸다. 실제 버전이 바뀐 것은 위 패키지와 그 하위 패치 몇 개(encodeurl·on-finished·range-parser 등)이고, 나머지 줄은 같은 버전의 위치 이동이다.

**근거**: D63(같은 메이저 고정), D65(운영 취약점 0 유지), D64(개발 도구 취약점은 별도 — 이번 범위 밖, 23건 중 나머지 20건).

**검증**: `npm audit --omit=dev` 0건. api lint·빌드, jest 61파일 671건, 화면 자동 테스트 35건 통과(로컬). 개발 도구 쪽 남은 20건(low 8·moderate 11·high 1)은 이번에 손대지 않았다 — 검증되지 않음(D64 재점검 대상).
