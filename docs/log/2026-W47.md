## 232. 비정상 접근 테스트 9건 — 만료 토큰·권한 밖 직접 호출·잘못된 입력, 깨진 JSON의 파서 문구 노출을 `INVALID_JSON`으로 (2026-11-20)

**계기**: 12주차 덱 "다음 할 일"의 비정상 접근 경로. 사용자가 범위를 세 경로(액세스 토큰 만료, 권한 밖 직접 호출, 잘못된 입력)로 정하고(토큰 위조·변조는 제외), 상태 코드와 오류 코드는 정확히, 메시지는 문구를 고정하지 않고 내부 정보가 없는지만 보기로 했다(사용자 결정 C — 401·403 메시지가 Nest 기본 영어 문구라 의도한 문구가 아니다).

**한 일**: 기존 61개 파일과 겹침을 먼저 대조했다. 토큰 없이 401(상태만)은 smoke·branches-public, 역할별 채용 403과 데이터 미변경은 hr-authority, 회원의 처리 대기함 403은 inbox가 이미 본다 — 기존 파일은 옮기거나 고치지 않고, 새 파일 `apps/api/test/abnormal-access.spec.ts`에 빈 곳만 넣었다(9건): 만료 토큰 401 `UNAUTHORIZED`·대조군 200, 토큰 없음 401, 회원·직원이 `GET /members` 403 `FORBIDDEN`·자기 지점 관리자 대조군 200, `POST /members`에 깨진 JSON 400 `INVALID_JSON`·정의되지 않은 필드·타입 오류 400 `VALIDATION_ERROR`. 만료 토큰은 서버의 `JwtService`로 만료 시각만 과거로 발급해 테스트가 서명 키를 읽지 않는다.
처음 실행에서 깨진 JSON 응답이 `400 BAD_REQUEST "Unterminated string in JSON at position 13 …"`로 파서 문구를 그대로 내보내 실패했다. 사용자 결정(전용 코드)에 따라 `AllExceptionsFilter`가 JSON 요청에서 Nest가 body-parser SyntaxError를 바꿔 넘긴 BadRequestException을 골라 400 `INVALID_JSON` "요청 본문(JSON) 형식이 올바르지 않습니다."로 답한다(이 저장소 코드는 BadRequestException을 직접 던지지 않는다). 두 웹앱의 오류 표에 없는 코드는 서버 메시지를 그대로 쓰므로 표는 고치지 않았다.

**근거**: 보안약점 체크리스트 에러-1(오류 메시지 정보노출), 진행률 D80 검증 묶음. 공통 에러 포맷 system-overview §4.

**검증**: 새 파일 9건 통과, api 전체 jest 62파일 680건 통과(로컬 실DB), eslint·tsc 통과. 처음 전체 실행에서 PT 구매 2건이 실패했는데 원인은 로컬 기준 DB 시드가 옛 값(PT 횟수 비어 있음·60,000원)이라서였고, `prisma:seed`(upsert)로 다시 넣은 뒤 통과했다. 경로의 잘못된 % 인코딩(URIError)도 같은 방식으로 파서 문구가 나갈 수 있으나 이번 범위 밖 — 검증되지 않음. 진행률 문서(검증 11/11)에 이 항목을 더할지는 사용자 결정 대기.
