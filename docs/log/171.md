# 171. 중간발표 캡처 6장 — 로컬 실행 화면, 재현 스크립트 포함 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 4-7 구성안의 "캡처 6장"을 진행하라고 했다(덱 제작 전 단계).

**한 일**:
- 로컬 환경: 이 세션 컨테이너에서 PostgreSQL 16을 직접 띄우고(Docker 데몬 없음) `prisma migrate deploy` → `apps/api`에서 `npm run seed:demo`(기준 시드 + 시연 데이터, D58) → api·관리자 웹·회원 웹 실행. 배포 DB는 건드리지 않았다.
- `docs/presentation/assets/4-7_중간발표/deck-source/capture/capture.cjs`(Playwright) — 데모 계정 버튼으로 로그인, 관리자 화면 2배 해상도, 머리말 아래 개발용 안내 문구·마포 계약 정보 아래 OCR 설계 안내 숨김(4-0 §5). 회원 웹은 iPhone 13 에뮬레이션으로 저녁 필라테스 회차를 실제 API로 예약·모의 결제했다(로컬 DB에 예약 1건 생김).
- `capture/sheet.sh` — 요구사항정의서.xlsx에서 "RFP 충족 판정" 시트만 남겨 LibreOffice로 PDF → PNG, 집계·판정 기준·F1~F4 범위로 자름. 두 번 돌려 같은 파일(해시 일치).
- 결과 `screenshots/`: after-support(강남점 요청 처리 창) · after-qa(마포 계약 정보 + 운영 실적) · after-permission(역할 기본 권한, 지점 관리자) · ov-scope-admin(회원 상세, 경로 표시) · ov-scope-member-2-pay(결제 단계 — 덱용) + 보조 2장(회차 선택·결제 완료) · appx-sheet(91% 집계). 파일 대응과 다시 찍는 법은 deck-source README.
- 구성안 4-7 캡처 절 머리를 "찍음"으로.

**근거**: 4-0 §5(실제 앱 캡처, 실제 API로 만든 상태, 개발용 문구 가림), 4-7 캡처 목록, D58.

**검증**: 캡처 7장(+보조)을 눈으로 확인 — 화면이 비지 않았고 개발용 문구가 없으며 수치(91%, 마포 운영 실적, 결제 38,000원)가 보인다. 덱 안에서의 크기·잘림은 덱 제작 때(검증되지 않음). 회원 화면은 에뮬레이션(실기기 아님), 시트 이미지는 LibreOffice 렌더(엑셀 화면 아님).
