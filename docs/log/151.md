# 151. 처리 대기 배지 — 사이드바 메뉴·그룹 머리·상단 합계(D61 후속) (2026-10-21)

> [진행 로그 인덱스](README.md)

**계기**: D61(처리 대기함)이 "알림은 대기함 건수를 배지로 쓰는 정도면 충분"이라고 남긴 후속을 사용자가 요청했다. api·스키마 변경 없음 — 같은 `GET /inbox`를 쓴다.

**한 것**(관리자 웹):
- 사이드바 메뉴 옆 숫자 — 대기함 항목의 `link`와 같은 경로의 메뉴(예: 근태관리 = 승인 대기 휴가, 시설·혼잡도 = 미갱신 시설). 그룹이 접혀 있으면 그룹 머리에 합계. 상단 "처리 대기 N"(누르면 대시보드 카드). 99 넘으면 99+.
- 요청 수(D40 ⑩ 방문당 호출 가정): 대기함은 대시보드 카드와 같은 캐시 `['inbox']`. 화면을 옮길 때 30초보다 오래된 값일 때만 다시 받고(`refetchQueries stale`), 쓰기(useMutation)가 성공하면 다시 받는다(`MutationCache.onSuccess` → invalidate) — 승인한 화면에 머물러도 배지가 준다. 주기적 폴링은 하지 않는다.

**검증**: 관리자 웹 lint·빌드. 화면 자동 테스트 10건 통과 — `admin-inbox`에 근태관리 메뉴 배지·상단 합계 표시, 휴가를 승인하면 메뉴 배지가 1 준다(1이었으면 사라짐)를 더했다. 그룹 머리 합계·본사·직원 화면의 배지는 lint·빌드만(검증되지 않음).
