# 078. 목록 응답 전화번호 마스킹 — RFP 사용자인터페이스보안의 비용 작은 몫 (2026-10-07)

> [진행 로그 인덱스](README.md)

**계기**: 브리프 B5-1. RFP 사용자인터페이스보안(1-2 #7)·회원관리 Q10이 요구하는 응답 마스킹이 코드에 없었다(요구사항추적표 §2-3). 본사 계정은 83곳 회원 전화번호를 목록 한 번에 받았고, 강사 목록은 MEMBER도 볼 수 있어 강사 연락처가 회원에게 나갔다.

**한 일**: 범위를 사용자에게 먼저 물었다(4문항). 선택: 목록만 마스킹, SUPER_ADMIN에게도 적용, 회원·직원·강사 목록 포함, 형식 `010-****-1234`.
- `apps/api/src/common/privacy/mask-phone.ts`에 `maskPhone`·`maskPhones`를 추가했다. 숫자 10자리 이상이면 앞 3자리·끝 4자리를 남기고, 짧으면 끝 4자리만 남긴다. 하이픈은 제자리에 둔다.
- `GET /members`·`/staff`·`/instructors` 컨트롤러가 응답 직전에 마스킹한다. 서비스 `list()`는 원문을 유지한다. 원문이 필요한 곳은 `?q=` 전화번호 검색과 중복 전화번호 경고다.
- 상세(`GET /members/:id`·`/staff/:id`·`/staff/me`)와 등록·수정 응답은 원문으로 둔다.
- 문서: 회원관리 ADR-MEM-04·§11·요약 카드·A-7·A-8, 인사정보관리 STF-T03·요약 카드·A-8, 요구사항추적표 1-2 #7·§2-3·§3.

**근거**: 회원관리 ADR-MEM-04. 옛 설계(회원관리 A-7 원문, 인사정보관리 STF-T03)가 이미 "목록 마스킹, 상세 전체 노출"이었다. 그 설계에 함께 있던 "상세 열람 AuditLog 기록"은 B5-2로 넘겼다.

**검증**:
- 새 `phone-masking.spec.ts` 15건 통과. 전체 jest는 29개 파일, 327 통과 + todo 1이다. `branch-isolation`은 기대값을 바꾸지 않고 통과했다.
- api lint 오류 0. 경고 1건(`main.ts`의 사용하지 않는 eslint-disable)은 이번 변경과 무관하다. api 빌드 통과.
- admin-web lint·빌드 통과. 자동 테스트가 없어 로컬 dev 서버와 Playwright로 수동 확인했다. 서초점 관리자 회원 목록은 `010-****-5678`·`010-****-0000`이고, 회원 상세와 수정 폼은 원문 `010-1234-5678`이다.
- 강사·지점 상세 화면은 같은 목록 API를 쓴다. API 테스트로만 확인했고 화면은 눈으로 보지 않았다.
