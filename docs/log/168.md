# 168. 배포 DB 채용 계정 점검 — 데모 비밀번호로 열리는 채용 계정은 0개 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: log/164(ADR-AUTH-08)는 배포 DB에 `mustChangePassword` 열을 기본값 false로 더했다(표시 0개). 새 코드 배포 전 배포에서 채용된 계정이 있었다면 데모 비밀번호로 열리고 변경 강제도 걸리지 않는다 — 이를 확인했다(사용자 승인, 읽기 전용).

**한 일**: 배포 DB `Account` 전체를 역할·활성·표시·출처(id가 `account-`·`demo-account-`로 시작하면 시드)별로 SELECT 한 번 집계.

| 역할 | 수 | 출처 | 만든 시각 |
|---|---|---|---|
| SUPER_ADMIN | 1 | 시드 | 2026-10-20 재시드 |
| BRANCH_ADMIN | 5 | 시드 | 〃 |
| STAFF | 18 | 시드 | 〃 |
| MEMBER | 17 | 시드 | 〃 |

**결과**: 41개 모두 시드·활성·표시 없음. 채용·가입으로 생긴 계정 0개 — 재시드(log/143) 뒤 배포에서 채용이 없었다. 조치할 것 없음, 쓰기 없음.

**S2에 넘길 사실**: 시드 계정 41개 중 비밀번호 변경이 막힌 것은 데모 5개(`DEMO_ACCOUNT_IDS`, log/091)뿐이다. 나머지 36개도 공개된 데모 비밀번호로 들어갈 수 있고 방문자가 비밀번호를 바꿀 수 있다 — S2 대응 범위에 함께 넣는다.

**S2 결정(같은 날, 사용자)**: 대응하지 않는다(수용). 실서비스로 배포·운영할 계획이 없고 데이터가 시연용 더미라, 비밀번호 교체(배포 DB 쓰기)나 읽기 전용 스위치(코드·재배포)의 비용이 막는 것보다 크다. 시연 데이터가 훼손되면 재시드 절차(log/143)로 되돌린다. 재고 트리거: 실데이터를 받거나 실제 운영할 때. security-plan S2를 "수용"으로 바꿨다.

**근거**: 권한관리 ADR-AUTH-08, security-plan S2·S3.

**검증**: 실측(배포 DB 읽기 조회 1회). 코드 변경 없음.

**커밋**: docs만.
