# 20. 자원문서관리(9번째, 마지막) 도메인 사이클을 문서화했다 — 9개 도메인 전체 완료 (2026-09-25)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "자원문서관리 도메인 사이클 진행해줘"로 요청. §15~19에서 8개 도메인에 반복 적용해온 것과 같은 방식(`architecture-driver` 스킬의 11단계, Driver 상한 2-5개, 시간경계·우회·인간실수 체크리스트)을 마지막 도메인에 적용했다. 이 도메인은 다른 8개와 성격이 다르다 — 원본 RFP가 명시적으로 요구한 기능이 아니라, RFP 과업1("인적/물적자원 관리 현황" 분석)이 요구했지만 아무 문서도 다룬 적 없던 공백을 메우려고 이 프로젝트가 재해석해 신설한 도메인(reference/기업구조및관리시스템분석.md §1)이라, "하" 우선순위이자 마지막 순번이었다.

**한 일**: 옛 자원문서관리 부록 A·부록 A(자산·비품관리, 문서관리 신규 설계)와 `apps/api/src/modules/assets/`·`documents/`의 컨트롤러·`mock-data.service.ts` 관련 함수를 코드로 직접 대조해 3개 Driver로 정리, [domains/자원문서관리.md](../domains/자원문서관리.md)로 작성했다. 자원문서관리 문서는 §4·§5에만 대체 배너를 달았고(§1~3·§6~7은 도메인 사이클 형식에 안 맞는 산출물2 성격 서술이라 원본에 유지 — 여러 도메인에 걸친 architecture/entities.md와 같은 종류의 예외), [02_도메인별_우선순위.md](../process/02_도메인별_우선순위.md)·[log/archive/05_문서_마이그레이션_추적.md](archive/05_문서_마이그레이션_추적.md)를 갱신했다.

**발견**: 이번에도 코드를 직접 열어봤기 때문에 드러난 격차가 있다. ① **계약종료(TERMINATED) 지점 차단이 이 도메인에도 빠져 있었다** — `createAsset`·`createDocument` 둘 다 `Branch.contractStatus` 체크가 없어, CLAUDE.md 핵심 불변식이 회원·게시판·예약·혼잡도관리에 이어 **다섯 번째로 같은 패턴으로 빠진 도메인**임을 확인했다(ADR-RES-01). 자산 도메인은 SUPER_ADMIN도 직접 쓸 수 있어 "역할과 무관하게 대상 branchId로 판정"해야 하는, 다른 도메인엔 없던 특이점도 있었다. ② `resignStaff`가 계정 비활성화·파견 종료는 원자적으로 처리하면서 **HR_RECORD 문서의 보존기한 재계산은 건드리지 않는다** — 재직 중 업로드된 인사서류가 실제 퇴사일과 무관하게 "업로드일+3년"으로 영구 고정되는 결함(ADR-RES-02, 옛 문서 §5-6이 이미 요구했지만 Phase2로 미뤄뒀던 항목). ③ `CONTRACT` 문서의 `retentionUntil`이 옵션이라 관리자가 비우면 조용히 "영구 보관" 취급되어 보존기한 임박 알림에 영원히 안 뜨는 결함(ADR-RES-03) — 이건 옛 문서도 몰랐던 것으로, 이번 사이클의 인간실수 체크리스트를 실행하다가 새로 찾았다(옛 문서는 "관리자가 직접 입력하도록 함"이라고 의도만 적어뒀지 강제하는 코드가 없다는 걸 아무도 확인한 적이 없었다).

**검증**: 문서만 작성했다(코드 변경 없음 — 근태관리 때부터 이어온 이 프로젝트의 관행대로 "도메인 사이클=문서 우선, 구현은 별도 명시적 요청 대기"를 그대로 따랐다). `apps/api/test/branch-isolation.spec.ts`가 이미 이 도메인의 지점 격리(자산 수정/상태변경, 문서 상세조회, 목록 미섞임, 문서 생성 시 타지점 주입 방어)를 검증하고 있다는 것도 이번에 확인했다 — 자산 생성 시 타지점 주입 방어만 전용 테스트가 없다(코드는 문서와 동일 패턴이라 안전할 것으로 보이나 미검증으로 정직하게 기록).

**9개 도메인 전체 요약**: 상 4개(권한관리·회원관리·인사정보관리·예약및결제, 2026-09-22) → 중 1개(근태관리, 2026-09-23, 구현까지 완료) → 중/하 3개(강사프로그램게시·혼잡도관리·게시판, 2026-09-23 문서화 → 2026-09-25 7개 ADR 전부 구현) → 하 1개(자원문서관리, 2026-09-25 문서화). **9개 도메인 전체의 도메인 사이클(문서화)이 이제 완료됐다.** 이번에 발견한 3개 ADR(RES-01~03)은 아직 문서만 있고 구현 전 — 다른 7개 ADR과 같은 패턴("한 개씩 진행 → 검토 → 수정 → 보고")으로 처리할 수 있는 상태로 남겨둔다.
