# 223. 리팩토링 ② — 두 웹앱에 똑같이 있던 파일을 `packages/web-shared` 한 벌로 (2026-11-12)

> [진행 로그 인덱스](README.md)

**계기**: 리팩토링(log/222)의 두 번째. admin-web·member-web의 같은 이름 파일을 비교하니 `password-rule`(9줄)·`slow-requests`(48줄)·`SlowRequestNotice`(16줄)가 글자까지 같고, `rich-content`(17줄)는 주석 한 단어만 달랐다. 값 타입 5개도 같았다. `packages/types`는 아무 앱도 import하지 않는 36줄이었다.

**한 일**: [D78](../decisions/D78.md) — `packages/types` → `packages/web-shared`로 바꾸고 위 파일을 옮겼다(`git mv`, 반대쪽 사본 삭제). 두 앱의 import 11곳을 `@sports-erp/web-shared`로, 앱 `lib/types.ts`는 공유 값 타입을 re-export. 옮기기 전 값 타입을 두 앱 원본과 글자 단위로 대조했다(처음 적은 결제·예약 상태 값이 틀려 원본 값으로 고침 — 대조가 잡았다). `package-lock.json`은 워크스페이스 이름 변경분만 바뀜.

**검증**: admin-web·member-web lint·빌드 통과, api 빌드 뒤 화면 자동 테스트(e2e) 24건 통과(로컬). 사용자 PC의 웹 배포는 루트에서 `npm ci` 뒤 `npm run build:web`이면 그대로 된다(워크스페이스 링크는 `npm ci`가 만든다).
