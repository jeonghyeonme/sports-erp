> [진행 로그 인덱스](README.md)

**계기**: log/132의 조항별 판정에서 코드로 금방 메울 수 있다고 본 부분 조항 셋(F3-2·F4-3 일부·N6-5)을 사용자가 고치자고 했다.

**사용자 결정(D53 방식, 2026-10-19)**: 상위 목표 = 노하우 습득(D53), 클라이언트 = 현장 사용자(D58). 셋 다 추천안. **사용자 설명**: 없음 — 추천안 선택.
- 병가 일수: 사용 일수만 집계. 유형별 한도(`LeaveBalance`에 유형 열)는 스키마 변경이고, 병가는 법정 한도가 없어 회사 규정마다 달라 한도 값을 정할 근거가 없다.
- 공지 첨부: 이미지(png·jpg·webp)는 본문 아래에 바로, 그 밖의 파일은 이름 + 내려받기. RFP의 "공지 글·이미지"에 맞춘다. 이미지 하나에 다운로드 URL 요청 1회가 는다(글당 첨부 5개 상한).
- 입력 속성: 두 앱 전부.

**한 일**:
- api `GET /leave-balance/:staffId`가 `usedByType`(올해 승인된 휴가의 유형별 일수 합)을 함께 준다. 집계는 조회 라우트에서만 하고(`leaveBalanceWithUsage`), 신청·승인 트랜잭션이 쓰는 `leaveBalance`는 그대로다. 해를 걸친 휴가는 시작일의 해로 센다. 관리자 웹: 직원 상세 휴가 제목줄에 "병가 n일 · 경조사 n일"(기타는 있을 때만), 근태관리 카드를 "휴가 일수"로 바꾸고 연차 행 이름을 "연차 부여·사용·잔여"로, 아래에 병가·경조사·기타 사용 행.
- 회원 웹 `components/NoticeAttachments.tsx`: 공지 상세 응답의 `attachments`를 받아 이미지는 다운로드 URL로 `<img>`(받는 동안 4:3 자리), 그 밖은 버튼으로 내려받기. 로컬 메모리 드라이버의 상대 경로(`dev-storage`, 공개 경로)와 Supabase 절대 서명 URL을 모두 처리한다.
- 입력 103곳 점검(체크박스·파일 제외): 관리자 웹 연락처 5곳 `type="tel"`·`inputMode="tel"`·`autoComplete="off"`(남의 번호를 넣는 화면이라 자동완성 끔), 숫자 9곳 `inputMode="numeric"`, 로그인 이메일·비밀번호와 채용 이메일 자동완성, 문서 파일 URL `type="url"`, 서버 길이 제한이 있는 근태 정정 사유(200)·인사 변경 값(30)에 `maxLength`. 회원 웹은 가입·내 정보 이름 `autoComplete="name"`, 생년월일 `bday`, 회원번호 `autoComplete="off"`·`spellCheck={false}`. 입력창 크기: `.field input`은 폭 100%이고 고정 폭 입력이 없으며 텍스트 영역 9개 모두 `rows`가 있다. 한글 자판을 강제하는 웹 표준은 없어 텍스트 칸은 기본값으로 둔다(두 앱 `<html lang="ko">`).
- 요구사항추적표 §3: F3-2·N6-5 부분 → 구현, F4-3은 시설 지정이 남아 부분 유지. 집계 45/64(70%) → 47/64(73%), 기능·성능 24/28 → 25/28(89%). §2-3 미구현·부분 11 → 9건. 요구사항 정의서 재생성.

**처음 시도한 속성 일괄 삽입이 코드를 깨뜨렸다**: 태그 끝을 `>`로 찾는 정규식이 `onChange={(e) => …}`의 `=>`에서 멈춰 속성을 화살표 사이에 넣었다. 빌드 전에 diff에서 보고 되돌린 뒤 `value={…}` 바로 뒤에 넣는 방식으로 다시 했다.
