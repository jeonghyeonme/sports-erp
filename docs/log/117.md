# 117. 프로젝트 상위 목표를 결정 기록으로 — 결정마다 인용할 기준을 만들었다 (2026-10-15)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 유튜브 영상(분석좌, "이 영상 1개로, AI시대 속 방황을 끝내드립니다")의 "돋보기" 개념(상위 목표 → 답안지 → 핵심 변수)을 모든 프로젝트의 결정에 쓰고 싶어 했다. 그래서 사용자 전역 가드레일(`~/.claude/CLAUDE.md`, 저장소 밖)에 9절 "결정 전 세 질문"을 추가했다. 9절은 결정마다 상위 목표를 묻고, 이미 기록된 상위 목표는 인용하라고 한다. 그런데 이 프로젝트에는 기록된 상위 목표가 없었다.

**한 일**:
- [D52](../decisions/D52.md) 새 결정. 상위 목표는 "AI 활용·실무 개발 노하우와 도메인 지식을 빠르게 익히는 것이 먼저, 포트폴리오 품질은 그다음"이다. 배우는 방식은 AI가 핵심 변수 후보를 내고, 사용자가 "왜 핵심인지" 설명하도록 질문으로 유도하는 것이다. 사용성·성능·스케일링은 모두 챙기되, 우선순위는 클라이언트가 중시하는 것에 따른다. 전역 9절은 시험 적용으로 한다.
- 결정 인덱스에 D52 한 줄을 추가했다.
- 루트 `CLAUDE.md` 머리말에 상위 목표 한 줄과 D52 링크를 넣었다(매 턴 로드, 100 → 101줄).
- 처음 요청은 "D51로 기록"이었다. 원격 `dev`에 D51(RFP 문구 기준, log/112)이 이미 있어서 D52로 만들었다.

**근거**: 사용자 결정(2026-10-15 대화). D38의 "한 사실은 한 곳에" 원칙에 따라 내용과 경위는 D52에 두고, CLAUDE.md에는 요약과 링크만 둔다.

**검증**: `node scripts/doc-check.mjs` 통과. 코드 변경이 없어 lint·빌드·jest는 대상이 아니다. 9절이 실제 결정에서 잘 발동하는지는 검증되지 않았다(다음 결정부터 관찰).
