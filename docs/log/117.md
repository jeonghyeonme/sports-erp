# 117. RFP 중간 작업 M2·M7 — 관리자 근태 정정·누락일 등록, 변경 이력 범위 확대 (2026-10-15)

> [진행 로그 인덱스](README.md)

**계기**: 작업 브리프 B2 권장 순서 둘째 묶음(D51). 요구사항추적표 §2-3의 두 행 — RFP 1-1 근태 "현장별>개인별 근태 등록 관리", 1-2 #3 데이터관리방안(변경이력: 회원·자산 상태, 근태 정정 미기록).

**사용자 결정(2026-10-15)**: 정정은 지점 관리자만 / 기존 기록 수정 + 누락일 등록, 상태는 관리자가 고름 / 이력은 `entity=Staff`, `ATTENDANCE_CORRECTED` / M7 범위는 근태 정정·회원 상태·자산 상태 셋 다.

**구현 중 정한 것(사용자에게 보고)**: 지점 관리자 **본인 근태 정정을 막지 않았다**. 처음엔 막으려 했으나 정정 권한이 지점 관리자뿐이라 막으면 그 사람의 근태를 고칠 사람이 없어진다. 변경 이력에 처리자=대상으로 남는다(ADR-ATT-04 감수하는 것 ②).

**한 일**:
- api `PUT /attendance/:staffId/:date`(근태관리 ADR-ATT-04): 그날 근태를 관리자가 정한 값으로(없으면 생성), KST "HH:mm" 시각, 사유 필수, 오늘 이후 불가, 그날 기록의 지점 검사(ADR-ATT-03), 행 락·unique 409, 같은 값이면 쓰지 않음.
- 변경 이력(D52): `ATTENDANCE_CORRECTED`(Staff)·`MEMBER_STATUS_CHANGED`(Member)·`ASSET_STATUS_CHANGED`(Asset)을 각 변경과 같은 트랜잭션에. 회원 상태 변경은 상태가 실제로 바뀔 때만, 자산은 조건부 갱신이 성공할 때만. 변경 이력 조회가 자산 이름(자산코드)을 붙인다.
- admin-web: 직원 상세 "근태" 섹션에 행별 "정정"·"+ 누락일 등록"(그 지점 관리자에게만), 정정 모달(날짜·상태·출퇴근 시각·사유). 변경 이력 화면 이벤트 3종·대상 "자산"·내용 문구("2026-10-13 · 지각 09:40~ → 정상 08:58~18:03 · 사유: …"). 오류 해결 문구 4개(`error-hints.ts`), 도움말(직원 상세·변경 이력).
- 정리: log/116에서 기본 설정 prettier로 바뀌었던 `StaffDetailPage.tsx`·`ProgramsPage.tsx`의 따옴표·줄 폭을 저장소 모양(작은따옴표, 120자)으로 되돌렸다. log/116의 직원 상세 도움말 오류 목록에 `ATTENDANCE_SCOPE_VIOLATION`이 빠져 있던 것(치환 실패)도 이번에 넣었다.
- 테스트: `attendance-correction.spec.ts` 새 파일(11건), `branch-isolation` 공격 표에 근태 정정 1행(PUT 메서드 추가).

**근거**: 근태관리 ADR-ATT-04·ADR-ATT-03·A-7("근태기록 직접 수정은 관리자만, 정정 사유 필수"), D52(D44·D47 위에), D46(가드).

**검증**:
- jest: `attendance-correction`·`branch-isolation`·`branch-scope-coverage` 통과(로컬 PG16). 전체 jest는 커밋 hook이 돈다. 동시 정정 경합 테스트는 없다 — **검증되지 않음**.
- admin-web lint·빌드 통과. member-web은 바뀌지 않았다.
- 화면: 복사본 DB(`sports_erp_manual`, 확인 뒤 삭제)에서 Playwright로 지점 관리자 정정(지각 → 정상)·누락일 결근 등록 → 본사 변경 이력에 두 건이 이전 → 이후·사유로 보이는 것 확인. **화면은 자동 테스트가 없어 검증되지 않음(수동 확인만)**. 회원·자산 상태 변경 이력은 API 테스트로만 확인했다.
