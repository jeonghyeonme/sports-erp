# 175. 중간 제출물 구성 — 중간보고서를 "혼자 읽는 덱"으로 재구성, 실운영은 하지 않음 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 중간고사 대체 제출 요구("프로젝트 중간보고서 · 각 주차별 발표자료 및 증빙자료를 압축해 업로드")를 보여 주며, 독자(지도교수)가 전체 맥락을 피곤하지 않게 파악하는 것, RFP를 충실히 이행했다는 증빙을 함께 원했다. 대화로 제출물 구성·증빙 형식·이후 방향을 정했다 — 결정은 [D67](../decisions/D67.md).

**정한 것(대화 순서)**:
- 패키지: "요약 보고서 + 증빙 묶음"(질문별 폴더) 안 → 요구 목록 비교(주차별 축이 비어 있음, 2주차 덱 파일 없음, 3주차 이후 덱은 아티팩트) → 사용자: 주차별 발표자료는 직접 내보내고, 중간보고서는 슬라이드 아티팩트, RFP 이행 증빙은 HTML 아티팩트, 둘 다 PDF로. 주차별 이행 증빙은 만들지 않음. 산출물은 전부 재생성. 한 폴더에 모아 사용자가 압축.
- RFP 이행 증빙: 조항마다 원문 → 판정 → 구현 → 화면 → 결정 기록(견본 F1~F4, 브랜치 `claude/rfp-evidence`). GitHub CI 링크는 빼고 화면 캡처·결정 기록이면 충분(사용자). "구현한 것"은 쉬운 말 한 줄로 **교체**(기술 근거를 작은 글씨로 남기는 안은 기각).
- 중간보고서: 기존 4-7(20분 발표용, 파트 A → B, 24장)을 점검 — RFP 이행 현황(B7~B12)은 의도에 맞고, 읽는 덱이 아님·순서(최근 작업이 맨 앞)·맞물림 지도와 시나리오 부재·제출 패키지 연결 부재·혼잡도 사유 낡음이 어긋남. 사용자: 분량을 맞추지 말고 한 장에 어려운 곳은 늘린다 → 45장으로 재구성. 6주차 발표(10/11) 이후 작업은 어떤 발표에도 나온 적이 없어 8장으로 펼치고, 1~6주차는 2장으로 줄여 주차별 자료를 가리킨다. 이행 현황 표는 7장으로(쉬운 말이 들어가 글씨를 지키려고 권한·인사 / 근태·게시판, 시스템 / 보안을 나눔), 검증 3장, 마무리 8장(바꾼 것·남은 것·다음 계획 4장·AI 협업·시연 접속).
- 이후 방향: 실운영은 하지 않음(부분 3조항은 범위 밖, 순간 몰림 원인 확인 등 실운영 전 조치 삭제, 키오스크 제외). 다음 계획 세 갈래 — 사용감 확보, 계약서 OCR·AI 분석 적용 검토(차별화전략 §1-1 — RFP 조항이 아니라 우리가 더한 기능), 회원 앱 형태 재검토(PWA 접근성 한계). 계획 수준으로만 쓴다.
- 기본값으로 정한 것: 진행 경과는 뒤쪽(Ⅵ), AI 협업 장 1장 넣음, 시나리오는 본사·지점 흐름 1장 + 화면 1장, 회원 1장.

**한 일**: 4-7 구성안을 새로 씀(이행 현황 표 행은 기존 B8~B12에서 옮기고 혼잡도 행을 ADR-FAC-05로 최신화), D67, STATUS 다음 할 일 4.
