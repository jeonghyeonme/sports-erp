# 52. D37 — 회원 앱을 범위에서 빼고, API의 Lambda 전환 코드를 넣었다 (2026-09-30)

> [진행 로그 인덱스](README.md)

**범위 결정(사용자)**: 회원 앱(`apps/member-app`)을 개발 범위에서 뺐다. 웹(admin-web)에만 집중한다.
- 사용자가 "나중에 회원 앱을 넣으면 DB도 AWS로 옮기는 게 어떤가"라고 물었다. 검토한 결론은 **지금은 옮기지 않고 조건으로 남기는 것**이다(D37 §5).
  - 지연: Supabase 서울 리전이 이미 AWS 서울 위에 있어 얻는 게 쿼리당 1~2ms뿐이다.
  - 커넥션: RDS 최소 인스턴스도 상한이 비슷하다.
  - 비용·운영: RDS Proxy·VPC/NAT 비용이 붙고, Supabase 운영 도구도 잃는다.
  - 되돌리기: `pg_dump` + 연결 문자열 교체로 끝나 비용이 낮다. 미리 정할 이유가 없다.
- 회원 앱 제외로 D37 결정 2(Workers 유료 전환)도 보류했다. 범위 안 요청량(하루 1만 건 수준)은 무료 한도 안이다.
- 기록: D37 §5, 2-3 §2-4, CLAUDE.md 구조 설명, design-constants ⑬.

**왜 진입점만 추가했나(D37 결정 5)**: 도메인 코드는 D36으로 이미 무상태다. 바뀌어야 하는 건 "HTTP 요청이 들어오는 방식"뿐이다.
- 그래서 `lambda.ts`를 새로 두고, 서버·Lambda·테스트가 전역 설정을 공유하도록 `configureApp()`을 뽑았다. 전에는 테스트 헬퍼가 `main.ts` 설정을 손으로 복제하고 있었다.
- 비밀 헤더 검사는 Nest 가드가 아니라 Lambda 핸들러 앞단에 뒀다. 이유는 두 가지다.
  - 테스트·로컬 서버는 Worker를 거치지 않아 이 검사가 없어야 한다.
  - 거부할 요청은 Nest까지 갈 필요가 없다.
- JWT·ORIGIN 비밀값은 "배포 환경에서 없으면 부팅 실패"로 바꿨다. 지금은 환경변수를 빠뜨려도 공개된 기본값(`change-me`)으로 조용히 떠서 토큰 위조가 가능했다.

**구현 중 판단한 것**:
1. **런타임 Node 22.** Lambda nodejs20.x는 Node 20 지원 종료(2026-04)로 폐기 대상이다. 새 함수는 22로 만든다.
2. **zip 크기.** 처음엔 41MB로 직접 업로드 한도(50MB)에 가까웠다. `@prisma/engines`(34MB, 마이그레이션용 스키마 엔진)와 Prisma CLI는 런타임에 안 쓴다. 빼서 22MB가 됐다. 뺀 뒤 실제 호출이 되는지까지 확인했다(아래).
3. **bcrypt 네이티브 바이너리.** 미리 빌드된 바이너리를 못 받으면 빌드한 OS의 glibc에 묶인다. 그래서 CI는 운영 의존성 설치를 Lambda 공식 이미지 안에서 한다(`LAMBDA_DOCKER=1`).
4. **패키징이 개발 환경을 건드리지 않게.** 운영 의존성 설치는 매니페스트만 복사한 스테이징 폴더에서 한다. 저장소의 `node_modules`를 `--omit=dev`로 지우지 않는다.
5. **스로틀 응답은 503 `SERVER_BUSY`.** ADR 초안은 `RATE_LIMITED`였다. 하지만 그건 IP별 로그인 제한의 코드다. "서버 전체가 붐빔"과 구분해 503 + `Retry-After`로 정했다. 앱이 스스로 내는 429(회원 연동 초과)는 공통 포맷이라 구분해서 그대로 통과시킨다.
6. **배포가 조용히 멈추지 않게.** Render 자동배포가 멈춘 걸 아무도 몰랐던 게 이번 점검의 발견이었다. 그래서 워크플로 안에서 health를 확인하고, 실패하면 별칭을 이전 버전으로 되돌린다.

**검증**:
- **jest:** 309 통과(todo 1). 격리·계약·인사 권한 기대값 변경 없음.
- **lint·빌드:** api lint 에러 0(기존 경고 1), 빌드 성공. admin-web lint·빌드 성공. Worker `tsc` 통과.
- **패키징된 zip을 Amazon Linux 2023 컨테이너에서 실행했다.**
  - Lambda 공식 이미지는 이 세션에서 받을 수 없었다(ECR 다운로드 403). 그래서 같은 OS 이미지에 Node 22를 얹었다.
  - 합성 Function URL 이벤트로 12가지를 확인했다. 결과는 D37 §6 표와 같다.
  - cold init 1.2초, 따뜻한 조회 p50 23ms.
- **Worker:** 가짜 fetch로 429 변환·헤더 위조 차단·origin 다운 처리를 확인했다.
- **검증되지 않음:** 실제 AWS 위의 동작(Function URL, 풀러, 동시성 상한, 스로틀 응답 형식)·배포 워크플로 실행·k6 S1~S4. 사용자가 `aws-lambda/README.md` 체크리스트대로 설정한 뒤 잰다.
