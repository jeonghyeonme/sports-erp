## 241. 사용감 — 시설 카드 버튼 세로 쌓임, 공지 등록 버튼 스크롤, 회원 확인 시트가 화면 밖에 뜨던 것 수정 (2026-11-23)

**요청**: STATUS "발표 뒤"의 사용감 항목(시설 카드 버튼 찌그러짐·남은 스크롤 2곳 B09·M02)을 점검해 고친다 — 이어서 사용자가 웹 재배포(사용자).

**점검**: 시연 데이터(`E2E_DENSE=1`, 회원 218명) 위에서 작업 단계 측정(log/198)과 캡처.
- **시설 카드(관리자, log/212 발견)**: 재현됨 — 카드 폭 약 230px에 입력칸(120px)·입력·정보 수정·운영 중단을 한 줄로 넣어 버튼 글자가 한 글자씩 세로로 쌓였다. 카드 폭은 화면 폭이 아니라 카드 수로 정해져(`auto-fit`) 기준 시드(서초점 시설 2개)에서는 1440px에서 안 보이고, 시연 데이터(4개)·800px에서 보인다.
- **B09 공지 작성**: "등록" 버튼이 1280×720에서 첫 화면 밖(y 803).
- **M02 회원 예약 취소**: 목록이 아니라 **확인 시트**가 문제였다 — 시트 배경이 본문 영역만 덮고 시트가 페이지 맨 아래(y 1241, 화면 높이 839)에 붙어, "예약 취소"를 누른 뒤 확인 버튼을 찾으러 스크롤해야 했다. 원인은 화면 전환 애니메이션(`.page-enter`, transform·`both`)이 걸린 조상 — Chromium에서 그 조상이 `position: fixed`의 기준 상자가 된다. 목록이 짧은 기준 시드에서는 페이지가 화면보다 짧아 드러나지 않았다. 같은 시트를 쓰는 예약 확인(M01)도 같은 문제였다.

**한 일**:
- 시설 카드: 현장 인원 입력(입력칸이 남은 폭을 씀 + 입력)과 관리 버튼(정보 수정·운영 중단, 오른쪽 정렬)을 두 줄로, 버튼 `nowrap`.
- 게시글 작성: 취소·등록 줄을 `.form-actions-sticky`(화면 아래에 붙음)로. `.content`가 가로 넘침용 `overflow: auto`라 sticky 기준이 되므로 그 줄이 있는 화면만 `:has()`로 `overflow: visible`.
- 회원 웹 `BottomSheet`: `createPortal(…, document.body)`.
- 검사: `admin-layout` 800px 검사에 "카드 안 버튼 줄바꿈"(수정 전 코드에서 입력·정보 수정·운영 중단으로 실패 확인), `member-reserve`에 "시트 배경이 화면 전체·시트가 화면 안"(포털을 뺀 빌드에서 실패 확인). 작업 단계 측정 도구는 끝이 있는 애니메이션이 끝난 뒤 위치를 재게 했다(시트가 올라오는 중에 재면 화면 밖으로 잘못 센다). 같은 파일의 중복 호출 두 줄(병합 흔적)을 정리.
- 디자인시스템 §3에 규칙 한 줄(저장 버튼 줄·카드 버튼·포털).

**측정 전후**(시연 데이터, 스크롤 수): B09 1 → **0**, M02 1 → **0**(시트), 시설 카드 버튼 줄바꿈 3개 → 0. 새로 보인 것: B05(체크인 버튼)·H01·H02(본사 대시보드 지점 행 — 운영 실적 차트 D75 아래로 밀림)·M01(회원 프로그램 목록)이 각 스크롤 1 — log/198 기준선(모두 0) 뒤 화면·데이터가 바뀐 결과로 보이며 이번 범위 밖, STATUS "발표 뒤"에 남김.

**근거**: log/198·212(발견), D73·디자인시스템 §3(화면 안 순서), D59(화면 자동 테스트).

**검증**: admin-web·member-web lint·빌드, e2e 타입체크, 화면 자동 테스트 35건 통과(로컬), 작업 단계 측정 20건(시연 데이터). 캡처로 시설 카드 1440px·글쓰기 1280×720(글을 길게 써도 등록 줄이 화면 아래)·회원 시트를 눈으로 확인. 운영 화면은 재배포 뒤 — 검증되지 않음. 회원 웹 시트는 Chromium(Pixel 7 흉내)만 봤다 — iOS Safari는 검증되지 않음.
