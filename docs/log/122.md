# 122. 시연 데이터 고밀도화 — 지점 5곳 기준 시드 + 시연 데이터 층, jest 고밀도 템플릿과 성능 테스트 (2026-10-18)

> [진행 로그 인덱스](README.md)

**계기**: STATUS 다음 할 일 3(log/106 계획, D51 5곳 방향). 착수 전에 D53의 미정 사항(클라이언트)을 정하기로 했다.

**사용자 결정(2026-10-18, D53 방식 — 사용자 설명 없음)**: 클라이언트 = 현장 사용자(지점 관리자·회원), 사용성·속도(추천안 아님) / 지점 5곳만(추천안 아님) / 시드 실행일 기준 상대 날짜 / 이번 세션은 시드 재작성만. 테스트 분리는 사용자가 "성능 테스트는 고밀도 데이터 위에서" 한다고 정하고, 목록을 보고 7개 파일을 고밀도로 골랐다 + 성능 테스트 추가.

**한 일**:
- 기준 시드 5곳(D58): `branch-generator.ts` 삭제, `side-branch-fixtures.ts`(마포 갱신 임박·송파 만료·노원 계약 종료 — 직원 2·회원 1~2·시설·강사·프로그램 각 1, 계약 날짜는 실행일 상대값). 강남은 ACTIVE(종료일 2027-09-30). 대조군 지점장은 BRANCH_ADMIN 계정.
- 시연 데이터 층 `prisma/demo-layer.ts` + 실행기 `prisma/seed-demo.ts`, `npm run seed:demo`. 고정 씨앗 PRNG(mulberry32), 새 id는 전부 `demo-`, 한 트랜잭션, 이미 얹힌 DB와 로컬이 아닌 DB는 거부. 히어로 관계(담당 회원·강사 겸임·회차 2건)는 건드리지 않고 이력만 더한다(이수진의 지난 요가 예약, 히어로 직원 근태). 채번 시퀀스는 새 번호의 최대 순번으로.
- jest: `denseDatabaseName`, globalSetup이 `<기준>_dense`를 만들고 teardown이 지운다. `useDenseTemplate()`(worker-db 모듈 상태 — 파일마다 새로 시작).
- 고밀도로 옮긴 7개 파일의 기대값: 시드 개수를 박은 곳을 DB 건수로(회원 미배정·자산·결제 날짜 필터·게시글 total), 픽스처 전제 2곳(격리 픽스처 회차는 내일 이후 첫 회차, 결근 미리보기는 어제 근태·휴가를 비운다). 격리 공격 표·기대 상태 코드는 바꾸지 않았다.
- 기준 시드 테스트: `branch-parity`(5개, 강남 대조군 ACTIVE), `contract-termination`(재배치 대기 시드 직원 = 노원 2명), `catalog-flow`(시설은 시드 원천 id 기준으로 센다).
- 새 `test/performance.spec.ts`: 현장 화면 14개 경로, 첫 요청은 빼고 5회 중앙값 < 1,500ms, 응답에 데이터가 실렸는지 먼저 본다.

**근거**: D53, D58, D40(대체되는 데이터 부분), D29·D30(템플릿 복제), ADR-RSV-05(고정 날짜 회차 문제), data-integrity §5(채번), ADR-STF-07(종료 지점 파견 종료).

**검증**:
- jest 전체 41개 파일 483건 통과(약 100초, 고밀도 템플릿 생성 약 3초 포함).
- 시연 층 두 번(빈 DB 2개) 실행 → 예약·근태·회원 지문 동일. 적용 약 2.6초: 계정 30·직원 14·파견 18·회원 211·회차 709·예약 5,673·결제 5,673·근태 1,507·업무일지 910·혼잡도 스냅샷 1,666 등.
- SQL 점검: 활성 예약이 정원을 넘는 회차 0, 계약 종료 지점의 오늘 이후 회차 0·종료일 이후 근태 0, 회원번호 시퀀스 = 최대 번호.
- 성능 로컬 중앙값(ms): 회원 목록 12, 회원 검색 9, 결제 목록 17, 결제 하루 필터 13, 근태 월 요약 9, 결근 미리보기 8, 자산 7, 게시판 7, 회원 내 예약 9, 프로그램 저녁 필터 6, 회원 공지 7, 본사 지점 목록 7, 본사 전체 결제 12, 회차 전체 14.
- api lint·빌드 통과. **관리자 웹·회원 웹 화면은 시연 층 데이터로 열어 보지 않아 검증되지 않음**(문구 2곳만 바꿈).

**남은 것**:
- 배포 DB는 아직 83곳 — 78곳 정리와 시연 층 적용은 배포 DB 쓰기(승인). 배포 DB에 쓰려면 기존 데이터(운영 중 생긴 행)와의 관계를 먼저 확인해야 한다.
- 지점별 시나리오(engineering-risks §4)와 R1·R2는 이번 범위 밖.
- 시연 층은 변경 이력(AuditLog)을 만들지 않는다 — 본사 "변경 이력" 화면은 비어 있다.
