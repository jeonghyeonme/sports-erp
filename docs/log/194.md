# 194. 기능별 동시성 점검 — 종료 지점 판정·계약 회차·퇴사/발령 빈틈 세 곳 수정 (D70, 2026-11-01)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 중간 발표 자료에서 결제·예약·취소의 동시성·멱등성 문제를 고쳤던 것을 보고 "지금 만든 계약 갱신 같은 것도 체크 안 했으니, 기능별로 DB 락이 필요한 곳이 있는지 체크해 달라"고 했다.

**점검**: api 쓰기 라우트 전부(컨트롤러 18개)를 서비스까지 따라가 "읽고 나서 쓰기" 사이에 다른 요청이 낄 수 있는지 봤다. 이미 막힌 것 — 정원(회차 행 락)·결제/취소(예약 행 락)·출퇴근/정정/휴가/업무일지·채번·갱신 토큰·PT 차감(조건부 +1)·회원 연동·처리 대기 승인·D69 계약 쓰기(지점 행 배타 락). 빈틈 셋과 영향이 작은 것들을 보고했고, 사용자가 셋을 고치기로 했다(결정 전문 [D70](../decisions/D70.md)).

**한 일**
- **종료 지점 판정**: 10개 경로의 `loadGate()`(트랜잭션 밖 읽기)를 쓰기 트랜잭션 안 `lockBranchForShare`로. 오류 판정 순서는 그대로 두고, 트랜잭션 안의 검증은 `tx`만 쓰게 회원 도메인 도우미에 `tx` 인자를 붙였다. 쓰이지 않게 된 `loadGate()`·`branch-gate.ts`·서비스 7곳의 `BranchService` 주입·`BranchesModule` 전역 제공을 지웠다(삭제는 사용자 확인).
- **계약 회차 번호**: `CorrectContractDto`·`SetContractFileDto`에 `roundNo`(필수), `lockContract`가 다르면 409 `CONTRACT_ROUND_CHANGED`. 관리자 웹 정정 창·파일 올리기 창이 연 때의 회차 번호를 보내고 오류 안내 문구를 더했다.
- **퇴사·발령**: 두 트랜잭션 처음에 `lockStaff`.
- 테스트: `test/concurrency-gaps.spec.ts` 신규, `row-lock.ts`의 `holdRowLock`에 "락을 잡은 채 커밋 전 쓰기" 인자, `contract-renewal.spec`에 회차 번호 2건, 기존 요청 본문에 `roundNo`.

**근거**: D70, D29(대체), ADR-STF-07(공유 락 방식), ADR-RSV-07·engineering-risks R1(행 락으로 재현하는 방식, log/123), D69, D37(연결 1개).

**검증**: 새 동시성 테스트를 고치기 전 코드(`src`만 잠시 stash)로 돌려 13건 중 12건 실패(409 기대에 201, 동시 발령 한쪽 500)·대조군 1건 통과를 확인한 뒤 되돌렸다. 고친 코드로 api jest 55개 파일 600건, tsc·eslint(오류 0), admin-web lint·빌드, 화면 자동 테스트 16건(Windows 로컬 우회 실행 — log/191) 통과. 운영 화면에서 회차 번호 409 안내를 직접 띄워 보지는 않았다 — 검증되지 않음.

**남은 것**: 요청 단위 멱등 키(두 번 누르면 두 번 — PT 차감·수강/PT/회차 중복), 마지막 저장 우선 수정들, 전역 P2002→409 변환은 하지 않음(D70 "하지 않은 것"). 배포는 스키마 변경이 없어 병합만 하면 된다.

**커밋**: 이 작업 한 건(D70 구현·테스트·문서).
