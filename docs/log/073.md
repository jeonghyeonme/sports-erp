# 073. 배포 DB refreshToken 기존 행 정리 — 사용자 승인 후 실행 (2026-10-06)

> [진행 로그 인덱스](README.md)

**계기**: ADR-AUTH-04 코드가 PR 병합으로 Lambda에 배포된 뒤(Actions 배포 #8 성공·헬스체크 통과), 사용자가 [log/071](071.md) §3의 정리 SQL 실행을 승인했다.

**실행 전 확인** (Supabase `sports-erp`, 읽기 전용 조회)

| 항목 | 값 |
|---|---|
| 전체 행 | 2,371 (log/071의 "약 1.2만"과 다름) |
| 만료·폐기 행 | 0 |
| 계정별 | `account-minsu`(k6 계정) 2,370 · `account-haneul` 1 |

1.2만 행 중 폐기 행은 배포된 ADR-AUTH-04 코드가 그사이 로그인 때 지운 것으로 본다(추정 — 지운 시점의 기록은 없다). 그래서 §3의 첫 DELETE(만료·폐기 삭제)는 지울 행이 없었다.

**실행**
- §3 SQL을 BEGIN…COMMIT 한 번에 보냈으나 도구 호출이 60초 시간 초과로 끊겼다. 다시 조회해 행 수가 그대로이고, 남은 트랜잭션·락이 없음(`pg_stat_activity`)을 확인했다 — 반영되지 않았다.
- 효과가 있는 두 번째 DELETE("계정마다 최신 5개만 남김")만 단일 문장(CTE + `DELETE … RETURNING`)으로 다시 실행했다. 단일 문장이라 그 자체로 원자적이다.

**결과**

| 계정 | 전 | 후 |
|---|---|---|
| `account-minsu` | 2,370 | 5 (2,365 삭제) |
| `account-haneul` | 1 | 1 |
| 합계 | 2,371 | 6 |

남은 토큰의 최소 만료일은 2026-10-18이다. 관리자 계정의 세션은 영향이 없다.

**반영**: STATUS의 승인 대기·열린 위험 항목 삭제, 권한관리 ADR-AUTH-04 결과 줄에 실행 사실.
