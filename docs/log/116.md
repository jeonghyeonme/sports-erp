# 116. RFP 중간 작업 M1·M3 — 인사기록 한 화면, 프로그램 종목·연령대·시간대 필터 (2026-10-14)

> [진행 로그 인덱스](README.md)

**계기**: 작업 브리프 B2의 권장 순서 첫 묶음(D51). 요구사항추적표 §2-3의 두 행 — RFP 1-1 #2 "모든 인사기록정보 한 화면", 1-1 #7 "종목/시간대/연령대별 리스트".

**사용자 결정(2026-10-14)**: M1 — 문서함 직원 필터를 API에 더한다(`relatedStaffId`). M3 — 시간대는 오전(~12시)·오후(12~18시)·저녁(18시~) 3구간, 회원 웹과 관리자 웹 둘 다.

**구현 중 바꾼 것**: 질문할 때는 시간대 근거를 `ProgramScheduleTemplate.startTime`(요일 템플릿)으로 제시했는데, 열어 보니 이 테이블은 쓰는 코드가 없고 행도 0건이었다(요일 템플릿 회차 생성은 강사프로그램게시 A-8 범위 제외). 그래서 같은 3구간을 **오늘(KST) 이후 회차 `ScheduleSlot.startTime`** 기준으로 판정했다 — ADR-PRG-04에 대안과 함께 적었다. 사용자에게 보고한다.

**한 일**:
- api: `GET /programs`에 `category`·`ageGroup`·`timeBand` 쿼리(ADR-PRG-04). `GET /documents`에 `relatedStaffId` 쿼리 + `@ScopedResource('staff', { query: 'relatedStaffId' })`(ADR-RES-04, D46). 지점 관리자에게는 기존 범위(본인 지점 + 전사)가 그대로 겹친다.
- admin-web `StaffDetailPage`: 근태(월 선택, 상태별 일수 + 기록 표, KST 월)·휴가(올해 연차 잔여 + 신청 내역)·인사서류 섹션 추가. 업무일지는 기존. 데이터는 기존 API(근태관리 A-5).
- admin-web `ProgramsPage`: 종목(전체 목록에서 뽑음)·연령대·시간대 선택 → 서버 필터. 결과 없음 문구에 "시간대는 오늘 이후 회차가 있는 프로그램만" 안내.
- member-web `ProgramsPage`: 종목·연령대·시간대 3칸(360px 한 줄). 종목·연령대는 받은 목록을 화면에서 거르고(호출 0회, design-constants ⑩), 시간대만 서버에 다시 묻는다. 전체 연령(ALL) 프로그램은 어느 연령대에서도 보인다. 카드에 연령대 표시.
- 도움말(`help-content.ts`) 직원 상세·프로그램·근태 현황 문구.
- 테스트: `list-filters.spec.ts` 새 파일(11건), `branch-isolation` 공격 표 2행(서초↔강남 `relatedStaffId`), `branch-scope-coverage`의 id 쿼리 목록에 `relatedStaffId`.

**근거**: D51(우선순위), 강사프로그램게시 ADR-PRG-04, 자원문서관리 ADR-RES-04, D46(전역 가드), 근태관리 A-5(기존 API).

**검증**:
- jest: `list-filters`·`branch-isolation`·`branch-scope-coverage` 통과(로컬 PG16). 전체 jest는 커밋 hook이 돈다.
- admin-web·member-web lint·빌드 통과.
- 화면: Playwright 수동 확인(복사본 DB `sports_erp_manual`에 시연 회차·근태·휴가·인사서류를 넣고 확인 뒤 삭제 — 기준 DB 오염 없음). 회원 웹 360px 시간대 "오후" → 어린이 수영만, 관리자 프로그램 "저녁" → 시니어 골프만, 직원 상세 근태·휴가·인사서류 표시. **화면 동작은 자동 테스트가 없어 검증되지 않음(수동 확인만)**.
- 시드 데이터에는 오늘 이후 회차가 없어(서초 요가 9/21·22뿐) 배포 DB에서도 시연 회차(서초 아침 요가 12/31까지)가 있는 지점만 시간대 필터에 걸린다.

**커밋**: api programs·documents 컨트롤러·서비스, 테스트 3개, admin-web `StaffDetailPage`·`ProgramsPage`·`help-content.ts`, member-web `ProgramsPage`·`types.ts`·`styles.css`, 도메인 문서 3개(강사프로그램게시·자원문서관리·인사정보관리), 요구사항추적표 §2-3 두 행 삭제, 작업 브리프 B2, STATUS.
