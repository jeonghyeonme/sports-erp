## 읽은 것 — 줄일 후보 (결정 전, 착수 때 근거로)

1. **회원을 찾는 데만 3단계**(메뉴 → 검색어 → 검색 버튼). B02·B03·B04가 모두 이 앞머리를 지난다. PT 세션 차감(B04)은 PT 수업마다 반복되는데 6단계 중 4단계가 "회원 찾기 + 탭 바꾸기"다.
2. **기본값이 없는 칸**: PT 패키지 구매일(B03)은 거의 항상 오늘인데 비어 있다. 누락일 등록(B10)은 출근·퇴근 시각을 매번 친다(정기 근무 시간이 있으면 채울 수 있다).
3. **첫 화면 밖의 폼**: 회차 등록 폼(B08)은 예약 현황·주간 시간표 아래라 스크롤 2~3번. 직원 근태관리의 휴가 신청·업무일지 폼(S02·S03)과 휴가 승인함(B06)도 첫 화면 밖이다. 데이터가 많을수록 늘었다(B08·S03·M02).
4. **이미 짧은 것**: 처리 대기함 → 승인(B06 2단계), 오늘 예약 체크인(B05 — 예약 현황 기본 기간이 오늘), 지점 실적(H01), 회원 공지·취소. 손대지 않는다.
5. 측정하며 본 것: 관리자 웹 `Modal`에 `role="dialog"`가 없다(보조기기가 모달로 읽지 못한다 — log/197 B 목록에 더함). 예약 현황에 회원 이름 검색이 없어 체크인할 사람을 눈으로 찾는다(시드 기준 행이 적어 숫자에 안 드러난다).

**세지 않은 것(한계)**: 화면을 읽고 대상을 찾는 시간, 서버 대기, 잘못 누르고 되돌리기. 행 수가 많은 목록에서 찾기(쪽 넘김)는 이번 작업들에선 생기지 않았다. 단계 수는 "가장 짧은 정상 경로"다.
