# 22. FAC-02가 남겼던 이월 항목(비활성 시설 재활성화 화면)을 채웠다 (2026-09-25)

> [진행 로그 인덱스](README.md)

**계기**: §17에서 ADR-FAC-02를 구현할 때 "비활성 시설을 보고 재활성화할 수 있는 화면이 없다"를 의도적으로 범위 밖에 남기고 확인 대화상자에만 그 사실을 적어뒀었다. 사용자가 이 이월 항목을 지정해 마저 채워달라고 요청.

**한 일**: `GET /facilities`에 `?isActive=false` 쿼리를 추가했다(기본은 여전히 활성만 — ADR-FAC-02 결정 그대로, 새 쿼리는 그 위에 얹은 것). admin-web `FacilitiesPage`에 BRANCH_ADMIN 전용 "운영 중/운영 중단" 탭을 추가하고, 비활성 카드에는 "재활성화" 버튼을 달아 기존 `PATCH isActive=true`를 그대로 재사용했다(별도 엔드포인트 없이 — ADR-FAC-02가 이미 "PATCH 하나로 양방향 처리"를 결정해뒀던 것과 일관). 비활성화 확인 문구도 "다시 활성화할 방법이 없다"에서 "운영 중단 탭에서 되돌릴 수 있다"로 정정했다(더 이상 사실이 아니게 된 경고를 그대로 뒀으면 그게 새로운 결함이었을 것).

**설계 판단 하나 추가로 내림**: 탭 UI 자체를 누구에게 보여줄지가 이번에 새로 결정해야 했던 것이다 — ADR-FAC-02엔 없던 범위라 여기서 결정: 재활성화를 실제로 할 수 있는 BRANCH_ADMIN에게만 탭을 노출한다(SUPER_ADMIN의 전사 감사용 조회는 이번 요청 범위 밖으로 남겨둠). 백엔드 쿼리 파라미터 자체는 기존 `GET /facilities`처럼 역할 제한 없이 열어뒀다 — 비활성 시설 정보가 민감하지 않고, 기존 활성 목록도 원래 전 역할에 열려 있던 것과 일관되게 두는 게 맞다고 판단했다.

**검증**: `apps/api/test/facility-lifecycle.spec.ts`에 2건 추가(`isActive=false` 필터링, 비활성→재활성화 왕복). `npm run test`(15 suites, **218 passed**), `eslint`·`nest build`·admin-web `tsc -b && vite build` 전부 클린.
