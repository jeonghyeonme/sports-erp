# 169. 메모리 85% 경보 운영 적용 — F10-2 부분 → 구현, RFP 충족 89% → 91% (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자 작업으로 남아 있던 Lambda 메모리 85% 경보(F10-2, aws-lambda/README §6)를 사용자가 AWS 콘솔에서 적용했다. 세션은 단계별 안내와 패턴 테스트 결과 판독을 맡았다.

**한 일(사용자, 콘솔)**:
- 로그 그룹 `/aws/lambda/sports-erp-api`에 지표 필터(README §6 패턴 그대로) → 네임스페이스 `sports-erp`, 지표 `MaxMemoryUsedMB`, 값 `$max_mem`.
- 경보 `sports-erp-api-memory-85`: 평균·5분·> 870MB(1,024MB의 85%), 누락된 데이터는 양호로 처리, 기존 SNS 이메일.

**패턴 확인(실측, 사용자 화면)**: 최근 로그 50개 이벤트 중 REPORT 3줄이 일치, `max_mem` 셋 다 167MB(약 16%). 그중 하나는 콜드 스타트 줄(`Init Duration: 1451.75 ms`)인데 추가 필드가 패턴 끝 `...`로 들어가 `max_mem` 위치가 같았다 — README의 "검증되지 않음"을 해소.

**판정 변경**: 요구사항추적표 F10-2 부분 → 구현(측정값 + 운영 경보, §3 "구현" 기준). 집계 기능·성능 27/28 → 28/28(100%), 전체 57/64 → 58/64(89% → 91%), 부분 포함 95% 그대로. §2-3의 메모리 행 삭제, §4 사용자 작업 없음.

**남은 것**: 경보 상태가 "정상(OK)"으로 바뀌는지는 아직 보지 않았다(사용자 확인 대기 — 새 지표라 처음엔 "데이터 부족"). 중간발표 구성안 4-7과 요구사항 정의서(Excel 판정 시트)는 89% 기준이라 다시 갱신 필요(발표자료·산출물이라 요청 시).

**근거**: RFP 시스템가용성 "메모리 평균 85% 이하"(log/114), D37(실행 환경 1,024MB), D42.

**검증**: 콘솔 패턴 테스트(사용자 화면 캡처로 확인). 경보 OK 상태는 검증되지 않음. doc-check.

**커밋**: `aws-lambda/README.md` §6, `docs/reference/요구사항추적표.md`(F10-2·§2-3·§3-0·§4), STATUS, log.
