# 12. ADR-ATT-02(결근 확정)를 실제로 구현했다 (2026-09-23)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "1번부터 순서대로 진행해줘"라고 정한 순서(①날짜 버그 ②ADR-ATT-02 ③ADR-ATT-03 ④스킬 개선)의 2번째. ADR-ATT-02는 `offDays`(ATT-T05/STF-T04, 인사정보관리·근태관리 두 사이클에서 각각 발견된 미구현 필드)가 선행돼야 한다고 이미 적어 뒀던 터라, 먼저 그것부터 만들었다.

**구현**: `MockStaff.offDays`(0=일~6=토, 파트타임은 항상 `undefined`) + `CreateStaffDto`/`UpdateStaffDto` 검증(정수 배열, 0~6 범위) → `mock-data.service.ts`에 `isWorkDay`(근무일 판정)·`previewAbsences`(잠정 결근 미리보기, **저장 안 함**)·`confirmAbsences`(관리자 확정 시에만 `AttendanceRecord(status=ABSENT)` 영속화, 재확정해도 중복 안 생김 — `previewAbsences`가 이미 기록 있는 날짜를 제외하므로 자연히 멱등) → `GET /attendance/absence-preview`(SUPER_ADMIN도 조회 가능)·`POST /attendance/absence-confirm`(**BRANCH_ADMIN만**, SUPER_ADMIN도 403 — "현장 운영 비개입 원칙"을 쓰기 액션에 실제로 적용한 사례).

**검증**: `attendance-absence.spec.ts` 7건(미리보기 비영속, 확정 영속+멱등, 승인휴가/체크인기록/파트타임 제외, 권한 2종) — `npm run test`(10 suites, **154 passed**), `eslint`(0 errors), `nest build`(성공). 근태관리·인사정보관리 두 도메인 문서의 검증현황·데이터모델을 함께 갱신(ATT-T05/STF-T04가 두 문서에 걸쳐 있었으므로).

**남은 것**: ADR-ATT-02의 "감수하는 것"(관리자가 확정을 잊으면 이력 공백)은 여전히 유효 — 시스템이 아니라 운영 절차로 완화해야 한다는 판단은 안 바뀜.
