# 152. 사용자 매뉴얼·교육 자료 — 화면 도움말을 원천으로 생성(RFP 과업4·산출물5) (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 사용자 매뉴얼·교육 자료 진행을 요청했다. 고른 것(추천안): 매뉴얼은 Word + 화면 캡처 자동 생성, 교육 자료는 역할별 빠른 시작 1편(PDF), 게시판 탑재는 사용자가 브라우저로 올림(배포 DB·저장소 쓰기 — 세션은 supabase.co 업로드가 막혀 있다).

**한 것**:
- `scripts/deliverables/capture-manual.mjs` — 화면 테스트 전용 DB(`sports_erp_e2e`)에 기준 시드 + 시연 데이터 층(D58)을 넣고, 빌드한 api·웹을 `e2e/serve.mjs` 구조로 띄워 역할별 22장을 찍는다(관리자 웹 1440폭, 회원 웹 360폭 2배). 배포 환경에는 닿지 않는다. 결과 `scripts/deliverables/figs/manual/`.
- `scripts/deliverables/manual.js` — **원천은 관리자 웹 화면 도움말(`help-content.ts`)과 오류 해결 문구(`error-hints.ts`)**를 TypeScript 변환으로 그대로 읽는다(한 사실은 한 곳에만, D38 — 화면이 바뀌면 도움말을 고치고 다시 돌린다). `docs/deliverables/사용자매뉴얼.docx`(33쪽 — 시작하기, 본사·지점 관리자·직원 장은 메뉴 순서대로 화면마다 요약·단계·캡처·"이런 문구가 뜨면", 회원 앱 장은 회원 웹 "이용 안내"와 같은 내용, 부록 오류 해결 표)와 `교육자료_빠른시작.docx`·`.pdf`(5쪽 — 역할별 "처음 하루" 4~5단계 + 캡처, soffice로 PDF).
- `docx_common.js` — `numbered(items, ref, instance)`(목록마다 번호를 1부터), `cover(..., { toc: false })`(PDF로 낼 짧은 문서는 빈 목차 쪽을 뺀다). 기존 산출물 생성기의 기본 동작은 같다.
- 추적표: T4-1 부분 → 구현. P5는 게시판 탑재가 남아 부분. 전체 84% → 86%(55/64).

**검증**: 두 문서를 PDF로 바꿔 쪽 그림으로 확인(번호 재시작, 캡처 배치, 빠른 시작 목차 없음). 매뉴얼 내용의 정확성은 화면 도움말과 같다 — 도움말 자체가 화면과 맞는지는 각 화면 작업 때 본 것까지(검증되지 않음).

**남은 것(사용자)**: 정하늘로 본사 공지(분류 "교육자료")를 쓰고 `교육자료_빠른시작.pdf`를 첨부 → 세션이 DB로 확인하면 P5 구현(88%).
