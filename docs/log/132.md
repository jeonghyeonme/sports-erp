# 132. RFP 조항별 충족 판정 — 추적표 재실측과 요구사항 정의서 재생성 (2026-10-19)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 RFP 남은 목록·추적 현황 갱신과 "기능 명세서에 기반한 구현 유무 판단"(프로젝트가 RFP를 얼마나 따라가는가)을 요청했다. 추적표 §2는 10-05 실측, 요구사항 정의서는 10-14 생성이라 M1~M10(log/116~121)과 화면 점검 수정(log/125~130)이 빠져 있었다.

**한 일**:
- RFP 원본을 PyMuPDF로 다시 추출해(p.3~7) 요구사항 표의 글머리(•) 하나를 한 조항으로 나눴다 — 기능·성능 29, 시스템~제약 25, 과업·산출물·개념도 18, 모두 72조항.
- 조항마다 코드·화면·테스트·문서를 대조해 구현 / 조정 / 부분 / 미구현 / 해당 없음으로 판정했다(요구사항추적표 §3, 기준은 그 절 위). 집계: 구현 39·조정 6·부분 15·미구현 4·해당 없음 8 → 충족률(구현+조정) 45/64 = 70%, 부분 포함 94%. 기능·성능만 보면 24/28 = 86%.
- 추적표 §1의 낡은 칸(인사 변경 신청·첨부·달력·필터·느린 요청 안내·변경 이력·경로 표시)을 고치고 §2를 2026-10-19 기준으로 다시 실측했다(라우트 99·관리자 화면 20·회원 화면 14·테스트 파일 42). §2-3 미구현 표를 조항 판정과 맞췄다 — 끝난 것은 빼고, 이번 대조에서 새로 찾은 넷(휴무·병가 누적 일수, 회원 웹 공지 첨부 미표시, 입력 필드 속성, 개발보안·라이선스 점검 기록)을 넣었다. 옛 §3 결론은 §4로 옮기고 남은 것을 코드·문서·사용자·제외 유지로 나눴다.
- 요구사항 정의서 생성기(`scripts/deliverables/requirements.py`): 10-14 이후 생긴 라우트 16개의 설명을 쓰고, 로컬 전용 `dev-storage` 경로는 명세에서 뺐다. `/staff-change-requests`를 인사정보관리에, `/support-requests`를 공통에 묶었다. 추적표 §3에서 "RFP 충족 판정" 시트를 만들고, 미구현 시트는 §2-3 상태가 "부분"이면 부분으로 표시한다. 다시 생성한 결과: 기능(API) 97개 모두 화면 있음, 미구현·부분 11건.

**새로 찾은 것(코드 확인)**: 근태 월 요약은 휴가를 `onLeave` 한 칸으로만 세고 `LeaveBalance`는 연차만 관리한다 — 병가·경조사 누적 일수를 보는 곳이 없다. 회원 웹 `NoticeDetailPage`는 첨부를 읽지 않는다 — 지점 공지에 올린 이미지가 이용자에게 보이지 않는다. 입력 속성은 회원 웹 `inputMode` 5곳뿐이다.

**판정의 한계**: "직관적 UX"(N6-2)·"확장성 고려"(F1-4)처럼 기준이 정성적인 조항은 근거(화면 점검 수정, 공통 가드)를 적고 구현으로 봤다. 판정은 존재·동작 확인이며, 관리자·회원 웹은 자동 테스트가 없어 lint·빌드와 수동 확인까지만 검증됐다.
