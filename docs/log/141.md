# 141. 지점별 시나리오 — 휴가 겹침(연차 이중 차감) 결함 재현·수정, 나머지 장면 이상 없음 (2026-10-20)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 고른 완성도 순서 ②(log/140 다음). [engineering-risks](../architecture/engineering-risks.md) §4에서 R1·R2(log/123) 말고 남은 장면을 돌렸다.

**한 일**: `apps/api/test/branch-scenarios.spec.ts`(8건)로 장면마다 재현 테스트를 먼저 쓰고 돌렸다.
- 마포(갱신 임박) 계약 종료 전이와 채용 5건을 동시에 → 활성 파견 0, 종료보다 먼저 커밋된 채용은 재배치 대기 결과에 들어간다. 이상 없음(지점 행 락, ADR-STF-07). 발령 동시성은 `contract-termination`이 이미 보고 있었다.
- 파견 이동 날 근태 귀속(서초 → 강남): 발령 뒤 체크인은 강남 기록(서초 요약에 없음), 체크인 뒤 같은 날 발령은 서초에 남고 체크아웃이 두 번째 기록을 만들지 않는다. 이상 없음(ADR-ATT-03).
- 재시도 중복(느린 응답 15초 안내·몰림 503 뒤 다시 누름, D55): 같은 회차 예약 동시 2건 → 1건·409, 결제 승인 동시 2건 → 1건. 이상 없음.
- **휴가 신청 — 결함**: 겹침 검사가 없어 같은 3일 연차를 두 번 신청하면 둘 다 받아졌고, 둘 다 승인하면 사용 일수가 0 → 6일이 됐다. 동시에 5번 보내면 5건이 생겼다.

**사용자 결정(D53 방식, 2026-10-20)**: 상위 목표 = 노하우 습득(D53). 고치는 방식 — 앱에서 직원 행 락 + 겹침 검사(추천안). 대안은 DB 제외 제약(btree_gist, 배포 DB 확장·마이그레이션 필요)과 승인 때만 막기였다. **사용자 설명**: 없음 — 추천안 선택.

**고친 것(근태관리 ADR-ATT-05)**: `integrity.ts`에 `lockStaff`(직원 행 `FOR UPDATE`). 신청은 그 락 뒤 대기·승인 휴가와 하루라도 겹치면 409 `LEAVE_REQUEST_OVERLAP`(반려된 것과는 겹쳐도 된다), 승인도 같은 락 뒤 이미 승인된 휴가와 겹치면 409 — 막기 전에 쌓인 겹침이 있어도 연차는 한 번만 깎인다. 관리자 웹 오류 "해결" 문구 추가. 시연 DB에 겹치는 대기·승인 휴가는 0건(SQL 확인)이라 시연 데이터는 그대로다.

**돌리지 않은 것**: 몰림 503 자체(Lambda 동시 실행 상한 10 초과) — 로컬에서 상한을 재현할 수 없다. 503 뒤 재시도의 데이터 측면은 위 재시도 중복으로 봤다. 운영 측정은 STATUS 5(S2 거절 원인)와 함께.

**검증**: `branch-scenarios.spec.ts` 8건 + `attendance-rules.spec.ts` 9건 통과. 수정 전에는 휴가 두 건(재신청 201, 동시 5건 생성)이 실패하는 것을 확인했다. 전체 jest는 커밋 hook에서.

**커밋**: api 근태·integrity, 시나리오 테스트, 관리자 웹 오류 문구, 근태관리 ADR-ATT-05·검증현황, engineering-risks §4 결과 표, data-integrity §6, STATUS, log.
