# 165. PG 연계 확인 문서·업무위탁 절차 — N7-3·N8-2를 사용자 한 단계 앞까지 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "할 수 있는 모든 작업 진행"을 지시했다. 남은 부분 조항 중 문서로 진척할 수 있는 N7-3(결제의 금융·보안기관 연계 가능 여부 확인)·N8-2(개인정보보호법 제26조 업무위탁)를 진행했다.

**한 일**:
- [pg-integration-check](../architecture/pg-integration-check.md) 새 문서 — 결론(지금 구조에 PG를 붙일 수 있다, 카드 정보는 우리 서버를 지나지 않는다, 테스트 키는 계약 없이 발급, 실서비스는 가맹 계약·심사), 연계 구조(결제 위젯 → 성공 주소 → 서버 승인 API, 금액은 DB 값과 대조, 어댑터 ADR-RSV-03 자리), 실서비스 전 할 일, 사용자 PC에서 할 실제 호출 순서.
- security-plan §7-1(제26조 위탁 문서 항목 7개와 Supabase·AWS·Cloudflare DPA 맺는 법·보관할 것)·§7-2(연 1회 감독 절차 — 이 기록이 감독 기록), S9 행에 절차 연결.
- 추적표 N7-3·N8-2 근거와 §2-3·§4 문구.

**판정은 그대로 부분**: N7-3은 테스트 키로 실제 승인을 부르지 않았고(이 환경은 docs.tosspayments.com·law.go.kr·kisa.or.kr DNS 실패), N8-2는 DPA 서명·보관과 감독 기록이 아직 없다 — 문서만으로 "구현"이나 "조정"으로 올리지 않았다(4-0 §3, 추적표 §3 판정 기준). 둘 다 사용자가 할 단계가 구체적으로 정해졌다. 수치 89% 그대로.

**근거·출처**: 토스페이먼츠 키 정책은 토스페이먼츠 블로그(자사 글), DPA는 각 회사 페이지(Supabase·AWS 보안 블로그·Cloudflare). 제26조 항목은 2차 자료 — 조문 원문 대조 필요라고 문서에 적었다. PG 연동 순서는 작성자 지식(원문 대조 못함, 문서에 표시).

**검증**: 문서 작업 — doc-check 통과. 코드 변경 없음.
