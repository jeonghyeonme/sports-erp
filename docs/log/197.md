# 197. 사용감 확보 전수조사 — 목록·검색·정렬·시각화·디자인·RFP 추적·미뤄 둔 일을 한 목록으로, 추적표 D68~D71 재대조 (2026-11-08)

> [진행 로그 인덱스](README.md)

**계기**: D67 ① 사용감 확보에 들어가기 전에, 사용자가 프로젝트 전수조사를 요청했다 — RFP 추적에서 부족한 곳, 디자인, 이전에 하기로 한 작업까지 목록으로. 조사 뒤 "저장하고 1번(추적표 재대조·문서 불일치 정리)부터"로 결정.

**조사 방법**: 코드·문서를 읽어 셌다(관리자 웹 화면 23개의 `Pager`·검색 입력·정렬·`ExportCsvButton`, api 목록 서비스의 `skip/take`, `styles.css`의 `@media`, `window.confirm`, 도메인 문서 §11의 "검증되지 않음", 차별화전략·D67·작업 브리프). **앱을 띄워 화면을 보지는 않았다** — 디자인 항목은 코드 근거이고 화면 확인은 검증되지 않음.

## 조사 결과 목록

**A. 사용감(D67 ①)**
- A-1 목록 쪽 나누기: 서버 쪽 나누기(D43)는 회원·예약·결제·자산·지점 상세·회원 상세·업무지원·게시판·변경 이력. 전부 한 번에 불러오는 목록은 직원·프로그램·강사·시설·문서·계약 보존 — 쌓이는 문서가 첫 후보(D69 2차 파일 업로드와 겹친다).
- A-2 검색: 글자 검색은 회원(이름·번호·전화)·직원·권한, 지점명 검색만 대시보드·시설·강사·프로그램. 예약·자산·문서·업무지원·변경 이력은 선택 필터만.
- A-3 정렬: 머리글 정렬은 0곳(`aria-sort` 없음). 디자인시스템 §3 "정렬 가능한 열은 머리글에 표시"가 적용된 화면이 없다. 화면마다 정렬이 코드에 고정.
- A-4 CSV: 회원·예약·근태·본사 근태 4곳. 직원·자산·문서·프로그램은 없음 — 필요 여부 결정 필요.
- A-5 시각화: 차트 라이브러리 없음, 대시보드 숫자는 현재값만(log/129에서 가짜 추세를 뺀 뒤 기간 집계 API가 없음). 기간 데이터는 지점 상세 월 실적 표뿐. 차별화전략 §2 영업 리포트(`performance-report`) 미구현 — 겹친다.
- A-6 작업 단계: 역할별 주요 작업의 클릭·화면 수 기준선이 없다 — 측정이 먼저.

**B. 디자인**
- B-1 디자인시스템 §6 예고 5항목 미작성: 폼 오류, 모달 vs 페이지, 빈 상태, 차트, 반응형.
- B-2 반응형: 관리자 웹 `@media`는 900px 하나 — 데스크톱 전용 가정.
- B-3 `window.confirm` 3곳(시설 운영 중단, 계약 파일 실물 이관 2곳) — 확인 모달 패턴 미정(디자인시스템 §5 문구를 이번에 실측대로 고침).
- B-4 화면 안 직접 스타일 `style={{}}`: StaffDetail 35·Facilities 23·MemberDetail 23, `.tsx` 안 색상 값 11곳 — 토큰 이탈 후보.
- B-5 큰 화면 파일: StaffDetail 892줄·MemberDetail 674줄·Programs 596줄.
- B-6 디자인시스템 §4 "점진 전환 중"인데 미전환 화면 목록이 없다.

**C. RFP 추적**
- C-1 추적표 §2·§3이 D68~D71 전 — 이번에 재대조(아래 "한 일").
- C-2 남은 6조항(부분 N7-3·N8-2·T3-2는 실운영 조건, 미구현 T2-1·P2-2·P2-3은 의도적 제외)은 코드로 못 올린다.

**D. 이전에 하기로 한 일**
- D-1 D69 2차 문서 실제 파일 업로드(STATUS 1순위였음). D-2 D67 ③ 회원 앱 형태 재검토. D-3 최종 발표 자료(사용자).
- D-4 `PaymentGateway` 어댑터 추출(예약및결제 D3 미착수 — 실 PG를 붙일 때만).
- D-5 "검증되지 않음" 테스트: 프로그램 허용 안 된 상태 전이 409·FREE_ACCESS 정규화, 혼잡도 정원 1 미만 거부·5단계 경계값, 채용·발령 동시 요청, 화면 자동 테스트 없는 화면(예약 달력·인사 화면·계약 파일 보존).
- D-6 게시판 Phase 6 교육 기록(TrainingLog) 미착수 — 범위 여부 미정.

**E. 문서 불일치(이번에 고침, 코드 주석 1건은 남김)**
- 작업 브리프 "승인 대기 1건" ↔ STATUS "없음", 끝난 D56·D57 사용자 작업 행이 남아 있었음.
- 권한관리 AUTH-T01 "구현 여부 확인 필요" ↔ 범위 제외 확정.
- 디자인시스템 §5 `window.confirm` 1곳 ↔ 실제 3곳.
- STATUS 변경 이력 "18종" ↔ 코드 19종(`apps/api/src/prisma/audit.ts`의 `AuditAction` — D60 `PERMISSION_CHANGED`가 빠져 있었다). 같은 파일 주석은 D71(`CONTRACT_FILE_ARCHIVED`·`PURGED`)을 아직 D69로만 적고 있다 — 코드 변경이라 이번엔 남김(다음 api 작업 때 함께).
