# 076. 남은 작업을 세션 단위 브리프로 정리 — 다른 세션이 바로 시작할 수 있게 (2026-10-07)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 남은 일의 계획을 세우고, 다른 세션에서 이어서 작업할 수 있게 준비만 해 달라고 했다.

**한 일**
- [작업 브리프](../process/04_작업_브리프.md)를 새로 만들었다. STATUS의 할 일을 B1~B7로 나누고, 각각 근거·범위·완료 기준·주의점을 적었다. 사용자만 할 수 있는 일은 표로 따로 모았다.
- STATUS의 할 일을 B 번호로 다시 썼다. 승인 대기의 "회원 앱을 다시 넣을 경우"는 D40이 대체했으므로 지웠다.
- 문서 지도(docs/README) process 행에 브리프를 추가했다.

**조사해서 브리프에 넣은 사실**(2026-10-07 코드 기준)
- 회원 기능에 필요한 API는 대부분 이미 있다: 인증, `members/register`·`link`, 프로그램·회차·시설·게시글 조회, 예약·취소, 모의 결제, 내 정보.
- 관리자 웹에 이미 MEMBER 메뉴(데스크톱)가 있다.
- Worker는 `apps/admin-web/dist`만 정적 자산으로 서빙하고, 없는 경로는 관리자 `index.html`로 넘긴다(SPA 폴백). 회원 웹을 별도 앱으로 같은 Worker에 붙이면 `/m/*` 새로고침 처리를 따로 해야 한다. 그래서 앱 형태(A 관리자 웹 안 `/m` / B 별도 앱·같은 Worker / C 별도 Worker)를 첫 세션에서 정하게 했다(권장 B, D41로 기록 예정).
- api 코드에는 응답 마스킹과 `auditLog` 쓰기가 없다(B5).

**검증**: doc-check. 코드 변경 없음.
