# 091. 비밀번호 변경 화면 — 데모 계정 잠금, 불일치 400, 세션 전부 폐기 (2026-10-09)

> [진행 로그 인덱스](README.md)

**계기**: `PATCH /auth/password`는 있었지만 화면이 없었다([요구사항추적표](../reference/요구사항추적표.md) §3). 인사 화면(log/090)으로 채용한 직원은 데모 공통 임시 비밀번호로 시작하는데, 바꿀 방법이 없었다.

**사용자 결정(2026-10-09)** → [권한관리](../domains/권한관리.md) ADR-AUTH-05
1. 범위: 관리자 웹 + 회원 웹.
2. 데모 계정 5개(로그인 화면 "데모 계정으로 바로 체험하기")는 403으로 막는다. 막지 않으면 배포 화면에서 한 사람이 바꿔 모두의 데모가 깨진다.
3. 바꾸면 그 계정의 모든 세션(refresh token)을 끝내고 다시 로그인하게 한다.
4. 현재 비밀번호가 틀리면 401 대신 400 `CURRENT_PASSWORD_MISMATCH`. 회원 웹 인터셉터는 401을 토큰 만료로 보고 refresh 후 재시도, 그래도 401이면 로그아웃한다. 그래서 틀린 비밀번호 한 번에 로그아웃되는 문제가 있었다.

**한 일**
- **api** (`AuthService.changePassword`)
  - 데모 계정 id 목록(`DEMO_ACCOUNT_IDS`, `fixtures/demo-password.ts`)이면 403 `DEMO_ACCOUNT_LOCKED`.
  - 불일치는 400. 비밀번호 갱신과 refresh token 폐기를 한 트랜잭션으로 묶었다.
- **admin-web**
  - 상단 "비밀번호 변경" → 모달(현재·새·확인, 8자·일치·같은 값 검사).
  - 성공하면 `logout(notice)`로 로그인 화면에 "새 비밀번호로 다시 로그인하세요"를 남긴다. 데모 계정이면 폼 대신 안내만 보인다.
  - 로그인 화면의 데모 계정 목록을 `lib/demo-account.ts`로 옮겨 같이 쓴다.
  - 로그아웃 버튼이 클릭 이벤트를 안내 문구로 넘기지 않게 `() => logout()`으로 바꿨다.
- **member-web**
  - 내 정보 맨 아래 "비밀번호" 칸. 펼칠 때만 폼을 보인다.
  - 성공하면 서버가 이미 토큰을 폐기했으므로 `/auth/logout`을 다시 부르지 않는다(호출 수 ⑩). 로그인 화면에 안내를 남긴다.
  - `errors.ts`에 두 코드의 회원용 문구를 넣었다.
- 해결 문구(admin-web `error-hints.ts`): `CURRENT_PASSWORD_MISMATCH`, `DEMO_ACCOUNT_LOCKED`.

**검증**
- `auth-password.spec` 6건 통과. 변경 전 서비스 코드로 돌리면 5건이 실패한다(8자 미만 검사는 원래 있던 DTO 규칙이라 통과).
- 커밋 hook: api jest 전체, 세 앱 lint·빌드 통과.
- 화면은 **검증되지 않음(수동 확인)**. 로컬 Playwright(`sports_erp_dev`)로 확인한 것:
  - 김민수(데모): 안내만 보인다.
  - 채용 직원: 틀린 현재 비밀번호 → "해결" 줄과 함께 오류, 로그인 유지. 성공 → 로그인 화면 안내, 새 비밀번호로 재로그인.
  - 가입 회원(360px): 틀림 → 오류·로그인 유지. 성공 → 로그인 화면 안내.

**남은 것**
- 이미 발급된 access token은 만료(기본 30분)까지 쓸 수 있다.
- 데모 계정 목록이 api·admin-web·member-web 세 곳에 따로 있다. 시드 계정을 바꾸면 함께 고친다.
- 비밀번호 재설정(분실)은 없다.
