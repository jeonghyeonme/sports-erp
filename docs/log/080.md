# 080. k6 실측을 결정 기록(D42)으로 남겼다 — 상한 10·1,024MB 유지, 처리 여유 확대는 기록만으로 닫음 (2026-10-07)

> [진행 로그 인덱스](README.md)

**계기**: 작업 브리프 B2. D37 §4(검증 기준)는 측정 전에 쓴 것이고, 2026-10-04 k6 실측([056](056.md))은 log에만 있었다. D38 규칙상 D37은 고치지 않고 새 결정 파일로 남긴다.

**한 일**:
1. 결정 번호 확인: `dev`와 원격 브랜치 전체에 D41 이상이 없었다. 다만 작업 브리프 B1이 회원 모바일 웹 결정을 `D41`로 예정해 두어서, 충돌을 피하려고 **D42**를 썼다. decisions README 요약표에 D41을 비워 둔 이유를 적었다.
2. 사용자에게 두 가지를 물었다.
   - 처리 여유 확대(승인 대기): 선택지 A 계정 한도 상향 / B 요청당 쿼리 수 줄이기 / C 기록만 → **C(상한 10 유지)**.
   - S1 "에러 0" 기준과 실측 거절 1건: 미달로 기록 / 기준 재정의 → **미달로 기록, 기준 유지**.
3. [D42](../decisions/D42.md) 작성: 측정 표, 가정 대비 차이, 상한 10·1,024MB 유지 근거, 대안 표, 재고 트리거.
4. STATUS에서 B2 할 일과 "처리 여유 확대" 승인 대기를 지우고, 열린 위험의 처리 한계 항목을 D42 기준으로 고쳤다. 작업 브리프에서 B2 절을 지웠다.

**근거**: D37 §1·§4·§6, [056](056.md) 근거 표(실측: 로그인 p95 237ms, 처리 p50 약 110ms·p95 약 165ms, 한계 약 50~55 rps), design-constants ⑪·⑫(계산: 몰림 상한 약 8 rps, 민감도 약 24 rps), log/055(계정 동시 실행 한도 10). 메모리 유지는 D37 §4의 상향 조건(로그인 지연 기준)을 충족했기 때문이다. W가 긴 원인은 여전히 추정이다.

**검증**: `node scripts/doc-check.mjs` 통과. 코드·AWS 설정 변경 없음.
