# 224. 리팩토링 ③ — admin-web의 화면마다 복사된 오류 타입·역할 이름표·이번 달 함수를 한 곳으로 (2026-11-12)

> [진행 로그 인덱스](README.md)

**계기**: 리팩토링(log/222·223)의 세 번째. admin-web에서 같은 이름으로 여러 파일에 정의된 것을 본문까지 비교했다(스크립트).

**한 일** (동작 변경 없음):
- `interface ApiErrorBody { code?; message? }`가 **26개 파일**에 똑같이 있었다. 게다가 실제 서버 오류 모양(`{ error: { code, message } }`)과도 달랐다 — 아무도 그 필드를 직접 읽지 않고 `apiErrorMessage()`만 불러서 드러나지 않았을 뿐이다. `lib/use-api-list.ts`에 실제 모양의 `ApiError` 타입 하나로 바꾸고 25곳이 그것을 쓴다(쓸모없어진 `AxiosError` import도 정리).
- 역할 표시 이름 `ROLE_LABEL` 4벌 → `lib/status-labels.ts` 한 벌(log/125 F8의 "여러 화면이 같이 쓰는 표시 이름은 여기" 원칙). 감사 로그는 이제 회원 역할도 한글로 보인다.
- 이번 달(KST) `kstMonth` 2벌 → `lib/kst-date.ts`의 `kstToday()` 기반 하나.

**안 한 것**: `STATUS_LABEL`·`EMPTY_FORM`·`toEditForm`은 이름만 같고 화면마다 대상이 달라 그대로. 큰 화면 파일(직원 상세 933줄 등) 쪼개기는 줄 수가 줄지 않고 옮기기만 해서 이번 범위에서 뺐다.

**검증**: admin-web lint·빌드 통과, 화면 자동 테스트(e2e) 24건 통과(로컬). 리팩토링 세 건 합계(log/222~224): 약 −270줄, 중복 정의 40여 개 제거.
