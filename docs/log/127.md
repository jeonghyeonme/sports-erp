# 127. 화면 점검 F1·F2 수정 — 근태 화면 KST(새벽 체크인 막힘 포함), 연차 사용일 정합 (2026-10-19)

> [진행 로그 인덱스](README.md)

**계기**: log/125 발견 F1·F2. 사용자가 둘 다 고치자고 했다. 판단이 갈릴 대안이 없는 결함 수정이라 D53 질문은 생략하고 근거 규칙만 인용한다. F1은 date-time-handling의 "KST 기준" 규칙이고, F2는 근태관리 A-3과 ADR-ATT-01(승인 때 ANNUAL만 차감)이다.

## F1 — 근태관리 화면(`apps/admin-web/src/pages/AttendancePage.tsx`)

- **시각 표시**: `formatTime`에 `timeZone: 'Asia/Seoul'`이 없어, 한국이 아닌 기기에서 9시간 밀려 보였다. 직원 상세(`StaffDetailPage`)와 같게 지정했다.
- **"오늘"(더 큰 결함, 점검 중 새로 확인)**: `todayStr()`이 `toISOString().slice(0, 10)`(UTC)였다. 그래서 **한국 기기에서도 00:00~08:59 KST에는 어제가 "오늘"이 된다.** "오늘의 근태"가 어제 기록을 보여 주면 체크인 버튼이 비활성이 된다. 새벽 근무 직원(06:30 새벽 수영 등)이 화면에서 출근을 누를 수 없었다. 휴가 신청·업무일지의 기본 날짜도 어제로 들어갔다. KST 날짜로 고쳤다.
- **재현**: 2026-10-19 03:06 KST, 시연 DB(어제까지 근태)에서 Playwright로 확인했다.

| | 수정 전 | 수정 후 |
|---|---|---|
| UTC 기기 | "오늘의 근태" 체크인 오후 11:38·체크아웃 오전 08:52(어제 기록, 9시간 밀림), 이번 달 첫 행 오후 11:35 / 오전 08:35 | 체크인 -·체크아웃 -(오늘 기록 없음), 첫 행 오전 08:35 / 오후 05:35 |
| 한국 기기 | "오늘의 근태"에 **어제 기록**(오전 08:38 / 오후 05:52) → 체크인 버튼 비활성 | 체크인 -·체크아웃 -, 버튼 활성 |

**같은 종류가 남은 곳(이번에 고치지 않음, 후속)**: UTC "오늘"(`new Date().toISOString().slice(0, 10)`)이 아래 곳에 더 있다. 모두 새벽에 기본 날짜가 하루 앞선다.
- admin-web `ReservationsPage.tsx:31`(회차 추가 기본 날짜)
- admin-web `AssetsPage.tsx:69`(취득일 기본값)
- admin-web `DocumentsPage.tsx:32`(보존기한 판정 기준일)
- `AbsenceConfirmSection.tsx:33`
- member-web `ProgramSlotsPage.tsx:194`
- `WeeklyTimetable.tsx`는 이미 KST 함수를 쓴다.

## F2 — 연차 사용일(`apps/api/prisma/demo-layer.ts`)

- **log/125 정정**: F2를 "시연 직원 15명 중 11명 불일치"로 적었는데, 그 SQL은 병가·경조사까지 셌다. 앱은 승인 때 **연차(ANNUAL)만** 차감한다(ADR-ATT-01). 연차만 세면 시연 층이 만든 직원 14명은 이미 맞았다. 틀린 것은 **기준 시드 직원**(김민수·박서연·마포·노원 등)에게 시연 층이 얹은 승인 연차였다. 김민수는 잔여 행이 있는데 사용 0일이었고, 나머지는 잔여 행이 아예 없어 앱이 처음 조회할 때 0일로 만들었다.
- **수정**: 기준 시드 직원의 올해 승인 연차 합을 같은 트랜잭션에서 잔여에 반영한다. 행이 있으면 더하고, 없으면 앱과 같은 총일수 규칙(`annualLeaveTotal` = `annualLeaveTotalDays`)으로 만든다.
- **확인**: 시연 DB 재생성 후 직원 23명 전원의 "잔여 행 사용일 = 올해 승인 연차 합" 불일치 0건. 화면은 김민수 "부여 17일·사용 1일·잔여 16일".

**검증**:
- admin-web lint·빌드 통과, api `tsc --noEmit`·빌드 통과.
- api jest 41개 파일 486건 통과(고밀도 템플릿도 이 시연 층을 쓴다).
- 화면은 위 Playwright 수동 확인뿐이다(화면 자동 테스트 없음).
