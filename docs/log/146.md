# 146. 세부 권한 1단계 — 역할 상한 안의 역할 기본값·개인 예외, 서버 판정(D60, ADR-AUTH-07) (2026-10-20)

> [진행 로그 인덱스](README.md)

**계기**: RFP 부분 조항 F1-2(사용자별·프로그램별 입력·수정·삭제·조회·출력)·N7-2(그룹별·개인별·기능별). 사용자가 설계안을 보고 "역할 기본값 + 개인 예외", "개인 허용은 역할 상한 안에서만"을 고르고 구현을 승인했다(스키마 변경). D60이 D1(4-Role 고정)을 대체한다.

**한 것(1단계 — 서버 판정)**:
- 스키마: enum `PermissionAction`(READ·CREATE·UPDATE·DELETE·EXPORT), `RolePermission`(역할 기본값 — 바꾼 칸만 행, role CHECK 지점 관리자·직원), `AccountPermission`(개인 예외, 계정 삭제 시 함께 삭제). 마이그레이션 `20261020135659_d60_permission_matrix`.
- 카탈로그 `src/common/permissions/permission-catalog.ts`: 기능 15개마다 역할별 상한(지금 `@Roles`와 같게). 직원 상한은 프로그램·게시판·시설·강사 조회뿐.
- `@Permission(feature, action, { exportable })`·`@PermissionExempt(이유)` — 라우트 약 90곳에 붙였다(면제: 본인 업무, 퇴사는 인사 권한).
- 전역 `PermissionGuard`(BranchScopeGuard 다음): 지점 관리자·직원에게만, 상한 안 칸이면 개인 예외 → 역할 기본값 → 허용. `?export=true` 목록은 출력 권한도 본다. 거부 403 `PERMISSION_DENIED`.
- 개인 예외는 매 요청 계정 조회에 include로 실어 읽는다(왕복 증가 없음). 역할 기본값은 실행 환경마다 30초 캐시(`PermissionService.invalidate()`).

**검증**: api jest 47개 파일 524건 통과 — 새 `permission-matrix`(10건: 대조군·역할 차단·개인 허용·개인 차단 즉시 반영·출력만 차단·상한 초과 불가·격리 유지·직원 칸·캐시·CHECK), `permission-coverage`(4건: 선언 누락·카탈로그 밖 칸·쓰이지 않는 상한 칸). 기존 격리·인사 권한·계약 종료 테스트는 기대값 변경 없이 통과. lint 통과.

**남은 것**: 2단계 — 본사가 역할 기본값 표·개인 권한을 바꾸는 API와 화면, 변경 이력(AuditLog `PERMISSION_CHANGED`), 캐시 무효화. 3단계 — `/auth/me`로 적용 권한을 내려 관리자 웹 메뉴·버튼(등록·수정·삭제·CSV)을 숨기고 CSV는 `?export=true`로 부르기, 화면 자동 테스트, 추적표 F1-2·N7-2. 배포 DB에 테이블 2개·enum을 먼저 만든다(승인 대상, 병합 전).

**배포 순서 주의**: 계정 조회가 `AccountPermission`을 include하므로, 테이블 없이 코드가 배포되면 **모든 인증 요청이 실패**한다. 배포 DB 적용 → 병합 순서를 지킨다.
