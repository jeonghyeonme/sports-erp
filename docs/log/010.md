# 10. 스킬을 ERP 프로젝트에 설치하고 근태관리에 시험 적용했다 (2026-09-23)

> [진행 로그 인덱스](README.md)

`.claude/skills/architecture-driver/`에 설치(`infra/`는 이 프로젝트에 이미 GitHub·CI·훅이 있어 제외). CLAUDE.md에 `architecture-driver-skill @ 7416458` 버전 추적 라인을 남겼다. Bootstrap 1~4단계(구현 원칙 블록·docs 분리·진행 로그)는 이 프로젝트가 원본이라 이미 전부 갖춰져 있었다 — 스킬 정확도의 간접 검증.

**중 우선순위 첫 도메인 근태관리를 스킬의 `domain-doc-template.md`로 만들었다**(손으로 만든 이전 4개와 다른 산출 경로). Driver 3개:
- ADR-ATT-01(연차 승인 시점에만 차감 — 재확인)
- ADR-ATT-02(결근을 스케줄러 배치 대신 조회 시점 지연 계산으로 표현 — 근태관리 문서가 이미 제안해 둔 확장 경로)
- ADR-ATT-03(근태 기록의 지점 귀속을 체크인 시점 `branchId` 스냅샷으로 — **이번 사이클에서 새로 발견한 실제 버그**: 월중 파견 이동 시 과거 근무 기록이 잘못된 지점 요약에 집계되는 소급 왜곡. 코드를 실제로 추적해서(`attendanceSummary`가 현재 `Staff.branchId`로만 필터) 확인했다)

**또 하나의 01번 문서 정정**: Q-21의 임시 가정("연차 법정 산정은 범위 외")이 틀렸다 — 실제로는 근로기준법 단순화 공식이 이미 구현돼 있었다(`calcAnnualLeaveTotalDays`). 반대로 Q-21의 "파견 이동 시 근태 귀속" 부분은 코드가 정말로 안 다루고 있어서 ADR-ATT-03으로 이어졌다 — 같은 되묻기 항목 안에서 "가정이 틀린 절반"과 "가정이 맞았던(문제가 진짜였던) 절반"이 공존한 사례.

**ATT-T05/STF-T04 교차 확인**: `offDays`(정기 휴무 요일) 필드 부재가 인사정보관리·근태관리 두 도메인 사이클에서 독립적으로 발견됐다 — 같은 필드 하나가 두 도메인의 다음 작업을 막고 있다는 게 이번에 명시적으로 연결됐다.
