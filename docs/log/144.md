# 144. 배포 데모 로그인 실패(로컬 api 주소 번들) 재발 방지·첨부 실제 파일 확인·관리자 웹 이미지 미리보기 (2026-10-20)

> [진행 로그 인덱스](README.md)

**데모 로그인 실패**: 재시드(log/143) 뒤 배포 사이트에서 데모 버튼 로그인이 "데이터를 불러오지 못했다"로 끝났다. Playwright로 보니 다섯 계정 모두 `http://localhost:3000/api/v1/auth/login`을 불렀다 — 배포 번들에 `baseURL:"http://localhost:3000/api/v1"`이 박혀 있었다(깨끗한 로컬 빌드에는 없음). 사용자가 옮겨 간 PC의 `apps/admin-web`에 `VITE_API_BASE_URL`이 든 환경 파일이 있어 log/036과 같은 사고가 다시 났다(Vite는 프로덕션 빌드에도 `.env`·`.env.local`을 읽는다).
- 재발 방지(PR #96): `apps/admin-web/vite.config.ts`가 production 모드에서 api 주소에 localhost·127.0.0.1이 있으면 빌드를 멈춘다. `.env.example`의 값은 주석으로 바꿨다. 사용자 PC에서 이 검사가 실제로 빌드를 멈춰 원인 파일을 찾았고, 지운 뒤 재배포했다.
- 재배포 확인: 두 번들에 남은 localhost는 axios 기본값(`window.location.href||"http://localhost"`) 한 건뿐. 데모 5개 계정 모두 대시보드까지 실패 요청 없음(본사 지점 5·직원 23, 서초 회원 60, 강남 회원 49).

**첨부 실제 파일(D57, 사용자가 브라우저에서 올림)**: 본사 공지 `demo-post-hq-1`에 PDF(332,708바이트)와 PNG를 올렸다. 세션이 배포 DB를 읽어 `Attachment` 행과 `storage.objects`(버킷 `attachments`)가 경로·크기·형식까지 일치함을 확인했다. 본사·서초 관리자·서초 직원은 상세의 첨부 목록과 서명 다운로드 URL(한글 파일명 유지)을 받고, 회원은 본사 공지라 404(`POST_NOT_FOUND`, 게시판 D1). 실제 내려받기는 사용자가 확인(세션은 supabase.co 접속 불가). Supabase 드라이버 첫 실사용 검증 끝.

**관리자 웹 이미지 미리보기**: 사용자가 "이미지 미리보기 안 됨"을 보고 — 회원 웹(log/137)에만 있고 관리자 웹은 파일 목록뿐이었다. 사용자 결정으로 관리자 웹 `PostAttachments`에 같은 방식(png·jpg·webp를 목록 위에 바로, 다운로드 URL을 화면 열 때 받음)을 넣었다. 로컬 메모리 드라이버의 상대 경로는 토큰을 붙여 blob으로 받는다. 화면 자동 테스트 `admin-branch`의 이미지 첨부 장면이 미리보기 이미지가 실제로 그려지는지(naturalWidth)까지 본다 — 7건 통과. 배포 Supabase 서명 URL로 그려지는지는 Worker 재배포 뒤 확인.
