# 149. 처리 대기함 — 대시보드 첫 카드(D61) (2026-10-21)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "ERP가 게시판 형태로만 있는 게 일반적인가"를 물었고(2026-10-20), 처리 대기함을 추천받아 2026-10-21 진행을 요청했다. 스키마 변경 없음.

**한 것**: api `GET /inbox`(`modules/inbox`) — 역할별 항목 건수(본사 4·지점 관리자 4·직원 2, D61 결정 2), 본인·본인 지점 범위, 지점 관리자 항목은 세부 권한(D60) 조회가 꺼지면 제외, `@PermissionExempt(common)`. 관리자 웹 대시보드 맨 위 "처리 대기" 카드(`WorkInbox`) — 0건이 아닌 항목을 칩으로, 누르면 처리 화면. 도움말 대시보드 문구, 요구사항 정의서 라우트 설명.

**검증**: api jest 49개 파일 535건 통과(새 `inbox.spec.ts` 5건 — 역할별 항목·회원 403, 휴가 신청 하나가 서초 관리자·신청 직원만 +1이고 강남 관리자는 그대로, 업무지원 요청은 본사 +1, 직원 출근 체크 전 1 → 체크인 뒤 0(정기 휴무일이면 0), 세부 권한으로 휴가 조회를 끄면 항목 제외·대조군 유지). 관리자 웹 lint·빌드. 화면 자동 테스트 10건 통과(새 `admin-inbox` — 직원 휴가 신청 → 김민수 대시보드 "승인 대기 휴가" → 근태관리로 이동). 본사·직원 화면의 카드 표시는 api 테스트만(화면 동작은 검증되지 않음).
