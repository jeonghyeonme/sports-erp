# 216. 11주차 발표 — 단계를 줄인 작업 네 개를 모두 변경 전·후 캡처로 비교, 17장 (2026-11-09)

> [진행 로그 인덱스](README.md)

**계기**: 사용자 — "단계 줄인 거 PT 세션 차감 말고 또 있지 않냐, 왜 그것만 캡처했냐" → "덱에 없는 것들 전부 추가". log/213 구성표에서 PT 세션 차감 하나만 대표로 골랐고, 나머지를 보이던 전후 표 장은 log/214에서 빠져 덱에서 사라졌다 — 내 선택의 빈틈.

**한 일**
- 측정 도구(log/198~200)에서 단계가 줄어든 작업은 넷: 회원 찾아 상세 열기 4 → 2, PT 세션 차감 6 → 3, **PT 패키지 등록 10 → 6**, **직원 근태 누락일 등록 8 → 7**. 덱에 없던 셋을 같은 방식(변경 전 `bd1fd0f` 앱을 별도 worktree·DB로 실행 vs 지금 앱, 단계마다 누를 곳에 주황 테두리·번호)으로 찍었다. 동작은 측정 도구 스크립트(B02·B03·B10)와 같고, 마지막 버튼(등록·저장)은 누르지 않아 데이터를 바꾸지 않았다.
- 기본값으로 채워진 칸(PT 구매일 = 오늘, 누락일 출근 시각 = 지점 기준 출근 시각)은 초록 점선으로 표시(`crop-compare.py`). 넓은 대상은 비율을 지킨 채 자르는 영역을 넓힌다.
- 생성기: `compare_body()`(카드 폭을 변경 전 단계 수로 정해 두 줄이 같은 폭 — 줄 길이 = 단계 수), 장 `ux-find`·`ux-ptreg`·`ux-miss` 추가 → 순서 회원 찾기 → PT 세션 차감 → PT 패키지 등록 → 근태 누락일 → 화면 안 순서. 14 → 17장. 각 장에 그 작업이 무엇인지 맥락 한 줄(log/215 원칙).
- 캡처 중 발견: 변경 전 앱의 모달은 Esc로 닫히지 않는다(D74에서 생긴 기능) — 캡처 스크립트는 "취소" 버튼으로 닫는다.

**근거**: 사용자 요청, D72(빠른 찾기)·log/199(기본값), 4-0 §3·§5.

**검증**: 새 3장 글자 24px 이상, 요소 102개 이하(상한 200). PT 패키지 등록은 변경 전 10장이라 카드 폭이 142px로 작다 — 렌더에서 읽히는지는 눈으로 확인하지 않았다(검증되지 않음, 사용자 확인). `node scripts/doc-check.mjs`.
