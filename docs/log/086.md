# 086. 변경 이력(AuditLog) — 인사 변경 3종 기록과 본사 전용 조회 (2026-10-08)

> [진행 로그 인덱스](README.md)

**계기**
- 브리프 B5-2. `AuditLog` 테이블은 있었지만 기록하는 코드가 없었다(요구사항추적표 §2-3, RFP 1-2 #3 "변경이력 관리").
- D17은 역할 전환을 누가 했는지 남지 않는다는 문제를 숙제로 남겼다.

**사용자 결정(2026-10-08)**

| 질문 | 답 |
|---|---|
| 기록 범위 | 인사 3종 — 역할 변경·퇴사·파견. 상세 전화번호 열람, 회원·자산 상태 변경은 이번에 하지 않는다 |
| 조회 수단 | SUPER_ADMIN 조회 API + admin-web 화면 |
| B5-3(Toast) | B5-2를 끝내고 이어서 한다 |

- 이벤트 범위·조회 권한·트랜잭션 규칙은 여러 도메인에 걸치는 결정이라 [D44](../decisions/D44.md)로 남겼다.
- 지점 계약 상태는 바꾸는 API가 없어(시드로만 정함) 기록 대상에서 빠졌다.

**한 일**
1. **기록 헬퍼** `apps/api/src/prisma/audit.ts`의 `recordAudit(tx, …)`. 대화형 트랜잭션 안에서만 부른다.
2. **연결**
   - `PATCH /permissions/staff/:id/role`: 역할 변경을 트랜잭션 안으로 옮겼다. 같은 역할로 바꾸는 요청은 기록하지 않는다.
   - `PATCH /staff/:id/resign`
   - `POST /staff/:id/assignments`
   - 처리자는 요청 계정이다. before/after에는 바뀐 필드만 넣는다(개인정보 미포함).
3. **조회** `GET /audit-logs`(SUPER_ADMIN 전용)
   - 필터: `entity`·`entityId`·`action`. 정렬은 최신순이다.
   - 페이지 형식은 D43과 같다. 기본 20건, 상한 100건.
   - 처리자 이름과 대상 직원 이름을 쪽 단위로 한 번에 모아 붙인다.
4. **admin-web 화면** — 본사 메뉴 "인사·권한 > 변경 이력"
   - 이벤트 필터와 이전/다음 쪽 이동이 있다.
   - 파견 전후 지점은 지점 목록으로 이름을 바꿔 보인다.
   - 다른 역할이 주소로 바로 들어오면 요청하지 않고 안내만 보인다. 처음에는 403 뒤 재시도 때문에 "불러오는 중"에 머물러서 고쳤다.

**근거**: D44, D17, D43(페이지 형식), [data-integrity](../architecture/data-integrity.md) 체크리스트(같은 트랜잭션), CLAUDE.md 인사 권한 분리.

**검증**
- api jest 전체를 통과했다(커밋 hook).
- 새 `audit-log.spec.ts` 9건
  - 역할 변경 기록, 같은 값이면 미기록
  - 퇴사 기록, 이미 퇴사(409)면 늘지 않음
  - 파견 전후 지점
  - 없는 지점 404·권한 없는 역할 변경 403이면 미기록
  - 조회 최신순·이름·meta, limit 상한 100
  - 지점 관리자·직원·회원 403
- `branch-isolation` 공격 표에 "서초 직원 변경 이력 조회"(강남 관리자 → 403)를 더했다.
- admin-web: lint·빌드를 통과했다. 1280px 스크린샷으로 SUPER_ADMIN 목록과 BRANCH_ADMIN 안내를 확인했다. 자동 테스트가 없어 화면 동작은 **검증되지 않음(수동 확인)**이다.

**남은 것**
- 회원·직원 상세 전화번호 열람 기록(ADR-MEM-04 숙제)
- 회원 상태·자산 상태 변경 기록
- 근태 정정 이력

모두 D44 재고 트리거에 적었다.
