# 129. 화면 점검 F3~F6 — 지점 운영 실적, 대시보드 가짜 추세 제거, 예약 날짜 필터, 당일 체크인 (2026-10-19)

> [진행 로그 인덱스](README.md)

**계기**: log/125 발견 F3~F6. 사용자가 다음 배포 전에 넷 다 고치자고 했다.

**사용자 결정(D53 방식, 2026-10-19)**: 상위 목표 = 노하우 습득(D53), 클라이언트 = 현장 사용자(D58)와 계약을 판단하는 본사. 넷 모두 추천안을 골랐다. **사용자 설명**: 없음 — 추천안 선택.

|---|---|---|---|
| F3 | 지점 상세에 어떤 실적? | 최근 3개월 월별 표 — 순매출·환불·예약·이용 완료·신규 회원 | 이번 달 합계만(추이가 없음) |

**한 일**:
- **F3** `GET /branches/:branchId/performance`(`branch-performance.ts`, 본사·지점 관리자, 격리는 전역 가드):
  - 최근 3개월(이번 달 포함, KST 달력월)을 오래된 달부터 돌려준다.
  - 지표마다 달 단위 GROUP BY 한 번씩, 쿼리 4개다. 월마다 나눠 세면 12개가 된다(D48 왕복).
  - 결제 시각은 UTC로 저장돼 있어 `+ 9 hours`로 KST 달에 묶는다.
  - 매출은 회차 예약 결제만 센다. 수강·PT 패키지 판매는 결제 기록이 없어 빠진다(화면에 적었다).
  - 지점 상세 계약 정보 아래에 "운영 실적 (최근 3개월)" 표를 넣었다. 이용 완료 옆에 예약 대비 %를 보인다.
  - `branch-isolation` 공격 표에 한 줄 추가했다.
- **F4** 본사 대시보드 카드의 `mockTrend`·`Sparkline`·증감률을 지우고 현재값만 둔다. 쓰지 않는 CSS도 지웠다. 디자인시스템 §3의 "KPI는 증감률·추세선 포함" 기준에 "실제 기간 집계가 있을 때만"이라는 조건을 붙였다.
- **F5·F6** 예약및결제 ADR-RSV-08:
  - `GET /reservations`에 `dateFrom`·`dateTo`(회차 날짜, KST)를 더했다. 거르면 회차 날짜·시작 시각순이고, 거르지 않으면 예전처럼 최근 예약순이라 회원 웹·회원 상세 탭은 그대로다. 형식이 틀리면 빈 목록이다.
  - 체크인은 회차 날짜가 KST 오늘일 때만 되고, 아니면 409 `CHECK_IN_NOT_TODAY`다.
  - 예약 관리 화면: 시작일~종료일(기본 오늘)·상태 선택·"오늘" 버튼을 넣었다. 체크인 버튼은 당일 회차에만 보인다. 해결 안내 문구(`error-hints`)를 더했다.

**검증**:
- api jest 42개 파일 493건 통과. 새 `branch-ops-findings.spec.ts` 7건:
  - F6: 당일 200 / 내일·어제·21일 뒤 409, 상태 유지 / 미확정은 기존 409.
  - F5: 오늘만·시각순 / 형식 오류 3종은 빈 목록 / 필터가 없으면 예전 목록.
  - F3: 3개월·이번 달이 마지막 / 승인 30,000 + 환불 20,000 → 순매출 +30,000·환불 +20,000·예약 +1(취소 제외)·이용 완료 +1·가입 +1 / **KST 1일 00:30 승인이 이번 달로 잡힘**(UTC 달이면 지난달) / 지점 관리자가 보는 값도 같음.
- 격리·커버리지 spec 통과. admin-web lint·빌드 통과.
- 화면(시연 DB, Playwright, 2026-10-19 KST)은 수동 확인이다:
  - 예약 현황 기본이 오늘(10-19) 회차 시각순이다. 체크인 버튼은 확정 14건에만 있고, 결제 대기에는 없다.
  - 대시보드 카드는 "전체 지점 수 5개"만 보인다.
  - 마포점 실적: 08월 6,940,000원·240건·94%, 09월 6,812,000원·266건·94%, 10월 3,811,000원·139건·91%.
- 화면 자동 테스트는 없다.

**배포**: api는 병합 시 Lambda 자동 배포, 화면은 Worker 재배포(사용자). 배포 DB는 83곳 얇은 데이터라 실적 표가 작게 나온다.
