# 188. 사용자 매뉴얼 재생성(D68 화면 반영)과 CI 화면 테스트 러너 고정 (2026-10-30)

> [진행 로그 인덱스](README.md)

**계기**: "PR 병합하고 사용자 매뉴얼 재생성해줘"(사용자). 병합 전에 PR #136의 CI를 보니 `e2e (Playwright)`만 실패했다.

**한 일**
- **CI 러너 고정**: 실패 원인은 코드가 아니었다. GitHub의 `ubuntu-latest` 러너가 Ubuntu 26.04로 바뀌었고, Playwright 1.56.1이 그 OS에 브라우저 설치를 거부했다("Playwright does not support chromium on ubuntu26.04-x64"). 그래서 테스트가 시작되지 않았다. `.github/workflows/ci.yml`의 e2e 작업만 `ubuntu-24.04`로 고정했다. 다른 작업(api·웹 빌드·doc-check)은 26.04에서 통과하므로 그대로 둔다. Playwright를 26.04를 지원하는 판으로 올리면 고정을 풀 수 있다.
- **사용자 매뉴얼 재생성**: 화면 캡처 22장을 `capture-manual.mjs`로 다시 찍었다. 시연 데이터가 실행일 기준이라 바뀐 화면이 아니어도 날짜·숫자가 바뀐다. 이어서 `manual.js`로 `사용자매뉴얼.docx`·`교육자료_빠른시작.docx/.pdf`를 다시 만들었다. 원천은 화면 도움말(`help-content.ts`)과 오류 안내(`error-hints.ts`)이다. 따라서 log/186·187에서 고친 지점 등록·계약 갱신·정보 수정·계약 이력 안내와 `BRANCH_CODE_TAKEN`·`INVALID_CONTRACT_PERIOD` 해결 문구가 그대로 들어간다.

**근거**: D59(화면 자동 테스트), RFP 과업4·산출물5(log/152 매뉴얼 생성 방식), D38(한 사실은 한 곳 — 매뉴얼은 도움말에서 생성).

**검증**: 다시 찍은 본사 대시보드("+ 지점 등록")와 지점 상세(계약 갱신·정보 수정·계약 이력) 캡처를 눈으로 확인했다. 매뉴얼 본문에서 새 문구가 나오는 것도 확인했다. 러너 고정 뒤 CI에서 화면 테스트 16건 중 15건이 돌아 통과했다. 실패한 1건은 log/186에서 추가한 계약 갱신 테스트였다. 변경 이력 메뉴로 옮긴 직후 지점 상세의 표 4개가 남아 있는 사이에 `main table`을 찾아 strict mode 위반이 났다(로컬에서는 타이밍상 통과). 변경 이력 제목을 먼저 기다리게 고쳤고, 로컬에서 따로 세 번 돌려 모두 통과했다.

**커밋**: `.github/workflows/ci.yml`, `scripts/deliverables/figs/manual/*.png`(22장), `docs/deliverables/사용자매뉴얼.docx`·`교육자료_빠른시작.docx/.pdf`.
