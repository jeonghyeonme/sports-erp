# 103. 계약 상태 변경 화면·재배치 대기 목록·본사의 종료 지점 직원 퇴사 — ADR-STF-07 후속 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: ADR-STF-07(log/099)이 남긴 숙제 세 가지. 계약 상태 변경은 API만 있고 화면이 없었다. 재배치 대기 직원을 모아 볼 곳도 없었다. 종료 지점 계정 처리도 남아 있었는데, 조정 세션 공지는 "정책이 없다"고 했지만 실제로는 권한관리 ADR-AUTH-02(쓰기 차단 + 본사의 수동 비활성화)로 이미 정해져 있었고, 그 수단만 없었다.

**한 일**:
- 계약 상태 변경 화면: 지점 상세의 계약 정보 카드에 본사 전용 "계약 상태 변경" 버튼을 달았다. 모달에서 상태를 고르면, 계약 종료일 때 영향을 안내하고 버튼이 빨간 "계약 종료 처리"로 바뀐다. 처리하면 결과 창에 재배치 대기 직원(상세 링크)과 담당이 풀린 회원을 보인다. 종료를 되돌릴 때의 안내도 넣었다.
- 사용자에게 세 가지를 물어 모두 권장안으로 정했다(ADR-STF-08).
  - ① 재배치 대기는 직원 화면 필터로 본다: `GET /staff?unassigned=true` + 본사용 "재배치 대기" 탭.
  - ② 계정 처리는 본사가 계약 종료 지점 직원을 퇴사 처리하는 것으로 한다. 운영 중인 지점 직원이면 403 `RESIGN_BY_BRANCH_ADMIN`.
  - ③ 시드만 고치고, 배포 DB는 나중에 승인받아 정리한다.
- 시드 생성기: 종료 지점 3곳의 파견을 계약 종료일로 닫고 담당 회원을 두지 않는다. 그 전에는 진행 중 파견 6건·담당 회원 4명이 남아 ADR-STF-07 이후 상태와 어긋났다.
- 도움말(지점 상세·직원·직원 상세)과 오류 해결 문구(`RESIGN_BY_BRANCH_ADMIN`)를 추가했다.

**근거**: 인사정보관리 ADR-STF-07·08(새로 기록), ADR-STF-05, 권한관리 ADR-AUTH-02, entities.md §2-1(계정·파견 직원), 디자인시스템 §5(쓰기 결과 알림). 스키마 변경 없음, 배포 DB 쓰기 없음.

**검증**(로컬 PG16, 새로 시드한 DB):
- `contract-termination.spec.ts` ADR-STF-08 5건 추가: 시드 정합성, 대기 목록, 지점 관리자 범위, 본사의 운영 중 지점 퇴사 403, 종료 지점 퇴사·계정 비활성화·감사 기록. 필터와 403 판정을 빼면 4건이 실패하는 것도 확인했다.
- api jest 34 스위트 400건 통과, admin-web lint·빌드 통과.
- 로컬 Playwright로 다음을 확인했다.
  - 지점 관리자에게는 버튼이 보이지 않는다.
  - 서초점 종료 처리 → 결과 창 2명 → 정상으로 되돌리기
  - 재배치 대기 탭 6명(시드 종료 지점 3곳)
  - 운영 중 지점 직원 상세에는 본사 퇴사 버튼이 없고, 종료 지점 직원 퇴사는 성공한다.
- 화면은 자동 테스트가 없어 **검증되지 않음**(위 수동 확인뿐).
- 확인 중 로컬 DB를 바꿨기 때문에 테스트 전에 다시 만들었다.
