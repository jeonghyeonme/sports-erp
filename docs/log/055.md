# 055. 클래식 AWS 계정에 Lambda 리소스를 만들었다 — 비밀값 단계만 사용자 실행으로 남겼다 (2026-10-03)

> [진행 로그 인덱스](README.md)

**계기**: [054](054.md)에서 "새로운 AWS 경험" 계정을 해지하고 클래식 계정으로 가기로 했다. 사용자가 클래식 계정을 만들었다. 이전 가입 이력 때문에 Free plan을 쓸 수 없어 **유료 플랜**이고, 지출 한도가 없다. CLI는 관리자 권한 IAM 사용자로 `aws login`했다. 계정 ID는 공개 저장소라 적지 않는다.

**한 일**(서울, 사용자 승인 후 로컬 Claude Code가 CLI로 실행):
- 비용 보호를 먼저 만들었다: Budgets 월 예산, 실제 비용 $1/$5/$20·예상 비용 $5/$20 이메일 알림.
- 런북 0번 확인: 서울 Lambda·Scheduler·IAM OIDC 모두 허용됐다(054의 SCP 차단 없음). 계정 동시 실행 한도는 10이라 3번의 예약 동시성은 생략했다. 한도 자체가 상한이다.
- 1~2번: `sports-erp-api-exec`, `sports-erp-api`(자리표시, env는 `NODE_ENV`만), 버전 1, 별칭 `live`.
- 3번: Function URL(NONE), `InvokeFunctionUrl` 공개 권한. 실제로 `{"Message":"Forbidden"}`이 나서 `InvokeFunction` + 조건 `lambda:InvokedViaFunctionUrl=true`를 추가했고, 이후 자리표시 503 응답을 확인했다.
- 4번: GitHub OIDC 공급자, `sports-erp-github-deploy`(README 4번 정책 그대로 — `main-5x9td9`만, 이 함수만).
- 6번: `sports-erp-scheduler` + `rate(5 minutes)` 워밍 일정, 로그 보존 14일, SNS `sports-erp-alerts`(이메일 구독 확인 대기) + 경보 3개(Throttles·Errors > 0, Duration p95 > 1000ms).
- 런북을 실제와 맞췄다: 로그인 전제(클래식 계정, 서울), 자리표시를 `dist/lambda.js`로(원안 `index.js`면 핸들러를 못 찾아 Errors 경보가 울린다), 3번 `--invoked-via-function-url` 명령, Windows Git Bash 주의(`MSYS_NO_PATHCONV=1`, zip 역슬래시).
- **비밀값 처리를 바꿨다**: 런북 원안은 "Claude가 `.env`를 source"였지만 전역 가드레일(§5)과 guard-bash hook이 막는다. 그래서 함수 환경 변수는 `aws-lambda/set-lambda-env.sh`로 나눠 **사용자가 `!`로 실행**한다. 값을 출력하지 않고, JWT는 없을 때만 생성한다.

**근거**: [D37](../decisions/D37.md)(서울 Lambda·OIDC 배포·동시성 상한 10), README·CLI-RUNBOOK 0~6번. 비밀값 분리는 전역 가드레일 §5(더 엄격한 쪽을 따른다).

**검증**: 각 리소스 생성 응답과 조회로 확인했다. 자리표시 함수 직접 호출 200(`statusCode:503` 본문), Function URL 503 "not deployed", 로그 그룹 보존 14일 조회, 예산 알림 5개 조회. `set-lambda-env.sh`는 `bash -n`만 통과했고 **실행되지 않음**(`.env` 미작성). 실제 앱 배포·DB 연결·Worker 경유는 **검증되지 않음**.

**커밋**: `aws-lambda/set-lambda-env.sh`(신규), `aws-lambda/CLI-RUNBOOK.md`, STATUS, 이 로그.
