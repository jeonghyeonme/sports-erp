# 126. 배포 URL로 화면 점검 — 목록 화면 위주, 배포본은 10-09 빌드·83곳 데이터 (2026-10-19)

> [진행 로그 인덱스](README.md)

**계기**: log/125는 로컬 점검이었다. 사용자가 배포 URL(`sports-erp-api-gateway.01-beauty-minimal.workers.dev`)로 다시 보라고 했고, 이 세션 네트워크에 그 호스트를 허용했다. 범위는 **목록 화면 위주**(사용자 지시)로 잡았다. 회원·직원 상세는 열면 배포 DB에 `PHONE_VIEWED` 열람 기록이 남으므로(D47) 열지 않았다.

**배포 DB에 남은 쓰기**: 데모 계정 로그인 3회(본사·서초 관리자·서초 회원) — 갱신 토큰 행(ADR-AUTH-04가 다음 발급 때 정리). 그 밖의 쓰기는 없다.

**방법**: log/125와 같은 Playwright 스크립트를 썼다. 주소만 배포 URL로 바꾸고 에이전트 프록시를 거쳤다. 상세 2화면을 빼고, 회원 목록·예약 관리 재방문 2화면을 더했다.

## 속도 — 측정 위치 주의

이 컨테이너는 미국 동부에 있다. 응답의 `cf-ray`가 `IAD`라, 요청이 Worker(IAD) → Lambda(서울)로 태평양을 건넌다. 그래서 아래 수치는 **한국 사용자 속도가 아니다**. 이 컨테이너에서 `/api/v1/health`를 5회 재면 0.84~1.22초다(연결마다 새 TLS).

| 화면 | 시간 | api 호출 |
|---|---|---|
| 첫 화면(로그인 포함): 지점 관리자·본사·회원 | 1.42·1.98·1.96초 | 2·2·3 |
| 예약 관리 첫 방문 → 재방문 | **2.85초 → 0.81초** | 4 → 5 |
| 목록(회원·직원·변경 이력·회원 웹 예약하기·내 예약·내 정보) | 0.35~0.46초 | 1~2 |
| 근태관리·본사 지점 상세 | 0.80·0.98초 | 7·7 |

예약 관리 첫 방문의 2.85초는 같은 화면이 api 3개를 동시에 부를 때 새 실행 환경이 뜨는 콜드 스타트로 보인다(D49: 콜드 스타트 약 1.4초). 재방문은 0.81초였다. 추정이며 Lambda 로그로 확인하지 않았다. 4xx/5xx·콘솔 오류·가로 넘침은 0건이었다.
