# 186. 위탁계약 갱신·정정·계약 이력·종료 임박 표시 구현 — D68 1차, 신규 지점 등록은 2차로 (2026-10-30)

> [진행 로그 인덱스](README.md)

**계기**: "B부터 진행"(사용자) — STATUS의 다음 할 일 중 D68(계획 확정, 착수는 사용자). D68이 권한 대로 두 번에 나눠, 이번에는 갱신·정정·이력·임박 표시를 하고 신규 지점 등록은 남겼다.

**한 일**
- API(본사 전용, `@Roles('SUPER_ADMIN')`, 경로 파라미터 `branchId`라 전역 `BranchScopeGuard`가 본다):
  - `POST /branches/:branchId/contract/renewals` `{ contractEndAt, contractPartner? }` — 새 종료일은 지금 종료일(상시 계약이면 시작일)보다 뒤, 상태를 정상(ACTIVE)으로. 종료(TERMINATED) 지점은 409 `BRANCH_TERMINATED`(D68 결정 1).
  - `PATCH /branches/:branchId/contract` `{ contractPartner?, contractStartAt?, contractEndAt? }` — 오타 정정, 상태는 그대로, 시작일 ≤ 종료일(D68 결정 2).
  - 날짜가 맞지 않으면 400 `INVALID_CONTRACT_PERIOD`. 날짜 형식은 `YYYY-MM-DD`만(시각이 붙거나 없는 날짜는 400).
  - 세 쓰기(갱신·정정·기존 상태 변경)를 `AuditLog`(entity `Branch`, action `CONTRACT_RENEWED`·`CONTRACT_CORRECTED`·`CONTRACT_STATUS_CHANGED`)에 **같은 트랜잭션**으로 남긴다. 정정은 바뀐 필드만, 바뀐 게 없으면 남기지 않는다. 상태 변경은 같은 상태로 다시 지정하면 남기지 않는다(D68 결정 3, D44). 지점 행 `FOR UPDATE` 락은 기존 상태 변경과 같다.
  - 지점 응답에 `contractDaysLeft`(KST 오늘 기준, 지난 종료일은 음수)와 `renewalNotice`(상태가 정상인데 종료 60일 이내)를 조회 때 계산해 붙였다. 상태 자동 전환은 없다(D68 결정 4, entities.md `renewalNoticeAt`).
- 관리자 웹: 지점 상세 계약 카드에 "계약 갱신"·"정보 수정" 버튼(`ContractEditModal`), "종료 60일 이내" 배지, 카드 아래 "계약 이력"(본사만, 최신 20건). 사실과 달랐던 안내 문구("본사가 입력한 계약 정보", "Phase 2~3 예정")를 고쳤다. 대시보드 "계약 갱신 임박 지점" 카드와 "갱신임박" 필터에 정상이지만 60일 이내인 지점을 포함하고, 계약만료일 옆에 남은 일수 배지. 변경 이력 화면에 계약 세 가지와 대상 "지점 OO점". 화면 도움말·오류 안내에 갱신·정정과 `INVALID_CONTRACT_PERIOD`.
- 남은 일수 계산이 화면(`Date.now()`, UTC 자정 파싱)에서 서버(KST)로 옮겨졌다.

**근거**: D68 결정 1~4·6·7, D44(이력은 변경과 같은 트랜잭션), ADR-STF-07(종료 지점 처리·행 락), D46(격리는 전역 가드).
