# 217. 11주차 발표 — 문서 파일 파트를 "업로드 추가"가 아니라 보안 설계로, 16장 (2026-11-09)

> [진행 로그 인덱스](README.md)

**계기**: 사용자 — 문서함 화면의 "옛 링크 문서"(파일 기능 전 시연용 링크 문서)는 언급할 필요가 없다 → 그렇다면 문서 파일 파트 자체가 "원래 있어야 할 기능을 이번에 추가했다"는 얘기 아닌가. 사실관계: 문서 실제 파일 업로드는 처음에 저장소·용량·바이러스 검사 기반이 없어 의도적으로 범위에서 뺐고(자원문서관리 A-8), 계약서 파일(D69)로 저장소 기반이 생기며 범위 제외를 풀어 이번에 넣었다(ADR-RES-05). 다만 청중에게는 "기본 기능을 이제 채웠다"로 들린다. 사용자 결정: 업로드 기능은 전제로 두고, 설계로 보안 등을 챙겼다는 쪽으로 고친다.

**한 일**
- 장 구분: "문서 파일 — 파일을 안전하게 올리고 여는 설계".
- `doc-flow`: 제목 "올리기와 열기를 이렇게 설계했습니다", 맥락 줄 "근로계약서 같은 인사서류가 들어가므로 위조된 파일 · 주소 유출 · 무단 열람에 대비해 설계". 올리기 4단계 흐름 + 보안 카드 세 장(화면이 보낸 정보를 믿지 않는다 — 서버가 저장소에서 크기·형식·위치 재확인 / 주소가 새어도 60초 뒤 무효 — 열 때마다 권한·지점 검사 후 새 주소 / 누가 언제 열었는지 남는다 — 변경 이력 "문서 열람"). 열기 흐름 줄은 카드로 흡수.
- 문서함 화면 캡처 장(`doc-shot`)은 뺐다(설계가 핵심이라 목록 화면은 메시지와 무관). 순서 장의 "문서 관리 실제 파일 업로드" → "문서 파일 관리", 항목 설명 "안전하게 올리고 여는 설계". 옛 링크 문서 언급은 슬라이드·노트에서 모두 뺐다. 17 → 16장.
- 노트에는 사실대로 남김: 이번 주 구현(ADR-RES-05), 계약서 파일과 같은 확인 로직, 형식·용량 한도, 운영 반영.

**근거**: 사용자 결정(2026-11-09), 자원문서관리 ADR-RES-05·A-8, D69 결정 9, 4-0 §3(발표 거리가 아닌 것은 뺀다).

**검증**: `doc-flow` 글자 24px 이상. 렌더는 눈으로 확인하지 않았다 — 검증되지 않음. `node scripts/doc-check.mjs`.
