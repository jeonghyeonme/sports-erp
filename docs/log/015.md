# 15. 남은 중/하 우선순위 3개 도메인(강사프로그램게시·혼잡도관리·게시판) 사이클을 실행했다 (2026-09-23)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "나머지 3개 도메인 사이클도 진행해줘"로 요청. §10~14에서 근태관리 1개 도메인에 스킬을 시험 적용해 KST 버그·ADR-ATT-02/03을 발견·수정한 뒤라, 같은 방식(11단계 + 4단계의 시간경계/우회/인간실수 체크)을 나머지 3개에 그대로 반복 적용했다. `architecture-driver` 스킬을 명시적으로 다시 불러 §14에서 추가한 체크리스트가 실제로 반영된 버전인지 확인 후 시작했다.

**한 일**: 옛 스펙 문서(1-8·1-9·1-5) 3개와 관련 컨트롤러·`mock-data.service.ts` 해당 함수들을 코드로 직접 대조해 각 도메인 3개(강사프로그램게시)/3개(혼잡도관리)/2개(게시판) Driver로 정리, [domains/강사프로그램게시.md](../domains/강사프로그램게시.md)·[domains/혼잡도관리.md](../domains/혼잡도관리.md)·[domains/게시판.md](../domains/게시판.md)로 작성했다. 옛 문서 3개에 대체 배너를 달고, [log/archive/05_문서_마이그레이션_추적.md](archive/05_문서_마이그레이션_추적.md)·[02_도메인별_우선순위.md](../process/02_도메인별_우선순위.md)를 갱신했다.

**발견**: 코드를 직접 열어봤기 때문에 스펙만 읽어서는 안 보였을 격차가 드러났다 — 특히 **게시판의 `posts.controller.ts`는 `visibleToMember` 필드 자체가 타입에 없고, `list()`/`findVisibleOrThrow()`가 `SUPER_ADMIN` 여부로만 분기해 MEMBER·STAFF·BRANCH_ADMIN을 구분하지 않는다.** 즉 회원 계정으로도 직원 전용 HQ 공지(교육자료 등)가 그대로 조회된다 — 게시판 A-7이 "회원에게는 비공개가 기본값"이라고 이미 정해뒀던 요구사항이 구현 단계에서 누락된 **실제 정보 노출 결함**이다(ADR-BRD-01로 기록, 아직 미수정). 혼잡도관리·강사프로그램게시 3개씩도 CLAUDE.md 핵심 불변식(계약종료 지점 차단)이 이 두 도메인에는 적용 안 돼 있었다는 동일 패턴의 격차를 포함한다.

**검증**: 문서만 작성했다(코드 변경 없음 — 이번 사이클은 근태관리 때와 마찬가지로 문서 우선, 구현은 별도 명시적 요청을 기다린다). 링크 검증 스크립트를 전체 `docs/*.md`(4.presentation·5.deliverables 제외)에 재실행해 깨진 링크 0건을 확인했다 — 실행 중 이번 작업과 무관한 기존 버그 하나를 추가로 발견해 수정했다: `decisions/`의 `app.module.ts`·`render.yaml` 상대링크가 `../../`로 한 단계 부족해 깨져 있던 것을 `../../../`로 고쳤다(사전에 존재하던 오류, 이번 3개 도메인 작업과는 무관).

**남은 것**: 강사프로그램게시 3개(ADR-PRG-01~03), 혼잡도관리 3개(ADR-FAC-01~03), 게시판 2개(ADR-BRD-01~02) — 총 8개 ADR 모두 문서만 있고 구현 전. 우선순위는 각 도메인 문서 §11에 정리했다. 자원문서관리(하 우선순위, 9번째 도메인)는 아직 착수 전.
