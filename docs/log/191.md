# 191. 계약서 OCR·AI 대신 계약 회차와 계약서 파일 — 갱신은 새 계약서로 새 회차, 종료 확정은 해지 합의서로 (D69 1차, 2026-10-31)

> [진행 로그 인덱스](README.md)

**계기**: D67 ②(계약서 OCR·AI 분석 검토)를 시작하며 목표를 다시 물었다. 사용자는 "업로드한 계약서를 보며 수동으로 갱신하는 게 더 확실하고 안전하다"고 보고 OCR·AI를 빼기로 했다(운영 확실성·효율). 이어 계약서가 계약 정보의 근거라는 점에서 회차 구조·권한·종료 조건·보존 규칙을 질문과 답으로 정했다 — 결정 전문은 [D69](../decisions/D69.md).

**한 일**
- 스키마(마이그레이션 `20261031120000_d69_contract_rounds`): `ContractRound`(지점·회차 번호 유일, 상대방·시작일·종료일 필수, 해지 확정일)·`ContractFile`(계약서/해지 합의서, 교체 시각, 회차·종류마다 지금 파일 1개 — 부분 unique). 지점의 계약 칸 3개를 1회차로 옮기고 삭제(종료일이 빈 지점이 있으면 마이그레이션이 멈춘다 — 값을 지어내지 않음). 문서의 계약서 행을 지우고 `CONTRACT` 분류·`Document_contract_retention_ck` 삭제.
- api: 갱신 = 새 계약서 필수·새 회차(시작일은 지난 회차 시작일보다 뒤), 정정·파일 교체는 가장 최근 회차만, 종료 확정은 해지 합의서 필요(409 `TERMINATION_AGREEMENT_REQUIRED`, 확정일을 회차에 남김, 되돌리면 지움), 종료 지점은 파일 올리기 409, 지점 등록은 1회차·계약서·종료일 필수. 계약 파일 업로드 URL(`contracts/` 경로, 게시판 첨부와 같은 한도 D57)·회차 목록·열람(60초 URL, 열 때마다 `CONTRACT_FILE_VIEWED` 기록). 열람 라우트는 `@ScopedResource('contractFile')`.
- admin-web: 지점 상세에 계약 회차 표(지난 회차·교체된 파일 읽기 전용, 계약서 미등록 표시), 갱신 모달에 새 계약서·시작일, 계약서·해지 합의서 올리기 모달, 해지 합의서 없으면 종료 확정 버튼 비활성, 지점 등록에 계약서·종료일 필수, "기간 종료(N일 경과)" 표시, 문서 관리에서 계약서 분류 제거, 도움말·오류 안내.
- 문서: D69, entities.md §2-1, CLAUDE.md 계약 종료 불변식, data-integrity 표, 자원문서관리(ADR-RES-03 폐지), 차별화전략 §1-1 기각 표시.

**계획과 달라진 것**: 시드에 샘플 계약서 PDF를 넣기로 했지만(제안 추가분) 로컬·테스트 저장소가 api 프로세스 안의 메모리라 시드가 파일을 넣어 둘 수 없다 — 기존 지점은 "계약서 미등록"으로 시작하고 본사가 화면에서 올린다. 그래서 배포 DB에 샘플 파일을 올리는 별도 쓰기도 필요 없어졌다.

**근거**: D69, D68(이력 같은 트랜잭션), D57(저장소), D46(지점 범위), D47(열람 기록 방식), ADR-STF-07(종료 시 파견 종료), ADR-RES-01(종료 지점 신규 업로드 차단과 같은 태도).

**검증**: api `tsc --noEmit`(테스트 포함)·`nest build`·eslint 오류 0(경고 1건은 기존 `main.ts`), admin-web lint·`tsc -b && vite build`, doc-check 통과. 마이그레이션 SQL은 `prisma migrate diff`(옛/새 스키마 비교)로 만든 뒤 손으로 데이터 이전·CHECK 순서를 넣었다. Docker를 살린 뒤(지난 비정상 종료로 남은 소켓 문제는 재시작으로 풀림):
- **마이그레이션 실제 적용**: 기존 로컬 DB(10-07 데이터, 지점 86곳)와 새로 만든 빈 DB 양쪽에 `migrate deploy`가 통과했다 — 기존 지점의 계약 칸이 1회차로 옮겨졌다.
- **jest 54개 파일 585건 통과**(빈 DB에 마이그레이션·기준 시드 — CI와 같은 출발점). 기존 로컬 DB로 돌리면 3건(지점 원천 대조·종료 지점 파견 0건·성능 목록)이 10-07에 넣은 `branch-gen-*` 지점 때문에 실패한다 — 코드가 아니라 로컬 데이터 문제라 기존 DB는 건드리지 않았다.
- **화면 자동 테스트 16건 통과**(Windows 로컬, 설치된 Chrome).

**검증 중 고친 것**
- **순환 import로 앱이 뜨지 않았다**: `post.service → branch.service → contract-file.service → post-attachment.service → post.service`. 첨부 형식·크기 검사 함수를 서비스 의존이 없는 `posts/attachment-rules.ts`로 옮겨 끊었다(타입체크·빌드는 이걸 못 잡는다 — Nest 주입이 런타임에 undefined).
- **시드 문서**: 계약서 자리를 처음엔 서초 직원 인사서류로 바꿨는데, 직원별 인사서류 목록 테스트(ADR-RES-04)가 정확한 목록을 비교해 깨졌고 재직자 인사서류는 보존기한이 정해지지 않는다(서비스 규칙과 어긋남) — 테스트 기대값은 두고 시드를 서초점 기타 문서(`doc-seocho-ops`, 보존기한 없음)로 바꿨다. 시드에서 보존기한 임박 시연 문서는 없어졌다(D69 2차 보존 알림에서 다시 본다).
- **화면 테스트의 PDF 바이트 문자열**에 줄바꿈이 그대로 들어가 문법 오류였다 — 한 줄 문자열로.

**남은 것(이번 범위 밖, 고치지 않음)**: `e2e/reset-db.mjs`·`e2e/serve.mjs`가 `new URL(...).pathname`을 경로로 써서 Windows에서 실패한다(`/C:/...` 작업 폴더, 백슬래시 비교). CI(Linux)는 영향 없음. 이번에는 같은 일을 손으로 하고(전용 DB 초기화·시드) 임시 설정·사본으로 돌렸다.
