# 101. 1년 지난 열람 기록 정리 방법 — 수동 SQL 절차로 정함 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: D47이 열람 기록(AuditLog `PHONE_VIEWED`)의 보존을 1년으로 정했지만 자동 삭제를 두지 않아, 실제로 지우는 방법이 정해지지 않았다.

**한 일**:
- 세 안을 사용자에게 보였다: A 수동 SQL(SQL Editor, 연 1회) / B 정기 배치(EventBridge → Lambda) / C 화면 버튼(본사 전용 삭제 API). 사용자가 **A**를 골랐다.
- B는 자동 배치를 범위 밖에 둔 원칙(노쇼 배치와 같은 원칙)과 어긋나고 AWS 설정·경보가 는다. C는 삭제 API·격리·권한 테스트가 새로 필요하다. 첫 1년은 지울 행이 없어 둘 다 지금 만들 이유가 약했다.
- 절차를 [architecture/data-retention.md](../architecture/data-retention.md)에 새로 적었다: 미리 세기 → 한 트랜잭션으로 삭제(건수 확인 후 COMMIT) → 용량 확인 → 로그 한 건. 대상은 `PHONE_VIEWED`만이고 인사 변경 기록(D44)은 지우지 않는다. 첫 실행은 2027-10-10 이후다. [docs/README](../README.md) 지도에 한 줄을 추가했다.
- D47은 고치지 않았다(결정 4 "수동으로 지운다"의 구체 절차일 뿐 결정이 바뀌지 않았다).

**근거**: D47 결정 4·재고 트리거(AuditLog 50MB), 루트 CLAUDE.md(배포 DB 쓰기는 승인 대상), design-constants ⑮(용량, 연 약 100MB 가정).

**검증**: 로컬 PG16에서 1년 넘은 열람 기록·최근 열람 기록·1년 넘은 인사 변경(`ROLE_CHANGED`) 기록을 하나씩 넣고 절차의 SQL을 실행했다. 1년 넘은 열람 기록 1건만 지워지고 나머지 2건은 남았다. 테스트 행은 지웠다. 배포 DB에서는 실행하지 않았다(지울 행도 없다). 코드 변경 없음.

**커밋**: `docs/architecture/data-retention.md`(새 파일), `docs/README.md`, `docs/STATUS.md`, 이 로그.
