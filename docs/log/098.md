# 098. 회원 웹 오류 해결 안내 — 오류 문구 아래 "해결:" 한 줄 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 "회원 웹 오류 해결 안내 시작하자"고 했다. 관리자 웹은 log/089에서 오류 아래에 "해결: …" 줄을 붙였고, 회원 웹은 STATUS에 남은 일로 적혀 있었다.

**한 일**
- `lib/errors.ts`의 문구 표를 `code → { message, hint }`로 나눴다. 관리자 웹 `error-hints.ts`와 같은 생각이다 — message는 "무엇이 안 됐는지", hint는 "어떻게 하면 되는지".
  - 기존 문구는 대부분 두 문장이 한 줄로 붙어 있었다. 이를 나누고, hint가 없던 코드에는 새로 썼다.
  - 새로 다루는 코드: `INVALID_CREDENTIALS`, `ACCOUNT_INACTIVE`, `VALIDATION_ERROR`.
  - `VALIDATION_ERROR`는 서버 검증 문구(어느 칸이 왜 틀렸는지)를 message로 그대로 쓰고 hint만 붙인다.
- 네트워크 끊김도 message("네트워크에 연결할 수 없습니다.")와 hint(연결 확인)로 나눴다.
- `describeError()`는 지금처럼 문자열 하나를 돌려준다(`message\n해결: hint`). 호출하는 화면 17곳은 고치지 않았다. 줄바꿈은 `.form-error`·`.error-panel p`에 `white-space: pre-line`을 줘서 보이게 했다.
- **함께 고친 버그**: 비밀번호를 틀리면 "로그인이 만료됐습니다. 다시 로그인해 주세요."가 나왔다.
  - 원인: `INVALID_CREDENTIALS`(401)가 표에 없어서 "401 = 세션 만료" 분기로 떨어졌다.
  - 이제 "이메일 또는 비밀번호가 맞지 않습니다. / 해결: 대소문자를 구분합니다."로 나온다.
- member-web CLAUDE.md에 "오류 문구는 이 표 하나" 규칙을 적었다.

**검증**
- member-web lint·타입체크 통과.
- 로컬 api + vite를 Playwright iPhone 13 에뮬레이션으로 확인했다. 세 경우 모두 두 줄로 보였다.
  - 틀린 비밀번호 → 로그인 화면 `.form-error`
  - 없는 공지 → `.error-panel`
  - 오프라인 → 네트워크 안내
- **검증되지 않음**
  - 나머지 코드(예약 정원·결제·연동 등)의 실제 화면 — 문구만 바꿨다.
  - 배포 — Worker를 다시 배포해야 보인다.
