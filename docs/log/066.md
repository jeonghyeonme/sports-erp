# 066. 주 개발 브랜치를 `dev`로 정했다 — `main-5x9td9` 이름 변경 준비 (2026-10-06)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 브랜치·커밋 정리를 요청했다. 그 과정에서 "`main`은 완성본으로 유지하고, 지금 기준 브랜치 이름(`main-5x9td9`)은 별로다. 세션마다 임시 브랜치를 쓰는 건 좋지만 주 개발 브랜치는 명시돼 있으면 좋겠다"고 했다. 이름은 사용자가 `dev`로 골랐다.

**분석(2026-10-06)**: 원격 브랜치 9개 중 `main-5x9td9`를 뺀 8개는 모두 그 내용이 `main-5x9td9`에 이미 들어 있다. 조상이거나 `git cherry` 기준 미반영 패치가 0개다. 열린 PR은 없다(#1~#17 모두 병합).
- 삭제 후보 7개: `local/lambda-k6`, `fix/lambda-url-not-public`, `docs/lambda-cli-runbook`, `docs/restructure`, `claude/affectionate-turing-sz8f1p`, `claude/upbeat-fermi-1lc6tk`, `claude/eager-hypatia-ilap57`(이 세션, 마지막에)
- `main`은 사용자 결정으로 유지한다.
- 함께 발견: CI push 트리거가 `main`에만 걸려 있어 기준 브랜치에 병합된 뒤에는 CI가 돌지 않았다.

**한 일(저장소 안)**: [D39](../decisions/D39.md)를 추가했다. `main-5x9td9`를 쓰던 현재 문서·설정을 `dev`로 바꿨다.
- 설정: `deploy-api-lambda.yml` 트리거, `ci.yml` push 트리거(`[main, dev]`), `render.yaml`
- 문서: CLAUDE.md 브랜치 규칙, `apps/api/CLAUDE.md`, wrap-up 스킬, README, `aws-lambda/` 두 문서(OIDC `sub` 예시 포함), STATUS
- 산출물: 아키텍처 설계서의 배포 행. 다시 생성했다.

**사용자가 할 일(저장소 밖, 이 순서)**:
1. AWS IAM 배포 역할 신뢰 정책의 `sub`에 `...:ref:refs/heads/dev`를 추가한다(전환 중에는 두 값 배열).
2. 이 PR을 병합한 뒤 GitHub Settings → Branches에서 `main-5x9td9`를 `dev`로 이름을 바꾼다.
3. Actions에서 `dev`로 배포를 수동 실행해 health까지 초록인지 확인한다. 그 뒤 신뢰 정책에서 옛 값을 뺀다.
4. Render는 브랜치를 바꾸거나 일시정지한다(일시정지 권장).
5. 로컬에서 브랜치 이름을 바꾸고 추적 대상을 `origin/dev`로 바꾼다.

**검증**: doc-check 통과. 워크플로 변경은 YAML 문법만 확인했다. 실제 트리거 동작은 이름을 바꾼 뒤 첫 push·수동 실행에서 확인된다(미검증).
