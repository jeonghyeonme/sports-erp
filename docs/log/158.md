# 158. 운영 의존성 취약점 18 → 4건 — 같은 메이저 고정·bcrypt 6, 도달 불가 2건은 미룸 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 Worker 재배포 중 `npm install`의 "71 vulnerabilities (4 low, 18 moderate, 45 high, 4 critical)"를 보고, 운영 의존성부터 처리하라고 했다.

**한 일**: [D63](../decisions/D63.md).
- 분류(실측, `npm audit --omit=dev`): 운영 18건 — 강제 없는 `npm audit fix`로 4건(proxy-addr·follow-redirects·source-map-js·brace-expansion), 루트 `overrides`로 같은 메이저 고정 5건(body-parser·qs·multer·lodash·file-type), bcrypt 6으로 2건(tar·node-pre-gyp — bcrypt 자신 포함 3줄), 남은 2건(4줄)은 메이저 업그레이드가 필요하고 도달 불가.
- 잠금 파일은 npm으로 다시 풀었다 — override는 기존 잠금을 따르므로 `@nestjs/common`·`@nestjs/platform-express`를 같은 범위로 지웠다 다시 깔았다(`apps/api/package.json` 범위가 `^10.4.22`로 바뀜). bcrypt 6이 `apps/api/node_modules`에 깔려(Lambda 묶음은 루트 `node_modules`만 복사, log/155) 잠금의 두 항목(bcrypt·node-addon-api)을 루트 자리로 옮기고 `npm install`로 확인했다(`npm ls` 이상 0). `npm dedupe`는 5분 넘게 멈춰 중단.
- 도달 판정: api에 `@Sse` 0건. 두 웹의 `<Link>`·`navigate` 대상은 코드 상수·서버가 정한 처리 대기함 링크뿐이고 `redirect`·`returnTo` 쿼리가 없다.
- 문서: D63, 개발보안 점검표 API-2·기준 목록, 보안관리계획 S10·점검 주기, 라이선스 목록 재생성(243개, 검토 대상 0 — bcrypt 6 등으로 패키지 수가 줄었다), STATUS.

**검증**: api lint·build·tsc, jest 50개 파일 541건(bcrypt 6으로 시드 해시 로그인 포함), admin-web·member-web lint·빌드, 화면 자동 테스트 10건 통과. Lambda 묶음(`package-lambda.sh`, require(esm) 검사 포함)에 bcrypt 6과 linux-x64 바이너리가 들어가고 묶음 안에서 해시·비교가 된다, tar·@mapbox는 빠졌다. 실제 Lambda 부팅은 병합 뒤 배포 health check로 본다. 결과: 운영 18 → 4건(중간), 전체 71 → 55건(심각 0).

**커밋**: 루트 `package.json`(overrides)·`package-lock.json`, `apps/api/package.json`(bcrypt 6, nest 범위), docs.
