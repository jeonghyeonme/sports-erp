# 147. 세부 권한 2단계 — 본사 관리 API·권한 관리 화면·개인 권한·변경 이력(D60, ADR-AUTH-07) (2026-10-20)

> [진행 로그 인덱스](README.md)

**계기**: log/146(1단계 — 서버 판정)을 배포한 뒤 사용자가 2단계 진행을 요청했다. 스키마 변경 없음(AuditLog action은 문자열 열).

**한 것**:
- api(본사 전용 `PermissionsController`): `GET /permissions/catalog`(기능·동작·역할 상한), `GET /permissions/roles`(역할별 적용 값 — 행이 없으면 허용), `PUT /permissions/roles/:role`(한 칸, `allowed=true`는 행 삭제 = 상한대로), `GET|PUT /permissions/staff/:staffId/overrides`(칸마다 역할 기본값·개인 예외·실제 적용 값, `mode` DEFAULT/ALLOW/DENY). 상한 밖 칸·모르는 기능 400 `PERMISSION_OUTSIDE_CEILING`, 표 밖 역할 400 `PERMISSION_ROLE_NOT_GOVERNED`. 같은 값이면 쓰지 않는다.
- 변경 이력: 같은 트랜잭션에서 `PERMISSION_CHANGED` — 역할 기본값은 대상 `Role`(entityId = 역할, 이름 "지점 관리자(역할)"), 개인 예외는 대상 `Staff`. 역할 기본값을 바꾸면 그 실행 환경의 30초 캐시를 비운다(다른 실행 환경은 최대 30초 늦게).
- 관리자 웹: 권한 관리 화면을 "직원 역할 / 역할 기본 권한" 탭으로, 역할 기본 권한은 역할 칩 + 기능×동작 체크 표(상한 밖 "—"). 직원 상세(본사, 재직자)에 "개인 권한" — 칸마다 기본(허용/차단)·허용·차단 선택과 가능/불가 배지. 변경 이력 화면에 "세부 권한 변경"(기능·동작 이름과 전후). 오류 해결 문구 3개, 도움말 갱신.

**검증**: api jest 48개 파일 529건 통과(새 `permission-admin.spec.ts` 5건 — 카탈로그·처음 전부 허용, 역할 칸 끄기 → 바로 403 → 켜기 → 행 삭제·이력 2건·이력 화면 대상 이름, 개인 허용·차단·기본값과 적용 값·이력, 상한 밖·표 밖 역할·모르는 기능 400·없는 직원 404, 지점 관리자는 403). admin-web lint·빌드. 화면 자동 테스트 8건 통과(새 `admin-permissions` — 본사가 "지점 관리자 업무지원 요청 입력"을 끄면 김민수 api 403, 김민수 개인 권한 허용 → 201, 뒷정리). 체크박스는 서버 응답 뒤 바뀌는 제어 컴포넌트라 테스트는 `uncheck()` 대신 `click()`을 쓴다.

**남은 것(3단계)**: `/auth/me`가 적용 권한을 내려 관리자 웹이 메뉴·버튼(등록·수정·삭제·CSV)을 권한대로 숨기기, CSV를 `?export=true`로 부르기, 화면 자동 테스트, 추적표 F1-2·N7-2 구현 판정. 지금은 꺼진 기능의 버튼이 보이고 누르면 403 문구("본사에 문의")가 뜬다.
