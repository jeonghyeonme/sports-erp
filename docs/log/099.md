# 099. 지점 계약 종료(TERMINATED) 전이 시 진행 중 파견 자동 종료 — 계약 상태 변경 API 신설과 지점 행 락 (2026-10-10)

> [진행 로그 인덱스](README.md)

**계기**: 루트 CLAUDE.md 불변식에 "TERMINATED 전이 시 기존 파견 자동 종료는 설계만 있고 미구현"으로 남아 있던 숙제(entities.md §2-1, ADR-STF-05 숙제, `contract-termination.spec`의 `it.todo`). 조사해 보니 계약 상태를 바꾸는 코드 경로(API·배치)가 아예 없었다 — `BranchService`는 조회 전용, RENEWAL_DUE 자동 전이 배치도 없다.

**한 일**:
- 사용자에게 네 가지를 물어 모두 권장안으로 정했다: ① SUPER_ADMIN 전용 `PATCH /branches/:branchId/contract-status` 신설 ② 종료일 = 전이한 날(KST 오늘) ③ 담당 회원·강사 프로필은 ADR-STF-06처럼 해제 ④ `Staff.branchId`는 그대로(스키마 변경 없음), 활성 파견 없는 재직 직원 = 재배치 대기.
- `BranchService.changeContractStatus` — 지점 행 `FOR UPDATE` → 상태 변경 → TERMINATED로 **바뀔 때만** `endAssignmentsAtTerminatedBranch`(파견 종료·담당 회원 해제·강사 연결 해제·직원별 감사 기록 `ASSIGNMENT_ENDED`)를 같은 트랜잭션에서. 응답에 `previousStatus`·`reassignmentTargets`·`unassignedMembers`.
- 헬퍼는 `staff/terminated-branch-assignments.ts`에 따로 뒀다. 처음엔 `staff.service.ts`에 넣었다가 branch.service → staff.service → document.service → BranchService import 순환으로 Nest DI가 깨졌다(전 스위트가 `Nest can't resolve dependencies of the DocumentService`로 실패).
- 경합: API가 생기며 ADR-STF-05가 감수했던 "ACTIVE로 읽은 채용·발령이 종료 뒤 커밋" 경합이 실제로 가능해졌다. 채용·발령이 대상 지점을 `lockBranchForShare`(`FOR SHARE`, `prisma/integrity.ts`)로 읽게 했다.
- admin-web 변경 이력 화면에 `ASSIGNMENT_ENDED` 문구("파견 종료(계약 종료)") 추가. 계약 상태 변경 화면은 만들지 않았다(범위 밖, 숙제).

**근거**: 인사정보관리 ADR-STF-07(새로 기록), ADR-STF-01·04·05·06, entities.md §2-1, D44(감사 기록), DI-03(트랜잭션 헬퍼). 스키마 변경 없음, 배포 DB 쓰기 없음.

**검증**(로컬 PG16, 시드 DB):
- `contract-termination.spec.ts`에 8건 추가(todo 대체): 종료일·재배치 대상·담당/강사 해제·감사 기록·계정 유지, 이후 빼내는 발령 201, RENEWAL_DUE·EXPIRED 대조군(파견 2건·담당·강사 그대로, 감사 0건), 재지정 무변화, BRANCH_ADMIN 자기 지점 403, 잘못된 값 400·없는 지점 404, 동시성.
- 전이 코드를 끄면(`terminating = false`) 핵심 테스트와 동시성 테스트가 실패하는 것 확인. 발령 쪽 락을 빼면 동시성 테스트가 5회 중 5회 실패(서초에 활성 파견 6건 남음), 락이 있으면 3회 모두 통과.
- `branch-isolation.spec.ts` 공격 표에 "서초점 계약 상태 변경"(강남 관리자) 추가.
- api jest 전체 34 스위트 395건 통과. api lint 0 error(경고 1건은 기존 `main.ts`), api·admin-web·member-web 빌드 통과. admin-web 화면 문구는 **검증되지 않음**(자동 테스트 없음, 수동 확인 안 함).
