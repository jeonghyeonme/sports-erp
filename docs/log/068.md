# 068. 회원 앱 보류 근거를 다시 계산하고, 범위를 수도권 83곳 + 회원 모바일 웹으로 바꿨다 — 발표 덱부터 (2026-10-06)

> [진행 로그 인덱스](README.md)

**계기**: 덱 8번(`prop-memberapp`) 그래프("회원 앱 포함 하루 19.6만 건 → 무료 한도의 두 배")를 보고 사용자가 물었다. 아무리 98곳이라도 지점당 하루 100명이 안 될 텐데, 이렇게까지 나오나?

**다시 계산한 것**:
- 19.6만은 98곳 × 지점당 하루 200명(design-constants ③: 등록률 25% × 방문율 36%, 둘 다 약한 가정) × 방문당 10건(⑩, 약한 가정)이었다.
- 지점당 100명으로 바꾸면 98곳 약 10.8만, 수도권 83곳 약 9.3만이다(관리자 웹 약 1만 포함).
- 시드 생성 규칙으로 센 수도권 지점: 서울 71, 경기 9, 인천 3. 지방은 부산·대구·대전·광주·울산 각 3곳으로 15곳이다.
- 처리량 피크는 약 8 rps이고 실측 한계는 약 50 rps다.

**사용자 결정**: [D40](../decisions/D40.md)
- 지방 15곳을 지우고 수도권 83곳만 남긴다. 회원 앱만 수도권에 여는 안도 제시했지만 사용자가 더 간단한 지점 축소를 골랐다.
- 회원 기능은 모바일 웹으로 만든다(키오스크 겸용 가능).
- 지점당 하루 100명 가정으로 간다.
- 발표가 먼저라 덱부터 고친다. 덱은 "처음부터 이 방식으로 계산했다"는 서사로 정리한다.

**한 일**:
- 덱 6장을 바꾸고 게시했다(39장 유지).
  - `prop-memberapp`: 그래프를 "98곳 10.8만(초과) vs 수도권 83곳 9.3만(한도 안)"으로 바꾸고, 계산·결정 문구와 노트를 고쳤다.
  - `prop-scope`: 하는 것에 회원 모바일 웹을, 하지 않는 것에 지방 15곳·네이티브 앱을 넣었다.
  - `prop-business`: "전국 98개 현장" 아래에 "이 프로젝트는 수도권 83곳 대상"을 덧붙였다.
  - `week-memberapp`: "결정 ② · 범위"로 바꿨다. 실제 결정일이 9/30이 아니라서 날짜를 뺐다.
  - `week-next`: 다음 할 일을 회원 모바일 웹으로, 보류를 지방 15곳으로 바꿨다.
  - `closing`: 노트만 고쳤다.
  - 섹션 설명 2곳(deck.json)도 고쳤다.
- 게시 직전 게시본을 다시 받아 대조했다. 편집기 수정분이 없어서 덮어쓸 것은 없었다. 편집기로 고친 5장은 건드리지 않았다.
- [design-constants](../architecture/design-constants.md)의 ③을 100명으로 바꾸고 ④~⑬을 다시 계산했다.

**남은 것**:
- **지점 축소 코드**: 시드 생성기에서 지방을 빼고, `branch-parity` 기대값 98 → 83, 관리자 웹 안내 문구를 고친다.
- **배포 DB의 지방 15곳 삭제**: 사용자 승인이 필요하다.
- **회원 모바일 웹 개발.**
- 요구사항추적표·산출물(제안서·설계서·정의서)의 98곳·회원 앱 서술을 고친다.
- **덱과 데이터의 불일치**: 덱은 83곳인데, 데이터 쪽 반영 전까지 관리자 웹과 DB는 98곳이다. 발표 시연 전에 맞춰야 한다.
