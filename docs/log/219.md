# 219. 회원 앱 PT 패키지 구매와 PT 회차 예약 — 예약 때 1회 잡고 체크인 때 차감, 현장 판매 유지 (예약및결제 ADR-RSV-09) (2026-11-09)

> [진행 로그 인덱스](README.md)

**계기**: 11주차 덱의 PT 패키지 등록 장을 보던 사용자가 "회원 앱으로 PT를 사면 직원이 따로 등록해 줘야 하나" 물었다. 확인 결과 회원 앱에는 PT 구매가 없고(내 정보에서 횟수 보기만), PT 회차는 예약 대상이 아니었다(`NOT_RESERVABLE`, PT 패키지 결제는 A-8 범위 제외). 사용자: 현장 결제 기능은 남기되 회원 앱으로도 PT 예약·결제가 되어야 한다 — 원래 있었어야 할 기능이라 발표자료에는 넣지 않는다. 스키마 변경 승인. 정할 것 셋(상품·차감 시점·노쇼)은 추천안대로.

**한 일**
- **스키마**(마이그레이션 `20261109120000_rsv09_pt_app_purchase_reservation`): `Payment.reservationId` 선택 + `ptSessionId`(unique, CHECK `Payment_target_ck` — 둘 중 정확히 하나), `Program.ptPackageSessions`(CHECK `Program_pt_package_ck`), `Reservation.ptSessionId`, `PTSessionLog.reservationId`(unique). `prisma migrate diff`로 스키마와 일치 확인.
- **API**: `POST /payments/pt-packages`(MEMBER — PT 횟수 + 승인 모의 결제를 한 트랜잭션, 금액·횟수는 서버가 프로그램에서), PT_PACKAGE 회차 예약(결제 없이 확정, 패키지 행 락 위에서 쓸 수 있는 횟수 = 총 − 사용 − 잡힌 것), 체크인 차감 + 사용 기록에 예약, "세션 사용"은 잡힌 횟수를 쓰지 않음(409 `PT_SESSION_RESERVED`), PT 회차 열기 허용(정원 기본 1), 결제 목록이 PT 구매도 지점별로(`kind`), PT 목록에 `reservedSessions`. 공용 `members/pt-holds.ts`(`heldByPTSession`·`lockPTSessions`).
- **시드**: 서초 PT 프로그램 10회 600,000원(옛 60,000원은 회당 가격처럼 적혀 있었다), 시연 층 PT도 같게.
- **회원 웹**: 예약하기 목록에 PT(가격 "PT 10회 600,000원"), PT 회차 화면에 "예약에 쓸 수 있는 PT N회"·패키지 구매 시트(모의 결제)·결제 없는 예약 확인, 내 예약·취소 안내 문구, 내 정보 PT에 잡힌 횟수. 오류 문구 2개.
- **관리자 웹**: 프로그램 폼에 PT 패키지 횟수, 회차 등록·주간 시간표에 PT, 결제 목록·CSV에 "PT 패키지 구매" 구분, 회원 상세 PT 탭에 잡힌 횟수, 오류 해결 문구·도움말.
- **문서**: 예약및결제 ADR-RSV-09·요약 카드·§11·A-8·A-9, 회원관리 요약 카드, entities.md, data-integrity 제약 표. 운영 실적 "회차 결제 순매출"(D75)은 회차 예약 결제만 센다 — PT 앱 구매는 넣지 않았다(지표 이름 그대로, ADR에 감수로 적음).
