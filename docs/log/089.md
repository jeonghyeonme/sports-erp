# 089. 화면별 도움말 — 상단 버튼·오른쪽 패널, 오류 아래 "해결" 한 줄 (2026-10-09)

> [진행 로그 인덱스](README.md)

**계기**: RFP 1-2 #4 온라인 도움말("화면별 기능사용 순서 안내, 오류처리·해결방법 안내")이 [요구사항추적표](../reference/요구사항추적표.md) §2-3에 미구현으로 남아 있었다. 공통 Toast(log/087)로 상호작용 메시지는 닫혔고, 화면별 안내와 해결 방법이 남았다.

**사용자 결정(2026-10-09)**
- 형태: 상단 "도움말" 버튼 → 오른쪽 패널(① 이 화면에서 하는 일 ② 자주 나는 오류와 해결). 툴팁·첫 방문 투어는 고르지 않았다.
- 범위: admin-web 전 화면, 역할별 단계.
- 오류: 오류 문구(인라인·Toast) 아래 해결 한 줄 + 패널에 같은 목록. 해결 문구는 코드 → 문구 표 한 곳에서 관리.

**한 일**
1. `lib/error-hints.ts` — api 오류 코드 약 75개 → 해결 한 줄. 코드는 api의 `AppException` 코드를 전수로 모았다(인증·지점 격리·계약 종료·지점 불일치·없음·입력값·상태 전환·근태·예약결제·회원 연동·서버).
2. `apiErrorMessage`가 아는 코드면 `\n해결: …`을 붙인다. 모든 인라인 오류(`forbidden-note`)와 `toast.error`가 이 함수를 거치므로 화면 코드는 바꾸지 않았다. 응답이 아예 없으면(네트워크·서버 기동 중) `UPSTREAM_UNAVAILABLE` 안내를 쓴다. `.forbidden-note`·`.error-text`에 `white-space: pre-line`.
3. `lib/help-content.ts` — 경로 16개(대시보드·지점 상세·회원·회원 상세·직원·근태·프로그램·강사·예약·게시판·게시글·시설·자산·문서·권한·변경 이력). 공통 단계 + 역할별 단계 + 관련 오류 코드. 단계는 각 화면의 실제 버튼·권한 분기(`canManage` 등)를 보고 썼다.
4. `components/HelpPanel.tsx` + `AppLayout` 상단 버튼. 배경 막 없이 본문 옆에 붙어 열린 채로 화면을 쓸 수 있고, 다른 화면으로 가면 그 화면 도움말로 바뀐다. Esc로 닫는다. 900px 이하에서는 본문 위에 겹쳐 띄운다.
5. **덤으로 찾은 버그**: 로그인 실패 문구가 `data.message`(옛 응답 모양)를 읽어 항상 "로그인에 실패했습니다."였다. `apiErrorMessage`로 바꿔 서버 문구 + 해결 줄이 나온다(같은 버그가 `apiErrorMessage`에서 2026-09-18에 고쳐졌었다).

**대안**
- 툴팁: 버튼·필드마다 붙여야 해 범위가 크고, "순서 안내"를 담기 어렵다.
- 서버가 해결 문구까지 내려 주기: 문구는 화면 맥락("상단 버튼을 누르세요")이라 클라이언트에 두었다. member-web은 이번 범위 밖이다.

**검증**
- admin-web lint 0건, 빌드(tsc) 성공. 자동 테스트가 없어 화면 동작은 **검증되지 않음(수동 확인)**.
- 로컬 Playwright(api `sports_erp_dev`): 틀린 비밀번호 → "이메일 또는 비밀번호가 올바르지 않습니다.\n해결: …" 표시, 지점 관리자로 대시보드 → 회원 → 예약 관리 이동 시 패널 제목이 따라 바뀜(예약: 단계 3·오류 9), Esc로 닫힘.

**남은 것**: member-web 오류 해결 줄(같은 표를 공유하려면 packages/types로 옮겨야 한다), 문구 다듬기는 실사용 후.
