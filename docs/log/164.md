# 164. 보안 남은 조치 3건 — 정수 입력 상한, 비밀번호 조합 규칙, 채용 임시 비밀번호와 첫 로그인 변경 강제 (2026-10-22)

> [진행 로그 인덱스](README.md)

**계기**: 사용자가 RFP 추적에서 남은 작업을 보고 "지금 할 수 있는 모든 작업 진행, 승인 필요한 건 승인"이라고 했다. 개발보안 점검표의 남은 조치(입력-14·보안-6·보안-9)를 처리했다. 보안-6은 인증 방식 변경·스키마 변경·배포 DB 쓰기라 원래 승인 대상 — 이번 지시로 승인됨.

**한 일**:
- **입력-14(정수형 오버플로우)**: 상한 없는 DTO 정수 15개(가격·정원·현재 인원·수량·내용연수·취득가액·PT 회수·문서 크기)에 `@Max`. 값은 `common/validation/input-limits.ts` 한 곳. 수정 전 코드로 `input-limits.spec.ts`를 돌려 int4를 넘는 값이 500인 것을 먼저 재현했다(3건 실패 → 수정 후 통과).
- **보안-9(비밀번호 조합)**: 새 비밀번호 8~72자·영문과 숫자 포함(`IsNewPassword`, 72자는 bcrypt 상한) — 가입·연동·변경. 로그인은 보지 않는다. 두 웹에 같은 규칙 `lib/password-rule.ts`로 먼저 안내.
- **보안-6·S3(채용 임시 비밀번호)**: 권한관리 ADR-AUTH-08. 채용이 12자 무작위 임시 비밀번호를 만들어 해시만 저장하고 응답에 한 번 싣는다(관리자 웹 채용 알림에 표시, 닫으면 다시 못 봄). `Account.mustChangePassword`(마이그레이션 `20261022120000_sec6_must_change_password`)가 켜진 계정은 `JwtAuthGuard`가 `@AllowDuringPasswordChange`(내 정보·비밀번호 변경) 밖을 403 `PASSWORD_CHANGE_REQUIRED`로 막고, 변경이 끈다. 관리자 웹은 업무 화면 대신 "임시 비밀번호 변경" 창만 보인다(닫으면 로그아웃). 오류 해결 문구·채용 도움말 갱신.
- **배포 DB**(사용자 승인): 배포 DB는 Prisma 마이그레이션 표 없이 SQL로 맞춰 와서(log/143) 같은 SQL(`ALTER TABLE "Account" ADD COLUMN "mustChangePassword" BOOLEAN NOT NULL DEFAULT false`)을 Supabase 마이그레이션으로 먼저 적용했다 — 기본값이 있는 열 추가라 지금 운영 코드에 영향이 없고, 이 코드가 병합·배포되면 바로 쓴다. 확인: boolean·NOT NULL·기본 false, 계정 41개 중 표시 0.
- 문서: 권한관리 ADR-AUTH-08·요약 카드·§11·A-3, 점검표(대응 34 → 37, 부분 4 → 1 — 남은 것은 보안-16 계정별 로그인 제한, 수용), security-plan S3 해결, 요구사항추적표 N2-1·§1-2 #2·§4 문구.

**근거**: 개발보안 점검표 입력-14·보안-6·보안-9, security-plan S3, ADR-AUTH-05(데모 계정 잠금은 그대로), D53(답안지: NIST SP 800-63B).

**검증**: api jest 52개 파일 551건 통과(새 `input-limits` 3건·`password-change-required` 3건, `auth-password`에 조합 규칙 3건, `member-register`에 1건, `staff-write`·`auth-password`는 임시 비밀번호를 쓰도록 고침 — 데모 비밀번호로 채용 계정에 들어가던 것이 이번에 막은 동작이라 기대값을 바꿨다. 격리·계약·인사 권한 테스트는 기대값 변경 없음). api·두 웹 lint·빌드. 화면 자동 테스트 11건 통과(새 `admin-first-login`). 회원 웹 가입·연동·변경의 규칙 안내 화면은 lint·빌드만(검증되지 않음).

**추적표 판정**: 바뀌지 않는다(N2-1은 이미 구현). 수치 89% 그대로.
