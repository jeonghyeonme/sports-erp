# 092. 회원 가입·지점 회원 연동 화면 — 공개 지점 목록, 먼저 묻기, 전화번호 숫자 비교 (2026-10-09)

> [진행 로그 인덱스](README.md)

**계기**: 회원 웹은 이미 계정이 있는 회원만 로그인할 수 있었다. `POST /members/register`·`/link`는 있었지만 화면이 없었다([요구사항추적표](../reference/요구사항추적표.md) §3). 시연에서 "처음 오는 회원은 어떻게 들어오나"가 빠져 있었다. 같은 날 사용자가 Worker를 배포해 회원 웹이 운영에 올라갔다.

**사용자 결정(2026-10-09)** → [회원관리](../domains/회원관리.md) ADR-MEM-05
1. 지점 선택: 로그인 없이 부르는 공개 지점 목록 API를 둔다. 지점 코드를 직접 넣게 하는 안은 고르지 않았다.
2. 진입: 로그인 화면 → "처음 오셨나요?"(`/join`)에서 지점에서 이미 등록했는지 먼저 묻는다. 지점 등록 회원이 새로 가입해 회원이 둘이 되는 일을 줄인다(ADR-MEM-01).
3. 가입 항목: 연락처·생년월일을 화면에서 필수로 받는다. API는 그대로 선택이다.

**한 일**
- **api**
  - `GET /branches/public`(`@Public()`): id·이름·지역만, TERMINATED 제외, 지역·이름순.
  - `MemberService.link`: 회원번호로 찾은 뒤 전화번호를 **숫자만** 비교한다.
    - 화면을 만들다 발견했다. 지점이 하이픈을 넣어 저장했는데 본인이 숫자만 넣으면 불일치가 나고, 그때마다 시간당 5회 시도를 잃었다.
    - 저장된 번호가 비어 있으면 일치로 보지 않는다. 회원번호·전화번호 중 무엇이 틀렸는지 구분하지 않는 기존 규칙(ADR-MEM-01)은 그대로다.
- **member-web**
  - `/join`: 선택 화면이다. 요청은 보내지 않는다.
  - `/signup`: 지역 → 지점, 이름·연락처·생년월일·성별(선택)·이메일·비밀번호. 만 19세 미만이면 법정대리인 동의 체크(KST 기준 만 나이).
  - `/link`: 회원번호(대문자로 바꿈)·등록 전화번호·이메일·비밀번호.
  - 가입·연동 응답의 세션을 `startSession`으로 바로 쓴다. `/auth/login`을 다시 부르지 않는다. 가입 화면의 요청은 지점 목록 1회 + 가입 1회다(⑩).
  - 오류는 회원용 문구로 보인다(이메일 중복·미성년 동의·연동 불일치·이미 연동·시도 초과·지점 없음). 가입 화면의 `BRANCH_TERMINATED`는 예약용 문구 대신 "새 회원을 받지 않습니다"로 보인다.
  - `PHONE_RE`·`isMinor`·`todayKst`를 `lib/format.ts`로 모아 내 정보 수정과 같이 쓴다.

**검증**
- `branches-public.spec` 3건, `member-link.spec` 2건 추가. 연동·가입 관련 17건 통과. 커밋 hook에서 api jest 전체, 세 앱 lint·빌드 통과.
- 화면은 **검증되지 않음(수동 확인)**. 360px Playwright(`sports_erp_dev`)로 확인한 것:
  - 로그인 → 선택 화면 → 가입: 지역 3개(경기·서울·인천), 미성년 동의 없이 제출하면 오류, 체크 후 가입 → 홈에 이름.
  - 연동: 틀린 번호 → 불일치 문구. `seocho2025-014` + `01099990000`(하이픈 없음) → 홈.

**남은 것**
- 약관·개인정보 수집 동의 화면이 없다(보안요건 1-2 #8 개인정보처리방침과 함께).
- 공개 지점 목록은 Worker rate limit 대상이 아니다(GET, 쓰기 없음).
- 이 변경은 Worker를 다시 배포해야 화면에 보인다.
