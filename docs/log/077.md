# 077. 회원 모바일 웹 형태를 정하고(D41) 뼈대를 만들었다 — B1-1 (2026-10-07)

> [진행 로그 인덱스](README.md)

**계기**: [작업 브리프](../process/04_작업_브리프.md) B1-1. D40이 회원 기능을 모바일 웹으로 만들기로 했지만, 앱 형태와 Worker 배포 경로는 정하지 않았다.

**한 일**:
- 사용자가 브리프의 A/B/C안 중 **B안(`apps/member-web` 별도 앱, 같은 Worker)**과 **refresh token을 localStorage에 두는 방식**을 골랐다. → [D41](../decisions/D41.md)
- `wrangler dev`로 `/m/*` 새로고침을 먼저 시험했다(가짜 자산 폴더 + scratch 설정). 결과는 아래 표와 같다.
  - Worker 코드에 임시 로그를 넣어 Worker를 거치는 요청만 셌다. `/members`, `/m/`, `/m/assets/*`는 Worker를 거치지 않았다. `/m/login`, `/m/favicon.svg`는 Worker를 거쳤다.
  - 처음 설정(`!/m/assets/*`만 제외)에서는 회원 웹에 들어올 때마다 Worker를 1회 거쳤다. design-constants ⑬(하루 9.3만 건, 한도 10만)에 83곳 × 100명 = 하루 약 0.83만 건이 더해져 한도를 넘는다(계산). 그래서 `!/m/`를 추가해 진입 경로는 자산 계층이 바로 처리하게 했다.

| 경로(navigate 요청) | 결과 | Worker 경유 |
|---|---|---|
| `/`, `/members/abc` | 관리자 `index.html` | 아니오 |
| `/m` | 307 → `/m/` | 아니오 |
| `/m/` | 회원 `index.html` | 아니오(`!/m/`) |
| `/m/login`, `/m/reservations/123` | 회원 `index.html` | 예 |
| `/m/assets/*.js` | 파일 그대로 | 아니오 |
| `/api/v1/*` | 프록시(시험에서는 origin이 없어 502) | 예 |

- `apps/member-web` 뼈대: Vite(`base '/m/'`, 출력 `admin-web/dist/m`), 360px 모바일 셸(상단 바 56px, 누르는 요소 44px, 본문 14px, 입력창 16px — iOS 확대 방지), 로그인 화면, 빈 홈 화면.
  - 인증: access token은 메모리, refresh token은 localStorage. 앱을 시작하면 refresh → `/auth/me`로 복원한다. 401을 받으면 refresh를 한 번만 보내고(동시 요청은 같은 refresh를 기다린다) 원래 요청을 다시 보낸다. MEMBER가 아닌 계정은 로그인 직후 발급된 토큰을 `/auth/logout`으로 폐기하고 거부한다.
  - 개발 서버(5174)는 `.env` 대신 vite 프록시로 `localhost:3000`에 붙는다. 루트에 `dev:member`, `build:web`(admin → member 순서) 스크립트를 추가했다. `.claude/launch.json`에 `erp-member`를 추가했다.
- Worker: `run_worker_first`에 `/m/*`, `!/m/`, `!/m/assets/*`를 추가했다. `index.ts`의 `/m/*` 화면 경로는 `/m/`(회원 index)를 주고, 확장자가 있는 경로는 자산을 그대로 준다. README 배포 절차를 `npm run build:web`으로 바꿨다.

**근거**: D40 결정 2, D41, D25(같은 오리진), design-constants ⑩·⑬, 권한관리 A-6(refresh rotate).

**검증**:
- member-web·admin-web lint 0건, `npm run build:web` 성공, cloudflare-worker `tsc -p .` 통과.
- 실제 빌드 결과물 + 실제 `wrangler.jsonc`로 `wrangler dev`: `/`·`/members`는 관리자 화면, `/m/`·`/m/login`·`/m/home/x`는 회원 화면, `/m/assets/*.js`는 200.
- 화면: 이 PC에는 Playwright가 없고 Docker도 꺼져 있어 실제 api·DB를 띄울 수 없었다. 배포 API에 로그인하면 배포 DB에 refresh token 행이 생기므로 쓰지 않았다. 그래서 **scratchpad의 모의 api(auth 4개 라우트만 흉내)**와 데스크톱 앱 내장 브라우저(360×740)로 확인했다.
  - 토큰 없이 `/m/`에 들어가면 `/m/login`으로 간다.
  - 관리자 계정은 거부 문구가 나오고 토큰을 저장하지 않으며 `/auth/logout`을 호출한다.
  - 회원 로그인 → 홈("이수진님, 안녕하세요"·지점명)으로 간다.
  - 깊은 경로를 새로고침하면 refresh 1회로 복원된다.
  - access token을 만료시킨 뒤 동시 요청 3건을 보내면 refresh 1회 후 3건 모두 성공한다.
  - 로그아웃하면 토큰을 지우고 로그인 화면으로 간다. 무효 refresh token이면 로그인 화면으로 간다.
  - 가로 넘침이 없다(scrollWidth 360).
- **실제 api와의 연동은 검증되지 않음.** 자동 테스트는 없다.
