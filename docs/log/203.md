# 203. CSV 확대 — 직원·자산·문서·프로그램 출력 권한과 CSV 내려받기(권한관리 ADR-AUTH-09) (2026-11-08)

> [진행 로그 인덱스](README.md)

**계기**: 목록 일관화 2차(D74) 네 갈래 중 사용자가 "CSV 확대"를 먼저 골랐다. PR #144 병합 뒤 `dev`에서 새 브랜치 `claude/csv-export`(앞 작업 브랜치는 rebase 병합으로 다시 쓸 수 없어 새 이름 — 사용자 허락).

**한 일**
- **권한 설계**(권한관리 ADR-AUTH-09): 권한 카탈로그(D60)의 지점 관리자 상한에 `staff`·`asset`·`document`·`program` EXPORT를 더하고, `GET /staff`·`/assets`·`/documents`·`/programs`에 `exportable: true`. 행이 없으면 상한대로라 기본 허용 — 본사가 권한 관리 화면에서 끌 수 있다(화면은 카탈로그를 API에서 받아 새 칸이 자동으로 보인다). 대안(조회만으로 허용·별도 출력 라우트)은 ADR에.
- **CSV 열**(`lib/export-columns.ts`): 직원(지점·코드·이름·직급·고용형태·입사일·퇴사일·상태 — 연락처·이메일 없음), 자산(지점·코드·품명·분류·구분·수량·취득일·취득가액·위치·상태), 문서(지점·제목·분류·대상 직원·보존기한·등록자·등록일 — 파일 주소 없음), 프로그램(지점·이름·종목·이용방식·가격·강사·상태·시작일).
- **버튼**: 네 화면 목록 머리에 "CSV 내려받기" — 지금 탭·필터·검색·머리글 정렬 그대로 받는다. 화면 거르기는 함수로 빼 화면과 CSV가 같이 쓴다(`filterStaffGroups`·`filterProgramGroups`). 자산은 서버 쪽 나누기라 `fetchAllPages`로 모든 쪽. 프로그램 화면은 직원에게 CSV를 그리지 않는다.
- **표시 이름 옮김**: 자산 분류·구분·상태, 문서 분류, 프로그램 이용방식·상태 표시 이름을 각 화면에서 `lib/status-labels.ts`로 옮겼다(화면과 CSV가 같이 쓰도록).

**함께 찾은 것**
- **D60의 "상한 밖 = 허용"**: `PermissionService.allows`는 상한 밖 칸을 표가 다루지 않는 것으로 보고 허용한다. 그래서 직원의 `/programs?export=true`는 403이 아니라 조회와 같은 200이다(받는 데이터가 같다). 처음엔 403을 기대하는 테스트를 썼다가 실제 규칙대로 고쳤다. 관리자 웹 `useCan()`도 적용 권한에 없는 칸을 `true`로 보므로, 프로그램 화면은 역할로 직원에게 CSV 버튼을 숨겼다. 규칙을 "상한 밖 출력 = 거부"로 바꿀지는 D60 변경이라 하지 않았다.
- 변경 이력 화면(`AuditLogsPage`)의 자산 상태 표시 이름이 자산 화면과 다르다("수리 중" vs "수리중", "폐기 대기" vs "폐기대상") — 이번엔 고치지 않았다.

**근거**: 권한관리 ADR-AUTH-09, D60(세부 권한), D74(목록 일관화 2차), ADR-MEM-04(목록은 가린 값), RFP F1-2(출력).
