# 4-10. 13주차 발표 — 슬라이드 구성안 (최종안, 2026-11-23)

> [4-0 공통지침](4-0_발표자료_공통지침.md)을 따른다. 11-22 초안(부하 장만 확정)에 11-22~23 작업(사용감·운영 확인·PT 흐름, log/241~247)과 RFP 충족률 분모 변경(D82, log/248)을 합친 최종안이다 — 덱 제작 전 사용자 확인. 소스·데이터: [assets/4-10_13주차발표/deck-source/](assets/4-10_13주차발표/deck-source/README.md)

## 발표 조건 (가정 — 12주차와 같다)

- 시간 15분 안팎, 청중은 지도교수·평가자, 라이브 데모 없음(로컬 시연 데이터 캡처 + 운영 측정 수치).
- 범위: 12주차 덱 게시(2026-11-16) 이후 ~ 2026-11-23 `dev` `19e2098`(PR #166) — log/231~233·238~247. 12주차 덱 작업 자체(log/234~237)는 뺀다.
- 12주차 마지막 장(`wrap`)의 다음 할 일 4묶음에서 출발한다.

## 서사

12주차에 "남았다"고 한 일을 끝냈다 — **검증**(비정상 접근·운영 부하)은 숫자로 마치고, **운영에서 직접 써 보며** 시연 데이터·화면의 빈틈을 찾아 고쳤다. 그 결과 운영 환경에서 회원이 예약·결제·취소와 PT 구매·예약을 끝까지 할 수 있게 됐다. RFP 충족률 100%(해당 없음 10·의도적 제외 3을 분모에서 뺌), 진행률 80% → 88%.

## Q&A 대비 (슬라이드에는 넣지 않음)

**부하**
- 왜 서버에 직접? — 웹 앞단(Cloudflare Worker)을 거치면 로그인 제한(IP당 60초 10회)이 로그인 몰림을 막고 무료 일일 한도(10만 건)를 쓴다. 앞단과 같은 비밀 헤더를 붙여 Function URL에 보냈다.
- 초당 50이 왜 "평소"? — 설계 계산(D37)의 기준 요청량. 실운영 데이터가 없어 가정이다(D67).
- 초당 99가 한계? — 이번 조건에서 실제로 처리한 양(측정 하한). 상한을 올리려면 DB 연결 수(Pool Size 15)부터.
- 10월보다 빨라진 이유? — 가르지 못했다. 응답 시간은 내 PC까지의 네트워크 포함, 서버 처리 시간은 다시 재지 않았다.
- 10월의 순간 거절(47건)은? — 이번에 재현되지 않았지만 원인은 모른다("해결"이 아니다).
- 데이터 규모 — 배포 DB 시연 데이터(회원 218명, 지난 90일). 실제 현장 수십 곳 규모로는 재지 않았다.

**비정상 접근**
- 토큰 위·변조는? — 사용자 결정으로 범위에서 뺐다. 서명 검증은 라이브러리(Passport JWT)가 한다.
- 주소의 잘못된 `%` 인코딩도 같은 식으로 파서 문구가 나갈 수 있다 — 범위 밖, 검증되지 않음.

**운영 사용**
- 왜 테스트가 시트 문제를 못 잡았나? — 화면 테스트의 기준 데이터는 목록이 짧아 페이지가 화면보다 짧았다. 이제 "시트 배경이 화면 전체, 시트가 화면 안"을 직접 본다.
- 재시드하면 운영 데이터가 날아가지 않나? — 실운영을 하지 않는다(D67). 운영에서 사람이 올린 것(계약서·교육자료)은 이어 붙여 살렸다. 시연 회차는 12-12까지라 그 뒤 시연에는 다시 재시드.
- PT 회차는 누가 여나? — 트레이너(지점 관리자)가 관리자 웹 "회차 등록"으로 연다(정원 1). 시연 데이터는 월·수·금 10·19시를 미리 열어 둔다.
- AI 역할 분담 — 구현은 Claude, PR 리뷰·기획 문서는 Codex(구독 안에서, 요청할 때만). 리뷰 기준(도메인 불변식 9개)은 저장소 `AGENTS.md`에 있다(log/231·233).

**RFP 100%**
- 다 한 건가? — 아니다. 72조항 중 발주기관·계약이 필요한 10개(해당 없음)와 근거 자료가 없어 하지 않기로 한 분석 3개(의도적 제외)를 분모에서 뺐다. 12주차의 94%(D76)와 기준이 다르다 — 같은 기준이면 95%, 조항 전부로는 82%(D82).
- 의도적 제외 3개를 왜 안 했나? — 실제 매출·계약 데이터 없이 기대효과를 예측하면 지어낸 숫자가 되고, 비교 기업의 내부 시스템·매뉴얼에 접근할 수 없다(차별화전략 §2-1).
- PG 연계는? — 연계 가능 여부를 문서로 확인하고 어댑터로 설계했다. 실운영을 하지 않아(D67) 테스트 키 호출은 하지 않았다 — 그래서 "구현"이 아니라 "조정".

**검증 범위**: api 자동 테스트 62파일 681건(실DB), 화면 자동 테스트 35건(역할별 핵심 경로) — 그 밖은 lint·빌드·수동 점검. 회원 홈 PT 카드·비활성 카드는 화면 자동 테스트 없음(캡처·운영 확인).
