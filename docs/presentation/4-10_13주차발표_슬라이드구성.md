## Q&A 대비 (부하 — 슬라이드에는 넣지 않음)

- **왜 서버에 직접?** 웹 앞단(Cloudflare Worker)을 거치면 로그인 제한(IP당 60초 10회)이 로그인 몰림을 막고, 무료 일일 한도(10만 건)를 쓴다. 그래서 Function URL에 앞단과 같은 비밀 헤더를 붙여 보냈다.
- **초당 50이 왜 "평소"?** 설계 계산(D37)의 기준 요청량. 실제 운영 데이터가 없어 가정이다(실운영 안 함, D67).
- **초당 99가 한계?** 이번 조건에서 실제로 처리한 양이다(측정 하한). 동시 실행 상한 10 ÷ 처리 시간으로 계산한 이론값과 다르고, 상한을 올리려면 DB 연결 수(Pool Size 15)부터 봐야 한다.
- **10월보다 빨라진 이유?** 가르지 못했다 — 서버 처리 시간은 다시 재지 않았고, 네트워크·웜 상태 차이일 수 있다. 새 화면 조회를 섞어도 같은 결과라는 것만 말한다.
- **데이터 규모**: 배포 DB의 시연 데이터(회원 211명 등, 지난 90일). 실제 위탁 현장 수십 곳 규모의 데이터량에서는 재지 않았다.
- **서버 쪽에 남는 것**: 로그인 약 1,900번의 기록이 배포 DB에 쌓인다(사용자 승인, 2026-11-22).
