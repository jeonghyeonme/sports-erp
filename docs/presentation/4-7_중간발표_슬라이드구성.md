# 4-7. 중간발표 — RFP 추적 현황 파트 슬라이드 구성 (2026-10-19 기준)

> 공통 지침은 [4-0](4-0_발표자료_공통지침.md). 이 문서는 **더 큰 중간발표 덱의 한 파트**(RFP를 얼마나 구현했나)만 다룬다 — 표지·마무리는 덱 전체 구성에서 정한다. 덱 소스는 6주차 소스를 복사해 `assets/4-7_중간발표/deck-source/`에서 시작한다(아직 만들지 않음). **덱 미제작 — 이 문서는 구성안이다.**
>
> 모든 수치는 [요구사항추적표](../reference/요구사항추적표.md) §3(2026-10-19)에서만 가져온다. 새로 세거나 반올림을 바꾸지 않는다. 추적표가 바뀌면 이 문서의 수치를 추적표에 맞춰 고친다.

## 발표 조건

- **분량**: 약 10분, 10장(파트 표지 포함). 라이브 데모 없음.
- **청중**: 교수·평가자 — RFP 대비 완성도를 평가하는 사람. 관심은 "얼마나 했나"보다 **"그 숫자를 공정하게 셌나"**다. 그래서 판정 방법을 숫자보다 먼저 보이고, 유리한 수치(구현+조정)와 너그러운 수치(부분 포함)를 항상 함께 쓴다.
- **위치**: 큰 중간발표 덱의 한 파트. 앞 파트와는 파트 표지로, 뒤 파트와는 마지막 장의 한 문장으로 잇는다.
- **자료**: 6주차 덱 소스(`assets/4-6_6주차발표/deck-source/`)의 생성기·디자인 규칙을 이어 쓴다. 화면 캡처는 조정 사례 화면과 엑셀 판정 시트. 충족률은 별도 도표 없이 큰 숫자 표로 보인다(사용자 선택 — 도표 미선택).
- **결정 근거(D53)**: 상위 목표가 "실무 노하우·도메인 지식 습득이 먼저"라, 이 파트는 성과 자랑보다 **요구사항을 조항 단위로 추적하고 판정 기준을 공개하는 실무 방식** 자체를 보여주는 데 둔다.

## 서사

RFP 72조항을 원문 글머리 하나씩 쪼개 다섯 가지로 판정했다 → 전체 충족 70%(부분 포함 94%), 시스템의 핵심인 기능·성능은 86% → 방식을 바꾼 6건은 모두 결정 기록이 있다 → 점수를 깎는 것은 대부분 코드가 아니라 문서·절차형 조항이고, 남은 것은 코드 / 문서 / 의도적 제외 유지로 나눠 메운다.

## 발표 노트 요점 (장별, 덱 제작 시 노트에 옮긴다)

- **2 `rfp-method`**: "조항을 어떻게 나누느냐가 숫자를 정한다"를 먼저 말한다. 해당 없음 8개(발주기관 승인·확약서·하자보수·대면 교육 등)를 분모에서 뺀 이유를 한 문장으로. **판정은 자기 평가다** — 외부 검수가 아니라고 먼저 밝힌다.
- **4 `rfp-score`**: 70%와 94%를 반드시 같이 말한다. "94% 완성"이라고 말하지 말 것 — 94%는 일부만 한 조항까지 넣은 값이다.
- **5 `rfp-function`**: "기능은 거의 다 했다"가 아니라 "기능 29조항 중 미구현 0, 부분 4"로 말한다. 부분 4개는 무엇이 빠졌는지 한 마디씩.
- **6 `rfp-adjust`**: 조정을 충족으로 세는 이유 — 결과는 냈고 바꾼 이유가 결정 기록으로 남아 있어서. 납득하지 않는 평가자를 위해 부분 포함/제외 수치를 함께 둔 것이라고 덧붙인다.
- **7 `rfp-adjust-shot`**: 회원 화면은 회원 모바일 웹(네이티브 앱 아님)이라고 밝힌다. 모의 결제는 실제 돈이 오가지 않는다.
- **8 `rfp-gap`**: 의도적 제외는 "못 했다"가 아니라 "근거 없는 숫자를 만들지 않기로 했다"로 말한다. 미구현 4개 = 보안관리계획(N8-1) + 의도적 제외 3(T2-1·P2-2·P2-3).

## Q&A 대비

- **판정 주체**: 자기 평가다. 근거(경로·테스트·결정 번호)를 조항마다 공개해 검증 가능하게 했다(추적표 §3, 엑셀 시트).
- **해당 없음 8개를 빼는 게 유리하지 않나**: 분모에 넣어도 판정 대상이 될 수 없는 조항(발주기관·계약·대면)이다.
- **자동 테스트 범위**: API는 실DB로 지점 격리·계약 종료 차단·인사 권한·동시성·도메인 규칙을 본다(42개 파일 495건, CI 통과 — 추적표 §2). 관리자 웹·회원 웹은 자동 테스트가 없고 lint·빌드만이다.
- **성능 조항**: 운영 측정은 했지만 순간 몰림 거절(로그인 몰림 38건 등) 원인은 미확인이다(추적표 §2-3 성능 요구).
- **첨부(F4-2)**: 화면·API는 있으나 배포 저장소에서 실제 파일 올리기·내려받기는 검증 전이다.
- **세부 권한을 왜 안 했나**: 역할 4개 + 지점 격리로 조정(D1). 사용자별·기능별 권한 표는 범위가 커서 결정이 먼저다.
