# 4-7. 중간보고서 — 읽는 덱 구성안 (2026-10-22 재구성)

> 공통 지침은 [4-0](4-0_발표자료_공통지침.md). **중간고사 대체 제출물 "프로젝트 중간보고서"** 를 슬라이드(파워포인트 형식)로 만든다 — 발표자 없이 지도교수가 혼자 넘겨 읽는 덱이다. 슬라이드 아티팩트로 만들어 PDF로 내보낸다(사용자). 덱 소스는 `assets/4-7_중간발표/deck-source/`(캡처·캡처 스크립트만 있음, 덱 미제작). 2026-10-19~22의 20분 발표용 구성(파트 A → 파트 B, 24장)을 이 문서가 대체한다 — 경위는 [log/175](../log/175.md), 제출물 구성은 [D67](../decisions/D67.md).
>
> **게시된 덱(2026-10-23, 55장):** https://claude.ai/artifact/M2NBGeZcaBdTgkT1msjwQb (비공개 — 공유는 소유자가 Share 메뉴에서). 아래 45장 구성에 장 구분 6장(Ⅱ~Ⅶ)을 더했고, Ⅳ장 이행 현황 표는 조항 한 줄씩(RFP 이행 증빙과 같은 문장)이라 높이에 맞춰 11장으로 나눴다(기능 4 · 성능 1 · 시스템~제약 3 · 과업·산출물·개념도 3). 생성기는 `assets/4-7_중간발표/deck-source/viz/deck47.js`.
>
> RFP 이행 상태는 모두 [요구사항추적표](../reference/요구사항추적표.md) §3에서만 가져온다(새로 판정하지 않는다). 수치는 덱 제작 때 그날 커밋에서 다시 확인한다.

## 이 덱의 조건

- **독자**: 지도교수. 관심은 **전체 맥락 파악** — ERP라 기능이 많고 서로 맞물려, 소개받는 쪽이 피곤하지 않아야 한다(사용자, 2026-10-22).
- **읽는 덱**: 발표 노트에 기대지 않는다. 장마다 핵심 메시지 한 줄 + 그 근거가 본문에 다 있어야 한다. 시간 배분·Q&A 절은 두지 않는다.
- **분량**: 맞추지 않는다 — 한 장에 무리하게 넣지 않고, 어렵다고 판단되면 장을 늘린다(사용자). 지금 약 45장.
- **순서**: 맥락 → 설계 → RFP 이행 → 확인 → 진행 경과 → 마무리. "맥락만 보려면 Ⅱ장까지"가 성립해야 한다.
- **함께 내는 것**(D67): RFP 이행 증빙(HTML 아티팩트 → PDF, 조항별 쉬운 말 한 줄 + 화면 + 결정 기록), 주차별 발표자료(사용자가 직접 내보냄), 다시 생성한 산출물. 이 덱은 그것들을 가리키는 길잡이 역할도 한다.
- **쉬운 말**: 이행 현황 표의 "구현한 것"은 RFP 이행 증빙의 쉬운 말 한 줄과 **같은 문장**을 쓴다(덱 제작 때 그 데이터에서 가져온다 — 아래 표의 문장은 초안).
- **6주차와 같은 모양**: 6주차 덱 생성기(`assets/4-6_6주차발표/deck-source/`)의 디자인 규칙을 따른다. 개요·설계 도식은 종합발표 덱 소스(`assets/4-5_종합발표/deck-source/`)를 최신 사실로 고쳐 쓴다.
- **결정 근거(D53)**: 상위 목표가 실무 노하우·도메인 지식 습득이라, 기능 나열보다 **도메인 이해 → 설계 규칙 → 요구사항별 이행 → 검증**의 흐름으로 보인다.
