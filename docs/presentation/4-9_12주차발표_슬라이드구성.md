## 가독성 정리 (2026-11-16, 사용자 피드백)

진행률 장의 `%` 줄바꿈 지적에 따라 전 장을 점검했다. 막대 칸 폭·nowrap 고정(progress), 단어 중간 줄바꿈 제거(report-shot·deliv·deliv-source·verify), 카드·캡션·각주를 명사구로 줄임(agenda·report-print·narrow·wrap). 내용(수치·메시지)은 바꾸지 않았다(log/232). 이어서 덱 캡처에서 찾은 800px 상단 바·표 라벨 꺾임을 고치고 `narrow`·`wrap`을 다시 찍었다(log/233).

## Q&A 대비 (슬라이드에는 넣지 않음)

- 리포트의 "최근 6개월 증감"은 시연 데이터(90일치)라 대부분 "앞 기간 기록 없음". 평균 대비는 지점 규모 보정 없음(도움말에 "추세와 함께 본다").
- 조항 변경 제안 메모는 넣지 않았다(사용자 결정) — 저장하려면 새 테이블(스키마 변경 승인).
- 신규 수주 입찰(PT)용 전사 리포트는 아직 제안 단계(차별화전략 §2).
- 기업 분석(RFP 20쪽 이상): 제출본 14쪽은 요약·제안, 분석 본문은 기업구조 분석·차별화전략·도메인 문서에 나뉘어 약 26쪽 분량(추적표 §1-3).
- 검증 범위: api 자동 테스트 671건(실DB), 화면 자동 테스트 35건(역할별 핵심 경로) — 그 밖은 lint·빌드·수동 점검. 여전히 수동: 직원 수정·퇴사 화면, 회원 앱 날짜 띠, 계약 파일 이관·정리 버튼.
- 운영 의존성 취약점 3 → 0(NestJS 11.2.10·multer 2.5.0·follow-redirects 1.16.3, log/230), 개발 도구 쪽 20건은 범위 밖.
- 코드·문서 정리(옛 이름, 두 웹 공유 패키지 D78, 진행 기록 주 단위 D79)는 발표 거리에서 뺐다(4-0 §3).
