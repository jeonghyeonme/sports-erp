D48·D49. 출발점: 10/4 k6 — 요청당 처리 약 110ms(가정 50ms), 실질 처리 한계 약 50 rps. 측정: 로컬에 왕복 지연을 넣어 홈 조회 4종을 재 보니 평균 DB 왕복 20.5회. 원인: 트랜잭션 풀러 호환 모드가 작업마다 시작·정리·종료를 덧붙여 왕복이 약 3.5배, 인증만으로 요청마다 왕복 10회. 대응 1단계(적용): 인증 조회를 하나로, 목록 조회를 묶음(D48). 2단계: Session pooler로 접속 변경(D49) — 운영 Lambda에 적용됨(10/11 배포, 2026-10-12 사용자가 환경 변수 5432·pgbouncer 없음 확인). 로컬 기준 왕복 약 6회. 운영 재측정(10/12, D50·log/109): 서버 처리 시간 p50 약 110 → 40ms, p95 약 165 → 51ms. 과부하(300 rps)에서 실제 처리 약 52 → 93 rps. "약 6회"는 로컬 측정이고 운영 왕복 수는 재지 않았다. 처리 시간은 서버 기준(CloudWatch)이고 사용자가 느끼는 시간은 네트워크가 더해진다(k6 50 rps 성공 p95 178 → 150ms).
