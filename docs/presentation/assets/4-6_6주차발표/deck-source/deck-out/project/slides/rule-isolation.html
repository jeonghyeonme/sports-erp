D46. 왼쪽(전): 요청이 들어오면 기능(컨트롤러)마다 지점 검사를 각자 했다 — 같은 검사가 약 10곳에 복사. 새 기능을 만들며 검사를 빠뜨리면(빨간 점선) 남의 지점 데이터가 보일 수 있었고, 그걸 막을 장치가 없었다. 오른쪽(후): 모든 요청이 지나는 공통 검사 한 곳에서 지점을 본다. 기능은 "무슨 리소스를 다루는지" 선언 한 줄만 붙인다. 선언이 빠진 기능은 실제 라우트 목록을 훑는 테스트가 실패시킨다. 변이 확인: 시설 수정의 선언 하나를 일부러 빼면 선언 누락 검사 1건 + 격리 공격 2건, 테스트 3건이 실패했다(log/095). 부수 효과: 남의 지점 id를 주면 조용히 자기 지점으로 바꿔 주던 목록들(자산·결제·근태 요약 등)이 이제 거부한다 — 화면은 남의 지점 id를 보내지 않아 영향 없음. 왼쪽 "새 기능"의 뚫림은 구조상 가능했던 위험을 그린 것이지, 실제로 뚫린 사고가 있었다는 뜻이 아니다 — 그렇게 말하지 말 것.
