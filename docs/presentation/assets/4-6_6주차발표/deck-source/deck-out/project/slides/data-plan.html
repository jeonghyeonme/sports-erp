계획이다 — 아직 만들지 않았다. 지점을 계약 상태별로 하나씩, 정상은 두 곳(서초·강남, 격리 확인용). 지점마다 직원 4~6명, 회원 30~60명, 2~3개월치 예약·결제·출결 이력. 각 지점에 확인할 장면을 붙였다: 정상 A — 아침 동시 입장, 결제 중 관리자 취소, 몰림 시간 처리량 / 정상 B — 지점 격리, 파견 이동 중 근태 귀속, 두 기기 동시 로그인 / 갱신 임박 — 본사 집계 성능, 실적 데이터 신선도 / 만료 — 차단하지 않는 경계 / 계약 종료 — 종료와 채용·발령 동시 요청, 과거 조회. 점검 목록은 docs/architecture/engineering-risks.md(동시성·멱등성·부분 실패 등 17개 범주). 배포 DB를 다시 채우는 일은 별도 승인을 받는다.
