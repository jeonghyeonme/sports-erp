계약 종료 확정
↔ 회원 등록 · 예약 등		종료된 지점에 새 데이터가 저장됨쓰기 처리 안에서 지점을 잠그고 읽음
퇴사
↔ 파견 발령		퇴사자에게 파견이 남음두 처리 모두 직원을 잠금

지점 잠금은 공유 잠금 — 종료 확정과 겹칠 때만 기다리고, 평소 쓰기끼리는 서로 기다리지 않습니다

두 곳은 겹칠 수 있는 요청을 잠가서 순서대로 처리한 것이다. ① 계약 종료 확정과 회원 등록·예약 등: 종료 판정을 트랜잭션 밖에서 미리 읽어, 종료 확정과 같은 순간에 들어온 등록이 종료된 지점에 저장됐다(실DB로 10개 경로 재현). 지금은 쓰기 트랜잭션 안에서 지점 행을 공유 잠금으로 읽는다 — 종료 확정이 진행 중이면 끝날 때까지 기다렸다가 거절한다. 공유 잠금으로 한 이유: 같은 지점의 평소 쓰기끼리는 서로 기다리지 않고, 종료 확정과 겹칠 때만 기다린다. ② 퇴사와 파견 발령: 퇴사와 동시에 들어온 발령이 퇴사자에게 진행 중 파견을 남겼고, 같은 직원 동시 발령은 한쪽이 서버 오류가 났다. 두 처리 모두 시작할 때 직원 행을 잠근다. 질문이 나오면: 고치기 전에 재현 테스트를 먼저 만들어 실패를 확인했다. 잠금 순서(직원 → 지점)와 종료 처리(지점 → 파견)가 엇갈리지 않아 교착이 없다.
