잠금으로 안 되는 곳

계약 정정은 회차 번호를 같이 보냅니다

본사 A

1회차 화면을 열어 둠

본사 B

갱신 → 2회차가 생김

본사 A

정정 저장 → 회차 번호가 달라 거절, 다시 열라고 안내

사람이 화면을 보는 동안 DB 잠금을 유지할 수 없어서, 저장할 때 확인합니다

계약 정정과 계약 파일 교체는 이미 지점 행 잠금으로 순서대로 저장되고 있었다. 문제는 순서가 아니라 대상이다. 본사 A가 1회차 화면을 열어 둔 사이 본사 B가 갱신해 2회차가 생기면, A가 1회차를 고친다고 생각한 정정·교체가 2회차에 들어갔다. 지금은 화면을 연 때의 회차 번호를 요청에 함께 보내고, 지금 회차와 다르면 거절하고 화면을 다시 열라고 안내한다. 잠금이 아닌 이유: 사람이 화면을 보는 시간 동안 DB 잠금을 쥐고 있을 수 없어서, 저장할 때 확인한다. 운영 화면에서 이 거절 안내를 직접 띄워 보지는 않았다.
