Ⅶ. 마무리 · AI와 함께 개발한 방식

AI가 만든 것을 검사와 기록이 붙잡는 구조

결정 전

근거부터 인용

어느 결정 기록에 근거하는지 먼저 밝히고, 없으면 대안과 이유를 먼저 남긴다

커밋 전 · PR

기계가 막는다

lint · 빌드 · 자동 테스트 · 문서 검사 — 실패하면 커밋도 병합도 안 된다

기록

한 사실은 한 곳에

현재 상태 · 진행 기록 · 결정 기록 — 언제든 "왜 이렇게 됐나"를 따라간다

상위 목표 — AI 활용과 실무 노하우·도메인 지식 습득이 먼저, 포트폴리오 품질은 그다음

AI(Claude Code)와 대화로 개발했다. 사람이 매번 diff를 보지 않아도 방향을 잡을 수 있게 세 겹을 뒀다. 결정 전: 어느 결정 기록(D 번호·도메인 ADR)에 근거하는지 먼저 인용하고, 없으면 대안·트레이드오프를 먼저 남긴다. 커밋 전: 세 앱의 lint·빌드와 API 자동 테스트, 문서 검사(링크·ID·크기 상한)가 커밋을 막는다. PR마다 CI가 같은 검사와 화면 자동 테스트를 돈다. 기록: 현재 상태(STATUS)·진행 기록(log, 170여 건)·결정 기록(D 67개 + 도메인 ADR) — 한 사실은 한 곳에. 상위 목표는 AI 활용·실무 노하우와 도메인 지식 습득이 먼저, 포트폴리오 품질은 그다음(D53).
