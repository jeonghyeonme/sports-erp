# 4-8. 8주차 발표 슬라이드 구성 (2026-10-26 ~ 11-02) — 초안

> 공통 지침은 [4-0](4-0_발표자료_공통지침.md). 덱 소스는 `assets/4-8_8주차발표/deck-source/`(아직 없음 — 6주차 `deck46.js`를 복사해 시작). **덱 미제작, 구성안 초안(2026-11-02).**
>
> 형식은 6주차 덱(질문형 목차 → 파트 표지 → 결정·흐름·화면 → 마무리, 23장·15분)을 따른다. 중간보고서(4-7)는 혼자 읽는 덱이라 형식이 다르고, 이 발표는 다시 **말로 하는 주간 진행 발표**다.

## 발표 조건 (확인 필요 — 6주차 기준으로 가정)

- 15분, 라이브 데모 없음(가정). 범위는 10/26(월) ~ 11/2(월).
- 청중은 지난 발표와 같다(개발 지식이 있는 사람). 중간보고서 덱을 읽었다고 가정하지 않는다.
- 주차 이름: 1주차 9/7 기준으로 세면 10/19 주가 7주차(중간보고서 제출 주)라 이번이 8주차 — 사용자 확인.

## 서사

중간보고에서 "다음 계획 ② 계약서 OCR·AI 검토"를 걸었다 → 검토하려고 보니 **계약을 시스템에서 관리할 수가 없었다**(바꿀 수 있는 건 상태 하나) → 갱신·정정·등록(D68) → 회차와 계약서 파일(D69) → 보존과 실물 이관(D71)으로 **계약의 처음부터 끝까지**를 채웠고, OCR·AI는 **넣지 않기로 결정**했다 → 계약 쓰기를 만들면서 기능 전체의 **동시성 빈틈을 점검**해 세 곳을 막았다(D70).

근거(D53): 사업 구조 1번 — 지점은 계약 현장이고 계약 개수가 본사 매출이다. 계약 관리가 비어 있으면 "위탁운영사 ERP"라는 말이 성립하지 않는다.

## Q&A 대비

- 화면 검증: 계약 화면은 화면 자동 테스트 2건이 본다 — 새 계약서로 갱신 → 회차·계약 이력 확인, 계약서와 함께 새 지점 등록(`e2e/tests/admin-hq.spec.ts`). 정정·종료 확정·계약서 열람 화면과 보존 화면(D71, 로컬 미리보기만)은 화면 자동 테스트 밖 — API 테스트로만 검증.
- 종료일이 지나도 상태를 자동으로 바꾸지 않는다(표시만, 본사 판단). 스케줄러가 없어서 보존 정리도 버튼이다 — 예약 작업(C안)은 새 인프라라 보류(D71).
- 계약 회차 도입은 Prisma 스키마 변경(승인 받음, 배포 DB 마이그레이션 2026-11-01·02). 지점 행의 계약 칸은 없앴다.
- 동시성: 두 번 누르면 두 번(PT 1회 사용 두 번 차감 등)은 남아 있다 — 데이터가 깨지진 않아 영향이 작다고 판단(D70 하지 않은 것).
- RFP 충족률 81%는 중간 기준 — D68~D71 반영 여부 재대조 전(요구사항추적표 §2가 "문서는 실제 파일 업로드 없음" 등 옛 문장). **발표 전에 재대조하거나 숫자를 말하지 않는다.**
- 실운영은 하지 않는다(D67) — 운영 반영은 시연용 배포 환경.
