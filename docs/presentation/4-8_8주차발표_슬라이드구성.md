## Q&A 대비

- 이전 설계·버린 대안(슬라이드에 넣지 않음): 계약 이력을 지점 행 + 변경 이력으로만 두는 안(D68)에서 회차 테이블로 바꿈(D69). 계약서를 문서 관리에 두는 안은 문서 API마다 계약서 제외 조건이 필요해 택하지 않음. 실물 이관 = 즉시 삭제였던 설계를 이관 표시와 정리로 나눔(D71). 정리 주체는 조회 시 자동·매일 예약 작업 대신 본사 버튼(D71 대안). 종료 판정은 실DB 이전 시기의 임시 방식(D29)을 대체(D70).

- 화면 검증: 계약 화면은 화면 자동 테스트 2건이 본다 — 새 계약서로 갱신 → 회차·계약 이력 확인, 계약서와 함께 새 지점 등록(`e2e/tests/admin-hq.spec.ts`). 정정·종료 확정·계약서 열람 화면과 보존 화면(D71, 로컬 미리보기만)은 화면 자동 테스트 밖 — API 테스트로만 검증. 회차 번호 거절 안내는 운영 화면에서 직접 띄워 보지 않았다(log/194).
- 계약 회차 도입은 Prisma 스키마 변경(승인 받음, 배포 DB 마이그레이션 2026-11-01·02). 동시성 수정(D70)은 스키마 변경 없음.
- 동시성 "하지 않은 것" 나머지: 회원 상태·프로그램·시설 수정의 마지막 저장 우선, 세부 권한 같은 칸 동시 변경의 500(D70).
- 공유 잠금의 비용: 종료 확정이 진행 중일 때만 그 지점 쓰기가 잠깐 멈춘다. 운영 DB 연결이 요청당 1개라(D37) 트랜잭션 안에서는 그 연결만 쓴다.
- RFP 충족률 재대조(2026-11-02): 구현·조정이 아닌 6조항(PG 실제 호출 N7-3 · 업무위탁 DPA N8-2 · 검수·도입 T3-2 · 유사기업 분석 T2-1·P2-3 · 기대효과 P2-2)은 D68~D71과 관계없어 58/72 = 81% 그대로. 요구사항추적표 §2의 영역별 문장(공통 행에 계약 기능 없음, 자원문서관리 행 "문서는 실제 파일 업로드 없음")은 D68~D71보다 오래됐다 — 판정에는 영향 없음.
- 실운영은 하지 않는다(D67) — 운영 반영은 시연용 배포 환경. 보존 3년·실물 7년은 사용자가 정한 값(D69 결정 7)이지 스포이즘 내부 규정이 아니다.
