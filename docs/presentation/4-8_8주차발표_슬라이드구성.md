## 서사

중간보고에서 "다음 계획 ② 계약서 OCR·AI 검토"를 걸었다 → 검토하려고 보니 **계약을 시스템에서 관리할 수가 없었다**(바꿀 수 있는 건 상태 하나) → 계약을 관리하면서 **계약서 종류마다 다루는 규칙과 실수 방지 장치**를 정했고 → OCR·AI는 **넣지 않기로 판단**했다 → 계약 쓰기를 만들고 나서 기능 전체의 **동시성을 다시 점검해 놓친 세 곳**을 막았다.

근거(D53): 사업 구조 1번 — 지점은 계약 현장이고 계약 개수가 본사 매출이다. 계약 데이터의 오류는 곧 "이 지점을 막을지"의 오류라, 편의보다 확실성을 골랐다.

## Q&A 대비

- 화면 검증: 계약 화면은 화면 자동 테스트 2건이 본다 — 새 계약서로 갱신 → 회차·계약 이력 확인, 계약서와 함께 새 지점 등록(`e2e/tests/admin-hq.spec.ts`). 정정·종료 확정·계약서 열람 화면과 보존 화면(D71, 로컬 미리보기만)은 화면 자동 테스트 밖 — API 테스트로만 검증. 회차 번호 거절 안내는 운영 화면에서 직접 띄워 보지 않았다(log/194).
