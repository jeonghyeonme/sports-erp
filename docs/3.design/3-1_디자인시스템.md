# 디자인 시스템

> [00_공통설계서](../1.spec/00_공통/1-1_공통설계서.md)에서 분리된 문서입니다. 페이지가 늘어날수록 컴포넌트·화면 패턴 지시사항이 계속 쌓일 성격의 문서라, 1-1문서(아키텍처 전반)와 분리해 여기서 독립적으로 키웁니다. 새 화면을 만들거나 기존 화면을 이 기준으로 맞출 때 참고하세요. 이 방향을 채택한 의사결정 근거는 [09_기술결정사항 D19](../2.decisions/50_결정및이슈기록/2-1_기술결정사항.md#d19-디자인-방향-전환--saas-스타터-톤에서-고밀도-엔터프라이즈-라이트로) 참고.

## 1. 왜 이 방향인가

기존 admin-web(D15, "Rounded Rectangle 기준" 토큰화)은 인디고 포인트컬러(`#4f46e5`, Tailwind/shadcn 기본값)·큰 라운드(`radius-lg/xl`)·소프트 섀도우·파스텔 4색 아이콘 칩으로 구성되어 있습니다. 이건 스타트업 랜딩페이지/SaaS 스타터 템플릿 미학에 가깝고, **"본사 관리자가 수십 개 지점을 매일 들여다보는 운영 콘솔"**이 줘야 할 신뢰감·밀도와는 맞지 않습니다. 실제 다지점 운영 관리 소프트웨어(Mindbody, Zenoti, ServiceTitan 같은 피트니스·서비스 프랜차이즈 관리 도구)를 기준으로 재정의합니다.

**방향**: 고밀도 엔터프라이즈 라이트. 무채색 기반(슬레이트 스케일) + 포인트 컬러 1개만 기능적으로 사용, 카드보다 테이블·리스트 중심, 여백보다 정보 밀도 우선.

## 2. 디자인 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-bg` | `#f8fafc` | 페이지 배경 |
| `--color-surface` | `#ffffff` | 카드/테이블/사이드바 아닌 패널 |
| `--color-surface-alt` | `#f1f5f9` | 테이블 헤더, 보조 배경 |
| `--color-border` | `#e2e8f0` | 기본 구분선 — 그림자 대신 이 보더가 요소를 구분하는 주 수단 |
| `--color-border-strong` | `#cbd5e1` | 테이블 헤더 하단, 강조 구분선 |
| `--color-text` | `#0f172a` | 본문 |
| `--color-text-muted` | `#64748b` | 보조 텍스트, 라벨 |
| `--color-sidebar-bg` | `#0f172a` | 사이드바/헤더 배경(기존 유지) |
| `--color-sidebar-text` | `#cbd5e1` / 활성 `#ffffff` | |
| `--color-primary` | `#0f766e` (teal-700) | **유일한 포인트 컬러** — 링크, 활성 탭, 주요 버튼, 포커스 링. 장식용으로 남용하지 않음(인디고 → 티얼로 교체) |
| `--color-primary-soft` | `#f0fdfa` | 선택된 행/탭 배경 정도로만 최소 사용 |
| `--radius-sm` | `4px` | 입력창, 버튼, 작은 요소 |
| `--radius-md` | `6px` | 카드, 테이블, 패널 — 기존 `lg/xl`(14~28px) 전부 이 값으로 통일 |
| `--radius-pill` | `999px` | **뱃지·태그 전용**(작은 인라인 라벨만). 사이드바·메인 영역·카드 같은 큰 컨테이너에는 pill/대형 radius 금지 |
| `--shadow-*` | 원칙적으로 사용 안 함 | 요소 구분은 그림자가 아니라 `--color-border`로. 드롭다운/모달처럼 실제로 위에 뜨는 요소에만 `0 1px 2px rgba(0,0,0,0.06)` 최소 섀도우 허용 |

**상태(semantic) 색상**(기존 badge 색상 유지 — 이건 장식이 아니라 의미 전달이라 문제 없음): success `#dcfce7`/`#15803d`, warning `#fef9c3`/`#a16207`, danger `#fee2e2`/`#b91c1c`, neutral `#e2e8f0`/`#475569`. **아이콘 칩의 blue/violet/emerald/amber 4색(장식용, 의미 없음)은 폐기** — 아이콘은 전부 단색(`currentColor` 또는 `--color-text-muted`)으로 통일하고, 색은 상태를 표현할 때만 씁니다.

## 3. 레이아웃 원칙

- **떠 있는 카드 레이아웃 폐기**: 현재 `app-shell`이 16px 패딩 안에 사이드바·메인 영역을 각각 둥근 모서리 카드로 띄우는 구조(bento-box 스타일)인데, 이를 **엣지투엣지**로 바꿉니다 — 사이드바는 뷰포트 왼쪽에 딱 붙고, 사이드바/본문 경계는 그림자가 아니라 1px 보더.
- **KPI는 큰 숫자 카드가 아니라 추세선(sparkline) 포함 소형 패널**로 — 현재 `.kpi-card`(아이콘 칩 + 큰 숫자)를 "라벨 + 현재값 + 전기 대비 증감(%, 화살표) + 스파크라인"으로 교체. 숫자 하나만 던지는 카드는 "장난감 대시보드"처럼 보이는 가장 큰 원인 중 하나입니다.
- **테이블은 얼룩말(zebra) 줄무늬 대신 보더 위주**로, 헤더는 옅은 배경(`--color-surface-alt`) + 작은 대문자 스타일(11px, `letter-spacing`, muted 색)로 — 정렬/필터 가능한 컬럼은 헤더에 시각적으로 표시. 행 높이는 기존보다 낮춰 밀도를 올립니다.
- 타이포 스케일: 11/12/13(기본 본문)/14/16/20px로 명시적 스케일을 두고, 11~20px 사이 임의 값을 쓰지 않습니다.

## 4. 적용 범위와 우선순위

`apps/admin-web/src/styles.css`는 2026-09-18(커밋 `66d9ace`)에 이 문서의 토큰을 전역 `:root`로 리라이트했습니다(2-1문서 D19). 기존 화면을 한 번에 전부 다시 칠하기보다, **새로 만드는 화면(Write API 붙는 화면들)부터 이 기준을 적용**하고 기존 화면은 점진적으로 맞추는 방식으로 진행했습니다 — 2-1문서의 "1인 개발 범위 안에서 현실적으로" 원칙과 동일합니다. 다만 전역 토큰 리라이트가 곧 모든 화면이 이 문서의 §3 레이아웃 원칙(엣지투엣지, 스파크라인 패널, 테이블 보더 위주 등)까지 완전히 반영했다는 뜻은 아닙니다 — 그 부분은 화면별로 점진 전환 중입니다.

## 5. 앞으로 이 문서에 추가될 것 (예고)

페이지·컴포넌트가 늘어나면서 이 문서에 채워질 항목들 — 지금은 비어 있고, 실제로 화면을 만들 때 그 화면의 패턴을 여기 추가한다:

- 폼/입력 컴포넌트 패턴(에러 상태, 유효성 검증 메시지 위치)
- 모달/드로어 사용 기준(언제 모달 vs 언제 페이지 전환)
- 빈 상태(empty state) 문구·레이아웃 톤
- 데이터 시각화(차트) 스타일 — 1-7/2-4문서의 시계열 리포트 기능이 구현되면 필요해짐
- 반응형 브레이크포인트(현재는 데스크톱 전용 가정, 태블릿 이하 고려 안 함)
