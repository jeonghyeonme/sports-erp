# 06. 예약 및 결제 (Reservation & Payment)

## 1. 개요 및 조정사항

원본 요구사항: 무/유료 프로그램 게시 후 프로그램별 예약, 모바일 결제(결제 처리방법은 원본에서도 "추후 논의"로 명시되어 있어 조정 여지가 큼).

**조정**: 실제 PG(이니시스/토스페이먼츠 등) 연동은 사업자 등록·심사가 필요해 개인 포트폴리오로는 불가능하므로 **Mock Payment(모의결제) 모듈**로 대체합니다. 단, 결제 상태 전이(대기→승인→실패/환불)와 예약 상태 연동 로직은 실제 서비스와 동일하게 완전히 구현해 "결제 도메인을 이해하고 있다"를 보여줍니다. (선택: 토스페이먼츠 테스트 API 키를 이용하면 실제 연동 흐름까지 무료로 시연 가능 — Phase 2 스트레치 목표로 제안)

## 2. 사용자 스토리

- 회원으로서, 앱에서 다니는 지점의 프로그램 목록을 보고 원하는 시간대에 예약하고 싶다.
- 회원으로서, 유료 프로그램은 예약과 동시에 결제하고 싶다.
- 회원으로서, 예약을 취소하면 결제된 금액이 환불 처리되길 원한다(정책에 따라 부분/전액).
- 지점 관리자로서, 오늘 예약 현황과 노쇼(No-show) 여부를 체크하고 싶다.

## 3. 데이터 모델

### ScheduleSlot (프로그램 회차)
| 필드 | 설명 |
|---|---|
| id, programId(FK), date, startTime, endTime, capacity, bookedCount(computed or cached) | |

### Reservation
| 필드 | 설명 |
|---|---|
| id, memberId(FK), scheduleSlotId(FK), status(신청, 확정, 취소, 완료, 노쇼) | |

### Payment
| 필드 | 설명 |
|---|---|
| id, reservationId(FK, unique), memberId, amount, method(enum: MOCK_CARD, FREE) | |
| status | enum(대기, 승인, 실패, 환불) |
| mockApprovalNo | string — 모의 승인번호(실제 결제인 것처럼 시연용) |
| approvedAt, refundedAt | |

인덱스: `ScheduleSlot(programId, date)`, `Reservation(memberId, status)`, `Reservation(scheduleSlotId)` unique 제약은 (memberId+scheduleSlotId) 조합에 걸어 중복예약 방지

## 4. 화면 목록

## 5. API 명세

| Method | Endpoint | 권한 | 설명 |
|---|---|---|---|
| GET | /api/v1/programs/:id/slots?date= | 공개(로그인 필요) | 회차별 잔여좌석 조회 |
| POST | /api/v1/reservations | Member | 예약 생성 — 먼저 `Program.status=RUNNING`인지 확인(아니면 409 `PROGRAM_NOT_RUNNING`), 그 다음 `Program.pricingType`으로 분기: `PAID_SESSION`(price=0)은 즉시 확정, `PAID_SESSION`(price>0)은 status=신청+결제 대기. `FREE_ACCESS`/`PT_PACKAGE` 대상 프로그램으로 호출 시 400(`NOT_RESERVABLE`) |
| POST | /api/v1/payments/:reservationId/mock-pay | Member | 모의결제 승인 → Reservation.status=확정 |
| PATCH | /api/v1/reservations/:id/cancel | Member(본인)/BRANCH_ADMIN | 취소 → 결제건 있으면 환불 처리 |
| GET | /api/v1/reservations?memberId=&status= | Member(본인)/BRANCH_ADMIN(지점) | 목록 |
| PATCH | /api/v1/reservations/:id/check-in | BRANCH_ADMIN | 현장 체크인(완료 처리), 미체크인 회차 종료 시 배치로 노쇼 처리 |
| GET | /api/v1/payments?branchId=&dateFrom=&dateTo= | BRANCH_ADMIN | 결제(매출) 내역 |

## 6. 비즈니스 로직 & 엣지케이스 (이 기능이 가장 까다로운 영역 — 상세 기술)

- **동시 예약(정원 초과) 방지**: `bookedCount`를 별도 캐시 필드로 두지 않고, 예약 생성 시 트랜잭션 내에서 `SELECT COUNT(*) FROM Reservation WHERE scheduleSlotId=? AND status IN ('신청','확정') FOR UPDATE` 후 `capacity`와 비교 → 초과 시 409(`SLOT_FULL`). 락으로 동시성 문제 방지(포트폴리오에서 "동시성 처리를 고려했다"를 보여줄 수 있는 포인트)
- **중복 예약 방지**: 동일 회원이 동일 회차에 이미 `신청/확정` 상태 예약이 있으면 재예약 차단
- **진행중이 아닌 프로그램**: `Program.status`가 `PREPARING`/`PAUSED`/`ENDED`인 프로그램에는 예약 자체가 불가합니다(409 `PROGRAM_NOT_RUNNING`) — 07문서 §3-2
- **자유이용형(`FREE_ACCESS`) 프로그램**: 애초에 이 API의 대상이 아닙니다. 예약이라는 개념 자체가 없고, 이용 기록은 08문서의 `FacilityCheckIn`(QR 체크인)만으로 남습니다 — `Reservation`/`Payment` 어느 쪽에도 row가 생기지 않음
- **무료 회차(`PAID_SESSION`, price=0)**: 정원 관리는 필요하지만 결제는 없는 경우 — Payment 레코드 없이 즉시 `Reservation.status=확정`
- **유료 회차(`PAID_SESSION`, price>0) 결제 흐름**: `예약 생성(status=신청, Payment.status=대기)` → `모의결제 승인 API 호출` → 성공 시 `Payment.status=승인` + `Reservation.status=확정`. 5분 내 결제 미완료 시 예약 자동 취소(배치 or TTL) — 좌석 선점 방지
- **취소/환불 정책**: 회차 시작 24시간 전 취소는 전액 환불, 24시간 이내는 환불 불가(정책값은 Program 또는 Branch 설정으로 관리 — 하드코딩 금지). 모의결제이므로 실제 환불 처리는 상태값만 변경(`Payment.status=환불`)
- **노쇼 처리**: 회차 종료 후 체크인 안 된 `확정` 예약은 배치로 `노쇼` 처리(환불 대상 아님)
- **PT세션형(`PT_PACKAGE`) 프로그램과의 관계**: 05문서의 `PTSession`으로 별도 관리하며, PT 이용은 Payment 없이 `PTSession.usedSessions` 차감으로 처리 — Reservation/Payment 트랙과 완전히 분리되고, `Program.pricingType=PT_PACKAGE`로 어느 트랙을 탈지 판별

## 7. 권한/보안 규칙

- 회원은 본인 예약만 생성/취소/조회
- BRANCH_ADMIN은 본인 지점 프로그램에 연결된 예약만 조회/체크인/취소 처리 가능
- 결제 금액은 서버에서 Program 가격을 재조회해 검증(클라이언트가 보낸 금액 신뢰 안 함) — 기본적인 결제 보안 원칙

## 8. 구현 우선순위

**Phase 1(필수)**: 회차 조회, 예약 생성/취소, 무료 프로그램 흐름, 정원 초과 방지(동시성 처리)
**Phase 2(선택, 스트레치)**: 모의결제 승인/환불 플로우, 노쇼 자동 처리 배치, 취소 정책(24시간 규정), 토스페이먼츠 테스트 연동으로 업그레이드

## 9. 테스트 체크리스트

- [ ] 정원이 1자리 남은 회차에 2명이 동시에 예약 요청 → 1명만 성공
- [ ] 동일 회원이 같은 회차 중복 예약 시도 시 차단
- [ ] 유료 예약 후 결제 미완료 상태에서 취소 시 정상 롤백
- [ ] 취소 정책 시간(24시간) 기준 환불 여부 분기 정확히 동작
- [ ] BRANCH_ADMIN이 타 지점 예약을 체크인 처리 시도 시 403
- [ ] `FREE_ACCESS`/`PT_PACKAGE` 프로그램에 예약 생성 시도 시 400(NOT_RESERVABLE)
- [ ] `PAUSED`/`ENDED` 상태 프로그램에 예약 생성 시도 시 409(PROGRAM_NOT_RUNNING)
