# 디자인 시스템

> [00_공통설계서](../architecture/system-overview.md)에서 분리된 문서입니다. 페이지가 늘어날수록 컴포넌트·화면 패턴 지시사항이 계속 쌓일 성격의 문서라, architecture/entities.md(아키텍처 전반)와 분리해 여기서 독립적으로 키웁니다. 새 화면을 만들거나 기존 화면을 이 기준으로 맞출 때 참고하세요. 이 방향을 채택한 의사결정 근거는 [09_기술결정사항 D19](../decisions/D19.md) 참고.

## 1. 왜 이 방향인가

기존 admin-web(D15, "Rounded Rectangle 기준" 토큰화)은 인디고 포인트컬러(`#4f46e5`, Tailwind/shadcn 기본값)·큰 라운드(`radius-lg/xl`)·소프트 섀도우·파스텔 4색 아이콘 칩으로 구성되어 있습니다. 이건 스타트업 랜딩페이지/SaaS 스타터 템플릿 미학에 가깝고, **"본사 관리자가 수십 개 지점을 매일 들여다보는 운영 콘솔"**이 줘야 할 신뢰감·밀도와는 맞지 않습니다. 실제 다지점 운영 관리 소프트웨어(Mindbody, Zenoti, ServiceTitan 같은 피트니스·서비스 프랜차이즈 관리 도구)를 기준으로 재정의합니다.

**방향**: 고밀도 엔터프라이즈 라이트. 무채색 기반(슬레이트 스케일) + 포인트 컬러 1개만 기능적으로 사용, 카드보다 테이블·리스트 중심, 여백보다 정보 밀도 우선.

## 2. 디자인 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-bg` | `#f8fafc` | 페이지 배경 |
| `--color-surface` | `#ffffff` | 카드/테이블/사이드바 아닌 패널 |
| `--color-surface-alt` | `#f1f5f9` | 테이블 헤더, 보조 배경 |
| `--color-border` | `#e2e8f0` | 기본 구분선 — 그림자 대신 이 보더가 요소를 구분하는 주 수단 |
| `--color-border-strong` | `#cbd5e1` | 테이블 헤더 하단, 강조 구분선 |
| `--color-text` | `#0f172a` | 본문 |
| `--color-text-muted` | `#64748b` | 보조 텍스트, 라벨 |
| `--color-sidebar-bg` | `#0f172a` | 사이드바/헤더 배경(기존 유지) |
| `--color-sidebar-text` | `#cbd5e1` / 활성 `#ffffff` | |
| `--color-primary` | `#0f766e` (teal-700) | **유일한 포인트 컬러** — 링크, 활성 탭, 주요 버튼, 포커스 링. 장식용으로 남용하지 않음(인디고 → 티얼로 교체) |
| `--color-primary-soft` | `#f0fdfa` | 선택된 행/탭 배경 정도로만 최소 사용 |

**상태(semantic) 색상**(기존 badge 색상 유지 — 이건 장식이 아니라 의미 전달이라 문제 없음): success `#dcfce7`/`#15803d`, warning `#fef9c3`/`#a16207`, danger `#fee2e2`/`#b91c1c`, neutral `#e2e8f0`/`#475569`. **아이콘 칩의 blue/violet/emerald/amber 4색(장식용, 의미 없음)은 폐기** — 아이콘은 전부 단색(`currentColor` 또는 `--color-text-muted`)으로 통일하고, 색은 상태를 표현할 때만 씁니다.

## 3. 레이아웃 원칙

- **떠 있는 카드 레이아웃 폐기**: 현재 `app-shell`이 16px 패딩 안에 사이드바·메인 영역을 각각 둥근 모서리 카드로 띄우는 구조(bento-box 스타일)인데, 이를 **엣지투엣지**로 바꿉니다 — 사이드바는 뷰포트 왼쪽에 딱 붙고, 사이드바/본문 경계는 그림자가 아니라 1px 보더.
- **KPI는 큰 숫자 카드가 아니라 추세선(sparkline) 포함 소형 패널**로(운영 실적 카드로 구현 — §5 "운영 실적 차트", D75) — 현재 `.kpi-card`(아이콘 칩 + 큰 숫자)를 "라벨 + 현재값 + 전기 대비 증감(%, 화살표) + 스파크라인"으로 교체. 숫자 하나만 던지는 카드는 "장난감 대시보드"처럼 보이는 가장 큰 원인 중 하나입니다. **단, 증감률·추세선은 실제 기간별 집계가 있을 때만 붙인다** — 현재값에서 역산한 자리값은 시연 데이터가 진짜처럼 보일수록 오해를 키워 본사 대시보드에서 뺐다(log/129). 기간 집계가 없는 카드는 현재값만 둔다.
- **테이블은 얼룩말(zebra) 줄무늬 대신 보더 위주**로, 헤더는 옅은 배경(`--color-surface-alt`) + 작은 대문자 스타일(11px, `letter-spacing`, muted 색)로 — 정렬/필터 가능한 컬럼은 헤더에 시각적으로 표시. 정렬은 `components/SortTh.tsx`(↕ / ▲ / ▼, 지금 정렬 열만 포인트 색, `scope="col"`·`aria-sort`) — 화면 전체 로드 목록은 화면에서, 서버가 쪽을 나누는 회원·자산·업무지원은 서버가(`sort`·`dir`, 바뀌면 1쪽부터, log/205), 시간순이 뜻인 결제·예약·게시판·변경 이력은 정렬 없음(D74).
- **목록 검색은 치는 대로**(0.3초 뒤, Enter는 바로) — 검색 버튼을 두지 않는다(D74). 행 높이는 기존보다 낮춰 밀도를 올립니다.
- **화면 안 순서(D73)**: 처리할 일(승인함 등, 대기가 없으면 숨김) → 지금 상태 카드 → 자주 쓰는 입력 폼 → 쌓이는 기록(이력·내역 표). 데이터가 쌓일수록 길어지는 목록 아래에 폼을 두지 않는다 — 그런 폼은 머리글 "+ …" 버튼 + 모달로(회원 등록·직원 채용·지점 등록·회차 등록).
- 타이포 스케일: 11/12/13(기본 본문)/14/16/20px로 명시적 스케일을 두고, 11~20px 사이 임의 값을 쓰지 않습니다.

## 4. 적용 범위와 우선순위

`apps/admin-web/src/styles.css`는 2026-09-18(커밋 `66d9ace`)에 이 문서의 토큰을 전역 `:root`로 리라이트했습니다(docs/decisions/D19.md). 기존 화면을 한 번에 전부 다시 칠하기보다, **새로 만드는 화면(Write API 붙는 화면들)부터 이 기준을 적용**하고 기존 화면은 점진적으로 맞추는 방식으로 진행했습니다 — decisions/의 "1인 개발 범위 안에서 현실적으로" 원칙과 동일합니다. 다만 전역 토큰 리라이트가 곧 모든 화면이 이 문서의 §3 레이아웃 원칙(엣지투엣지, 스파크라인 패널, 테이블 보더 위주 등)까지 완전히 반영했다는 뜻은 아닙니다 — 그 부분은 화면별로 점진 전환 중입니다.

## 5. 알림 — Toast와 인라인 (2026-10-08, B5-3)

admin-web의 쓰기 결과를 알리는 규칙이다(사용자 결정, log/087). 부품은 `components/ToastProvider.tsx`, 훅은 `lib/use-toast.ts`의 `useToast()`.

| 상황 | 방식 | 예 |
|---|---|---|
| 쓰기 성공 | `toast.success` — 3초 뒤 자동으로 닫힘 | "회원을 등록했습니다", "'아침 요가' 상태를 바꿨습니다" |
| 쓰기 오류 | **인라인**(`forbidden-note`) — 문제가 난 폼·영역 바로 옆. 무엇을 고쳐야 하는지 그 자리에서 보이게 한다 | 등록 모달 안의 409 문구 |
| 인라인으로 보일 자리가 없는 쓰기 오류 | `toast.error` — 6초 | 목록 행의 작은 버튼(예약 취소·체크인, 강사 재활성화) |
| 사용자가 직접 행동해야 하는 정보 | `toast.warning` — **닫을 때까지 남는다** | 프로그램 휴강·종료 시 영향 예약 안내(ADR-PRG-02) |
| 조회 실패·빈 상태 | 인라인(`forbidden-note`·`empty-state`) | — |

- 위치는 화면 오른쪽 아래, 최근 3개까지 쌓는다. 실제로 위에 뜨는 요소라 최소 그림자를 쓴다(§2). 색은 상태 의미만 쓴다(왼쪽 4px 띠: success·danger·warning).
- `window.alert`·`window.confirm`은 쓰지 않는다. 확인이 필요한 동작은 `components/ConfirmModal.tsx`(제목 + 무엇이 일어나는지 + 취소·실행 버튼, 되돌릴 수 없으면 실행 버튼을 `btn-danger-outline`) — D74, 남아 있던 3곳 교체(log/202).
- 모든 모달(`components/Modal.tsx`)은 `role="dialog"`·제목 연결, 열리면 첫 입력 칸으로 초점, Esc로 닫고 연 버튼으로 초점을 돌려준다(D74).
- 문구는 "~했습니다" 완료형, 대상 이름을 넣는다. 오류 문구는 서버 `error.message`(공통 에러 포맷)를 쓰고, 아는 코드면 둘째 줄에 `해결: …`이 붙는다(아래 "화면별 도움말").
- member-web은 이 부품을 쓰지 않는다 — 모바일 화면은 화면 안 안내(`notice`)로 결과를 보인다(log/083).

### 화면별 도움말 (2026-10-09, log/089)

- 상단 바 오른쪽 "? 도움말" 버튼 → 본문 오른쪽에 붙는 패널(폭 320px, 배경 막 없음, Esc로 닫기). 900px 이하에서는 본문 위에 겹친다.
- 패널 내용은 `lib/help-content.ts`의 경로별 항목: 요약 한 줄 → "이 화면에서 하는 일"(공통 + 내 역할 단계, 번호 목록) → "자주 나는 오류"(코드 + 해결).
- 해결 문구는 `lib/error-hints.ts` 한 곳에만 쓴다. 오류 문구 아래 줄과 패널이 같은 표를 쓴다. 새 api 오류 코드를 만들면 이 표에 한 줄을 더한다.
- 새 화면을 만들면 `help-content.ts`에 그 경로를 더한다. 단계 문구는 버튼 이름을 따옴표로 그대로 쓰고, 그 역할에 안 보이는 버튼은 쓰지 않는다.

### 경로 표시 (2026-10-14, D51·log/112)

- RFP UI/UX "페이지 위치 정보를 MAP형태로 표시"의 해석. 관리자 웹 모든 화면의 본문 맨 위에 `홈 › 메뉴 그룹 › 화면 › 상세`를 보인다(`components/Breadcrumb.tsx`, `AppLayout`이 넣는다).
- 경로는 주소와 역할별 사이드바 메뉴에서만 만든다 — 화면마다 따로 넘기지 않는다. 마지막 칸(지금 화면)은 굵게, 앞 칸은 누르면 그 화면으로 간다. 그룹 이름은 링크가 아니다.
- 목록 아래 상세 화면 이름은 `Breadcrumb.tsx`의 `DETAIL_LABEL`에 더한다. 대상 이름(회원 이름 등)은 화면 제목이 보여 주므로 경로에 넣지 않는다. 상세 화면의 "← 목록으로" 링크는 경로 표시로 대신해 없앴다.

### 상단 바 회원 빠른 찾기 (2026-11-08, D72·log/200)

- 관리자 웹 상단 바 가운데 검색창(`components/MemberQuickSearch.tsx`) — 본사·지점 관리자 중 회원 조회 권한이 있는 사람에게만. 2자 이상, 0.3초 뒤 최대 5건, 고르면 회원 상세.
- 결과 줄은 이름(굵게) + 회원번호·가린 전화(본사는 지점, 휴면·탈퇴는 상태)를 muted 12px로. 펼침은 실제로 위에 뜨는 요소라 최소 그림자(§2). 선택 줄은 `--color-primary-soft`.
- 키보드 ↑↓·Enter·Esc, `role="combobox"`/`listbox`/`option`. 6건 이상이면 맨 아래 "회원 목록에서 모두 보기"(회원 화면 `?q=`).
- 상세 화면의 탭처럼 다시 열 때 같은 곳을 보여야 하는 상태는 주소 쿼리에 둔다(회원 상세 `?tab=`).

### 운영 실적 차트 (2026-11-08, D75·log/208)

- 직접 그린 SVG(`components/charts/`) — 월별 세로 막대(`MonthlyColumnChart`), 큰 것부터 가로 막대(`RankedBarChart`), 숫자 카드 추세선(`Sparkline`), 지표 묶음(`PerformanceCharts`·`PerformanceStatTiles`). 라이브러리 없음.
- 지표마다 차트 한 장(단일 계열 — 단위가 다른 값을 한 축에 겹치지 않는다, 범례 없음, 제목이 지표 이름). 막대는 ≤24px, 데이터 끝 4px 둥글게·기준선 쪽 직각, 격자는 1px 회색 실선, 축 글자 11px muted.
- 색: 표시는 `--chart-accent`(teal-600) 하나, 진행 중인 이번 달은 `--chart-accent-soft` + "진행 중" 글자, 추세선 `--chart-muted`(마지막 점만 강조색). 글자에 차트 색을 쓰지 않는다. 브랜드 `--color-primary`는 차트 채도 검사 미달이라 차트에 쓰지 않는다(dataviz 검사 스크립트).
- 숫자 카드: 지난달(끝난 달) 값 + 전달 대비(▲▼ 기호 + 초록·빨강, 색만으로 말하지 않는다) + 12개월 추세선. 원은 1만 이상이면 "1,266만원"(전체 값은 마우스를 올리면).
- 막대마다 마우스·키보드(Tab) 대상 칸(막대보다 넓다)과 툴팁(값 굵게 → 달), 차트 아래 "표로 보기". 막대 위 숫자는 두지 않는다(옆 막대와 겹친다). 2열, 900px 이하 1열.

### 회원 웹 앱 셸 (2026-10-10, D45·log/094)

회원 웹(`apps/member-web`)은 같은 색 토큰을 쓰되, 모바일 앱 인상을 위해 아래만 다르게 둔다.

- 탭 화면의 큰 제목 24px·800(관리자 웹 스케일 밖 — 앱의 large title). 하위 화면은 앱 바에 뒤로 가기와 16px 제목.
- 카드 모서리 14px(`--radius-card`), 하단 시트 20px + 손잡이. 앱 바·탭 바는 반투명 흰색 + 블러.
- 하단 탭은 24px 선 아이콘 + 11px 라벨, 활성 탭은 아이콘 뒤 연한 알약(`--color-primary-soft`).
- 움직임: 화면 전환 0.24s 떠오르기, 시트 0.28s 슬라이드 업, 눌림 0.97 축소. `prefers-reduced-motion`이면 끈다.
- 불러오는 중에는 글자 대신 스켈레톤(회색 상자)을 보인다.

## 6. 앞으로 이 문서에 추가될 것 (예고)
