# D77. 회원 앱 형태 재검토 결론 — 지금의 모바일 웹(PWA)을 유지하고 네이티브·하이브리드 앱은 만들지 않는다 (2026-11-09)

> 결정 기록 [인덱스](README.md) · 경위는 [log/218](../log/2026-W46.md#218) · [D67](D67.md) 3-③(회원 앱 형태 재검토)의 결론, [D40](D40.md) 결정 2·[D41](D41.md)·[D45](D45.md)를 유지한다

**컨텍스트**: D67이 이후 방향의 세 번째 갈래로 "PWA(D45)의 접근성 한계로 하이브리드·네이티브 앱을 비교(D40 재검토)"를 남겼고, 10주차 발표의 다음 할 일에도 있었다. 지금 회원 기능(가입·오프라인 회원 연동, 프로그램·회차 보기, 예약·모의 결제·취소, 공지, 혼잡도, 내 정보)은 회원 모바일 웹(`apps/member-web`, `/m/`)이 홈 화면 설치(PWA)까지 제공한다. 실운영은 하지 않는다(D67).

**검토한 대안**
- (a) **네이티브 앱**(React Native/Expo — D13의 원래 계획): 화면을 따로 다시 만들어야 하고 코드가 둘이 된다(웹과 앱), 스토어 계정·심사·버전별 배포가 생긴다. 지금 기능 가운데 휴대폰 고유 기능(푸시·카메라·생체 인증)이 필요한 것은 없어서, 만들어도 같은 화면을 앱 껍데기에 다시 담는 수준이다.
- (b) **하이브리드**(지금 회원 웹을 앱으로 감싸기): 화면은 재사용하지만 스토어 배포·빌드 경로가 따로 생긴다. 얻는 것은 스토어 노출 정도다.
- (c) **지금 모바일 웹(PWA) 유지(채택)**: 같은 스택·같은 Worker(D40·D41), 배포 한 번으로 관리자 웹과 함께 반영된다.

**결정**: (c). 사용자 판단(2026-11-09) — 유지보수 부담이 크고, 네이티브로 만들어도 지금으로선 구색을 갖추는 것에 그친다. 지금 형태로 회원 기능이 충분히 동작한다.

**결과**: 좋아진 것 — 코드·배포 경로가 하나로 유지되고 새 인프라가 없다. 감수하는 것 — 앱스토어에 노출되지 않는다, 푸시 알림·QR 체크인처럼 휴대폰 기능에 기대는 기능은 만들 수 없다(둘 다 이미 범위 제외 — 게시판·혼잡도관리 A-8).

**재고 트리거**: 푸시 알림·QR 체크인처럼 휴대폰 기능이 필요한 기능을 범위에 넣을 때, 또는 실운영을 다시 검토해(D67) 설치·접근의 불편이 이용률 문제로 측정될 때.
