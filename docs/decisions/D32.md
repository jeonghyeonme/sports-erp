# D32. D29 4단계 — 회원·예약·결제·수강·PT를 DB로 옮기고, 미러 없이 끝낸다. 인증의 mock 폴백도 여기서 없앤다

> 결정 기록 [인덱스](README.md) · 원래 2-1 기술결정사항 문서의 한 절이었다(2026-10-01 분해).

**컨텍스트(Driver)**: D29 순서의 마지막 참조 단계다. 회원·회원 계정·수강·PT(+사용 기록)·예약·결제가 대상이다. D30·D31과 다른 점이 셋 있다. ① 이 데이터를 동기적으로 읽는 **아직 mock인 도메인이 없다.** 근태·게시판·자산·문서는 회원·예약·결제를 읽지 않는다. 지점 건수와 프로그램의 예약 집계만 읽는데, 둘 다 이미 DB로 옮긴 모듈 안에 있다. ② 이 단계가 끝나면 **모든 계정이 DB에 있다.** D26이 만든 인증의 "Prisma 먼저, 없으면 mock" 이중 경로가 존재할 이유가 사라진다. ③ 예약 생성에서 mock의 단일 스레드 가정이 끝난다. 정원 검사(ADR-RSV-01)가 처음으로 진짜 동시성 아래에 놓인다.

**결정 1 — 미러를 두지 않는다**: D30·D31 미러는 "아직 mock인 독자"를 위한 것이었다. 여기엔 그런 독자가 없다. 미러를 두면 쓰는 사람 없는 복사본만 늘어난다. mock의 해당 배열·메서드를 지우고, 지점 건수(`branchCounts`)와 프로그램의 예약 집계(`bookedCount`·`futureActiveReservationsForProgram`)는 DB 조회로 바꾼다. 대안은 "테스트가 읽으니 미러를 남기자"였다. 테스트를 위해 운영 코드에 복사본을 두는 것은 거꾸로라서 기각했다. 테스트는 Prisma로 읽게 바꾼다. **같은 이유로 D31의 시설·강사·프로그램·회차 미러도 없앤다.** 그 미러의 독자는 예약·회원·지점 건수·프로그램 현황판이었는데, 전부 이번에 DB 조회로 바뀌어 읽는 코드가 남지 않는다. 남는 미러는 D30 직원 미러뿐이다. 근태·문서·게시판이 아직 mock이기 때문이다.

**결정 2 — 인증 mock 폴백 제거(D26 과도기 종료)**: 회원 계정까지 DB로 오면 mock 계정은 하나도 남지 않는다. `AuthService`의 login·refresh·logout·changePassword와 `JwtStrategy`에서 mock 경로를 지운다. 회원가입·연동 직후 로그인(`issueSession`)도 DB 계정으로 발급한다. 이메일 유일성 검사도 D30 결정 4의 "양쪽 저장소 보기"에서 DB 부분 unique(ADR-MEM-02) 하나로 합쳐진다. 다만 채용·가입·연동 모두 앱이 먼저 409를 내고, 경합은 P2002를 409로 바꿔 받는다. mock의 `accounts`에는 D30 미러(직원·관리자 계정)만 남는다. 게시판·문서가 작성자 이름을 읽는 용도다.

**결정 3 — 예약 생성은 D28 헬퍼로 직렬화한다(ADR-RSV-01·02)**: 트랜잭션 안에서 `lockScheduleSlot`으로 회차 행을 잠근 뒤 활성 예약을 센다. 중복 예약은 앱 검사 + 부분 unique 인덱스 이중화(ADR-RSV-02)다. 인덱스 위반(P2002)은 `ALREADY_RESERVED` 409로 바꾼다. 결제(PENDING)는 같은 트랜잭션에서 만든다. 검사 순서(회차 없음 → 프로그램 → 예약 불가 → 진행중 아님 → 회원 지점 불일치 → 계약 종료 → 중복 → 정원)는 mock 그대로 둔다. 에러 코드 우선순위가 테스트로 고정돼 있기 때문이다.

**결정 4 — 채번과 연동 실패 제한은 D27·D28이 마련한 자리로**: 회원번호는 `allocateBranchCode(MEMBER)`로 뽑는다. mock은 "같은 prefix 회원 수 + 1"(동시 등록 시 중복)이고 연도를 호스트 시간대로 구했는데, 이제 KST 연도로 바뀐다. 연동 실패 제한(ADR-MEM-01, 시간당 5회)은 mock의 프로세스 메모리 `Map`에서 `MemberLinkAttempt` 테이블로 옮긴다. 인스턴스가 여럿이거나 재시작돼도 제한이 유지된다. Lambda 전제(D26)에서는 메모리 제한이 사실상 무력했다.

**결정 5 — 옮기면서 드러난 시간대 결함 두 건은 고친다(date-time-handling.md 규칙)**: ① 취소 환불 마감 판정이 회차 시작을 `new Date("YYYY-MM-DDTHH:mm:00")`(호스트 시간대)로 만들었다. 서버가 UTC면 KST 회차 시각이 9시간 늦게 해석돼, 마감이 지난 취소도 환불됐다. 회차 날짜·시각은 KST이므로 `+09:00`을 붙인다. ② 결제 목록의 날짜 필터가 `approvedAt.slice(0,10)`(UTC 날짜)로 비교했다. KST 날짜(`toKstDateString`)로 바꾼다. 둘 다 이 프로젝트가 이미 정한 규칙(CLAUDE.md "날짜 계산") 위반이라 별도 결정 없이 고친다.

**데이터**: 히어로 회원 3명(이수진·오영희·한지민)과 생성 회원, 이수진 계정·수강 1건·PT 1건(사용 기록 3건)을 `member-fixtures.ts` 한 곳에서 만든다. seed.ts가 로컬에만 만들던 예약·결제 데모 행과 그 회차는 mock에 없던 데이터라 지운다(D29 이후 "시드와 mock은 같은 원천" 원칙). MEMBER 채번값은 시드한 회원번호의 prefix별 최댓값으로 맞춘다.

**감수하는 것**: 게시판·문서의 작성자 이름은 여전히 D30 미러(직원·관리자 계정)에서 읽는다. 회원이 작성자인 게시글·문서가 생기면 이름이 비어 보인다. 현재 API는 회원 작성을 허용하지 않으므로 해당 없음을 확인하고 넘어간다.
