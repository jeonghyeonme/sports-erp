# D57. 첨부 파일 저장소는 Supabase Storage — api는 서명 URL만 발급하고 파일은 브라우저가 직접 올리고 받는다 (2026-10-17)

> 결정 기록 [인덱스](README.md) · 경위는 [log/121](../log/121.md) · RFP 1-1 #4 게시판 "교육자료 첨부"(D51 M10). 게시판 쪽 결정은 게시판 ADR-BRD-04

**컨텍스트(Driver)**: `Attachment` 테이블만 있고 업로드 인프라가 없었다(게시판 A-8 범위 제외 — 사용자가 2026-10-17 구현 승인). api는 Lambda라 요청 본문이 6MB로 막히고, 실행 시간·메모리를 파일 전송에 쓰면 상한 10(D37·D50)을 더 빨리 채운다.

**상위 목표(D53)**: 노하우 습득 — 서버리스에서 파일을 다루는 표준(서명 URL)을 익힌다. **핵심 변수**: Lambda 본문 한도 6MB, 무료 용량, 업로드가 인증·지점 격리를 거치는가. **답안지**: "서버가 짧게 유효한 업로드 URL 발급 → 브라우저가 저장소로 직접 업로드"(S3 presigned URL, Supabase signed upload URL).

## 결정 (사용자 선택 2026-10-17, 사용자 설명: 없음 — 추천안 선택)

1. **저장소는 Supabase Storage**, 비공개 버킷 `attachments`(이름은 `SUPABASE_STORAGE_BUCKET`으로 바꿀 수 있다). api가 권한·지점 검사 뒤 1회용 업로드 URL과 60초 다운로드 URL을 발급하고, 파일 바이트는 api를 거치지 않는다.
2. **비밀값**: `SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`는 Lambda 환경변수에만 둔다(브라우저·Worker에 두지 않는다). `set-lambda-env.sh`가 `aws-lambda/.env`에 있으면 넣는다. 배포 환경에 값이 없으면 첨부만 503 `STORAGE_NOT_CONFIGURED`이고 앱은 뜬다.
3. **한도**: 파일당 10MB, 글당 5개, pdf·png·jpg·webp·docx·xlsx·pptx·hwp. api가 업로드 전(신고값)과 붙이기 때(저장소의 실제 크기·형식) **두 번** 본다. 버킷에도 같은 한도(파일 크기·MIME)를 걸어 서명 URL로 큰 파일을 올리는 것을 저장소가 막게 한다.
4. **로컬·테스트**는 메모리 드라이버 — 배포 환경이 아니고 Supabase 값이 없으면 자동. 업로드·다운로드는 api의 `/dev-storage/*`(토큰이 권한, 배포에서는 404).

## 대안 → 트레이드오프

| 대안 | 얻는 것 | 비용·위험 | 판단 |
|---|---|---|---|
| **Supabase Storage + 서명 URL(선택)** | 이미 쓰는 서비스, api가 권한을 쥔 채 Lambda 한도와 무관 | 무료 1GB(10MB면 약 100개), service role 키 관리 | 선택 |
| Cloudflare R2 + Worker 경유 | 무료 10GB, 전송료 없음 | Worker에서 인증·격리를 다시 보거나 api와 왕복, 버킷·바인딩 설정 | 기각(용량이 문제가 되면 재고) |
| URL만 붙이기(현행 유지) | 작업 없음 | RFP "첨부"를 못 채움, 외부 링크 관리는 현장 몫 | 기각 |

**재고 트리거**: 저장소 사용량이 700MB를 넘을 때(→ R2 또는 유료), 고아 파일(올리고 붙이지 않은 것·삭제된 글의 파일)이 늘어 정리가 필요할 때, 다른 도메인(문서함·업무지원 요청)에 첨부를 넓힐 때.
