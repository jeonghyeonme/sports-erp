# D38. 문서 구조를 "누가, 언제 읽나" 기준으로 재편한다 — 로딩 계층 + ID 인용 + 기계 검사 (2026-10-01)

> 결정 기록 [인덱스](README.md) · 경위는 [log/053](../log/053.md)

**컨텍스트(Driver)**: 이 프로젝트는 대화로 구현을 맡기는 방식이라 **문서가 곧 에이전트의 작업 환경(하네스)**이다. 2026-09-22에 시작한 문서 이전(옛 `1.spec/`·`2.decisions/` → `domains/`·`architecture/`·`process/`)이 내용 옮기기 단계에서 멈춰 있었고, 그 사이 세 가지가 반복 비용이 됐다.
- **방향 잡기 비용**: 현재 상태가 진행 로그(약 52k 토큰) 끝에, 결정 경위가 2-1 기술결정사항(약 56k 토큰) 한 파일에 묻혀 있었다. 세션마다 둘 중 일부를 찾아 읽어야 했다.
- **상주 비용**: 매 턴 들어가는 CLAUDE.md(약 7.7k 토큰)의 절반이 D26~D37 변경 이력과 테스트 현황 나열이었다.
- **탐색·기록 비용**: 코드 주석 약 220줄이 사라진 옛 번호(`06문서 §5`)나 옛 파일명을 인용했다. 기록하려면 긴 파일을 열어야 했고(Edit은 먼저 읽어야 한다) 같은 사실을 여러 문서에 갱신해야 했다. 끊긴 링크·옛 이름을 잡는 기계 신호가 없어 이전 작업이 멈춘 것 자체를 아무도 몰랐다.

옛 설계서를 지우려고 대조해 보니 "전체 병합 완료" 표시와 달리 §6(비즈니스 로직·엣지케이스)과 §9(테스트 체크리스트)가 도메인 문서에 없었다 — 코드 주석이 가장 많이 인용하던 절이다.

## 결정

1. **로딩 계층**: T0 루트 `CLAUDE.md`(불변식·라우팅만, 130줄 상한) · T1 `apps/*/CLAUDE.md`(그 폴더를 다룰 때만 로드) · T2 `docs/STATUS.md`(덮어쓰기, 80줄 상한)와 도메인 문서 맨 위 요약 카드(40줄 상한) · T3 보관(도메인 본문·부록, `decisions/D<번호>.md`, `log/NNN.md`).
2. **한 건에 파일 하나**: 2-1을 `decisions/D1~D37.md`로, 진행 로그를 `log/001~052.md`로 나누고 각 README를 인덱스로 둔다. 새 기록은 새 파일 + 인덱스 한 줄이라 기존 파일을 읽지 않는다.
3. **위치가 아니라 ID로 인용**: 도메인 문서 부록 번호를 옛 설계서 절 번호에 맞췄다(A-3 데이터 모델 … A-9 테스트). 그래서 `06문서 §6` → `예약및결제 A-6`으로 기계적으로 바꿀 수 있었다. 병합 때 빠진 §6·§9 등은 원문 그대로 부록 A-6·A-9로 옮긴 뒤 옛 설계서를 삭제했다(원문은 git `4633b13`).
4. **기계 검사**: `scripts/doc-check.mjs`가 끊긴 링크, 없는 경로 언급, 옛 문서 이름, 정의되지 않은 ADR, 진입 문서 크기 상한, 인덱스 누락을 검사한다. 커밋 전 hook(문서 변경 시)과 CI `docs` 잡이 실행한다.
5. **기록 절차 고정**: `.claude/skills/wrap-up/`이 마무리 순서를 정한다(STATUS 덮어쓰기 → 로그 한 건 → 필요 시 ADR·D·카드 → doc-check).
6. 폴더 번호(`1.`~`5.`)를 없앴다: `design/`·`presentation/`·`deliverables/`(파일명 `4-x`·`5-x`는 유지), 원본·분석 자료는 `reference/`(요구사항추적표·차별화전략·기업 구조 분석·RFP PDF), 1-1 공통설계서는 `architecture/entities.md`(§2 공유 엔티티)와 `architecture/system-overview.md`(나머지)로 나눴다.

## 대안 → 트레이드오프

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 링크만 고치고 옛 문서 삭제(05 추적표의 원래 계획) | 작업량 최소 | 상주·방향 잡기·기록 비용이 그대로이고 로그·2-1은 계속 커진다. 미병합 절이 사라진다 | 기각 |
| B. 옛 설계서를 `domains/` 옆에 원문 보관 | 정보 손실 0, 매핑 단순 | 같은 내용이 두 벌(부록 A와 옛 원문)이라 어느 쪽이 맞는지 다시 판단해야 하고 grep 잡음이 남는다 | 기각 |
| C. 진행 로그를 월별 파일로 분할 | 파일 수가 적다 | 로그 52건이 모두 9월이라 줄어드는 게 없다 | 기각 |
| **D. 계층 + 한 건 한 파일 + 부록 번호 정렬 + 기계 검사(채택)** | 진입 비용이 프로젝트가 커져도 거의 일정, 인용이 경로 변경에 강함, 다시 썩으면 CI가 잡음 | 파일 수가 많다(로그 52·결정 38). 부록에 옮긴 옛 원문 일부는 현재 상태와 다를 수 있다(머리말에 "ADR·A-8이 우선" 명시) | 채택 |
