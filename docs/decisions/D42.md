# D42. Lambda k6 실측 결과로 D37 설정을 확정한다 — 동시 실행 상한 10·메모리 1,024MB 유지, 처리 여유는 늘리지 않는다 (2026-10-07)

> 결정 기록 [인덱스](README.md) · 측정 경위는 [log/056](../log/056.md), 이 기록의 경위는 [log/080](../log/080.md) · [D37](D37.md) §4(검증 기준)의 측정 결과를 남기고, D37 §1의 처리 한계 가정(200 rps)을 실측값으로 대체한다

**컨텍스트(Driver)**:
- D37 §4는 측정 전에 쓴 검증 기준이고, §6 "감수하는 것"에서 "상한 10과 1,024MB는 §4 측정 결과로 다시 조정한다"고 남겼다.
- 2026-10-04에 k6로 S1~S4를 쟀다([log/056](../log/056.md)). 결과는 log에만 있고 결정 기록에는 없었다.
- STATUS "사용자 승인 대기"에 "처리 여유 확대" 선택지(계정 동시 실행 한도 상향 / 요청당 쿼리 수 줄이기 / 50 rps로 충분하다고 보고 기록만)가 남아 있었다.

## 1. 측정 결과 (2026-10-04, 사용자 PC → Function URL 직접, 서울, 실측)

| 시나리오 | 기준(D37 §4) | 실측 | 판정 |
|---|---|---|---|
| S1 로그인 0→40 VU(1초 간격) | p95 < 500ms, 에러 0 | p95 237ms, 에러 1(정점에서 상한 10 도달로 거절) | **에러 기준 미달** — 지연 기준은 통과 |
| S2 혼합 조회 50 rps × 5분 | p95 < 300ms, 거절 0 | p95 178ms, 거절 0, 실패 0 | 통과(동시 실행 9~10, 상한에 붙음) |
| S3 과부하 300 rps × 1분 | 거절 p95 < 100ms, 성공 p95 < 500ms | 거절 p95 13ms(약 1.38만 건), 성공 p95 182ms, 실패 0 | 통과 |
| S4 콜드 스타트 | Init < 1.5초 | Init Duration 1,063ms(첫 배포 직후, 30분 유휴 조건은 아님) | 통과로 갈음 |

- **S1은 기준을 바꾸지 않고 "미달"로 남긴다.** 거절 1건은 결정 1이 설계한 fail-fast(상한 초과 시 입구에서 거절)가 동작한 것이지만, 기준 "에러 0"을 사후에 재정의하지 않는다(사용자 결정, 2026-10-07).
- 측정 대상이 D37 §4의 "Worker 주소"가 아니라 Function URL이다. Worker 로그인 rate limit(IP당 60초 10회)이 S1을 막고 Workers 무료 일일 한도를 쓰기 때문이다. Worker 경유 지연은 이 표에 없다.

## 2. 가정 대비 차이

| 항목 | D37 가정 | 실측 | 차이 |
|---|---|---|---|
| 요청당 Lambda 처리 시간 W(일반) | 50ms(추정 25~50ms) | p50 약 110ms · p95 약 165ms | **약 2.2배** |
| 상한 10의 처리 한계(10 ÷ W) | 200 rps | 약 50~55 rps(S3에서 성공 분당 약 3,100건) | 약 1/4 |
| 로그인 p95 | 기준 500ms | 237ms | 기준 안 |
| 콜드 스타트 | 목표 1.5초 | 1,063ms | 목표 안 |

- W가 긴 원인은 "Lambda↔풀러 왕복 × 요청당 쿼리 4~8개"(D37 R5)로 **추정할 뿐 확인하지 않았다.**
- 필요한 처리량과 비교하면(design-constants ⑪·⑫, 수도권 83곳 + 회원 모바일 웹, D40): 순간 몰림 상한 약 8 rps, 3년 후 몰림 약 10.6 rps, 민감도(방문당 30건) 몰림 약 24 rps. **최악 가정에서도 실측 한계의 약 절반이다.**

## 3. 결정

1. **동시 실행 상한 10을 유지한다.** 계정 동시 실행 한도(10)가 곧 상한이다(log/055). 상향 요청은 하지 않는다 — 상한을 올리면 DB 커넥션(풀러 약 15)과 비용 차단(D37 결정 1)이 약해지는데, 위 비교상 얻을 것이 없다.
2. **메모리 1,024MB를 유지한다.** D37 §4의 상향 조건("S1·S3에서 로그인 기준을 못 맞추면 1,769MB")은 지연 기준이고, 로그인 p95 237ms로 충족했다. S1의 에러 1건은 메모리가 아니라 동시 실행 상한에서 생겼다.
3. **처리 여유 확대(STATUS 승인 대기)는 "기록만"으로 닫는다**(사용자 결정, 2026-10-07). 요청당 쿼리 수 줄이기(D37 R5)도 지금은 하지 않는다.
4. 설계 계산에는 W = 110ms(p50), 처리 한계 약 50 rps를 쓴다(design-constants ⑫에 이미 반영됨).

## 재고 트리거

- 회원 모바일 웹(B1) 배포 후 방문당 실제 호출 수(design-constants ⑩)를 쟀더니 몰림 도착률이 약 25 rps(한계의 절반)를 넘을 때 → B 먼저, 그다음 A.
- 운영 CloudWatch에서 Throttles가 반복될 때(경보 있음, D37 R10).
- 지점이 늘어(⑥) Workers 유료 전환(⑬)을 할 때 함께 다시 본다.
