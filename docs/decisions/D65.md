# D65. 미뤘던 메이저 업그레이드 — NestJS 11(Express 5)·react-router 7로 운영 의존성 취약점 0건, Express 5의 req.query 변화는 설정 한 곳에서 막는다 (2026-10-22)

> 결정 기록 [인덱스](README.md) · 경위는 [log/166](../log/166.md) · D63 결정 4(미룸)를 대체한다

**컨텍스트(Driver)**: D63이 도달 불가로 판정해 미룬 운영 의존성 취약점 2건(NestJS 10 SSE 주입 GHSA-36xv-jgw5-4q75, react-router 6 경로 이동 GHSA-wrjc-x8rr-h8h6·GHSA-337j-9hxr-rhxg — security-plan S10). 사용자가 2026-10-22 "할 수 있는 작업 전부, 승인 필요한 것도 승인"을 지시해 메이저 업그레이드를 했다.

**상위 목표(D53)**: 노하우 습득 — 메이저 업그레이드에서 "컴파일되면 끝"이 아니라 런타임 의미가 바뀐 곳을 테스트로 찾는 경험. **핵심 변수**: 지점 격리처럼 조용히 깨지는 불변식, Lambda 묶음 구성. **답안지**: 공식 마이그레이션 노트(Express 5 `req.query` getter·쿼리 파서 기본값 변경, path-to-regexp 문법) + 전체 테스트·배포 경로 재현.

## 결정

1. **react-router-dom 6 → 7.18.4**(두 웹). `<BrowserRouter>`·`<Routes>`만 쓰고 데이터 라우터·사용자 경로 이동이 없어 코드 변경 없음.
2. **NestJS 10 → 11.2.7**(common·core·platform-express·testing, jwt 11·passport 11·config 4·cli 11·schematics 11, @types/express 5). 12가 나와 있지만 고친 판(11.1.18+)이 있는 가장 작은 메이저로 간다.
3. **Express 5 대응은 `configureApp` 한 곳**: 쿼리 파서를 Express 4와 같은 `extended`로, 요청마다 `req.query`를 쓸 수 있는 보통 속성으로 고정한다. Express 5의 `req.query`는 읽을 때마다 새로 만드는 getter라 `BranchScopeGuard`가 넣는 `branchId`(D46)가 사라져 **지점 관리자에게 남의 지점 목록이 보였다** — `branch-isolation`·`list-pagination`·`contract-termination` 등 16건이 기대값 변경 없이 잡았다. 가드 설계(주입 방식)는 그대로 둔다.
4. **D63의 Nest 10용 overrides 4개(body-parser·qs·multer·file-type) 제거** — Express 5가 그 다음 메이저를 쓰므로 고정하면 오히려 깨진다. 제거 뒤 운영 audit 0건.
5. **Lambda 묶음**: npm이 api 의존성을 `apps/api/node_modules`에 두면(이번 NestJS·express, log/158의 bcrypt) 루트만 복사하던 묶음에서 빠진다 — `package-lambda.sh`가 워크스페이스 쪽을 루트 위에 덮어 api의 해석 순서와 같게 한다(잠금 파일을 손으로 옮기던 log/158 방식을 대체).
6. `@nestjs/jwt` 11의 `expiresIn` 타입(기간 문자열)에 맞춰 환경변수 값을 그 타입으로 넘긴다(동작 같음).

**결과(실측)**: 운영 의존성 취약점 4 → **0**(react-router 2줄·NestJS 2줄). 라이선스 점검 통과(운영 의존성 204개). api jest 52개 파일 551건, 화면 자동 테스트 11건, `dist/lambda.handler`를 Function URL 이벤트로 직접 호출(health 200·로그인·지점 격리 403·정수 상한 400·비밀 헤더 없음 403).

**감수하는 것**: Express 5의 나머지 차이(경로 문법 — 지금 와일드카드·선택 구간 라우트 없음, 오류 처리 세부)는 테스트가 닿는 범위까지만 확인됐다. 실제 Lambda 부팅은 병합 뒤 배포 health check로 본다.

**재고 트리거**: NestJS 12가 필요해질 때(Node 지원·새 권고), 라우트에 와일드카드를 쓸 때(Express 5 문법 `*splat`), `req.query`를 다른 곳에서 고쳐 쓰는 코드를 넣을 때.
