# D73. 화면 안 순서 — 할 일(처리 대기·입력)이 먼저, 쌓이는 기록은 뒤. 쌓이는 목록 아래에 있던 등록 폼은 헤더 버튼 + 모달로 (2026-11-08)

> 결정 기록 [인덱스](README.md) · 경위는 [log/201](../log/2026-W45.md#201) · 기준선은 [log/198](../log/2026-W45.md#198)

**컨텍스트**: 작업 단계 측정(log/198)에서 단계 수는 짧은데 스크롤이 드는 작업이 있었다 — 회차 등록(예약 관리 맨 아래, 스크롤 2~3), 직원의 업무일지·휴가 신청(이번 달 근태 기록 표 아래), 지점 관리자의 휴가 승인(근태관리 맨 아래). 공통 원인은 **데이터가 쌓일수록 길어지는 목록이 폼·처리 칸 위에 있다**는 것이다(시연 데이터에서 스크롤이 더 늘었다). D67 ① 사용감 확보, 후보 ③.

**검토한 대안**
- 화면 안 탭(예: 근태관리를 "오늘 · 휴가 · 업무일지 · 기록"으로) — 스크롤은 없어지지만 작업마다 탭 누름이 1번 늘고, 한눈에 보던 화면이 쪼개진다.
- 처리 대기함 링크에 위치 표시(`#휴가승인함`)로 스크롤 — 승인 한 가지만 고쳐지고 직원 폼은 그대로다.
- **순서 바꾸기 + 목록 아래 폼만 모달로(채택)** — 누름은 거의 늘지 않고, 규칙 하나로 다른 화면에도 쓸 수 있다.

**결정**
1. **화면 안 순서**: ① 처리할 일(승인함 등) → ② 지금 상태(오늘의 근태 같은 카드) → ③ 자주 쓰는 입력 폼 → ④ 쌓이는 기록(이력·내역 표). 쌓이는 목록 아래에 폼을 두지 않는다.
2. **근태관리**: 지점 관리자의 휴가 승인함을 맨 위로(결근 확정·지점 근태 요약은 맨 아래 — 결근 확정은 여전히 승인함 다음 순서). 업무일지·휴가 신청 폼을 카드 두 장으로 나란히 두고, 내 업무일지·내 휴가 신청 내역·이번 달 근태 기록은 그 아래로.
3. **예약 관리**: 회차 등록 폼을 머리글의 "+ 회차 등록" 버튼 + 모달로(회원 등록·직원 채용·지점 등록과 같은 모양). 프로그램별 회차 목록은 아래 "회차 목록" 절에 남긴다. 버튼은 회차 등록 권한(`program` CREATE, 지점 관리자)이 있을 때만.

**결과**: 좋아진 것 — 데이터가 쌓여도 폼·처리 칸의 위치가 변하지 않는다. 감수하는 것 — 회차 등록은 모달을 여는 누름이 1번 는다(6 → 7, 스크롤 2~3 → 0). 기록을 먼저 보던 사람은 조금 더 내려야 한다.

**재고 트리거**: 기록 조회가 입력보다 잦은 화면이 생길 때, 한 화면에 폼이 셋 이상이 될 때(그때는 탭을 다시 본다).
