# D76. RFP 충족률 분모에서 해당 없음을 뺀다, 검수·도입(T3-2)·업무위탁 DPA(N8-2)는 해당 없음으로 (2026-11-09)

> 결정 기록 [인덱스](README.md) · 경위는 [log/211](../log/2026-W46.md#211) · 원천은 [요구사항추적표](../reference/요구사항추적표.md) §3

**컨텍스트**: 2026-10-25(log/182)부터 충족률 분모는 조항 수 전부였다 — "해당 없음을 빼면 부풀려 보인다"는 이유. 그 결과 발주기관·계약·대면 행위처럼 이 프로젝트가 할 수 없는 조항이 미충족처럼 숫자를 끌어내렸다(58/72 = 81%). 최종 발표 전에 사용자가 판정 목록(조정 6·부분 3·미구현 3)을 다시 봤다. 실운영은 하지 않는다(D67).

**검토한 대안**
- (a) 지금대로 조항 수 전부 — 할 수 없는 조항이 점수를 깎아 무엇을 못 했는지가 오히려 흐려진다.
- (b) **해당 없음만 분모에서 뺀다(채택)** — 부풀림 우려는 집계 표에 해당 없음 건수를 그대로 두고 발표에서 "해당 없음 N개 제외"를 함께 밝혀 막는다. 미구현(의도적 제외)은 분모에 남긴다 — 하지 않기로 한 것이지 할 수 없는 것이 아니다.
- (c) 미구현까지 뺀다 — 기대효과·유사기업 분석을 숨기게 돼 기각.

**결정**
1. 충족률 = (구현 + 조정) / (조항 수 − 해당 없음). 집계 표의 해당 없음 열은 그대로 보인다. log/182의 "어떤 판정도 분모에서 빼지 않는다"를 대체한다.
2. **T3-2(개발 → 테스트 → 검수 → 도입 → 기대효과 분석) → 해당 없음**: 남은 검수·도입은 발주기관이 있어야 하는 절차다(N1-1·N1-2와 같은 이유). 기대효과 분석은 P2-2(미구현, 의도적 제외)가 따로 세므로 옮겨도 가려지지 않는다.
3. **N8-2(개인정보보호법 제26조 업무위탁) → 해당 없음**: 남은 DPA 서명·보관·감독 기록은 실제 개인정보를 맡기는 실운영이 전제다(D67). 위탁 고지·수탁자 표·절차 문서(security-plan §7, log/165)는 근거로 남긴다.
4. N7-3(PG 연계 확인)은 **부분 유지** — 테스트 키 실제 호출은 계약·실운영 없이 할 수 있는 일이다.

**결과**: 구현 52 · 조정 6 · 부분 1 · 미구현 3 · 해당 없음 10. 충족률 58/62 = **94%**(기능·성능 28/28 = 100%, 시스템~제약 17/18 = 94%, 과업·산출물 13/16 = 81%). 산출물 생성기(요구사항 정의서·RFP 이행 증빙·제안서)의 분모 계산과 문구를 같이 바꿨다 — 산출물 파일은 재생성 때(STATUS) 반영된다.

**재고 트리거**: 실운영을 다시 검토하면(D67) N8-2·T3-2를 부분으로 되돌린다.
