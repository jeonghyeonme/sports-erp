# D79. 진행 로그는 주 단위 파일로, 대체됐거나 끝난 결정은 `archive.md` 한 파일로 (2026-11-12)

> 결정 기록 [인덱스](README.md) · 경위는 [log/225](../log/2026-W46.md#225) · [D38](D38.md)의 "로그 한 건에 파일 하나" 규칙을 대체한다(로딩 계층·ID 인용·기계 검사는 유지)

**컨텍스트**: D38 이후 로그가 한 건 한 파일로 223개(약 5,700줄), 결정이 79개 쌓였다. 폴더를 열면 파일이 너무 많아 "어느 주에 무슨 일이 있었나"를 훑기 어렵고, 결정 가운데 다른 결정이 이미 대체했거나(D1→D60, D48→D49 등) 끝난 일회성 단계(실DB 전환 D26·D29~D35 등)가 지금 유효한 규칙과 섞여 있었다. 사용자 요청(2026-11-12): "레거시 너무 쌓인 것들은 정리하고, 결정·로그는 주 단위로 묶으면 좋을 듯".

**검토한 대안**
- 로그: (a) **주 단위 파일**(채택) — 9개 파일, 한 파일 80~2,000줄. (b) 월 단위 — 4개지만 10월 파일이 138건(약 3,500줄)으로 커진다. (c) 그대로.
- 결정: (a) **유효/지난 결정 분리**(채택) — 코드 주석 약 780곳이 `D37`처럼 번호로 가리키고, 유효한 결정은 "D37 찾기"가 파일 하나로 바로 닿는 편이 낫다. (b) 주 단위로 묶기 — 번호로 찾을 때 인덱스를 한 번 더 거친다. (c) 주제별 — 분류 판단이 들어가고 경계가 흐리다.

**결정**
1. 로그 = ISO 주 파일 `docs/log/YYYY-Www.md`. 기록마다 `<a id="NNN"></a>` + `## NNN. 제목 (날짜)`. **번호는 그대로 ID**다 — 코드 주석 `log/051`은 손대지 않고, 링크는 `log/2026-W40.md#051`로 고쳤다(스크립트, 원문 내용은 바꾸지 않음). 새 기록은 그 주 파일 끝에 붙인다.
2. 끝난 과정 문서(트러블슈팅 기록, 문서 마이그레이션 추적표)도 날짜의 주 파일에 번호 없는 앵커(`#troubleshooting`·`#migration-tracking`)로 넣고 `log/archive/`를 없앴다.
3. 결정 = 지금 유효한 것은 한 파일씩 그대로. **다른 결정이 대체했거나 끝난 일회성 결정 17개**(D1·D6·D14·D15·D21·D22·D23·D26·D29~D35·D48·D63)는 `docs/decisions/archive.md`에 원문 그대로, 번호 앵커와 "무엇이 대체했나" 한 줄을 붙여 모았다. 인덱스는 "지난 결정" 표로 나눴다. 앞으로 결정이 대체되면 그 결정을 archive.md로 옮긴다.
4. 기계 검사(doc-check): 로그 주 파일·기록 번호가 인덱스에 있는가, `docs/log/051`·`#051` 인용이 실제 기록을 가리키는가, `archive.md#Dn` 앵커가 있는가, 한 건 파일(`log/NNN.md`)을 다시 만들지 않았는가.

**결과**: `docs/log/` 226 파일 → 10(주 9 + 인덱스), `docs/decisions/` 79 → 63(유효 62 + archive). 내용 삭제 없음(기록 223건 + 번호 없는 2건 앵커 수로 확인).

**다시 볼 때**: 한 주 파일이 너무 커져(약 2,000줄 이상) 찾기 어려우면 그 주만 나눈다. 프로젝트 완료 뒤에는 전체를 한 번 더 묶을지 본다.
