# D82. RFP 충족률 분모에서 의도적 제외(미구현 3)도 뺀다, PG 연계 확인(N7-3)은 문서 확인으로 조정 — 59/59 = 100% (2026-11-23)

> 결정 기록 [인덱스](README.md) · 경위는 [log/248](../log/2026-W48.md#248) · 원천은 [요구사항추적표](../reference/요구사항추적표.md) §3 · [D76](D76.md)의 결정 1(분모 규칙)·4(N7-3 부분 유지)를 대체한다

**컨텍스트**: D76(2026-11-09)으로 충족률은 (구현 + 조정) / (조항 − 해당 없음) = 58/62 = 94%였다. 남은 미충족 4개는 부분 N7-3(PG 테스트 키 실제 호출 전)과 의도적 제외 3개(T2-1 유사 기업 시스템 분석·P2-2 도입 기대효과 분석·P2-3 유사기업 매뉴얼 분석 — 근거 자료가 없어 하지 않기로 함)다. 13주차 발표를 앞두고 사용자가 "부분은 완료로, 나머지 3개는 제외로 처리해 100%를 채우자"고 했다(2026-11-23). 실운영은 하지 않는다(D67).

**검토한 대안**
- (a) 지금대로(94%) — D76이 (c)로 기각한 이유("미구현까지 빼면 기대효과·유사기업 분석을 숨긴다")를 지킨다.
- (b) **사용자 요청대로 100% — 단, 이름은 사실대로(채택)**: 의도적 제외 3개는 판정 "미구현(의도적 제외)"을 그대로 두고 분모에서만 뺀다. N7-3은 "구현"이 아니라 **조정**으로 — 테스트 키 실제 호출은 하지 않았고, "연계 가능 여부 확인"을 문서 조사(pg-integration-check, log/165)와 결제 어댑터 설계(ADR-RSV-03)로 바꿔 냈다는 뜻이다(조정 = 결과는 냈고 방식을 바꿨으며 근거 결정이 있다).
- (c) N7-3을 "구현"으로 — 실제 호출을 안 했는데 "그대로 했다"고 적게 돼 사실과 다르다. 기각.
- (d) N7-3 테스트 키를 실제로 호출해 구현으로 — 가능하지만 PG사 가입·키 발급이 필요하고 사용자가 원하지 않았다.

**결정**
1. 충족률 = (구현 + 조정) / (조항 수 − 해당 없음 − 미구현(의도적 제외)). 집계 표의 미구현·해당 없음 열은 건수를 그대로 보인다. 발표·산출물에서 100%를 말할 때는 **"해당 없음 10·의도적 제외 3을 분모에서 뺐다"를 함께 적는다**(4-0 §3 — 미구현·한계는 숨기지 않는다).
2. N7-3 부분 → **조정**: 근거 = pg-integration-check(연계 가능 여부 문서 확인)·ADR-RSV-03(결제 어댑터)·D67(실운영 제외로 실제 호출 생략).
3. 결과: 구현 52 · 조정 7 · 부분 0 · 미구현 3(의도적 제외) · 해당 없음 10 → 59/59 = **100%**(영역별 기능·성능 28/28, 시스템~제약 18/18, 과업·산출물 13/13).

**결과**: 좋아진 것 — 할 수 없거나 하지 않기로 한 것과 한 것이 숫자에서 갈린다 / 감수하는 것 — "100%"만 떼어 보면 RFP 전부를 했다고 오해할 수 있다(옛 방식으로는 59/72 = 82%). 그래서 분모 설명을 숫자 옆에 늘 붙인다. 산출물(요구사항 정의서·RFP 이행 증빙·제안서·아키텍처 설계서)의 충족률 문구는 다시 만들 때 바뀐다.

**재고 트리거**: 기대효과·유사기업 분석 자료가 생기면 미구현을 분모로 되돌리고 채운다. PG 테스트 키를 실제로 호출하면 N7-3을 구현으로.
