# D45. 회원 웹을 PWA로 — 설치·앱 셸, 화면 파일만 캐시, `/m/assets/`와 `/m/sw.js`만 공개 파일로 둔다

> 결정 기록 [인덱스](README.md) · 경위는 [log/094](../log/094.md) · [D40](D40.md)(네이티브 앱 없음)·[D41](D41.md)(회원 웹 `/m/`) 위에 얹는다. D41 결정 2의 "`public/` 파일을 두지 않는다"를 이 결정이 좁힌다.

**상태**: 결정·구현(2026-10-10).

## 컨텍스트

- 회원 웹은 React+Vite 웹이다(D40은 네이티브 앱을 만들지 않기로 했다). 사용자가 "너무 웹 느낌"이라고 평가했고, 앱 설치가 간단한 PWA를 원했다.
- PWA는 앱 정보 파일(manifest)·아이콘·service worker가 필요하다. service worker는 범위(`/m/`)의 맨 위 `/m/sw.js`에 있어야 한다.
- D41은 `/m/` 아래 파일이 요청마다 Worker를 거쳐 무료 한도(하루 10만, design-constants ⑬)를 쓴다는 이유로 `public/` 파일을 금지했다. `/m/`와 `/m/assets/*`만 자산 계층이 바로 준다.

## 결정

1. **파일 위치**: manifest·아이콘은 `public/assets/` 아래에 둔다 → 빌드 후 `/m/assets/...`라 원래 Worker를 거치지 않는다. service worker만 `public/sw.js`(→ `/m/sw.js`)에 두고, Worker `run_worker_first`에 `!/m/sw.js`를 더해 자산 계층이 바로 주게 한다. **그 밖의 `public/` 파일은 여전히 두지 않는다.**
2. **캐시 범위(사용자 결정: "앱 화면은 뜨고 연결 없음 안내")**
   - 화면 파일만 캐시한다. `/api/*`는 캐시하지 않는다. 예약 정원·결제 상태·혼잡도가 오래된 값으로 보이면 안 된다.
   - 화면 진입은 네트워크를 먼저 쓰고, 실패하면 저장한 `/m/` 셸을 준다. 해시가 붙은 `/m/assets/*`는 캐시를 먼저 쓴다.
3. **오프라인 세션**: 세션 복원 요청이 네트워크 오류로 실패하면 저장된 refresh token을 지우지 않는다. "연결 없음" 화면을 보이고, 다시 연결되면 자동으로 재시도한다. 서버가 거절(401)했을 때만 지운다.
4. **설치 안내**: 홈 카드로 안내하고, 이미 앱으로 열었거나 사용자가 닫으면 보이지 않는다.
   - 안드로이드는 `beforeinstallprompt`로 버튼 한 번에 설치한다.
   - 아이폰은 설치 API가 없어 "공유 → 홈 화면에 추가"를 하단 시트로 안내한다.
5. **아이콘**: 운동 심볼(덤벨, 사용자 결정)을 SVG로 그리고, 192·512·maskable 512·apple 180·favicon 48 PNG로 뽑아 저장소에 둔다.

## 대안

- **vite-plugin-pwa**: 해시 자산까지 미리 캐시(precache)해 준다. 하지만 의존성이 늘고 산출물 이름·위치를 플러그인이 정한다. `/m/` 바로 아래 파일을 피해야 하는 제약 아래에서는 손으로 쓴 작은 service worker가 다루기 쉽다.
- **API 응답도 캐시(마지막 데이터 표시)**: 사용자가 고르지 않았다. 오래된 예약·결제 상태가 보이는 위험이 있다.
- **네이티브 래퍼(Capacitor 등)**: D40 범위 밖이다. 스토어 심사·빌드 파이프라인이 생긴다.

## 결과

- 좋아지는 것: 앱처럼 설치하고 실행할 수 있다(전체 화면·스플래시·아이콘). 화면 파일이 캐시되어 두 번째 실행부터 빠르다. 오프라인으로 열어도 로그인이 유지된다.
- 감수하는 것
  - 첫 방문 뒤 캐시가 쌓인다. 옛 해시 자산은 지우지 않지만, 캐시 이름(`CACHE`)을 올리면 한꺼번에 비운다.
  - 셸(`index.html`)은 네트워크 우선이라, 배포 직후 첫 실행부터 새 화면을 받는다.
  - `/m/sw.js`는 브라우저가 업데이트 확인으로 자주 부르지만, 자산 계층 요청이라 Worker 한도를 쓰지 않는다.
- 검증 범위: service worker 등록·오프라인 셸·manifest는 Playwright(Chromium)로 확인했다. 실제 아이폰·안드로이드에서의 설치는 사용자 확인이 필요하다.

**재고 트리거**: 오프라인에서도 일부 데이터(내 예약 등)를 보여 달라는 요구가 생길 때 → 읽기 전용 캐시를 화면별로 검토한다. `/m/` 바로 아래에 다른 파일이 필요해질 때 → Worker 예외를 더하거나 `/m/assets/`로 옮긴다.
