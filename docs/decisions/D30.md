# D30. D29 2단계 — 직원·파견·관리자 계정을 DB로 옮기고, mock에는 DB에서 채우는 미러를 둔다

> 결정 기록 [인덱스](README.md) · 원래 2-1 기술결정사항 문서의 한 절이었다(2026-10-01 분해).

**컨텍스트(Driver)**: 지점(D29)은 쓰기 API가 없어 "mock과 DB를 같은 목록에서 만들고 일치 테스트로 확인"하면 충분했다. 직원은 다르다. ① 채용·수정·퇴사·파견·권한 전환 **쓰기가 있고**, 생성 직원의 입사일은 실행 시각 기준 상대값이라 같은 생성기를 써도 mock과 DB가 날마다 달라진다. ② 아직 mock인 근태·휴가·업무일지·문서·회원(담당 직원)·작성자 이름·지점 건수가 **직원·계정을 동기적으로 읽는다.** ③ 생성 직원 192명은 mock에서 계정 id만 있고 계정 레코드가 없다. DB에서는 `Staff.accountId`가 필수 FK다. 강남 관리자 계정도 mock에만 있다.

**결정 1 — 원천은 DB, mock에는 "DB에서 채우는 미러"**:
| 대안 | 장점 | 한계 |
|---|---|---|
| A. 지점처럼 같은 생성기 + 일치 테스트 | 단순 | 쓰기가 생기는 순간 어긋나고, 날짜가 실행 시각 기준이라 일치 자체가 성립하지 않는다 |
| **B. 앱이 뜰 때 DB에서 mock 미러를 채우고, 직원 쓰기는 DB 커밋 뒤 미러에도 반영 (채택)** | mock 독자(근태 등)는 코드 변경 없이 DB와 같은 값을 본다. 원천은 DB 하나다 | 인스턴스가 여러 개면(Lambda) 다른 인스턴스의 미러는 낡는다. 다만 mock 전체가 원래 다중 인스턴스를 못 버티므로 새로 생기는 한계는 아니다. 근태 등이 옮겨지면 미러도 사라진다 |
| C. mock 독자를 전부 비동기로 바꿔 DB에서 직접 읽기 | 미러 불필요 | 근태·문서·회원 등 아직 옮기지 않은 도메인까지 한꺼번에 고치게 돼 단계가 무의미해진다 |

미러 범위: `Staff` 전체, `StaffAssignment` 전체, 관리자·직원 계정(역할 SUPER_ADMIN·BRANCH_ADMIN·STAFF). 회원 계정은 회원 도메인이 옮겨질 때까지 mock이 그대로 가진다.

**결정 2 — 쓰기는 DB 트랜잭션, 이미 정한 규칙을 그대로 코드로**:
- 퇴사: 직원 상태·퇴사일 + 계정 비활성화 + 진행 중 파견 종료를 한 트랜잭션으로 묶는다(ADR-STF-01).
- 파견: 옛 파견 종료 + 새 파견 + DB 회원 담당 해제 + 강사 연결 해제 + `Staff.branchId` 갱신을 이 순서로 한 트랜잭션에 넣는다(ADR-STF-04, D28 트리거가 순서를 강제).
- 채용: 계정 + 직원 + 최초 파견을 한 트랜잭션으로 만들고, 직원번호는 `allocateBranchCode`로 채번한다(ADR-STF-02). 이메일 중복은 부분 unique 위반(P2002)을 409로 바꿔 알린다.
- 권한 전환: `Account.role`을 바꾼다. JWT 전략이 매 요청 DB를 다시 읽으므로 재로그인 없이 바로 반영된다(ADR-AUTH-01). **D26에서 skip한 테스트 3건이 여기서 다시 살아난다.**

**결정 3 — 아직 mock인 도메인에 대한 부수효과는 DB 커밋 뒤 mock에 적용한다**: 파견의 mock 회원 담당 해제(ADR-STF-04)와 퇴사의 mock 인사서류 보존기한 재계산(ADR-RES-02)이 여기에 해당한다. 두 저장소를 한 트랜잭션으로 묶을 수 없어 원자적이지 않다. DB가 성공한 뒤 mock에서 실패할 경로는 없지만(메모리 갱신), 해당 도메인이 옮겨지면 같은 트랜잭션 안으로 들어간다.

**결정 4 — 계정이 두 저장소로 나뉜 동안 이메일 유일성은 양쪽을 본다**: 직원 계정은 DB, 회원 계정은 mock에 있다. 다만 미러(결정 1)가 직원·관리자 계정을 mock `accounts`에도 넣으므로, 회원 등록·연동이 쓰는 mock의 `isEmailTakenByActiveAccount`는 코드 변경 없이 DB 직원 이메일까지 본다. 채용은 반대 방향으로, DB 트랜잭션 전에 같은 mock 검사로 회원 계정 이메일을 먼저 확인하고(→ 409 `EMAIL_ALREADY_EXISTS`), DB 부분 unique 위반(P2002)도 409로 바꾼다. 두 검사 사이의 경합은 막지 못하지만, 회원 도메인이 옮겨지면 DB 부분 unique 하나로 합쳐진다.

**데이터 신설**: 생성 직원 192명에 계정을 만든다(이메일 `gen-001-1@staff.spoism.example` 형식, 역할 STAFF, 데모 비밀번호). mock에는 계정 레코드 자체가 없었으므로 새 데모 데이터다.
