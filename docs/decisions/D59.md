# D59. 화면 자동 테스트 — Playwright, 빌드 결과를 운영 구조로 띄워 역할별 핵심 경로, CI 전용 (2026-10-20)

> 결정 기록 [인덱스](README.md) · 경위는 [log/140](../log/140.md)

**컨텍스트(Driver)**: 관리자 웹·회원 웹은 자동 테스트가 0건이라 검증이 lint·빌드(타입체크)뿐이었다. 화면 결함은 모두 수동 점검으로만 찾았다 — 화면 점검 14건(log/125~130), UTC "오늘" 버그(log/127·128), 공지 첨부 미표시(log/132). 사용자가 "프로젝트 완성도"의 첫 순서로 화면 자동 테스트를 골랐다(2026-10-20).

**상위 목표(D53)**: 노하우 습득 — 실무 E2E 테스트의 표준 구성(브라우저 자동화·테스트 전용 DB·CI 잡)을 직접 만들어 본다. **핵심 변수**: 화면을 고칠 때 역할별로 매일 쓰는 경로가 깨지는 것을 사람이 보기 전에 잡는가. **답안지**: 테스트 피라미드(아래 넓은 단위·통합, 위 좁은 E2E) — 규칙은 이미 jest 통합 테스트가 보므로 E2E는 화면이 그 API를 제대로 부르는지만 얇게.

## 결정 (사용자 결정 2026-10-20 — 사용자 설명: 없음, 세부 구성은 세션이 정함)

1. **도구는 Playwright**(`@playwright/test` 1.56.1 — 세션 컨테이너에 미리 깔린 브라우저와 같은 판). 루트 워크스페이스 `e2e/`.
2. **운영과 같은 구조로 띄운다** — 개발 서버가 아니라 빌드 결과(`build:web`)를 `e2e/serve.mjs`가 Worker와 같은 규칙(같은 오리진, `/api` 프록시, `/m/*`는 회원 웹 index, 그 밖 SPA 폴백)으로 준다. api도 빌드한 `dist`(메모리 첨부 저장소). 시각은 서울 기준.
3. **테스트 전용 DB `sports_erp_e2e`** — 실행마다 `reset-db.mjs`가 마이그레이션을 다시 적용하고 기준 시드(5곳, D58)를 넣는다. 이름이 다른 DB는 지우지 않는다(안전장치). jest 기준 DB와 분리.
4. **범위는 역할별 핵심 경로 7건** — 본사(대시보드 → 지점 운영 실적 → 변경 이력), 지점 관리자(회원 등록·검색·마스킹, 회차 등록 → 주간 시간표, 공지 작성·이미지 첨부), 직원+지점 관리자(체크인 → 병가 신청 → 승인 → 병가 사용 일수), 회원(회차 예약 → 결제 → 취소·환불, 공지 첨부 이미지). 규칙의 경계값·권한 거부는 jest가 보고 E2E에서 반복하지 않는다. 화면 앞 준비 데이터(회원용 회차·공지)는 api로 만든다.
5. **CI에서만 돈다**(`e2e` 잡, 실패 시 리포트·trace 업로드). 커밋 전 hook에는 넣지 않는다 — 빌드 두 번과 브라우저 실행이라 1분이 넘고 브라우저 설치가 필요하다. 직렬 실행(workers 1, 같은 DB), 재시도 0(불안정은 원인을 고친다).

## 대안 → 트레이드오프

| 대안 | 얻는 것 | 비용·위험 | 판단 |
|---|---|---|---|
| **빌드 결과 + 운영 구조 서버(선택)** | 운영과 같은 번들·같은 오리진(상대 경로 `/api/v1`, `/m/` 폴백)을 본다 | 실행 전 빌드 필요, Worker 규칙을 `serve.mjs`에 한 번 더 적는다 | 선택 |
| vite 개발 서버 두 개 | 빌드 없이 빠르게 | 관리자 웹은 개발 모드에서 api 주소가 달라(.env.development) 운영과 다른 경로를 본다 | 기각 |
| wrangler dev(실제 Worker) | Worker 코드까지 | Worker secret·rate limit 설정이 필요하고 느리다 | 기각(재고 트리거) |
| 커밋 hook에도 넣기 | push 전에 잡는다 | 커밋마다 1분+·브라우저 필요 | 기각 |
| 화면마다 테스트(넓게) | 더 많이 잡는다 | 문구·배치 변경마다 깨져 유지비가 크다 | 기각 — 핵심 경로만, 늘릴 때는 실제로 깨졌던 곳부터 |

**결과**: 로컬 7건 약 19초(서버 기동 포함 약 45초), 두 번 연속 통과. 회원 웹 첨부 표시를 일부러 끄면 `member-notice`가 실패하는 것을 확인했다. 첫 작성 중 실제로 드러난 것: 테스트끼리 회차가 겹치면 회원 웹 날짜 띠가 가장 가까운 날을 먼저 고른다 — 테스트가 날짜를 직접 고르게 했다(화면 동작은 의도대로).

**재고 트리거**: Worker 코드(rate limit·`/m/` 폴백)를 바꿀 때 — `serve.mjs`와 어긋나면 wrangler dev 방식을 다시 본다. E2E가 3분을 넘거나 같은 테스트가 원인 없이 두 번 이상 깨질 때.
