# D81. 계약 갱신용 영업 리포트 — 지점 하나의 계약·운영 성과·서비스 품질을 인쇄용 한 장으로, 기존 기록에서 계산만 (2026-11-16)

> 결정 기록 [인덱스](README.md) · 경위는 [log/229](../log/2026-W47.md#229) · [차별화전략](../reference/차별화전략.md) §2(영업지원 리포트)를 "계약 갱신용"으로 좁혀 구현, [D75](D75.md)(운영 실적 집계·차트)를 재사용

**컨텍스트**: 사업 구조의 순환(운영 데이터 → 계약 판단)에서 마지막 고리가 비어 있었다. 지점 상세에 계약 회차(D69)와 12개월 운영 실적 차트(D75)는 있지만, 본사가 위탁계약 갱신 협상(계약 지속·조항 변경)에 들고 갈 근거를 한 장으로 모은 것은 없었다. 11주차 발표의 "다음 할 일" 첫째(사용자, 2026-11-16: "계약 갱신용 영업 리포트 — 지점별 기록으로 한 시각화를 재활용해 본사와 지점 간 계약 지속·조항 변경을 할 수 있게").

**검토한 대안**
- 형태: (a) **지점 상세에서 여는 인쇄용 리포트 화면**(채택 — 브라우저 인쇄로 PDF), (b) 서버·화면에서 Word/PDF 파일 생성(문서 라이브러리가 더 붙는다), (c) 지점 상세 안의 섹션(인쇄·배포용 모양이 아님).
- 조항 변경 제안 메모: 저장(새 테이블·스키마 변경 승인) / 인쇄에만 / **넣지 않음**(채택 — 리포트는 데이터만, 제안은 따로 문서로).

**결정**
1. `GET /branches/:branchId/renewal-report` — **본사 전용**(지점 관리자는 자기 지점도 403, 갱신 협상은 본사 업무). 읽기만, 스키마 변경 없음.
2. 내용(사용자 선택): ① 계약 개요·회차 이력(현재 회차·남은 기간·운영 기간·갱신 횟수, 회차 표), ② 운영 성과(D75와 같은 13개월 집계 — 지난 12개월 합계, 최근 6개월의 직전 6개월 대비, 전사 지난 12개월 합계 ÷ 지점 수 대비, 이용 완료율, 월별 차트 4장), ③ 서비스 품질·운영 안정성(회원 상태, 진행 중 프로그램·종목, 운영 중 시설·최근 90일 평균 혼잡도, 지난 12개월 업무지원 요청 처리·평균 처리 기간, 파견 인력 지금·전입·전출).
3. 화면: 지점 상세 "계약 정보"의 "갱신 리포트" → `/branches/:branchId/renewal-report`. "인쇄 · PDF 저장"은 브라우저 인쇄 — 인쇄 CSS가 메뉴·상단 바·버튼·도움말을 빼고, 차트는 두 열·viewBox로 인쇄 폭에 맞춘다(시연 데이터 마포점 A4 한 장).
4. "평균 대비"는 지점 규모 차이를 보정하지 않는다 — 도움말에 "추세와 함께 본다"고 적는다.

**결과**: 운영 데이터 → 계약 판단의 고리가 화면 하나로 닫혔다. 리포트의 숫자는 원천과 같은지 테스트로 본다(운영 실적 API와 같은 월별 값, DB 회차·회원·프로그램·시설·파견 수, 업무지원 처리 반영).

**다시 볼 때**: 조항 변경 제안을 시스템에 남겨야 할 때(새 테이블), 지점 규모 보정(회원 수당 지표)이 협상에 필요할 때, 계약서 조항 자체를 데이터로 다뤄야 할 때.
