# D75. 운영 실적 시각화 — 직접 그린 SVG 차트, 지표마다 한 장(단일 계열), 진행 중인 이번 달은 따로 표시 (2026-11-08)

> 결정 기록 [인덱스](README.md) · 경위는 [log/208](../log/2026-W45.md#208) · 조사는 [log/197](../log/2026-W45.md#197) A-5

**컨텍스트**: 대시보드 숫자 카드는 현재값만 있고(가짜 추세선은 log/129에서 뺐다), 지점 상세 운영 실적은 3개월 표뿐이었다. 사업 구조의 "운영 데이터 → 계약 판단"(CLAUDE.md)을 화면에서 읽으려면 기간 추이가 보여야 한다. 디자인시스템 §3·§6이 예고한 "추세선 있는 KPI 패널·차트 스타일"이 비어 있었다. D67 ① 사용감.

**사용자 선택(2026-11-08)**: 범위 = 본사 대시보드·지점 상세·지점 관리자 대시보드 모두 / 도구 = 직접 그린 SVG(라이브러리 없음) / 영업 리포트(차별화전략 §2)는 이번엔 빼고 차트만.

**검토한 대안(도구)**: Recharts — 툴팁·반응형이 기본이지만 번들 수백 KB·의존성·라이선스 목록(N10) 갱신. **직접 그리기(채택)** — 막대·선 두 가지만 필요하고 디자인 토큰을 그대로 쓴다. 대신 축·툴팁을 직접 만든다.

**결정**
1. **데이터**: 기존 지점 월별 실적(`branchPerformance` — 순매출·환불·예약·이용 완료·신규 회원)을 최대 13개월(지난 12개월 + 이번 달)로 늘린다(`?months=`, 1~13, 기본 3은 그대로). 전사 합계 `GET /branches/performance`(본사 전용) = 같은 지표의 모든 지점 합 + 지난달 지점별 순매출. 지표 정의는 바꾸지 않는다.
2. **모양**: 지표마다 차트 한 장(단일 계열 — 단위가 달라 한 축에 겹치지 않는다, 범례 없음). 월 추이는 세로 막대(≤24px, 위 4px 둥근 끝, 바닥은 직각), 지점 비교는 가로 막대(큰 것부터). 값 라벨은 마지막 달·막대 끝에만, 나머지는 축·툴팁·표.
3. **이번 달**: 진행 중이라 같은 색의 옅은 단계 + "진행 중" 표시. 숫자 카드는 **지난달(끝난 달)** 값과 그 전달 대비 증감, 12개월 추세선(회색, 마지막 점만 강조) — 진행 중인 달을 끝난 달과 비교하지 않는다.
4. **색**: 차트 표시는 `--chart-accent`(teal-600 `#0d9488`) 한 가지 — 브랜드 `--color-primary`(teal-700)는 채도가 낮아 차트 검사(채도 하한)를 통과하지 못했다(dataviz 검사 스크립트). 진행 중은 `--chart-accent-soft`, 추세선은 회색 `--chart-muted`. 글자는 색을 입히지 않는다(텍스트 토큰). 관리자 웹에는 어두운 화면이 없어 밝은 화면만 검사했다.
5. **읽기 보조**: 막대마다 마우스·키보드 초점에 툴팁(달·값), 모든 차트에 "표로 보기"(같은 값의 표).

**결과**: 좋아진 것 — 갱신 판단 근거(지점 실적 1년)가 한눈에, 대시보드 숫자에 방향이 생긴다. 감수하는 것 — 차트 부품을 직접 유지한다, 전사 집계는 지점 수만큼 커지는 쿼리 4개(지점별과 같은 GROUP BY, D48 왕복 수 유지).

**재고 트리거**: 계열이 둘 이상 겹치는 차트가 필요해질 때(범주 색 팔레트 검사 필요), 차트 종류가 세 가지를 넘을 때(라이브러리 재검토), 영업 리포트를 만들 때.
