# D72. 회원 찾기 줄이기 — 관리자 웹 상단 바 회원 빠른 찾기 + 회원 상세 탭을 주소에, 진행 중 PT가 있으면 PT 탭 먼저 (2026-11-08)

> 결정 기록 [인덱스](README.md) · 경위는 [log/199](../log/2026-W45.md#199)(대안 비교)·[log/200](../log/2026-W45.md#200)(구현·전후 측정)

**컨텍스트**: 작업 단계 측정(log/198)에서 회원을 다루는 작업이 모두 "회원 메뉴 → 검색어 → 검색 버튼 → 행" 4단계를 앞에 달고 있었다. PT 수업마다 하는 세션 차감(B04)은 6단계 중 5단계가 회원 찾기와 탭 바꾸기다. D67 ① 사용감 확보의 첫 적용.

**검토한 대안**(표는 log/199): A 회원 목록 입력 즉시 검색(4→3), B 상단 바 빠른 찾기(4→2), C 상세 탭 주소화·PT 먼저(PT 차감 −1), D 빠른 찾기 결과에서 바로 세션 사용(PT 차감 6→2, API 변경·잘못 누르기 위험).

**결정**(사용자, 2026-11-08): **B + C**.
1. **상단 바 회원 빠른 찾기** — 관리자 웹 모든 화면의 상단 바 검색창. 2자 이상 치면 0.3초 뒤 `GET /members?q=&limit=5`(이름·회원번호·전화 부분 일치)로 최대 5건을 보이고, 고르면 회원 상세로 간다. 새 API 없음 — 지점 격리(D46)·전화 마스킹(ADR-MEM-04)·권한(D60 `member` READ)은 목록 API가 그대로 본다. 회원 조회 권한이 없는 역할·사람(직원 등)에게는 검색창을 그리지 않는다. 키보드: ↑↓ 이동, Enter 열기(고른 것이 없으면 첫 결과), Esc 닫기. 결과 6건 이상이면 "회원 목록에서 모두 보기"로 회원 메뉴(같은 검색어)로 간다.
2. **회원 상세 탭을 주소에** — `/members/:id?tab=enrollments|pt|payments`. 주소에 탭이 없으면 진행 중 PT(`ptRemainingTotal` > 0)가 있을 때 PT 잔여세션 탭, 없으면 수강내역 탭을 연다. 탭을 바꾸면 주소를 바꾼다(뒤로 가기 기록은 쌓지 않음 — replace).

**결과**: 좋아진 것 — 회원 상세까지 어디서든 2단계, PT 세션 차감 6→3(전후는 log/200). 목록 화면을 거치지 않아 쪽 넘김·필터 상태를 잃지 않는다. 감수하는 것 — 글자를 칠 때마다(0.3초 지연·2자 이상) 목록 API 호출이 늘어난다(방문당 호출 수 가정 D40에 더해짐 — 무료 한도 위험은 STATUS 열린 위험). PT가 있는 회원의 수강내역을 보려는 사람은 탭을 한 번 더 누른다.

**재고 트리거**: 빠른 찾기 호출이 Workers 일일 한도에 의미 있게 잡힐 때(지연을 늘리거나 Enter 검색으로), 직원에게 회원 조회를 열 때, 회원 외 대상(직원·자산)도 빠른 찾기가 필요해질 때(전역 검색으로 확장 검토), PT 차감을 더 줄여야 할 때(대안 D).
