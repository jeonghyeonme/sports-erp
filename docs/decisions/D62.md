# D62. 게시글 본문을 서식 있는 HTML로 — 별도 작성·수정 화면 + 허용 목록 정화 두 겹 (2026-10-22)

> 결정 기록 [인덱스](README.md) · 경위는 [log/154](../log/154.md) · 게시판 도메인 결정은 게시판 ADR-BRD-06

**컨텍스트(Driver)**: 사용자 지적(2026-10-22) — ① 상세의 "수정"은 제목·본문만 고치는 칸이고 첨부는 상세에서 따로 올려 "첨부만 먼저 고치는" 흐름이었다 ② 글쓰기가 모달 안의 5줄 textarea라 공지·교육자료를 쓰기엔 어색하다(실무 그룹웨어 게시판은 별도 작성 화면 + 편집 도구). 서식을 넣으려면 본문이 HTML이 되는데, 회원 웹은 [D41](D41.md)에서 갱신 토큰을 localStorage에 두면서 "사용자 HTML 렌더링이 들어오면 httpOnly 쿠키로 바꾼다"를 재고 트리거로 걸어 두었다.

**상위 목표(D53)**: 노하우 습득 — 서식 편집기를 붙일 때 실무가 "무엇을 저장하고 어디서 거르나"를 어떻게 정하는지 직접 겪는다. **핵심 변수**: XSS(회원 웹 토큰 저장 위치), 기존 평문 글과의 호환, 번들 크기. **답안지**: OWASP XSS 지침 — 서식 HTML은 허용 목록 정화(sanitize)로 받고, 보일 때 한 번 더 거른다(심층 방어).

## 결정 (사용자 선택 2026-10-22: "WYSIWYG 편집기", "허용 목록 정화 + 두 겹 방어")

1. **화면**: 글쓰기 `/board/new`, 수정 `/board/:id/edit`를 별도 화면으로. 한 화면에서 제목·카테고리·대상(지점/시설)·본문·첨부를 다룬다. 새 글 첨부는 골라 두었다가 등록 직후 올리고(글 id가 있어야 올릴 수 있다, 하나가 실패해도 글은 남는다), 수정 화면 첨부는 바로 올리고 지운다. 상세는 읽기 전용(작성자의 첨부 올리기·지우기는 수정 화면으로, 본사의 지우기는 상세에도 남김).
2. **편집기**: TipTap v3(StarterKit — 제목 2·3단계, 굵게·기울임·밑줄·취소선, 목록 2종, 인용, 구분선, 링크, 되돌리기). 코드 블록·이미지·표·글자색은 넣지 않는다 — 이미지는 첨부(ADR-BRD-04)로. 편집기는 무거워(약 410KB, gzip 133KB) 작성·수정 화면에 들어갈 때만 내려받는다(지연 로딩).
3. **저장 형식**: 본문은 정화된 HTML. api가 저장 전에 `sanitize-html` 허용 목록으로 거른다(`posts/post-content.ts` — 태그 `p br h2 h3 strong em s u ul ol li blockquote hr a code pre`, 속성은 `a`의 `href`만, 스킴 http(s)·mailto, 링크는 `target=_blank rel="noopener noreferrer nofollow"` 강제). 태그로 시작하지 않는 입력(예전 방식·api 직접 호출)은 줄마다 `<p>`로 바꾼다. 거른 뒤 글자가 없으면 400 `POST_CONTENT_EMPTY`.
4. **두 번째 방어선**: 두 웹이 보일 때 DOMPurify로 같은 허용 목록을 한 번 더 적용한다. 예전 평문 글(블록 태그로 시작하지 않음)은 HTML로 해석하지 않고 글자로 그린다 — 데이터 이관 없음.
5. **D41 재고 트리거 검토 결과**: 회원 웹에 사용자 HTML이 들어오지만, 쿠키 전환(인증 방식 변경 — 승인 대상·api·두 웹·CSRF) 대신 허용 목록으로 위험을 닫는다. 허용 목록에는 스크립트를 실행할 수 있는 태그·속성(이벤트 속성, `style`, `img`, `iframe`, `javascript:`)이 없다. 토큰 저장 위치는 그대로다.

## 감수하는 것

- 허용 목록 밖 서식(표·글자색·본문 이미지)은 못 쓴다. 필요해지면 목록을 넓히되 api·두 웹을 함께 바꾼다(세 곳 동기화 — 목록이 코드 세 곳에 있다).
- `sanitize-html` 2.18.1은 ESM 전용 `htmlparser2` 12에 기대 jest 설정에 ESM 변환을 넣었다(`apps/api/jest.config.js`). 2.17.x 이하는 XSS 권고가 있어 내리지 않았다. Node 22의 `require(esm)`로 빌드·Lambda 번들은 그대로 돈다.
- 관리자 웹 처음 번들은 그대로(약 500KB), 편집기는 별도 묶음.

**재고 트리거**: 허용 목록을 넓혀야 할 때(특히 `img`·`style` — 그때는 D41 쿠키 전환을 함께 검토), `sanitize-html`·DOMPurify에 우회 권고가 나올 때.
