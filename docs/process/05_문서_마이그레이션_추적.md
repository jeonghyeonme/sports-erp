# 문서 구조 마이그레이션 추적표

> **상태**: 초안 (2026-09-22). **폴더 구조 1차 개편 완료(2026-09-22)**: 이 문서를 포함한 과정 기록물은 `docs/process/`, 도메인 사이클 산출물은 `docs/domains/<도메인명>.md`(번호 없이 도메인명으로 명명), 도메인에 안 걸리는 공용 값은 `docs/architecture/`로 분리했다(옛 `docs/requirements/` 폐지). 최종 목표 트리는 이 대화 기록 참고 — 별도 문서화는 아직 안 함.
> **목적**: `docs/domains/` 문서가 기존 `docs/1.spec/`·`docs/2.decisions/` 문서를 **흡수해서 대체**하는 과정을 추적한다. 원칙은 **도메인당 파일 하나만 남긴다** — "유지"(옛 문서를 레퍼런스로 남기는 것)는 최대한 피하고, 기본값은 **병합 후 원본 삭제**다.
> **실행 방식**: 병합(레퍼런스+결정 내용을 도메인 사이클 문서로 옮기는 것)은 해당 도메인 사이클 안에서 바로 한다. 다만 **물리적 삭제는 그 문서를 참조하는 다른 문서의 링크를 다 고친 뒤에만** 한다 — 안 그러면 참조 문서들이 깨진 링크를 갖게 된다. 그래서 각 행은 "병합 완료(원본 삭제 대기)" 상태를 거친다.

## 판정 기준

- **병합 완료 → 삭제 대기**: 옛 문서 전체(레퍼런스+결정 서술)를 도메인 사이클 문서로 이미 옮겼다. 옛 문서 상단에 대체 배너를 달아 편집을 막는다. 실제 삭제는 아래 "삭제 전 정리할 inbound 링크" 목록이 비워진 뒤 실행한다.
- **유지 (예외, 최대한 피함)**: 도메인 사이클 문서 형식에 안 맞고 다른 구조적 자리도 마땅치 않은 경우만. 예: 여러 도메인에 걸친 공통설계서(1-1), 발표자료 원본. 유지를 선택하면 반드시 이유를 적는다.
- **확인 필요**: 아직 대조를 안 해서 판정을 못 내린 것.

## 삭제 실행 계획

1. 위 표의 각 행에서, "삭제 전 정리할 inbound 링크" 목록의 각 파일이 옛 문서(`1-2_권한관리.md`, `1-6_회원관리.md` 등)를 참조하는 곳을 대응하는 `docs/domains/<도메인>.md`로 교체(또는 문맥에 맞게 제거).
2. `4-1_발표자료_핸드오프.md`는 보호 영역이라 발표자료 작업 요청이 있을 때 같이 처리하거나, 사용자에게 별도 확인 후 처리.
3. 한 옛 문서의 inbound 링크가 다 정리되면 그 문서만 개별적으로 삭제(도메인 사이클 전체가 끝날 때까지 기다리지 않는다 — `1-1_공통설계서.md`·`2-3_요구사항추적표.md`처럼 여러 도메인이 공유하는 파일은 마지막 도메인 사이클까지 남아 있는 게 자연스럽다).
4. 이후 도메인 사이클도 같은 패턴(병합 → 배너 → inbound 정리 → 개별 삭제)을 반복한다. [03_도메인_사이클_템플릿.md](./03_도메인_사이클_템플릿.md) §12에 반영했다.
