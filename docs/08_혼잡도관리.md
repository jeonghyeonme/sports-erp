# 08. 혼잡도 관리 (Congestion)

## 1. 개요 및 조정사항

원본 요구사항: 시설별(헬스장/수영장/골프장/독서실 등) 이용현황과 혼잡도를 5개 항목으로 나누어 게시, 실시간 혹은 최대 30분 이내 반영.

**조정**: 실제 IoT 인원 계측 센서나 CCTV 기반 인원 카운팅은 하드웨어가 필요해 불가능하므로, **① 예약/체크인 데이터 기반 자동 계산 + ② 관리자 수동 보정**의 하이브리드 방식으로 구현합니다. 이 방식은 실제 중소 피트니스 업계에서도 흔히 쓰이는 현실적인 대안이라, "왜 이렇게 설계했는지"를 발표에서 논리적으로 설명할 수 있는 지점입니다.

## 2. 사용자 스토리

- 회원으로서, 헬스장에 가기 전 앱에서 지금 얼마나 붐비는지 확인하고 싶다.
- 지점 관리자로서, 자동 계산된 혼잡도가 실제와 다르면 수동으로 보정하고 싶다(예: 특별 이벤트로 사람이 몰릴 때).
- 지점 관리자로서, 시설별 정원 대비 이용률을 설정/관리하고 싶다.

## 3. 데이터 모델

### Facility (07/06 문서에서 참조하는 시설 마스터 — 이 문서에서 최초 정의)
| 필드 | 설명 |
|---|---|
| id, branchId(FK), name(예: "본관 헬스장"), type(enum: GYM, POOL, GOLF, READING_ROOM, ETC), capacity(최대 동시 이용 인원), isActive | |

### CongestionSnapshot
| 필드 | 설명 |
|---|---|
| id, facilityId(FK), currentCount(int), capacity(int, 스냅샷 시점 값 캐시), level(1~5, computed), source(enum: AUTO, MANUAL), recordedAt | |

### FacilityCheckIn (시설 이용 체크인/아웃 — 혼잡도 자동계산의 원천 데이터)
| 필드 | 설명 |
|---|---|
| id, facilityId(FK), memberId(FK), checkInAt, checkOutAt(nullable) | 회원이 시설 입장 시 QR 체크인 또는 예약 기반 자동 체크인 |

인덱스: `CongestionSnapshot(facilityId, recordedAt DESC)`, `FacilityCheckIn(facilityId, checkOutAt)`(현재 이용중 인원 조회용 — checkOutAt IS NULL인 건수)

## 4. 혼잡도 계산 로직 (핵심 설계)

```
현재 이용 인원 = COUNT(FacilityCheckIn WHERE facilityId=? AND checkOutAt IS NULL)
                 + (해당 시간대 예약 확정 건수 중 아직 체크인 전인 임박 예약, 옵션)
이용률(%) = 현재 이용 인원 / capacity * 100

5단계 매핑(원본 "5개 항목" 요건):
  0~20%   → 1단계(여유)
  21~40%  → 2단계(보통)
  41~60%  → 3단계(약간 붐빔)
  61~80%  → 4단계(붐빔)
  81%~    → 5단계(매우 붐빔)
```

- **자동 스냅샷**: 5분 주기 스케줄러(Cron)가 시설별 현재 이용 인원을 계산해 `CongestionSnapshot(source=AUTO)` 기록 → 원본의 "최대 30분 이내 반영" 요건을 5분 주기로 상회 달성
- **수동 보정**: 관리자가 값을 직접 입력하면 `source=MANUAL`로 별도 기록되고, 이후 자동 계산이 재개될 때까지(다음 스케줄 tick) 그 값이 조회 API의 최신값으로 우선 노출
- **입장/퇴장 체크인 방식**: 회원 앱에 시설별 QR 코드를 게시(정적 이미지로 충분) → 회원이 스캔 시 `POST /facility-checkins`, 나갈 때 다시 스캔 시 체크아웃 처리. QR 스캔이 번거로운 회원을 위해 관리자가 대리로 체크인/아웃 처리하는 화면도 제공(현실적 사용성 확보)

## 5. 화면 목록

| 화면 | 대상 | 설명 |
|---|---|---|
| 혼잡도 현황(회원 앱 홈) | Member | 지점 내 시설별 혼잡도 카드(색상: 초록~빨강 5단계) |
| 시설 QR 체크인 스캐너 | Member(앱 카메라) | 입장/퇴장 스캔 |
| 시설 관리(마스터) | BRANCH_ADMIN | 시설 등록, 정원 설정 |
| 혼잡도 수동 보정 | BRANCH_ADMIN | 현재 인원 직접 입력 |
| 현재 이용자 목록 | BRANCH_ADMIN | 시설별 체크인 중인 회원 리스트(안전관리 목적으로도 유용) |

## 6. API 명세

| Method | Endpoint | 권한 | 설명 |
|---|---|---|---|
| GET | /api/v1/facilities?branchId= | 전체 | 시설 목록 |
| POST/PATCH | /api/v1/facilities | BRANCH_ADMIN | 등록/수정(정원 등) |
| GET | /api/v1/facilities/:id/congestion | 전체 | 최신 혼잡도(자동/수동 최신값) |
| POST | /api/v1/facility-checkins | Member | 입장 체크인(QR) |
| PATCH | /api/v1/facility-checkins/:id/checkout | Member/BRANCH_ADMIN | 퇴장 처리 |
| GET | /api/v1/facilities/:id/current-users | BRANCH_ADMIN | 현재 이용중 회원 목록 |
| POST | /api/v1/facilities/:id/congestion/manual | BRANCH_ADMIN | 수동 보정값 입력 |

## 7. 비즈니스 로직 & 엣지케이스

- **체크아웃 누락 처리**: 회원이 퇴장 스캔을 깜빡하는 경우가 실무에서 매우 흔함 → **시설 운영 마감 시각에 배치로 미체크아웃 건을 자동 체크아웃 처리**(그렇지 않으면 혼잡도가 영원히 부풀어 표시됨). 예: 매일 23:00에 `checkOutAt IS NULL`인 모든 건을 강제 마감
- **정원 0 또는 미설정 시설**: `capacity`가 0이면 이용률 계산에서 나눗셈 오류가 나므로 등록 시 capacity 필수값(1 이상) 검증
- **자동/수동 값 충돌**: 수동 보정 후 5분 뒤 자동 계산이 다시 override — 이게 의도한 동작임을 관리자 화면에 "자동 계산은 O분 후 갱신됩니다" 안내 문구로 명시(사용자 혼란 방지)

## 8. 권한/보안 규칙

- 회원은 조회 + 본인 체크인/아웃만 가능
- BRANCH_ADMIN은 본인 지점 시설만 관리, 수동 보정 및 현재 이용자 목록(개인정보 포함이므로 최소한의 정보만: 이름+체크인시각)

## 9. 구현 우선순위

**Phase 1(필수)**: Facility CRUD, 수동 혼잡도 입력 + 조회 API(가장 구현이 간단하면서 요구사항의 "게시" 자체는 충족)
**Phase 2(선택, 완성도 어필 포인트)**: QR 체크인/아웃, 5분 주기 자동 계산 스케줄러, 미체크아웃 자동 마감 배치, 현재 이용자 목록

> 시간이 매우 부족하면 Phase 1만으로도 "혼잡도 게시" 요구사항 자체는 충족됩니다. Phase 2(자동계산)는 프로젝트의 기술적 완성도를 가장 잘 보여주는 부분이라 가능하면 포함을 권장합니다.

## 10. 테스트 체크리스트
