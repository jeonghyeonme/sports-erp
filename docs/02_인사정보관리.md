# 02. 인사정보관리 (Staff Management)

## 1. 개요 및 조정사항

원본 요구사항: "현장별 인사관리 탭/코드 생성", "모든 인사기록정보 통합 조회", "권한/승인 시 수정 가능".

**조정**: "승인 기반 수정"의 복잡한 결재라인(다단계 결재)은 1인 개발 범위를 넘어서므로, **본인 신청 → 관리자 승인(1단계)** 구조로 단순화합니다. 대신 인사기록 자체(이력, 재직상태, 부서/직급)는 실사용 가능한 수준으로 충실히 구현합니다.

## 2. 사용자 스토리

- 지점 관리자로서, 신규 직원을 등록하고 직급/입사일을 관리하고 싶다.
- 본사 관리자로서, 전 지점 직원 현황을 하나의 화면에서 조회하고 싶다(원본 "한 화면 조회" 요건).
- 직원으로서, 내 인적사항 변경(연락처 등)을 신청하면 관리자 승인 후 반영되길 원한다.
- 지점 관리자로서, 퇴사 처리 시 퇴사일을 기록하고 계정을 자동으로 비활성화하고 싶다.

## 5. API 명세

| Method | Endpoint | 권한 | 설명 |
|---|---|---|---|
| GET | /api/v1/staff | SUPER_ADMIN(전체), BRANCH_ADMIN(본인 지점) | 목록, `?branchId=&status=&position=` |
| POST | /api/v1/staff | BRANCH_ADMIN | 신규 등록 (staffCode 자동 생성) |
| GET | /api/v1/staff/:id | 해당 지점 권한자 | 상세 |
| PATCH | /api/v1/staff/:id | BRANCH_ADMIN | 직접 수정(관리자는 승인절차 없이 즉시 수정 가능) |
| PATCH | /api/v1/staff/:id/resign | BRANCH_ADMIN | 퇴사 처리 → resignDate 기록 + status=퇴사 + **연결된 Account.isActive=false 자동 처리** |
| POST | /api/v1/staff/:id/change-requests | Staff 본인 | 변경 신청 |
| PATCH | /api/v1/staff/change-requests/:id/approve | BRANCH_ADMIN | 승인 → Staff 필드 반영 |
| PATCH | /api/v1/staff/change-requests/:id/reject | BRANCH_ADMIN | 반려 |

## 6. 비즈니스 로직 & 엣지케이스

- `staffCode` 생성 규칙: 지점 코드 + 해당 지점 내 순번(zero-padded 3자리). 동시 등록 race condition 방지를 위해 DB 트랜잭션 + 지점별 시퀀스 테이블 또는 `SELECT ... FOR UPDATE` 사용
- 퇴사 처리(`/resign`)는 **트랜잭션으로 Staff.status 변경 + Account.isActive=false를 원자적으로 처리**(01문서 §6과 연결되는 핵심 지점 — 이 API가 "퇴사 즉시 접근차단"의 실제 트리거)
- 변경 신청은 필드 단위로 diff 저장(전체 프로필 재제출이 아님) → 승인자가 무엇이 바뀌는지 명확히 확인 가능
- 퇴사한 직원은 목록에서 기본적으로 숨기되(`status != 퇴사`), 필터로 조회 가능하게 유지(이력 보존)

## 7. 권한/보안 규칙

- BRANCH_ADMIN은 본인 지점 직원만 CRUD, 타 지점 staffId 접근 시 403(00문서 BranchScopeGuard)
- Staff 본인(Role=STAFF)은 자신의 레코드 조회 + 변경 신청만 가능(직접 수정 불가). 01문서의 STAFF 권한 매트릭스와 동일하게 타 직원 레코드는 조회조차 불가
- 전화번호 등 연락처는 목록 화면에서는 뒷자리 마스킹(`010-****-1234`), 상세 화면 진입 시 전체 노출(접근 로그 AuditLog 기록)

## 8. 구현 우선순위

**Phase 1(필수)**: 직원 CRUD, 지점별 목록/필터, 퇴사 처리(+계정 비활성화 연동)
**Phase 2(선택)**: 변경 신청/승인 워크플로우, 통합조회 화면의 고급 필터, 연락처 마스킹 UI

## 9. 테스트 체크리스트

- [ ] 신규 직원 등록 시 staffCode 자동 생성 및 중복 없음

- [ ] 변경 신청 승인 시 Staff 레코드에 실제 반영, 반려 시 미반영
